Expand description

What arithmetic can fail with, carrying the interpreter’s error numbers.

Variants§

§

Overflow

Result exponent above MAX_EXPONENT, from mul/div/add/sub/ pow’s shared final range check (check_range, below). Error 42.901; additional() is [adjusted_exponent, "9"].

Fields

§adjusted_exponent: i32
§

Underflow

Result exponent below MIN_EXPONENT, same call sites as Overflow. Error 42.902; additional() is [exponent, "9"] – the raw exponent, not the adjusted one Overflow uses.

Fields

§exponent: i32
§

ZeroToNegativePower

Zero raised to a negative power: an underflow, not infinity. Error 42.903, no substitution. Raised only by pow.rs.

§

PowerOverflow

**’s own upfront magnitude check, refusing a hopeless computation before attempting it. Error 42.001; additional() is [base, "**", exponent]. Raised only by pow.rs.

Fields

§base: Number
§exponent: Number
§

DivideByZero

A zero divisor, for /, %, or // alike. Error 42.003, no substitution.

§

ExponentComputationOverflow

Three checked_add/checked_sub guards in muldiv.rs, believed unreachable (both operand exponents are already bounded to +/-MAX_EXPONENT, so their sum/difference cannot overflow i32 in practice). No substitution, because there is no valid exponent left to report if this ever does fire – that is the failure itself. Falls back to the bare 42.000 text, which the interpreter itself never emits.

§

IntegerDivideNotWhole

%’s quotient needs more digits than DIGITS allows. Error 26.011, no substitution. Raised only by muldiv.rs’s div.

§

RemainderNotWhole

//’s quotient needs more digits than DIGITS allows. Error 26.012, no substitution. Raised only by muldiv.rs’s div.

§

PowerExponentNotWhole

**’s exponent, after rounding to DIGITS, is not a whole number. Error 26.008; additional() is [exponent]. Raised only by pow.rs.

Fields

§exponent: Number
§

SystemResources

An up-front working-storage reservation sized by DIGITS failed, so a huge – and, since the u64 widening, perfectly legal – DIGITS fails here before any arithmetic starts. Error 5, no substitution.

impl ArithError

Source

pub fn code(self) -> u16

The major number a trapped Rexx program sees in RC (condition('o') ~code is this pair’s major half). For the sub-number too – what distinguishes 42.3 from 42.901 and 42.902, all of which are major 42 – see ArithError::sub_code, which also returns this same major alongside it.

Source

pub fn sub_code(&self) -> (u16, u16)

The (major, sub) pair identifying this failure’s exact entry in the generated message table – code() only ever exposes major (the interpreter number a trapped Rexx program sees in RC), so message/additional need this to pick the right table row, and so does any other caller that has to report the sub-number a trapped SYNTAX condition would carry (condition('o')~code’s minor half).

Source

pub fn additional(&self) -> Vec<String>

The substitution values in the interpreter’s own order – what condition('o')~additional returns for this failure: [5, 10] for a FuzzNotBelowDigits-shaped 33.001, [] (an empty array, not absent) for a no-substitution message like DivideByZero.

Source

pub fn message(&self) -> String

The interpreter’s message text for this failure, rendered from the generated table on demand – every sub-message verified against build/bin/rexx.
