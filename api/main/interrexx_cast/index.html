Numeric conversions that say what they keep.

The workspace denies as between numeric types (clippy::as_conversions): an as reads the same whether it is exact, rounds or drops bits, and which one it is can change with the target. This crate is the one place such a conversion is written, each under a name that says which it is:

  • CastFrom / CastInto: exact, for the pairs From does not cover because they involve usize or isize. A pair is implemented only on the targets where it is exact: u64 to usize exists on a 64-bit target and not on a 32-bit one, so code that needs it there does not compile and has to say what it does with a value that does not fit (try_from).
  • CastLossy: to a float, rounding to the nearest representable value.
  • CastTruncate: to a narrower integer of the same signedness, keeping the low bits, for hashing, masking and fixed-width fields.
  • TryCastFrom: from a float to an integer, toward zero, or None where the value is not finite or does not fit.
  • const fns for the exact widenings a constant needs, where neither a trait nor From can be called.

A change of signedness at the same width is cast_signed and cast_unsigned in std. A pointer’s address is addr, and an address made into a pointer is std::ptr::without_provenance.
