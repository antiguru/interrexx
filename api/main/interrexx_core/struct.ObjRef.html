Struct ObjRef 

Source 
pub struct ObjRef(/* private fields */);
Expand description

Not Send or Sync: a handle is meaningless off the island that allocated its slot, and only interrexx’s Islanded carries one to another OS thread (design section 2.5).

ⓘ
fn require_send<T: Send>(_: T) {}
require_send(interrexx_core::ObjRef::NIL);
ⓘ
fn require_sync<T: Sync>(_: T) {}
require_sync(interrexx_core::ObjRef::NIL);

A type that actually is Send and Sync passes the same two checks, so the failures above are ObjRef’s doing and not some unrelated mismatch:

fn require_send<T: Send>(_: T) {}
fn require_sync<T: Sync>(_: T) {}
require_send(0u64);
require_sync(0u64);

repr(transparent), so a register holding one is the u64 itself, which is what code generated for a frame reads and writes.

pub fn heap_bits(bits: u64) -> Option<Self>

The heap reference bits are, if they carry the heap tag: what an extension’s handle names once the table that minted it is gone. The slot may be free or reused; the heap’s own lookup decides.

Source

pub fn carried(bits: u64) -> Option<Self>

The value bits carries, if they are exactly the bits of an integer, a short string or .nil held in the handle itself; None for a heap reference and for bits no constructor produces. Such a value names no heap object, so it is the same value wherever the bits come from.
