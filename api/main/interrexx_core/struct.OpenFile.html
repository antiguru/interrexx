Expand description

The descriptor an open stream holds, with the logical positions one descriptor serves. The character positions are 1-based “next byte”, . A SEEK that would move one below 1 fails, so a write position is 0 only on a stream opened READ, which has none.

A stream is buffered unless it was opened NOBUFFER or is a terminal (rexxref streamclasses.xml, NOBUFFER): its writes reach the file when STREAM_BUFFER bytes have gathered, when the next write does not follow on, and before anything reads, measures or positions the descriptor through OpenFile::flushed, so another stream or process sees them only from then on. A drop writes what is left.

Fields§

§read_position: i64§write_position: i64§pending: Option<u8>

A byte taken from a transient stream to learn whether data waits, which the next read returns first. Only a device that cannot say how much waits without being read leaves one.

§transient: bool§line_mark: Option<(i64, i64)>

A character position and the line it lies in, from the last line operation. Any write landing before the position drops it, so it is always what a count from the start would answer.

§line_mark_digest: Option<u64>

Debug builds only: digests of the bytes OpenFile::line_mark and OpenFile::line_total were counted over, so a check of either runs only while those bytes are unchanged. Another stream object or process writing the file may leave the line answers stale (the reference documentation says so); the checks then stand aside.
