Module constants 

Source
Expand description

The constants the headers in include/ define, by their C names.

Each value is the one the interpreter uses: where Rust code already names the value, the table takes it from there, so the header and the code that reads what an extension passes cannot disagree. The header generator (header.rs) writes these tables, and the ABI dump (tests/abi_dump.rs) reads every value back through a C and a C++ compiler.

Constants§

API_VERSIONS
The interface versions and interpreter and language levels, in oorexxapi.h. A _<x>_<y>_<z> name is the version a release of that number carried; the unsuffixed name is the one this interpreter’s tables carry.
ARGUMENT_TYPEDEFS
The names a routine or method declaration may give as a special argument’s type, and BUFFER, each with the tokens of the Rust type it names, in oorexxapi.h. Each special argument’s name is the type of the argument its descriptor carries.
ARGUMENT_TYPES
Each value code’s name and the tokens of the Rust type of the argument an entry receives for it, ARGUMENT_TYPE_<name> in oorexxapi.h.
CLASSIC_CONSTANTS
The classic API’s codes, in rexxapidefs.h.
CLASSIC_LIMITS
The classic API’s limits and the codes RexxCallBack answers, in rexx.h.
ENTRY_CONSTANTS
The constants of a library’s entry tables and of the argument descriptors its stubs read, in oorexxapi.h.
ENVIRONMENT_KINDS
The kinds of command environment AddCommandEnvironment adds, in oorexxapi.h.
OPTIONAL_VALUES
The value codes that have an optional form, REXX_VALUE_OPTIONAL_<name>. A code that takes no argument, and the variable reference code, have none.
OPTION_NAMES
The names of the options of a new interpreter instance, each the C name and the string it stands for, in oorexxapi.h.
VALUE_ALIASES
Second names of value codes, each a platform’s name for the C type of another: the alias and the name it stands for.
