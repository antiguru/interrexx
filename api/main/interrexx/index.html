The executor.

Modules§

capi
The classic C API’s queue, registration and macrospace operations, over this process’s one API connection, and the entry-point (...Exe) registrations, which stay in the process.
compiled
The compiled program image rexxc writes: a #! line and a metadata header layout, with this build’s own magic number and format version, then the SHA-256 digest of everything after it, then the name of the routine the image holds, as a 4-byte little-endian length and its bytes, then the checked source. An image whose bytes after the digest do not give it is refused (r[env.invocation.rexxc.damaged]), so a damaged image does not run. The digest is not keyed: it catches damage, and an image edited on purpose can carry a digest of its own. No compatibility is promised between versions of this crate.
embedding
The embedding entry points over safe values: the classic RexxStart and the instance API’s RexxCreateInterpreter. The librexx exports read the caller’s C structures and write the answers back.
launcher
The rexx and rexxc command lines’ library half: option scanning, the program search, and the texts the launchers print themselves.

Constants§

DEADLINE_EXIT
The status a run abandoned at its own deadline exits with (Invocation::with_deadline).
DEADLINE_REPORT
The stderr line a run abandoned at its deadline leaves behind.
HASH_SEED_ENV
The environment variable that fixes the seed of the keyed string hash, so that a run’s hashCode answers can be had again: decimal digits naming a number below 2**64. The empty string is the same as no value.
HEAP_LIMIT_ENV
The environment variable that bounds the body bytes the heap may hold (r[env.invocation.heap-limit]): decimal digits, optionally followed by K, M or G for that many binary kilo-, mega- or gigabytes. The empty string is the same as no value, which leaves the heap unbounded. An Invocation::with_heap_limit overrides it.
INTERPRETER_STACK_BYTES
The interpreter thread’s stack, in bytes.
NOT_IMPLEMENTED_EXIT
The exit code for a construct this crate does not implement.
SIM_CHILD_ENV
Set in the environment of a child a run in the simulation mode starts: the child writes no rexx-sim: line, since its standard error may be one the parent program reads.
UNBUFFERED_ENV
The environment variable that asks for standard output to be handed over a line at a time, as ooRexx writes it, rather than in blocks: any value but the empty string (r[instr.say.deviation.40]).
