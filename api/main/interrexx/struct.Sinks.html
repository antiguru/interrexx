Expand description

What an embedding that owns real descriptors hands the interpreter’s two output buffers to as the program runs.

The interpreter never writes to a descriptor: it appends to two buffers, and without sinks nothing is written until the caller drains Outcome. With them, each buffer is handed over before a read, before the thread idles, before a command starts, and as Sinks::stdout_terminal says between those, which is the buffering of C stdio and Python 3 (Deviation 40). The rest stays for the Outcome.

Fields§

§stdout: Box<dyn FnMut(&[u8]) -> Result<()> + Send>

Takes what SAY and .STDOUT have written since the last handover, answering the error that kept it from the descriptor, which the stream writes to standard output then answer.

Send, because the interpreter runs on a thread of its own (on_interpreter_thread), which is where the sized stack it needs comes from.

§stderr: Box<dyn FnMut(&[u8]) -> Result<()> + Send>

The same for the trace sink, which is .STDERR’s descriptor too.

§stdout_terminal: bool

Whether stdout writes to a terminal, which is handed each line as it ends. Any other stdout is handed its buffer once it passes 64 KiB, and stderr is handed each line whatever it writes to.

§unbuffered: bool

Whether stdout is handed each line as it ends whatever it writes to, as a terminal is: what unbuffered_requested answers, or rexx -u (r[instr.say.deviation.40]).

§own_descriptors: bool

Whether stdout and stderr write this process’s own standard output and error. A command whose output or error is not redirected then writes that descriptor itself, once the buffers have been handed over; otherwise its writes are read back and handed over with the interpreter’s own.
