# Every extracted `base/keyword` body that does not pass today. One
# `GROUP::METHOD<TAB>unblocked_by` per line; lines starting with # are
# comments.
#
# Measured at ooTest r13624. This is the committed set `keyword_assertions.rs`
# polices in both directions: a body here that starts passing is as red as a
# body not here that starts failing, so an improvement shows up in a diff rather
# than being quietly absorbed.
#
# For a body that fails loudly the `unblocked_by` column is not hand-written: it
# is derived from the refusal on every run, using its owner or the known defect
# it names. The attribution describes what the body hits first.
#
#   RAISED  Not an attribution: the harness's own word for "exited non-zero and
#       named no construct". Each row carrying it needs its cause written here:
#
#       CALL::test_expression and CALL::test_literal fail under the C++ oracle
#       itself (Error 43, Routine not found) because they call ::routines the
#       standalone program does not carry (routine "label" and routine ""). An
#       unresolved routine name raises 43.1 here too, so this is agreement
#       with the oracle. Neither body can pass by implementing anything,
#       because the extraction dropped the ::routines they call.
#
#       CALL::test_on_name: the third clause of the body is `call charin "/"`.
#
#       NUMERIC::test_42: `::method "test_42"` is the only method in its
#       neighbourhood with no `return` before its trailing
#       `dig: Return digits()`, so the extracted program falls into that
#       subroutine and its RETURN value becomes the program's exit code. The
#       C++ oracle exits 3 on the same program, so this is the extraction and
#       not a divergence.
#
#       CATCH::* and FINALLY::*: the bodies use CATCH and FINALLY clauses, which
#       belong to language level 6.07; interrexx implements 6.06
#       (`docs/design/decisions.md`, the language level), which has no such
#       clause, so the condition a body expects its clause to catch ends the
#       program instead. The two missing-comma fixtures accept NOTREADY as
#       a code variable and reach the CATCH runtime refusal.
#
#       RAISE::test_RAISE_RETURN_result_signal_on and ...EXIT...: the bodies
#       call the group's ::routines raisableConditions and signalOnResult,
#       which the extracted program does not carry; the C++ oracle raises 43.1
#       on the same call, so this is agreement with the oracle.
#
