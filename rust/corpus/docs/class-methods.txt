# Table C's method row set: one row per (class, method, arm, status).
#
# One
# `class<TAB>method<TAB>arm<TAB>status<TAB>section<TAB>origin<TAB>reason`
# per line. `section` is the mth* section that documents the method, and
# `origin` is the file:line WHERE THE NAME CAME FROM -- so every row
# cites the book, and following the citation lands on the name.
#
# Those two are usually the same place and for a few rows they are not,
# because the book does not always display a section's own title. A
# class table's `<member>` links to its `mth*` section through an
# `<xref>` whose `xrefstyle` decides the rendered text: `select:title`
# renders that section's `<title>`, and `template:<text>` replaces it
# with `<text>` outright. Where a member overrides the title, the row
# set carries BOTH names -- the title's and the displayed one -- because
# measured on the oracle both answer, and the row whose name came from
# the override cites the member rather than the section.
#
# clsDateTime's constructor entry is the worked case: the member at
# utilityclasses.xml:2076 displays `new (Inherited Class Method)` and
# points at mthDateTimeInit, whose title is `init`. So `DateTime init`
# cites the section at :2570 and `DateTime new` cites the member at
# :2076. Measured, .DateTime~hasMethod("NEW") is 1 with the instance arm
# 0, and .DateTime~hasMethod("INIT") and .DateTime~new~hasMethod("INIT")
# are both 1. clsTimeSpan is the same shape at :11426.
#
# An xrefstyle that neither renders the title nor is one the extractor
# has decided about is a hard error, not a fallback to the title: the
# row it should have produced would never be derived, and a check
# comparing the derivation against this file cannot see a row that is
# absent from both sides.
#
# `arm` is which readback instrument the row is asked on -- `class` is
# `.X~hasMethod("M")` and `instance` is `.X~new~hasMethod("M")`.
# Neither instrument answers both questions: measured,
# `.Array~hasMethod("OF")` is 1 and `.Array~new~hasMethod("OF")` is 0.
#
# The completeness evidence over this file is that every `covered` row
# answers on ONE ARM OR THE OTHER on the oracle. The scope to `covered`
# is what makes it achievable: a `not-covered` class has no instance, so
# measured, all three of `.Alarm~hasMethod("CANCEL")`,
# `("TRIGGERED")` and `("SCHEDULEDTIME")` are 0 while `.Alarm~new`
# raises 93.901.
#
# The two concatenation operators have no printable spelling, so they are
# written as the placeholders the class tables use. Measured, the names are
# the empty string and a single blank: `.Object~method("")` and
# `.Object~method(" ")` both answer `The Method class`.
#

#
