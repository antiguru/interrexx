The interrexx Language Specification

The header files

rexxref: Rexx C++ Application Programming Interfaces

A native library, and a program that embeds the interpreter, is compiled against the header files that come with the interpreter, in the directory include/ of this repository. This page states what those files declare beyond the functions the other pages of this chapter describe: the files and their platform part, the types, the families of constants, the flag words of the exit parameter blocks, the C++ methods of the contexts, and the macros that declare a library's routines, methods and tables. What each function of the interface does is stated where a program can observe it, on the loading page, the calls page, the threads page and the command handlers page. The rules of this page are checked by compiling programs against the files, not by running Rexx examples.

Files and languages

[native.header.files]

The header set is rexx.h, the classic interface; rexxapidefs.h, its return, exit and queue codes; oorexxapi.h, the object-oriented interface; oorexxerrors.h, the error codes; and three files of a platform's own, rexxapitypes.h, rexxplatformdefs.h and rexxplatformapis.h, in the directory platform/<platform>/. A library includes oorexxapi.h, which includes all the others; a program that uses only the classic interface may include rexx.h alone, which includes the other classic and platform files. The files include a platform file by its bare name, so both include/ and its platform directory belong on the compiler's search path. Every file may be included more than once, and compiles as C99 or later and as C++11 or later.

[native.header.platform]

The names whose definition is a platform's are the types REXXPFN, process_id_t and thread_id_t, the struct REXXDATETIME, the type of the third parameter of RexxPullQueue, and the macros REXXENTRY, REXXEXPORT, __REXX64__ and SSIZE_MIN. A library may rely on each name existing on every platform, and on this much of its meaning:

  • REXXENTRY, and its other name RexxEntry, is the calling convention of every function the interpreter calls and every function it exports; a library writes it in the declaration of each of its own such functions.
  • REXXEXPORT marks a function the library exports by name.
  • REXXPFN is the type of an entry point that the classic registration functions take.
  • process_id_t and thread_id_t identify a process and a thread, as RexxSetHalt, RexxSetTrace and RexxResetTrace take them.
  • __REXX64__ is defined exactly where a pointer has 64 bits.
  • SSIZE_MIN is the least value of ssize_t.
[native.header.platform.unix]

On Unix, REXXPFN is void *, process_id_t is pid_t, thread_id_t is pthread_t, REXXENTRY and REXXEXPORT expand to nothing, and REXXDATETIME is a struct of its own, the third parameter of RexxPullQueue pointing at one. The header set is written for Unix only; another platform gets a directory of its own with the same three files.

[native.header.languages]

Compiled as C++, each context name (RexxInstance, RexxThreadContext, RexxMethodContext, RexxCallContext, RexxExitContext and RexxIORedirectorContext) names its context struct, and the struct has the methods of the context methods rule. Compiled as C, each names a pointer to its constant struct, and the structs have no methods. A function of the interface that takes RexxThreadContext * therefore takes a pointer to a pointer in C, while the interpreter passes a pointer to the struct, so C code has no supported way to use a context. A library written in C may use the types, the constants, the classic interface, the tables, and the routine and method declarations of the declaration rule whose code does not use its context; a library that calls the interpreter is written in C++.

[native.header.handles]

Each object type (RexxObjectPtr, RexxStringObject, RexxBufferStringObject, RexxArrayObject, RexxBufferObject, RexxPointerObject, RexxMethodObject, RexxRoutineObject, RexxPackageObject, RexxClassObject, RexxDirectoryObject, RexxStringTableObject, RexxSupplierObject, RexxStemObject, RexxMutableBufferObject and RexxVariableReferenceObject) is a pointer to an incomplete struct of its own. In C++, every one of them converts to RexxObjectPtr without a cast, and RexxBufferStringObject converts to RexxStringObject; no other conversion between them exists. In C none of them converts to another without a cast.

Types

[native.header.scalars]

wholenumber_t is a signed integer of the width of a pointer, the type of ssize_t. stringsize_t and logical_t are both the type of size_t; a logical_t is 0 for false and anything else for true. CSTRING is const char *, POINTER is void *, RexxReturnCode is int, and PEXIT, the parameter block an exit handler receives, is char *.

[native.header.handler-types]

The types of the functions a library or an embedding program gives the interpreter to call are function types, not pointers, except the two hooks of a package entry:

  • RexxRoutineHandler, and its other name RexxFunctionHandler, is a classic function: it takes the name it was called by, the number of its arguments, the array of its arguments as CONSTRXSTRING, the name of the current queue and the RXSTRING for its result, and answers a size_t that is 0 when it accepts the call, as the classic call rule describes.
  • RexxExitHandler is a classic exit handler: it takes the exit's function code, its subfunction code and its parameter block, and answers an int. RexxContextExitHandler is the same with the exit context before them.
  • RexxContextCommandHandler is a command handler: it takes the exit context, the name of the environment and the command, both as RexxStringObject, and answers the result object. RexxRedirectingCommandHandler takes the redirector context after them.
  • RexxPackageLoader and RexxPackageUnloader are pointers to a function that takes the thread context and answers nothing.
[native.header.special-types]

Seven names are types for a declaration's special parameters: OSELF and SCOPE are RexxObjectPtr, SUPER is RexxClassObject, ARGLIST is RexxArrayObject, NAME is CSTRING, and CSELF and BUFFER are POINTER. As a parameter of a routine or method declaration, NAME is the name the routine or method was called by, and ARGLIST is the Array of the arguments, which the argument list rule describes. As a parameter of a method, OSELF is the receiver, SUPER the class the method's scope inherits from, SCOPE the scope, and CSELF the address the receiver's variable CSELF holds as a Pointer or a Buffer. None of them is valid as a result, and none of them consumes an argument of the call.

[native.header.value-codes]

A value code names the type of a declaration's parameter or result. REXX_VALUE_<name> is the code of each name below, and ARGUMENT_TYPE_<name> is the C type of a parameter declared with it. The optional bit, REXX_OPTIONAL_ARGUMENT, is 0x8000. For a name with an optional form, REXX_VALUE_OPTIONAL_<name> is its code with the optional bit set, and ARGUMENT_TYPE_OPTIONAL_<name> is the same type as ARGUMENT_TYPE_<name>. The names that begin with two underscores are second names of a code, each of the same type. The constants of the entry tables and of an argument descriptor are:

[native.header.error-codes]

oorexxerrors.h defines a name for every error number m.n whose major number m is below 100: Rexx_ followed by the error's symbolic name, the symbol column of the table of error numbers in this repository (rust/crates/interrexx-inventory/data/errors.tsv), with the value m * 1000 + n. A minor number 0 stands for the major error itself.

Exit flag words

[native.header.exit-flags]

Seven exit parameter blocks begin with a word of one-bit flags. Each flag is an unsigned bit field, and the flags of a word take its bits from bit 0 upward in the order given here:

  • RXFNC_FLAGS, RXOFNC_FLAGS and RXEXF_FLAGS: rxfferr (bit 0), set when the function was found but refused the call; rxffnfnd (bit 1), set when it was not found; rxffsub (bit 2), set when the call is a CALL, which needs no result.
  • RXCMD_FLAGS: rxfcfail (bit 0), set when the command failed, which raises FAILURE; rxfcerr (bit 1), set when it ended in error, which raises ERROR.
  • RXMSQ_FLAGS: rxfmlifo (bit 0), set when the line goes on the queue last in, first out.
  • RXHLT_FLAGS: rxfhhalt (bit 0), set when a halt is to be raised.
  • RXTRC_FLAGS: rxftrace (bit 0), set when interactive tracing is to be on.

Context methods

[native.header.context-methods]

Compiled as C++, each context struct has a method for every function member of its own table, of the member's name, which takes the member's parameters after the context and calls the member with the context itself; on the thread context, StringSizeToObject and ObjectToStringSize spell stringsize_t as size_t, the same type, and NewBuffer and NewMutableBuffer take their size as a wholenumber_t. The method, call and exit contexts also have every method the thread context has but DetachThread, HaltThread and SetThreadTrace, each calling the thread context's member through their threadContext; their DisplayCondition answers a logical_t. The thread context, and so the three others, has the methods InterpreterVersion, LanguageLevel, AddCommandEnvironment and StackCommandEnvironment, which call the instance's member of that name; GetApplicationData, which answers the instance's applicationData; and Nil, True, False and NullString, which answer the table's RexxNil, RexxTrue, RexxFalse and RexxNullString.

[native.header.convenience]

The thread context, and so the method, call and exit contexts, also has methods of shorter names. Each calls a member named below it, with that member's parameters and result, except that StringSize spells stringsize_t as size_t; a name that calls several members is overloaded by their parameters. Declaring routines and methods

[native.header.declaration]

RexxRoutine<N>(returnType, name, t1, n1, ..., tN, nN), for N from 0 to 10, begins the definition of a routine of N parameters, and the function body written after it is the routine's code. Each tK is the name of a value code, as the value code rule lists them, with OPTIONAL_ before it for an optional parameter, and the parameter nK has the type ARGUMENT_TYPE_<tK>. returnType names the code of the result in the same way, and the body returns a value of its argument type. The body also sees a parameter context, the routine's RexxCallContext *. RexxMethod<N> declares a method in the same way, whose context is a RexxMethodContext *. The declaration defines two functions: <name>_impl, whose parameters are context and the declared ones and whose body is the code; and name, the entry a table row gives, which has C linkage in C++. Called with a null descriptor array, the entry answers the signature: the result's code, each parameter's code in order, then REXX_ARGUMENT_TERMINATOR. Called with an array, it calls <name>_impl with the values of elements 1 to N, each read as its parameter's code, stores the result in element 0 as the result's code, and answers a null pointer. REXX_TYPED_ROUTINE_PROTOTYPE(name) and REXX_METHOD_PROTOTYPE(name) declare such an entry, for a table in another source file than the declaration. Both expand to a declaration that ends in a semicolon, so a use compiles with or without a semicolon of its own.

[native.header.argument-exists]

In the code of a routine or method, argumentExists(i) is whether the argument of descriptor i was given, and argumentOmitted(i) whether it was omitted. i counts the declaration's parameters from 1, special ones included, not the arguments of the call. Both read the context, so only C++ code can use them. An omitted optional parameter of a numeric code is 0, and one of a pointer or object code is a null pointer.

[native.header.descriptors]

ARGUMENT_TYPE(t) is the signature word t without the optional bit, and IS_OPTIONAL_ARGUMENT(t) is whether the bit is set. GET_REXX_VALUE(v, t) is the value the descriptor v holds as the code named t, and SET_REXX_VALUE(v, t, value) stores value in v as that code and sets its type to the code, leaving its flags. Compiled as C++, a ValueDescriptor may be assigned a RexxObjectPtr, RexxStringObject, RexxArrayObject, RexxStemObject, RexxMutableBufferObject, CSTRING, POINTER, wholenumber_t, float or double: the assignment stores the value as the code of that type's own name and sets the type in the same way.

[native.header.tables]

A routine table is an array of RexxRoutineEntry and a method table one of RexxMethodEntry. Each row holds a style, the name the row is found by and an entry; the macros spell the name as the row's first argument is written. REXX_TYPED_ROUTINE(name, entry) is a row of style ROUTINE_TYPED_STYLE for an entry that the declaration rule defines, REXX_CLASSIC_ROUTINE(name, entry) one of style ROUTINE_CLASSIC_STYLE for a classic function, and REXX_ROUTINE(style, name, entry) one of the style given. REXX_METHOD(name, entry) and REXX_METHOD_ENTRY(name, entry) are rows of style METHOD_TYPED_STYLE. A table ends with REXX_LAST_ROUTINE() or REXX_LAST_METHOD(), a row whose fields are all zero. REXX_CLASSIC_ROUTINE_PROTOTYPE(name) declares a classic function, of type RexxRoutineHandler, with the linkage of the language compiled.

[native.header.package]

STANDARD_PACKAGE_HEADER is the first two fields of a package entry, each with the comma after it: the size of RexxPackageEntry and REXX_PACKAGE_API_NO. NO_VERSION_YET is a null package version. OOREXX_GET_PACKAGE(name) defines RexxGetPackage, with C linkage and marked REXXEXPORT, which answers the address of the package entry <name>_package_entry; the interpreter looks that function up when it loads the library.

Strings and names

[native.header.rxstring]

MAKERXSTRING(r, p, l) sets the RXSTRING or CONSTRXSTRING r to the l characters at p. RXSTRPTR(r) is its pointer, and RXSTRLEN(r) its length, or 0 where the pointer is null. RXNULLSTRING(r) is whether the pointer is null, RXZEROLENSTRING(r) whether it is not null and the length is 0, and RXVALIDSTRING(r) whether it is not null and the length is not 0. Each is an expression.

[native.header.linkage]

In C++, BEGIN_EXTERN_C() opens a block of declarations with C linkage and END_EXTERN_C() closes it; in C both expand to nothing. NULLOBJECT is the null object reference and NO_CSTRING the null CSTRING, both NULL; CONSTANT_STRING is another name of CSTRING and CONSTANT_RXSTRING of CONSTRXSTRING.
