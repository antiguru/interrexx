The interrexx Language Specification

Loading

rexxref: Directives > ::ROUTINE; Functions > Built-in Functions > RXFUNCADD

A native library provides code in one of two forms. A library with a package entry lists its routines and its methods in two tables, and the interpreter loads it as a whole. A library without one exports classic functions, each of which is registered by name, one at a time, with RXFUNCADD or a REGISTERED declaration. The examples use the fixture libraries: specfixture has a package entry and specclassic has not.

Libraries with a package entry

[native.loading.package]

A library with a package entry is loaded by a ::REQUIRES ... LIBRARY directive, by the loadLibrary method of a package, by an EXTERNAL "LIBRARY ..." declaration of a routine or a method, or by RXFUNCADD of any name it provides. From then on until the program ends, every routine of its routine table can be called by its name from every package of the program, by CALL or as a function, in any case and as a quoted name, as the search order places it, and RXFUNCQUERY answers 0 for each. Before the library is loaded, a call of one of its routines raises SYNTAX 43.1.

signal on syntax name a
say fxhello()
a: say condition('o')~code
signal off syntax
say rxfuncquery('FxHello') rxfuncquery('FxAdd')
say rxfuncadd('FxHello', 'specfixture')
say rxfuncquery('FxHello') rxfuncquery('FxAdd')
say fxhello()
say FXADD(1, 2) 'FxAdd'(3, 4) 'fxadd'(5, 6)
call fxadd 7, 8
say result

[native.loading.once]

A library is loaded once in a program. Its package entry's loader, if it has one, runs when the library is first loaded, before any of its routines can be called and, for a ::REQUIRES directive, before the program's first clause. A later directive, loadLibrary or RXFUNCADD for the same library loads nothing and runs nothing: loadLibrary answers 1, and RXFUNCADD answers 0 for a name the library provides. The fixture's loader counts its runs in .local.

say .local~specfixture.loads
say .context~package~loadLibrary('specfixture') .local~specfixture.loads
say rxfuncadd('FxEcho', 'specfixture') .local~specfixture.loads
p = .package~new('n1zqonce', .array~of('::requires "specfixture" LIBRARY'))
say .local~specfixture.loads

[native.loading.version]

A package entry names the oldest interpreter version it works with. A library whose entry asks for a newer interpreter than the running one is not loaded: the first attempt to load it raises SYNTAX 98.982, whichever of the ways of the package rule makes it. For a ::REQUIRES directive of the main program that is before the first clause. After that refusal the library counts as loaded and provides nothing: a later ::REQUIRES directive raises nothing, loadLibrary answers 1, RXFUNCADD answers 1, and none of its routines can be called.

say 'not reached'
::requires 'specnewer' LIBRARY

call try '::routine r external "LIBRARY specnewer FxNewer"'
call try '::requires "specnewer" LIBRARY'
say rxfuncadd('FxNewer', 'specnewer') rxfuncquery('FxNewer')
say .context~package~loadLibrary('specnewer')
exit

[native.loading.table]

The names in a package's routine table are compared without regard to case. When two rows have names that differ only in case, a call of that name runs the later row, and an EXTERNAL declaration whose entry is that name binds the earlier one, as the entry rule finds it. The fixture's table has FxTwin before FXTWIN.

say fxtwin() 'FxTwin'() twin()
::requires 'specfixture' LIBRARY

[native.loading.entry]

The entry that an EXTERNAL "LIBRARY library entry" declaration names is looked for in the routine table for a ::ROUTINE directive and in the method table for a ::METHOD directive, and is matched without regard to case. A declaration without an entry names the routine's or the method's own name. The two tables are separate: a routine is not found as a method, which raises SYNTAX 90.998, and a method is not found as a routine, which raises 90.999, as an entry that neither table has does. The routine that a declaration binds can be called by the name that the directive gives it, and the method is the method of that name of the class. The class methods loadExternalRoutine of Routine and loadExternalMethod of Method take the same operand.

o = .n1zqk~new
say hi() fxecho('own name') (o~me == o) o~fxmessage
say .routine~loadExternalRoutine('zz', 'LIBRARY specfixture FxAdd')~call(1, 2)
say .method~loadExternalMethod('m', 'LIBRARY specfixture FXSELF')~class
call try '::routine r external "LIBRARY specfixture FxSelf"'
call try '::routine r external "LIBRARY specfixture FxNoSuch"'
call try '::class k', '::method m external "LIBRARY specfixture FxHello"'
call try '::class k', '::method fxecho external "LIBRARY specfixture"'
exit

Classic functions

[native.loading.classic]

For a library without a package entry, RXFUNCADD(name, module, procedure) registers name for the function that the library exports under the name procedure, looked up as it is spelled and, when that finds nothing, in capitals. An omitted procedure is name. When the library exports such a function, the call answers 0 and name can be called from then on. When it does not, the call answers 1, and name is registered nonetheless, as for an unknown library: RXFUNCQUERY answers 0, a call raises SYNTAX 43.1, and RXFUNCDROP removes it. A registration of a classic function is the kind that RXFUNCDROP removes, after which a call raises 43.1.

say rxfuncadd('MyJoin', 'specclassic', 'FxClassicJoin')
say myjoin('x')
say rxfuncadd('MyUpper', 'specclassic', 'FxClassicUpper') myupper('y')
say rxfuncadd('MyLower', 'specclassic', 'fxclassicjoin') rxfuncquery('MyLower')

say mylower('z')

[native.loading.classic-call]

A classic function receives its arguments as strings, in order, and an omitted argument as no string; the number of arguments does not count omitted ones at the end. It receives the name of the function in capitals, however the call spelled it. Its answer is the result of the call. A function that leaves no result makes a function call raise SYNTAX 44.1 and a CALL drop the variable RESULT, and a function that refuses the call raises SYNTAX 40.1, whose message names the function as it was registered, in capitals.

call rxfuncadd 'MyJoin', 'specclassic', 'FxClassicJoin'
call rxfuncadd 'MyNone', 'specclassic', 'FxClassicNone'
call rxfuncadd 'MyFail', 'specclassic', 'FxClassicFail'
say myjoin(1, , 3) myjoin(1, , ) myjoin(, 2)
call myjoin 'a', 'b'
say result
signal on syntax name a
say mynone()

signal off syntax
result = 'set'
call mynone
say symbol('RESULT')

say myfail()

[native.loading.registered]

A ::ROUTINE directive with EXTERNAL "REGISTERED library entry" declares a classic function: when the package is installed, the routine's name is registered for the function entry of the library, as RXFUNCADD of the routine's name, the library and the entry registers it, and the routine is that function. An omitted entry is the routine's name, which is in capitals. The routine stays bound after RXFUNCDROP removes the registration. When the library exports no such function, the directive raises SYNTAX 90.999 and leaves the registration behind.

say rxfuncquery('n1zqrr')
say n1zqrr(1, 2)
say rxfuncdrop('n1zqrr') rxfuncquery('n1zqrr')
say n1zqrr(3)
