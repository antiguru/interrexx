The interrexx Language Specification

Introduction

This book specifies the language that interrexx implements: the Rexx language as ooRexx extends it. It describes what a program means, and what the interpreter must do when it runs one.

Who it is for

The book is written for three readers: an engineer changing the interpreter, who needs the exact behavior before touching code; an LLM agent doing the same work, which may read one page at a time with no history behind it; and a reviewer judging whether a change is correct. It assumes you can read Rexx, and it does not teach the language.

Authority

This book is normative in its own right: its rules define the language interrexx implements, and no other document or implementation does. When the interpreter and a rule disagree, one of them has a defect, and the disagreement is settled here before it is settled in code. Behavior the book does not state is not promised, and where a reader might expect a promise the book says explicitly that a behavior is not specified.

Rules and examples are normative. Everything else is informative: the overview at the top of a page, and every note, which is set as a block quote that begins Note. A note explains where a rule comes from or how another definition of Rexx differs; it never adds to or changes a rule.

Terms

ooRexx. The open-source C++ implementation of Object Rexx, version 5. interrexx is written to run ooRexx programs, and the book's examples are also run on ooRexx to measure where the two agree.

Deviation. A declared difference between interrexx and ooRexx, numbered in the project's register. A page lists in its front matter the deviations that touch its element, and states each as a rule whose identifier ends deviation.N. Every example on which interrexx and ooRexx answer differently belongs to such a rule; any other difference is a defect.

String method. A method of the String class. Many builtins run as one, as the conventions define.

Identity. Whether two values are the same object, as opposed to equal strings. It is observable only through identityHash and the identity collections (IdentityTable, IdentitySet), and the book says where it is not specified.

Reading a rule

Every statement the book makes about behavior is a rule. A rule has an identifier of dotted lowercase words, and it is a single short paragraph.

An identifier names the page that holds its rule, so a reader of the raw Markdown finds any rule from its identifier alone. The first word names the chapter: bif for built-in functions in builtins/, instr for instructions/, expr for expressions/, parse for parsing/, cond for conditions/ and class for classes/. The second word is the page's file name: bif.substr.pad is in builtins/substr.md, and the rules for a whole chapter, such as bif.index.call.count, are in its index.md. The conventions are one page, conventions.md, and every conv. rule is there. The checker rejects a rule on any other page.

Identifiers never change and are never reused. Other pages refer to a rule by that identifier, and so do comments in the test sources: a test that exercises a rule cites it, and the checker reports any rule that has neither a cited test nor an example.

Reading an example

An example is a short program followed by the exact text it writes to standard output. When the program ends with a non-zero exit code, the output is marked with that code. The checker runs every example with an empty standard input and compares the output byte for byte, so an example is evidence, not decoration. An example belongs to the rule above it.

Sources

Two documents are cited by section and are not copied: the ooRexx reference manual and the ANSI Rexx standard (X3.274-1996, cited from its final public draft, so the notes call it the ANSI draft). A page's front matter names the sections that describe its element. Both are informative: the rules are derived from them and from reasoning about the semantics, and where the two disagree the rule follows ooRexx and a note says how ANSI differs. Where both are silent, a rule matches ooRexx, and a note says so. The wording of this book is its own.

Strings and characters

[conv.string.chars]

A string is a finite sequence of characters, and a character is one byte: any of the 256 values from '00'x to 'FF'x. The length of a string is the number of bytes in it. No rule in this book decodes a string in UTF-8 or any other encoding, so a character that such an encoding writes as two bytes is two characters here.

say length('c3a9'x)
say c2x(substr('c3a9'x, 2))

2
A9
[conv.string.null]

The null string is the string of length 0, written ''. A builtin makes no check of an argument its page calls a string: no string there raises an error, so the null string and a string of any bytes are as valid as any other.

say length(upper(''))
say c2x(upper('61007a'x))

0
41005A
[conv.string.object]

An argument that a page calls a string and that is an object other than a string is replaced by the answer of its STRING method, and the builtin works on that answer. When the answer is not a string either, see Deviation 30.

[conv.position.origin]

Positions count from 1. Position 1 is the first character of a string, or its first word where a page counts words, position 2 the one after it, and so on. No character or word is at position 0.

Whole-number arguments

Note. Position and length arguments are whole numbers. The two rules below say which strings a whole-number argument accepts and what value it then has.

[conv.whole.form]

A whole-number argument must be a string of this form: optional whitespace; an optional sign, + or -, which may be followed by whitespace; one or more digits, with at most one period among or around them; optionally an exponent, which is E or e directly after the last digit or the period, an optional sign, and one or more digits; optional whitespace. Any other string raises SYNTAX 40.12, the null string and a string of only whitespace included.

say substr('abcdef', ' + 2 ', 1) substr('abcdef', '2.', 1),

    substr('abcdef', '2.E0', 1)

[conv.whole.digits]

Builtins that run as String methods

[conv.method]

A builtin that runs as a String method does its work by sending the String message of the same name. One of its arguments, usually the first and for a few builtins the second, is the receiver; the others become the message's arguments, in their order. The builtin and the message then give the same result for the same arguments. A builtin page says when its builtin is one of these. The range checks below, and the order of the checks, are rules for these builtins only; any other builtin's page states its own range checks.

say substr('abcd', 2, 2) 'abcd'~substr(2, 2) upper('ab', 2) 'ab'~upper(2)

bc bc aB aB

Note. The ooRexx reference manual (Functions > Built-in Functions) names the builtins that run this way; the ANSI standard, which has no String methods, does not.

[conv.position.check]

In a builtin that runs as a String method, a position argument is a whole-number argument whose value must be positive. A value of 0 or less raises SYNTAX 93.924; -0 is 0.

say substr('abc', 0)
a: say condition('o')~code
signal on syntax name b
say word('a b', '-0')
b: say condition('o')~code
signal on syntax name c
say substr('abc', -1)
c: say condition('o')~code

say '['substr('abc', 2, 0)']' '['substr('abc', 2, '-0')']'

Pad arguments

[conv.pad]

A pad argument must be a string of exactly one character. Any character may be the pad, the blank and '00'x included. A pad of any other length raises SYNTAX 40.23; so does the null string, and so does a character that an encoding writes as two bytes (two characters).

Omitted and empty arguments

[conv.arg.omitted]

An argument is omitted when its place in the argument list holds no expression: nothing before the first comma, nothing between two commas, or nothing after the last one. An omitted optional argument takes the default that its page states.

say substr('abc', 1, , '.') substr('abc', 2, )

abc bc
[conv.arg.empty]

An argument whose expression yields the null string is not omitted and never takes the default. It is checked like any other value: as a whole number it raises SYNTAX 40.12 (whole-number form), as a pad SYNTAX 40.23 (pad), and as a string it is the null string.

signal on syntax name a
say substr('abc', 1, '')
a: say condition('o')~code
signal on syntax name b
say substr('abc', 1, 5, '')
b: say condition('o')~code

The order of the checks

[conv.check.order]

In a builtin that runs as a String method, when more than one argument fails, the form checks run first: the whole-number checks of form and value, and the pad check, applied to the arguments from left to right, and the first failure is raised. Only when every argument passes them do the range checks of positions and lengths run, again from left to right. A builtin page that has checks of its own states where they fall in this order.

signal on syntax name a
say substr('abc', 0, 'x')
a: say condition('o')~code
signal on syntax name b
say substr('abc', 0, 1, '**')
b: say condition('o')~code
signal on syntax name c
say substr('abc', 'x', 1, '**')
c: say condition('o')~code
signal on syntax name d
say translate('abc', , , '**', 'x')
d: say condition('o')~code
signal on syntax name f
say substr('abc', 0, -1)
f: say condition('o')~code

Errors and results

[conv.error.name]

A rule that says something "raises SYNTAX m.n" means that the builtin returns no value and the SYNTAX condition is raised with error number m and subcode n. A trap for it sees condition('C') as SYNTAX, condition('O')~code as the string m.n, and the variable RC set to m. This book does not state the error message.

x = substr('abc', 0)
say 'not reached'
e: say condition('c') condition('o')~code rc

[conv.returns]

A rule that says a builtin "returns" a string means that the function call's value is exactly that string: the same characters in the same order, with no blanks added or removed.

Deviations

[conv.string.deviation.30]

interrexx does not convert an argument whose STRING method answers an object that is not a string, such as a Directory. When a builtin receives such an argument where its page calls for a string, interrexx ends the program with exit code 120 and a message that this is not implemented, after raising NOSTRING when a trap for it is set. ooRexx reads the answer as a string, and what it does then depends on the builtin: UPPER ends the program with Error 5, LENGTH answers an unrelated number, and STRIP crashes the interpreter. A program can rely on none of these answers.

o = .weird~new
say 'before'
say upper(o)
say 'after'
::class weird
::method string
  return .directory~new

Built-in functions

ANSI: 9.2.1; rexxref: Functions > Built-in Functions

Deviations: D4

This chapter has a page for each builtin function, and each page specifies the function call. The rules here hold for every builtin call; the pages link to them, and to the conventions, instead of restating them.

A page's syntax line names the arguments in order. A name in square brackets is an optional argument; every other argument is required. The number of names on the line is the most arguments the builtin takes, and the number of required ones is the fewest.

[bif.index.call.count]

The argument count of a call is the position of the last argument in it that is not omitted. Omitted places at the end of the list therefore add nothing to the count, and a call with only omitted places counts as a call with no arguments, a count of 0.

Words

[bif.index.words.split]

The builtins that count words split a string into words the same way. A word is a run of one or more characters, none of them whitespace, that has whitespace or an end of the string on each side. The words of a string are numbered from 1, left to right. Whitespace before the first word, between two words and after the last belongs to no word, so the null string and a string of only whitespace have no words. Every other character, line feed and '00'x among them, can be part of a word.

say words(' a'||'09'x||'b  c ') words('') words('  '||'09'x)
say word('one  two', 2) c2x(word('a'||'0a000c'x||'b c', 1))

3 0 0
two 610A000C62

Note. The ANSI draft (9.3.26 and the other word builtins) separates words by a set of blank characters that it leaves to the configuration: the blank and any others the configuration names. ooRexx fixes that set as the blank and the horizontal tab, and so does this book.

[bif.index.words.number]

Where a word builtin's page calls an argument a word number, that argument is a position that counts words: the word number n names word n of the string as the word rule numbers them. A word number greater than the number of words in the string is not an error, for every value that passes its check; it names no word, and the builtin's page says what the builtin answers then.

say '['word('a b', 3)']' wordindex('a b', 3) wordlength('a b', 999999999999999999),
    wordpos('a', 'a b', 3)
signal on syntax name e
say wordindex('a b', 0)
e: say condition('o')~code

Answers that are counts

[bif.index.count.answer]

WORDINDEX, WORDLENGTH, WORDPOS and VERIFY each answer a count: of characters or of words, or a position, which counts characters or words up to the one it names. A builtin that answers a count writes it as a whole number in decimal digits only: no sign, no leading zero, no period and no exponent, and 0 for zero. The caller's NUMERIC DIGITS setting plays no part, so the answer is exact however many digits it has.

numeric digits 3
say wordindex(copies(' ', 1000) || 'a', 1) wordlength(copies('z', 1234), 1),
    wordpos('y', copies('x ', 1200) || 'y') wordpos('q', 'a b')
say verify(copies('a', 1200) || 'b', 'a') verify(copies('a', 1300), '', 'N', 1234),
    verify('ab', 'ab')

1001 1234 1201 0
1201 1234 0

Note. The reference manual does not say how these answers are written or whether NUMERIC DIGITS applies to them; this rule matches ooRexx.

[bif.index.count.answer.deviation.4]

interrexx does not specify whether the answer of a builtin that answers a count is the same object as another string of equal value: as an equal number the program already holds, such as the start argument of a call that answers it, or a literal such as '1201', or the equal answer of another call. Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

w = copies('x ', 1200) || 'y'
n = 1200 + 1
say (wordpos('y', w, n) == n) (wordindex(copies(' ', 1200) || 'a', 1) == '1201'),
    (wordlength(copies('z', 1201), 1) == wordpos('y', w))
v = copies('a', 1300)
say (verify(v, '', 'N', n) == n) (verify(copies('a', 1200) || 'b', 'a') == '1201')

[bif.substr.length.default]

When length is omitted, it is the number of characters of string at position n and after it: LENGTH(string) - n + 1 when n is at most LENGTH(string), and 0 otherwise.

[bif.substr.result]

SUBSTR selects and pads by character, one byte each, and copies every byte unchanged: whitespace, control characters and '00'x are characters like any other, in string and as pad.

Deviations

[bif.substr.deviation.4]

interrexx does not specify whether the result of SUBSTR is the same object as another string of equal value: as string itself, when the call returns all of it unchanged as substr(s, 1) does, or as an equal string produced some other way, such as the literal 'abc' beside substr('abcdef', 1, 3). Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'abc' || 'def'
say (substr(s, 1) == s) (substr('abcdef', 1, 3) == 'abc')

The result

[bif.wordlength.result]

When string has a word n, WORDLENGTH returns the number of characters in that word, which is LENGTH(WORD(string, n)). Whitespace around the word does not count, and a character that the word rule places inside a word, such as a line feed, counts as one. The answer is written as a count, and whether it is a new object is not specified.

say wordlength('red  green blue', 2) wordlength('  abc  ', 1),
    wordlength(' x' || '0a'x || 'y ', 1)

5 3 3
[bif.wordlength.past-end]

When n is greater than the number of words in string, the result is 0. This holds for every n past the last word that passes its check.

say wordlength('red green', 3) wordlength('red green', 999999999999999999)

0 0
[bif.wordlength.empty]

When string has no words, the null string or a string of only whitespace among them, the result is 0 for every n that passes its check.

say wordlength('', 1) wordlength('09'x || ' ', 1)

WORDPOS

WORDPOS(phrase, string [, start])

ANSI: 9.3.28; rexxref: Functions > Built-in Functions > WORDPOS (Word Position)

WORDPOS searches a string for a sequence of words and answers the number of the word where the sequence begins. Words are those of the word rule, in the phrase and in the string alike.

Arguments

[bif.wordpos.method]

WORDPOS is a builtin that runs as a String method, and string, its second argument, is the receiver; phrase and start become the message's arguments, in that order. phrase and string are strings, and start is a word number. The arguments are checked in the order the conventions give, and the argument count by the builtin call rules: two are required and three is the most.

say wordpos('b c', 'a b c') 'a b c'~wordpos('b c')
signal on syntax name a
say wordpos('a', 'a', 0)

say wordpos('a', 'a', 'one')
b: say condition('o')~code

say wordpos(, 'a')
c: say condition('o')~code

[bif.wordpos.start.default]

When start is omitted, it is 1: the search begins at the first word of string.

say wordpos('a', 'a b a') wordpos('a', 'a b a', ) wordpos('a', 'a b a', 2)

The result

[bif.wordpos.result]

When phrase has at least one word, let m be the number of its words. WORDPOS then returns the smallest word number k, with k at least start, such that string has a word k + m - 1 and, for each i from 1 to m, word k + i - 1 of string is equal under == to word i of phrase. When there is no such k, the result is 0. A phrase with no words is the case of its own rule. The answer is written as a count, and whether it is a new object is not specified.

s = 'one two three two three four'
say wordpos('two', s) wordpos('two three', s) wordpos('two three', s, 3),
    wordpos('two three', s, 5) wordpos(s, s)

2 2 4 0 1
[bif.wordpos.whitespace]

Only the words of phrase and of string take part in the search. The whitespace before the first word, between two words and after the last, in either argument, plays no part: neither how long a run of it is nor whether it is blanks or tabs changes the answer.

s = 'one two three two three four'
say wordpos('two' || '09'x || '  three', s) wordpos(' two three ', s),
    wordpos('two three', 'one two' || '0909'x || 'three')

2 2 2
[bif.wordpos.exact]

Two words are equal only when they have the same characters in the same order. Case matters, no numeric comparison is made, and a word of phrase never matches only a part of a word of string. A character that the word rule places inside a word, such as a line feed, must match like any other.

s = 'one two three two three four'
say wordpos('Two', s) wordpos('tw', s) wordpos('wo', s) wordpos('two thr', s)
say wordpos('1', '01 1.0 1') wordpos('a b', 'a' || '0a'x || 'b'),
    wordpos('a' || '0a'x || 'b', 'a b a' || '0a'x || 'b')

[bif.wordpos.overlap]

Every word number from start on is a candidate for k, including a word inside an earlier candidate that matched in part. A partial match does not make the search skip past the words it covered, so a sequence found can overlap one that was tried before it.

say wordpos('a a', 'a a a', 2) wordpos('a b a', 'a b a b a', 2),
    wordpos('a a b', 'a a a b')

2 3 2
[bif.wordpos.partial]

A sequence must lie wholly within string. When the words of phrase match the last words of string but phrase has more words after them, the phrase is not found there, and the result is 0 unless it is found earlier.

s = 'one two three two three four'
say wordpos('four five', s) wordpos('three four five', s) wordpos('x y', 'x')

0 0 0
[bif.wordpos.past-end]

When start is greater than the number of words in string, the result is 0, for every start that passes its check. A start equal to the number of words searches the last word alone.

s = 'one two three two three four'
say wordpos('four', s, 6) wordpos('four', s, 7) wordpos('one', s, 999999999999999999)
