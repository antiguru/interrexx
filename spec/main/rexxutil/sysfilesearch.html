The interrexx Language Specification

SysFileSearch

SysFileSearch(target, file, stem, [options])

rexxref: Rexx Utilities (RexxUtil) > SysFileSearch

SysFileSearch reads a text file and stores the lines that contain a string in a stem or an array, in the order of the file, with their line numbers when asked. It answers 0, or 3 when the file cannot be read.

Note. The examples write the files they search themselves and remove them.

Arguments

[util.sysfilesearch.args]

target, file and stem are required, and options is optional. The call follows the argument rule: a missing required argument raises SYNTAX 88.901, a fifth argument raises SYNTAX 88.922, and an argument that is an object other than a string is read by its string value, or raises SYNTAX 88.909 when it has none. stem is the exception to the last point: an array object or a stem object is the stem itself, and any other object that has no string value raises SYNTAX 40.925, as a name that is not a stem name does. The null string is a value for target and file: for file it names no file that can be read, and for target it matches no line.

call try "sysfilesearch()"
call try "sysfilesearch('a')"
call try "sysfilesearch('a', 'c2zqfs01.txt')"
call try "sysfilesearch(, 'c2zqfs01.txt', 'f.')"
call try "sysfilesearch('a', , 'f.')"
call try "sysfilesearch('a', 'c2zqfs01.txt', , 'N')"
call try "sysfilesearch('a', 'c2zqfs01.txt', 'f.', 'N', 'x')"
call try "sysfilesearch(.nil, 'c2zqfs01.txt', 'f.')"
call try "sysfilesearch('a', .nil, 'f.')"
call try "sysfilesearch('a', 'c2zqfs01.txt', .nil)"
call try "sysfilesearch('a', 'c2zqfs01.txt', 'f.', .nil)"
call try "sysfilesearch('a', 'c2zqfs01.txt', 'a b', 'X')"

[util.sysfilesearch.order]

The arguments are checked in this order: the count and the conversion of the arguments to strings (88.9xx); options (SYNTAX 40.900 for a character that is not an option letter, a blank included); the name of the stem (SYNTAX 40.925, with the names that SysFileTree rejects). Only then is the file opened, so a stem or an option that is wrong raises its error whether or not the file exists. An options that is the null string is allowed and means no option.

What is stored

[util.sysfilesearch.stem]

The stem is filled as SysFileTree fills it: the number of lines stored in .0, the lines in .1 to .n in the order of the file, no other tail assigned or dropped, so entries of an earlier call stay when this call stores fewer, and an array object holds the lines at the indexes 1 to n and nothing else. A call that stores nothing sets .0 to 0.

d = 'c2zqfs04'
call sysmkdir d
f = d'/in.txt'
call lineout f, 'hit one'
call lineout f, 'miss'
call lineout f, 'hit two'
call lineout f
say sysfilesearch('hit', f, 'f.') f.0 f.1 f.2 symbol('f.3')
f.3 = 'old3'
say sysfilesearch('hit', f, 'f.') f.0 f.3
say sysfilesearch('nothing', f, 'f.') f.0 f.1 f.3
say sysfilesearch('hit', f, 'g') g.0 g.1 symbol('g')
s = .stem~new
say sysfilesearch('hit', f, s, 'N') s[0] s[1] s[2]
a = .array~of('k1', 'k2', 'k3')
say sysfilesearch('hit one', f, a) a~items a[1] a~hasindex(2) a~hasindex(3)
say sysfilesearch('hit', f, a) a~items a[1] a[2]
b = .array~new
say sysfilesearch('nothing', f, b) b~items
call sysfiledelete f
call sysrmdir d

[util.sysfilesearch.match]

A line is stored when target occurs in it as a run of characters; there are no wildcards, and blanks in target count. The search ignores case unless the option C is given. The letters C and I select a case-sensitive and a case-insensitive search and, when both are given, the last decides; N stores each line as its number in the file, one blank and the line. The letters may come in any order and in either case (the option rule), and a repeated one does no harm. The number is written without padding, and the lines of the file are counted from 1, empty ones included, so the numbers of the stored lines need not be consecutive. A target that is the null string, or that contains a line feed, matches no line.

[util.sysfilesearch.lines]

A line of the file ends at a line feed ('0A'x). A carriage return that comes directly before the line feed is not part of the line; a carriage return anywhere else, a null character and a '1A'x character are. The last line of the file counts, and is stored, when no line feed follows it, and a line feed at the end of the file starts no further line. A file with no characters has no lines.

d = 'c2zqfs03'
call sysmkdir d
f = d'/in.txt'
nl = '0A'x
body = ''
do i = 1 to 9
  body = body || 'row' || i || nl
end
body = body || 'row10' || '0D0A'x || 'cr' || '0D'x || 'only' || nl || 'nul' || '00'x || 'byte' || nl
body = body || 'ctl' || '1A'x || 'z' || nl || '0D0D0A'x || 'last row, no end'
call charout f, body
call charout f
call t 'ow1', 'N'
call t '0D'x, 'N'
call t 'cr'
call t 'nul'
call t 'ctl'
call t 'last', 'N'
call t 'only'
call sysfiledelete f
f = d'/endnl.txt'
call charout f, 'one match' || nl || 'two match' || nl
call charout f
call t 'match', 'N'
call sysfiledelete f
f = d'/empty.txt'
call charout f, ''
call charout f
say sysfilesearch('', f, 'f.') f.0 sysfilesearch('x', f, 'f.') f.0
call sysfiledelete f
call sysrmdir d

The answer

[util.sysfilesearch.answer]

The answer is 0 when the file was read, whether or not a line was stored, and 3 when the file could not be opened for reading: a name that no file has, the null string, a name that is a directory, a path through a file, or a file the program may not read. In that case .0 is set to 0 and the stem is otherwise left as it was; an array object is left with no items. The file name is read as every name is and as the home rule says (Deviation 34 says where ooRexx removes a different component for a ..).

d = 'c2zqfs05'
