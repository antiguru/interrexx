The interrexx Language Specification

SysFileTree

SysFileTree(filespec, stem, [options], [tattrib], [nattrib])

rexxref: Rexx Utilities (RexxUtil) > SysFileTree

Deviations: D154

SysFileTree looks for files and directories whose names match a pattern and stores what it finds in a stem or an array: one text line per match, and in the stem a count. It answers 0.

The rules here are those of a Unix-like system. The attribute arguments exist for the sake of other systems and have no effect here.

Note. Times, the sizes of directories, the permission bits a new file gets and the order in which matches are stored belong to the host or to the file system. The examples build a tree of their own, give its files fixed times with SysSetFileDateTime, print matches in a sorted order and show host-dependent values only by their form.

Arguments

[util.sysfiletree.args]

filespec and stem are required; options, tattrib and nattrib are optional. The call follows the argument rule: a required argument that is missing raises SYNTAX 88.901, a sixth argument raises SYNTAX 88.922, and an argument that is an object other than a string is read by its string value, or raises SYNTAX 88.909 when it has none. The stem argument is the exception to the last point: an array object or a stem object is the stem itself, as the next rule says, and any other object that has no string value raises SYNTAX 40.925, as a name that is not a stem name does.

[util.sysfiletree.order]

The arguments are checked in this order, and the first failure decides the code: the number of arguments and the conversion of each argument to a string (88.9xx); the name of the stem (SYNTAX 40.925); a filespec that is the null string (SYNTAX 40.21); options (SYNTAX 40.21 for the null string, SYNTAX 40.900 for a letter that is not an option); and last the two attribute masks (SYNTAX 40.900). The stem

[util.sysfiletree.stem]

When the call returns, the stem holds the number of matches in .0 and the matches in .1 to .n (as every function that fills a stem does; the stem rule). No other tail is assigned or dropped: a call that finds nothing sets .0 to 0 and leaves the entries of an earlier call in place, and a call that finds fewer matches than an earlier one leaves its surplus entries. The stem argument names a stem variable, with or without the final period and in any letter case (as for every stem argument; the stem rule), and an argument that is a stem object is filled in the same way. An argument that is an array object is filled differently: it holds the matches at the indexes 1 to n and no item at any other index. The order of the matches is not specified.

call lineout d'/a.txt', 'x'; call lineout d'/a.txt'

What is looked for

[util.sysfiletree.spec]

filespec is a path whose last component is the pattern. * matches any run of characters, including none and including a leading period, ? matches one character, [ ] matches one of the characters listed in it or in one of its ranges such as a-o, and [! ] or [^ ] one that is not. The entries . and .. that every directory holds are never matches. In a class, a ] that comes first and a - that comes first or last stand for themselves, a range whose ends are in the wrong order matches nothing, and a name such as [:upper:] or [:digit:] stands for the characters of that kind. A [ with no ] after it is an ordinary character, and so is \: nothing in a pattern is escaped. Only the last component is a pattern. In an earlier component *, ? and [ are ordinary characters of a directory's name, so s*/x looks in a directory whose name is s*. The match is case-sensitive, and the option letter I makes it ignore case for the last component only: the directory part of a path always has to be spelled as the directory is. A pattern with no wildcards matches the entry of that name.

[util.sysfiletree.spec.dir]

A filespec that names a directory without a slash at its end matches that directory itself, and one with a slash at its end, or with * after it, matches the entries in it. A filespec whose last component is . or .. names a directory and not a pattern: it matches the entries of that directory, as the same path with a slash at its end does, so dir/sub/.. and dir/. both match the entries of dir. A path that has a component that is a file, a component that does not exist, a directory on the way that the program may not search, or a directory that the program may not read whose entries are needed (the one the last component is matched in, or the one a filespec ending in a slash names), matches nothing and is not an error; the unreadable directory itself is still matched by its own name. A relative path is read as every name is. A filespec that starts with ~ is read as the home rule says, with these exceptions. A filespec that is ~name alone, where no user has that name, is a pattern for the entries of the current directory, so it matches a directory ~name there. A filespec that starts with ~name/, where no user has that name, starts at / when only one component follows the slash, and matches nothing when more follow. A HOME that does not start with a slash is taken from the current directory, as any relative name is. Each name stored is the full name of the match, formed as QUALIFY forms a name: made absolute, with the repeated slashes, the periods and the .. components of the path taken out (Deviation 34 says where ooRexx takes out a different component). Symbolic links in the path are not replaced.

Options

[util.sysfiletree.options]

options is a string of letters, read in either case (the option rule), with no blanks. B selects files and directories, D directories only and F files only; when more than one of them is given, the last decides, and when none is given, B applies. S, I, O, L, T and H change what is searched, how names are compared and how a match is written, and are described below; a letter may be repeated and the letters may come in any order. Omitting options, or leaving its place empty, is the same as B. options that is the null string raises SYNTAX 40.21.

What is stored

[util.sysfiletree.line]

Unless O is given, a match is stored as one line of four fields: the time of the last modification, the size, the attribute string and the full name, the date and the time separated by two blanks. The time is written in the form M/DD/YY for the date and H:MMa or H:MMp for the time on a twelve-hour clock, where the month and the hour are right-aligned in two columns, the year is the last two digits of the year, and midnight and noon are 12 with a and p. T writes the time as YY/MM/DD/HH/MM, and L as YYYY-MM-DD HH:MM:SS on a 24-hour clock; L wins when both are given. The time is the local time of the host. The fields after the time are the size in a field of ten columns, the attribute string and the name, each preceded by two blanks.

[util.sysfiletree.attr]

The attribute string has ten characters, written as a long listing of the host writes the mode of a file. Matches that cannot be found

[util.sysfiletree.none]

A path that matches nothing gives .0 equal to 0 and the answer 0, whatever the reason: a pattern that no entry fits, a directory or file that is not there, a path through a file, a directory whose entries the program may not read. An entry that cannot be examined is treated in one of two ways. An entry of a directory that the program may read but not search has a name that can be read and data that cannot, so it is left out of every listing, whatever options are given. A symbolic link that points to nothing is a file, listed with the data of the link itself: its size is the length of the name it holds, its permissions are those of a link, and its kind is l. It is not a directory, so the D option leaves it out. ooRexx lists both entries with the date, size and permissions that belong to another entry. The example is not run against it.
