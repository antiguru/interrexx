The interrexx Language Specification

SysSetFileDateTime

SysSetFileDateTime(filename, [newdate], [newtime])

rexxref: Rexx Utilities (RexxUtil) > SysSetFileDateTime

SysSetFileDateTime sets the time of the last modification of a file or directory, to a date and a time given as text or to the present time. It answers 0, or -1 when it did not set the time.

Note. The examples set times in the middle of a day and a month, far from the changes between summer and winter time, because the time is a local time of the host. They read the result back with SysGetFileDateTime.

Arguments

[util.syssetfiledatetime.args]

filename is required; newdate and newtime are optional. The call follows the argument rule: a missing filename raises SYNTAX 88.901, a fourth argument raises SYNTAX 88.922, and an argument that is an object other than a string is read by its string value, or raises SYNTAX 88.909 when it has none.

d = 'c2zqst05'
call sysmkdir d
call lineout d'/f.txt', 'x'; call lineout d'/f.txt'
f = d'/f.txt'
call syssetfiledatetime f, '2031-01-15', '12:30:45'
call try "syssetfiledatetime()"
call try "syssetfiledatetime(f, '2032-01-01', '01:01:01', 'x')"
call try "syssetfiledatetime(.nil)"
call try "syssetfiledatetime(f, .nil)"
call try "syssetfiledatetime(f, '2032-01-01', .nil)"
call try "syssetfiledatetime(.mutablebuffer~new(f), .mutablebuffer~new('2032-01-01'), .mutablebuffer~new('01:01:01'))"
call try "sysgetfiledatetime(f)"
call sysfiledelete f
call sysrmdir d
exit
try: procedure expose f
  parse arg ex
  signal on syntax name bad
  interpret 'r = ' ex
  say ex '->' r
  return
bad: say ex '->' condition('o')~code
return

What is set

[util.syssetfiledatetime.set]

A call with a newdate, a newtime, or both sets the time of the last modification of filename to the date and the time given, local time, and answers 0. An omitted newdate leaves the date of the present modification time, and an omitted newtime leaves its time of day; an argument whose place is empty is omitted. The time of the last access is not changed. filename may be a directory, and a symbolic link is followed, so that the time of its target is set. A name is read as every name is (Deviation 34 says where ooRexx removes a different component for a ..), and a name that starts with ~ as the home rule says.

d = 'c2zqst01'
call sysmkdir d
call sysmkdir d'/sub'
call lineout d'/f.txt', 'x'; call lineout d'/f.txt'
f = d'/f.txt'
say syssetfiledatetime(f, '2031-01-15', '12:30:45') sysgetfiledatetime(f)
say syssetfiledatetime(f, '2032-02-16') sysgetfiledatetime(f)
say syssetfiledatetime(f, , '01:02:03') sysgetfiledatetime(f)
say syssetfiledatetime(f, '2033-03-17', ) sysgetfiledatetime(f)
say syssetfiledatetime(f,, '04:05:06') sysgetfiledatetime(f)
say syssetfiledatetime(d'/sub', '1998-07-08', '09:10:11') sysgetfiledatetime(d'/sub')
say syssetfiledatetime(f, '1969-12-31', '23:59:59') sysgetfiledatetime(f)
say syssetfiledatetime(f, '2037-12-31', '12:00:00') sysgetfiledatetime(f)
say syssetfiledatetime(f, '1970-01-01', '12:00:00') sysgetfiledatetime(f)

[util.syssetfiledatetime.now]

A call with neither newdate nor newtime sets the time of the last modification to the present time of the host and answers 0; as in the rule above, the time of the last access is not changed. A newdate and a newtime that are both empty are omitted in the same way.

d = 'c2zqst06'
call sysmkdir d
call lineout d'/f.txt', 'x'; call lineout d'/f.txt'
call sysmkdir d'/sub'
f = d'/f.txt'
old = '2001-02-03 04:05:06'
do name over .array~of(f, d'/sub')
  call syssetfiledatetime name, '2001-02-03', '04:05:06'
  address system 'touch -a -d "2001-02-03 04:05:06" 'name
  a = sysgetfiledatetime(name, 'A')
  before = date('I')
  r = syssetfiledatetime(name)
  t = sysgetfiledatetime(name)
  after = date('I')
  say r (t \== old) (before <<= left(t, 10)) (left(t, 10) <<= after) length(t)
  say (sysgetfiledatetime(name, 'A') == a) a
  call syssetfiledatetime name, '2001-02-03', '04:05:06'
  r = syssetfiledatetime(name, , )
  t = sysgetfiledatetime(name)
  say r (t \== old) (substr(t, 5, 1) || substr(t, 11, 1) || substr(t, 14, 1))
end
call sysfiledelete f
call sysrmdir d'/sub'
call sysrmdir d

[util.syssetfiledatetime.form]

newdate is read as a year, a month and a day, three whole numbers in decimal digits separated by hyphens, and newtime as an hour, a minute and a second, separated by colons. Leading white space (blanks, tabs and the other space characters of the C locale) before a number is skipped, but a blank before a separator is not allowed. The year has at most four digits and each other number at most two, and a separator has to follow a number directly for the first two numbers of each; whatever follows the third number is not read, so that 2031-01-155 is the fifteenth. A date or time that has fewer than three numbers, other separators or a number that is too long for its place gives the answer -1, and the file is not changed. The null string is such a date or time, not an omitted one. A number may start with + or -; the sign counts toward its length, and a negative number is borrowed from the next larger field as the next rule says. A time that the file system cannot hold, such as one before 1901-12-13 20:45:52 or after 2446-05-10 22:38:55 UTC on a file system with 34-bit times, is not specified: the call may answer 0 and set another time. How a year below 1000 and a year above 9999 are read is not specified either.

[util.syssetfiledatetime.carry]

A number above the largest value of its field is carried into the next larger field, and one below the smallest value is borrowed from it: month 13 is January of the next year, month 0 is December of the previous year, day 0 is the last day of the previous month, day 31 of a month with 30 days is the first of the next, hour 24 is midnight of the next day, and minute and second 60 are the next hour and the next minute. The answer is 0 and the time set is the one reached.

Failing

[util.syssetfiledatetime.fail]

The answer is -1, and nothing is created or changed, when filename names nothing, when the file's time may not be set, or when the date or time is not of the form above. filename names nothing when no file has that name, when a path goes through a file or a directory the program may not search, when it is the null string, and when it has wildcards, which no function expands (the name rule). A file the program owns can be changed whether or not it may be written. A newdate and newtime that are omitted do not make a missing file exist.
