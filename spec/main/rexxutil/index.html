The interrexx Language Specification

RexxUtil

rexxref: Rexx Utilities (RexxUtil); Rexx Utilities (RexxUtil) > A Note on Error Codes

Deviations: D34, D101

RexxUtil is the set of functions that a program calls to work with files, directories, stems, the macrospace, processes, time and the terminal. This chapter specifies the functions that exist on a Unix-like system, one page per function. This page holds what every function shares: how the functions are made available, how their arguments are read, what a name of a file is, and what the numbers they answer mean.

The pages of this chapter are:

  • SysFileDelete, SysFileExists, SysIsFile, SysIsFileDirectory and SysIsFileLink: removing a file and asking what a name is.
  • SysMkDir and SysRmDir: making and removing a directory.
  • SysFileCopy and SysFileMove: copying and moving a file.
  • SysTempFileName and SysSearchPath: inventing a name that is not in use, and finding a file along a list of directories.
  • SysStemCopy, SysStemDelete, SysStemInsert and SysStemSort: working on a stem array, and SysDumpVariables: writing the variables of the current scope.
  • The macrospace and its functions SysAddRexxMacro, SysDropRexxMacro, SysQueryRexxMacro, SysReorderRexxMacro, SysClearRexxMacroSpace, SysSaveRexxMacroSpace and SysLoadRexxMacroSpace: the routines that the service keeps for every program, and how they are added, found, moved, saved and loaded.
  • SysFileTree and SysFileSearch: finding files by a pattern and lines of a file by a string, and SysGetFileDateTime and SysSetFileDateTime: the times of a file.
  • SysSleep, SysWait, SysFork, SysCreatePipe, SysQueryProcess and SysSetPriority: time and processes, and the event semaphore and the mutex semaphore functions.
  • SysCls, SysGetKey, SysGetErrorText, SysGetMessage, SysGetMessageX, SysFormatMessage, SysLinVer, SysUtilVersion and SysVersion: the terminal, messages and versions; and the Windows-only functions.

The rules state the behavior of a Unix-like system. The examples make their own files and directories, whose names start with c, a digit and zq, apart from one named after a function in the availability rule and the names that start with ~ before that prefix, and remove them again. What a function answers for a failure is what the answer rule gives: an error number of Linux for the functions that change files, and a fixed value for the functions that the rule names.

Availability

[util.index.available]

Every RexxUtil function that exists on a Unix-like system is provided by the interpreter from the start of a program, except SysPulseEventSem, which its rule says is not provided: it needs no registration, no library directive and no file. It is called like any other function, as name(arguments) or by CALL, and its name is read in any case. It is not a method of String: sending its name to a string as a message raises SYNTAX 97.1. A label of the code that makes the call, and a routine of the program, are found before it as the search rule says, and so a name written as a string reaches the function and not the label; a file of the name of the function in the current directory is not run in its place. Among the routines that are not labels, the RexxUtil functions are where the search order puts the functions that RXFUNCADD made callable. A routine of the program, a public routine of a package that it requires, and a macro added with the order B are found before a RexxUtil function of the same name. A file and a macro added with the order A are not.

Arguments

[util.index.args]

The RexxUtil functions follow the native call rule, not the rules for the number of arguments of the other builtins: a required argument that is not given, or is omitted, raises SYNTAX 88.901; an argument past the last one of the function raises SYNTAX 88.922; an argument that is an object other than a string is replaced by the string that its request with the argument STRING answers, and an object that has none raises SYNTAX 88.909, whatever its STRING method answers. Some arguments fall back to the STRING method when request answers no string: the stem name of SysStemCopy, SysStemDelete and SysStemInsert, the whole numbers of SysStemCopy, SysStemDelete, SysStemInsert and SysStemSort, the mode of SysMkDir, the number of SysGetErrorText, the num and the inserts of SysGetMessage, the set, the num and the inserts of SysGetMessageX, the arguments of SysSetPriority, a semaphore handle and a timeout, and the items of the substitutions of SysFormatMessage. The page of each says so. An omitted place at the end of the call adds nothing to the count, and an optional argument that is omitted takes the default that the function's page states. Each page says what its function reads as a string and what it reads as a number, and which other error codes it raises. The order of these checks is the subject of Deviation 101.

[util.index.whole]

A whole-number argument of a RexxUtil function is read as BEEP reads its arguments: its number is rounded to 20 significant digits, half up, whatever the NUMERIC DIGITS of the caller, and the value after that rounding must have no fractional part. [util.index.names]

A name of a file or a directory is a string. A name that does not start with a slash is taken from the current directory. The function cleans the name up before it uses it, in the way QUALIFY does: a run of slashes is one slash, a component that is a single period is dropped, a slash at the end is dropped, and a component of two periods is dropped together with the component before it, so that the name c1zqidxd/../c1zqidxn is the name c1zqidxn even when c1zqidxd does not exist. The characters * and ? are characters of the name: no function except SysFileTree expands a pattern, so a name that holds one names a file that has them or no file. A name of the null string names nothing. SysFileTree has exceptions to this rule, which its rule for the filespec states. The file of SysAddRexxMacro, SysSaveRexxMacroSpace and SysLoadRexxMacroSpace is not cleaned: the rule of SysAddRexxMacro says how those functions read it.

[util.index.home]

A name that is ~ alone, or that starts with ~/, has the ~ replaced by the value of the environment variable HOME as it is. When HOME is the null string, ~ alone names nothing and ~/ is replaced by /. When it is any other value that does not start with a slash, no name that starts with ~/, or is ~ alone, names an entry. A name that starts with ~ and a user's name, up to the first slash or the end, stands for the home directory of that user, as it does for DIRECTORY; when there is no such user, no file has that name, and the name is never read as the name of a file of the current directory, which ./~name reaches. SysFileTree has exceptions to this rule, which its rule for the filespec states, and the file of SysAddRexxMacro, SysSaveRexxMacroSpace and SysLoadRexxMacroSpace does not follow it: a ~ there is a character of the name (the rule of SysAddRexxMacro).

[util.index.stems]

Stem arrays

[util.index.stemname]

The name of a stem that SysStemCopy, SysStemDelete and SysStemInsert take is a string, read as the conventions read any string argument, so that a MutableBuffer that holds s. names the stem s., and an object that has only a STRING method names the stem that the method answers. The name is a symbol of letters, digits and the characters !, ? and _ that does not start with a digit, with one period after it or without, in any case. The name, with the period that a name without one is given, has at most 250 characters. Any other name raises SYNTAX 40.919: the null string, a name that starts with a digit or a period, a name with a period before its last character, one that holds a blank, a character that no symbol has, a name that is too long, or the text of .nil. The stem is the one of that name among the variables of the code that makes the call, so that in a procedure it is the procedure's own stem unless the procedure exposes it. SysStemSort reads a name that has more after its first period differently, and reads an object that is not a string differently too.

[util.index.stemarray]

A stem array is a stem whose tail 0 holds the number of items, n, and whose tails 1 to n hold the items, written as plain whole numbers, so that s.01 is not an item. A function that reads a stem array reads the tail 0 first. It is n when it is a whole number, written as 4, 4, 04, 4.0, 4e0 or +4. SysStemCopy, SysStemDelete and SysStemInsert read it rounded to 18 significant digits and need a magnitude below 10**18. SysStemSort reads it rounded to 9 significant digits and needs a magnitude below 10**9. The NUMERIC DIGITS of the caller plays no part. A stem without that tail, a tail that is not a whole number after that rounding, such as 1.5 or a word, a value at or above that limit, and a stem that has only a default value (s. = 'x') raise SYNTAX 40.922: the default of a stem is never the value of a tail that has none. A count below 0 is read as a number, and each function says what it does with it. An item that the function reads, and that has no value, because it was never assigned or was dropped, raises SYNTAX 40.924, and again the stem's default does not stand for it. A position or a number of items that is outside the array raises SYNTAX 40.923. An item can be any object, and a function that moves an item moves the object itself, so that the item is still the same object. A function that changes the count writes it as a plain whole number.

Answers

[util.index.codes]

A function that works on the system answers what it did, and a failure of the system is an answer, never a SYNTAX condition. A missing file, a directory in place of a file, a refused permission and a name that is already taken leave the program running. What a function raises is limited to bad arguments, which the page of each function lists. SysFileDelete, SysMkDir, SysRmDir, SysFileCopy and SysFileMove answer 0 when they did it. Otherwise they answer the system's error number for the failure: 2 for a name that nothing has or a directory in it that does not exist, 13 for a permission that the system refuses, 17 for a name that is taken, 20 for a name that must be a directory and is not (a component before the last, or the target of a directory that is moved when that is an entry other than a directory or a regular file, such as a fifo, and not a symbolic link that leads to a regular file), 21 for a directory where a file is needed, 22 for a directory moved into itself, and 39 for a directory that is not empty. Other failures answer the system's other numbers, such as 36 for a name that is too long. The page of each of these five functions gives the number of every failure it lists, and says where the function departs from the system's number. The other functions answer fixed values, which their pages state. SysFileTree answers 0 whether or not it could read what it was asked for. SysFileSearch answers 0, or 3 for a file that it cannot read. SysSetFileDateTime answers 0, or -1 for every failure. SysGetFileDateTime answers a time, or -1. SysTempFileName and SysSearchPath answer a name, or the null string. A function that answers a state, such as SysFileExists, answers 0 or 1 and has no failure to report.
