The interrexx Language Specification

Bag

Deviations: D33, D45, D78, D84, D109, D125

A Bag holds members, each an object that is its own index, and keeps every object that is put: put always adds, so one object can be a member many times, and items counts them all. Members are found as a relation finds its indexes, by the hashCode and the == that they answer to; the methods that take an item compare by == as well. The class inherits MapCollection and SetCollection, and through them Collection; the hierarchy rule lists what it inherits. Like Set it declares its own set operations, which read their argument as a list of members and not as a list of entries, and which count how often a member occurs.

A bag has no unknown method: a message that the method search does not resolve raises NOMETHOD, as the error rule of the chapter says. Examples that show an error use a small routine try, as the builtin pages do. Where several members qualify for a method that answers one, which one it answers is not specified, and the examples then hold one member or sort the answers (the hash order rule).

The class

[class.bag.creation]

Bag declares the instance methods [], []=, allAt, allIndex, allIndexes, allItems, at, difference, empty, hasIndex, hasItem, index, intersection, isEmpty, items, makeArray, put, putAll, remove, removeAll, removeItem, subset, supplier, union, uniqueIndexes and xor, the init that new runs (the new rule) and the class methods new and of; the copy of Object copies a bag as the copy rule says. The instance methods disjoint and equivalent are those of Collection (one rule covers them). A bag has no makeString, so it is not a string (the string rule), and no unknown. Making a bag

[class.bag.new]

new makes an empty bag. Its optional argument is a hint for how large the bag will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that Bag supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

say .bag~new~items .bag~new(0)~items .bag~new(3, )~items

call try '.bag~new("x")'
call try '.bag~new(.nil)'
call try '.bag~new(1.5)'

[class.bag.of]

of(item, ...) answers a new bag of the class that received it that holds the arguments, each as often as it is given, and with no argument an empty bag. An argument that is omitted before the last one raises SYNTAX 93.903, and a trailing omitted argument counts for nothing. The method does not send new to the class and does not send put to the bag: it sends init with no argument to the new object and stores the arguments itself, so an override of new or put in a subclass is not used.

Members

[class.bag.members]

A member is any object, .nil and the null string included, and the bag stores every object that was put, whether or not an equal one is there. A member is found by the lookup: hashCode answers the same string for the argument and for the stored object, and ==, sent to the argument with the stored object as argument, answers true. For an object that declares neither method that is the same object, and an Array is its own member only. A string is a member of its characters, compared by the strict comparison: case counts, a leading or trailing blank counts, and 5 and 5.0 are two members. A class that declares == has to declare hashCode so that equal objects hash alike, as the hash code rule says. A method that takes an index considers every member that is equal to the argument, and the bag does not merge them: the objects stay distinct, and allItems answers each of them.

b = .bag~new
do x over .array~of('Key', 'KEY', 5, 5.0, ' a', '', .nil, 'Key')
  b~put(x)
end
a = .array~of(1)
b~put(a)
say b~items b~items('Key') b~items('key') b~items('5.0') b~items('a')
say b~items(a) b~items(.array~of(1)) b~items('') b~items(.nil)
b~put(.eq~new('x', 'first'))
b~put(.eq~new('x', 'second'))
say b~items b~items(.eq~new('x', 'probe')),
  b~allAt(.eq~new('x', 'probe'))~items
t = .array~new

end

[class.bag.members.sends]

at, [], hasIndex, hasItem, index, remove, removeItem and items with an index look a member up by sending hashCode to the argument, once, and then == to the argument with a stored object as the argument, for stored objects that have the same hash code, until one answers true; each of those is compared before the lookup gives up. Which further stored objects are compared, by == or hashCode, and how often, is not specified (the hash order rule); when the bag is empty, the only message is hashCode. allAt, removeAll and supplier with an index send hashCode once and == to the stored objects of the same hash code, how often to each being left open by the hash order rule. put and []= send hashCode to the item and nothing else: no == is sent, as a member is added whether or not an equal one is there; with an index they send == to the item first (the put rule). The very object that is stored is no exception to the == (the deviation rule). In the example every member hashes to the same string, so each stored member is compared; index is shown by the item rule, and the messages of uniqueIndexes are left open by the hash order rule.

Adding and reading members

[class.bag.put]

put(item) and put(item, index) add the item and answer nothing; [index] = item is the same as put(item, index), and [] = item the same as put(item). An index may be given only as another name for the item: when one is, and the item is not the very object, == is sent to the item with the index as argument first, and an answer that is not true raises SYNTAX 93.949 and leaves the bag unchanged. An index that is omitted counts for nothing. The methods take one or two arguments: none, or an omitted item, raises SYNTAX 88.901, and a third argument raises SYNTAX 93.902. The item may be any object, .nil included, and is added also when an equal member is held, so items grows by one.

[class.bag.allat]

allAt(index) answers a new Array of the stored objects that are equal to the argument, one for each member, in an order that is not specified (the hash order rule), and an empty Array when there is none. allIndex(item) is the same question asked with the item: it answers a new Array of the stored objects equal to it, and for a bag the two answers are alike. Both are instances of Array for a subclass receiver too, and do not follow later changes. xor(other) answers the object that copy of the receiver answers, holding each member as many times as the receiver and the argument differ in how often they hold it. For each member of the argument, in the order of the list rule, hasIndex is sent to the copy with the member and then either remove with the member to the copy, when that answered true, or put with the member as the only argument to a new bag made by new with no argument. Last, the copy is sent putAll with the new bag as the argument, also when the new bag is empty. A member that the argument holds more often than the receiver is therefore in the answer for the surplus, and one that the receiver holds more often for its surplus. The receiver and the argument are not changed.

b = .bag~of('a', 'c', 'c', 'd')

say x~class~id x~items (x \== a) a~items b~items sorted(x)

Messages the methods send

[class.bag.sends]

put and []= send == to the item with the index as argument when an index is given, hashCode to the item and nothing to the receiver. The other methods that look a member up, at, [], hasIndex, hasItem, index, remove, removeItem, allAt, removeAll, items and supplier with an index, send hashCode and == to the argument and nothing to the receiver (the lookup rule); allIndex sends == to the argument (the allAt rule). putAll sends put to the receiver for each member it reads (the putAll rule). The set operations send to the receiver, the argument, the copy and the new bag the messages that their rule lists. allIndexes, allItems, makeArray, supplier, copy, items, isEmpty and empty send nothing to the members. No other method asks an override of at, put or any of the methods, and [] and []= do not use at and put. In the first example a subclass has every method overridden to record its name, and each call records only its own; in the second the members record every message a program is likely to override.

[class.bag.setops.sends]

The set operations send these messages, in this order, to the receiver, to the argument, to the object that copy of the receiver answers (the copy) and to the new bag that new with no argument, sent to the class of the receiver, answers. The argument is read first as the operand rule says: "reading" below stands for the isA and the allItems or makeArray that follows it, and "for each member" means once for each position that the list rule reads. union sends copy to the receiver, reads, and for each member sends put(member) to the copy; it answers the copy. difference sends copy to the receiver, reads, and for each member sends remove(member) to the copy; it answers the copy. intersection sends new to the class, copy to the receiver, reads, and for each member sends hasIndex(member) to the copy and, when that answers true, put(member) to the new bag and remove(member) to the copy; it answers the new bag. xor sends copy to the receiver, new to the class, reads, and for each member sends hasIndex(member) to the copy and then either remove(member) to the copy, when that answered true, or put(member) to the new bag; then it sends putAll to the copy with the new bag as the argument, whose answer it does not use, and answers the copy; the putAll of Bag then sends isA and allItems to the new bag and put to the copy for each member (its rule). subset sends copy to the receiver, reads, sends remove(member) to the copy for each member and then isEmpty to the copy; it answers what isEmpty answered. Nothing else is sent to the receiver, the argument or either bag. In the example the receiver is R, the argument A, the copy C and the new bag W; the last field is the identity of the answer, - for none of them.
