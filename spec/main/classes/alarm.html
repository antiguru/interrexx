The interrexx Language Specification

Alarm

rexxref: Builtin Classes > Utility Classes > Alarm Class; Builtin Classes > Utility Classes > Alarm Class > attachment; Builtin Classes > Utility Classes > Alarm Class > cancel; Builtin Classes > Utility Classes > Alarm Class > canceled/cancelled; Builtin Classes > Utility Classes > Alarm Class > init; Builtin Classes > Utility Classes > Alarm Class > scheduledTime; Builtin Classes > Utility Classes > Alarm Class > triggered

Deviations: D109, D119, D135

An Alarm is a one-shot timer. It is made for a moment, a target that wants to hear of it and, if the program likes, an object to attach; when the moment comes it sends its target triggered, and when it is cancelled before that it sends the target cancel. The target has to be an implementation of AlarmNotification, which states what the target is sent and when; this page states how an alarm is made, what its time may be and what its own methods answer. How the library runs an alarm beside the program, and so at which time the target is reached and by which activity, is specified in the environment chapter. The examples do not depend on it: they set an alarm for a time that the program does not wait for and cancel it, or they wait on a guard that the target opens, and they print nothing that varies with the clock.

The class

[class.alarm.creation]

Alarm has the instance methods attachment, cancel, canceled, cancelled, init, scheduledTime and triggered, besides the new that every class has. It may have private methods besides these; they are not part of this specification. Its only superclass is Object, it inherits no mixin class and is not itself a mixin class (the hierarchy rule). In particular an Alarm is not an implementation of AlarmNotification: it cannot be the target of another alarm. new is the one that Class supplies: it sends init the arguments of new, which the next rule states, and answers an instance of the class that received it, so a subclass of Alarm makes instances of itself. cancel and the readers canceled, cancelled and triggered are stated in the rules on cancelling.

say .alarm~id .alarm~superclasses~items .alarm~superclass~id,
  .alarm~queryMixinClass
have = .set~new
s = .alarm~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end
names = 'attachment cancel canceled cancelled init'
names = (names 'scheduledTime triggered')~makeArray(' ')
count = 0
do name over names
  if have~hasItem(name~upper) then count = count + 1
end
say count 'of 7'

b = .sub~new(60, n)
say a~class~id b~class~id a~isInstanceOf(.alarmnotification)

Making an alarm

[class.alarm.init]

new sends init(atime, target, attachment), and init sets the alarm up. It needs the first two arguments, so new with none or only the first raises SYNTAX 93.901 and an omitted first or second argument raises SYNTAX 93.903; a fourth argument raises SYNTAX 93.902. The checks of the arguments that are present are made in this order: first the target, which must be an implementation of AlarmNotification or SYNTAX 88.914 is raised, and then the time, which raises SYNTAX 93.951 for every value that the rules below do not accept, except the very large ones for which they name other errors. So a target that is no implementation is reported even when the time is wrong too, and a refused alarm is not set. attachment can be any object, and is .nil when it is omitted. The alarm is set when init ends normally. A subclass whose init does not send init to its superclass makes an alarm that is not set (Deviation 135).

n = .note~new
call try ".alarm~new"
call try ".alarm~new(60)"
call try ".alarm~new(, n)"
call try ".alarm~new(60, , 'x')"
call try ".alarm~new(60, n, 'x', 'y')"
call try ".alarm~new('abc', .nil)"
call try ".alarm~new('abc', n)"
call try ".alarm~new(60, n)"
call try ".alarm~new(60, n, .nil)"
call try ".alarm~new(60, n, .array~new)"
exit

[class.alarm.init.seconds]

A time that is a string without a colon is a number of seconds from now. It is read as a number as the DATATYPE N rule reads it, so blanks at either end are allowed and a decimal point or an exponent is too, and it has to be zero or more: a string that is no number, the empty string and a negative number raise SYNTAX 93.951. The number is cut to the microsecond before its sign is checked, so -0.0000001 is a time of zero. A number with more than 18 significant digits is first rounded to 18, and the number is read in full whatever the NUMERIC DIGITS setting. A number of 10**12 or more, or of -10**12 or less, once it is rounded as said above, raises SYNTAX 88.903 instead, and one for which the date and time of the moment in the host's offset, as scheduledTime would answer it, would fall after 31 December 9999 at 23:59:59.999999 or before 1 January 0001 at 00:00:00.000000 (the limits of DateTime) raises SYNTAX 40.19, which is checked before the sign. The largest and smallest times accepted so depend on the host's offset, as they do for addSeconds of a DateTime of now. A TimeSpan that does so raises SYNTAX 40.19 too. The alarm is set for the moment that many seconds after init read the clock, to the microsecond. The example reads the scheduled time back, with the bounds a clock cannot break, and prints only whether they hold; under NUMERIC DIGITS 3 it shows the alarm of a number of five digits set in full.

n = .note~new

call try '-1'

call try '-2e11'
call try '1e12'
call try '-1e12'
numeric digits 3
before = .datetime~new
a = .alarm~new('12345', n)

[class.alarm.init.clock]

A time that is a string with a colon names a time of day, and may name a date. The forms are hh:mm:ss and hh:mm:ss d Mmm yyyy, with exactly one blank before the date, and nothing else is accepted: not a blank at either end, not a time with fewer than the two digits of each part, not hours of 24 or more or minutes or seconds of 60 or more, not a fraction of a second, not a date alone, not an ISO date and not a year with fewer than four digits. hh, mm and ss are two digits each; d is one or two digits, the day of the month, which must exist in that month and year, and Mmm is the English name of the month cut to three letters, written with a capital first and lower case after it (Jan, Feb, Mar, Apr, May, Jun, Jul, Aug, Sep, Oct, Nov, Dec): jan, JAN and Sept raise SYNTAX 93.951. Without a date the alarm is set for the first moment after now at which the clock of the local time zone shows that time, which is today or tomorrow. With a date it is set for that moment, and a moment that is not after now raises SYNTAX 93.951. The example prints the time of day of the scheduled time, the whole moment of those with a date and, for the others, whether the scheduled time is after now and within a day of it.

[class.alarm.init.moment]

A time that is a DateTime sets the alarm for that moment, and it has to be after the moment init reads the clock: a DateTime that is not after now raises SYNTAX 93.951. A time that is a TimeSpan sets the alarm for that long after init read the clock; it must not be negative, and a span of zero is allowed. .nil, an array and an instance of Object raise SYNTAX 93.951. scheduledTime answers the moment that was set, as its rule says. Only a string, a DateTime and a TimeSpan are read as a time. A time of zero, whether it is the number 0 or a span of zero, sets an alarm that goes off at once; the second example makes one of each and waits until its target has been sent triggered twice.

n = .note~new
now = .datetime~new
call try '.datetime~new~addSeconds(600)'
call try '.datetime~new~addSeconds(-600)'
call try '.datetime~new'
call try '.timespan~fromSeconds(600)'
call try '.timespan~fromSeconds(-600)'
call try '.nil'
call try '.array~new'
call try '.object~new'
exit

[class.alarm.init.sends]

init sends messages that a program can override, in this order: first isA to the target, with AlarmNotification as its one argument, once; the answer decides whether the target is an implementation. Then, for a time that is a TimeSpan, the span is sent totalMicroseconds, sign, days and totalMicroseconds again, once each and in that order, and for a time that is a DateTime, it is sent - once, with a DateTime of the moment of the call as the argument. A time that is a string is sent nothing (Deviation 109 covers a subclass of String). When the span is negative init stops after sign and when the DateTime is not after now it stops after -; the further messages that build the text of the error are not specified. An alarm that is refused for its target sends the time nothing. init sends no message to the attachment, and none to the alarm itself, so an override of attachment or scheduledTime does not run. The example logs the sends of an override of each message in a subclass of TimeSpan and DateTime.

.environment~log = .list~new

What the alarm answers

[class.alarm.attachment]

attachment answers the object that new was given as the third argument, the very object, and .nil when there was none. It takes no argument (SYNTAX 93.902) and sends no message. It answers the same after the alarm has gone off and after it has been cancelled.

o = .object~new

b = .alarm~new(60, n)
c = .alarm~new(60, n, 'text')
say (a~attachment == o) (b~attachment == .nil) c~attachment
a~cancel
say (a~attachment == o)

[class.alarm.scheduledtime]

scheduledTime answers a DateTime, the moment for which the alarm was set, and it takes no argument (SYNTAX 93.902). For a time that was a DateTime it is that moment, equal to the object that was given. For a time that was a number of seconds or a TimeSpan, it is the moment init read the clock plus the span, to the microsecond; for a time of day, the moment that the clock rule finds. It does not change when the alarm goes off or is cancelled, and it sends no message. The first example shows that a DateTime is answered as it was given, and its == is true (the compare rule); the second shows the sum.

n = .note~new
dt = .datetime~new~addSeconds(600)
a = .alarm~new(dt, n)
say (a~scheduledTime == dt) a~scheduledTime~class~id
a~cancel
say (a~scheduledTime == dt)
signal on syntax name bad

[class.alarm.triggered]

triggered answers 1 when the alarm has gone off and 0 otherwise, so 0 for an alarm that is still waiting and for one that was cancelled before it went off. The flag is already 1 when the target is sent triggered, so the target's method sees it. It takes no argument (SYNTAX 93.902) and sends no message. The method is a reader of that flag; AlarmNotification's triggered is another method, which the target has (the notification rule). The library sends triggered to the target only, never to the alarm, so an override of triggered in a subclass of Alarm does not run when it goes off.

[class.alarm.cancel]

cancel takes no argument (SYNTAX 93.902) and answers nothing, so using its answer as a value raises SYNTAX 91.999.
