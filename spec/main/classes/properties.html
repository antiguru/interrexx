The interrexx Language Specification

Properties

rexxref: Builtin Classes > Collection Classes > Properties Class; Builtin Classes > Collection Classes > Properties Class > load (Class method); Builtin Classes > Collection Classes > Properties Class > new (Class method); Builtin Classes > Collection Classes > Properties Class > []=; Builtin Classes > Collection Classes > Properties Class > getLogical; Builtin Classes > Collection Classes > Properties Class > getProperty; Builtin Classes > Collection Classes > Properties Class > getWhole; Builtin Classes > Collection Classes > Properties Class > load; Builtin Classes > Collection Classes > Properties Class > put; Builtin Classes > Collection Classes > Properties Class > save; Builtin Classes > Collection Classes > Properties Class > setLogical; Builtin Classes > Collection Classes > Properties Class > setProperty; Builtin Classes > Collection Classes > Properties Class > setWhole

Deviations: D29, D33, D78, D109

A Properties is a Directory whose items are strings, with methods to read and write them as text, as logical values and as whole numbers, and to load and save them as lines of a file. It inherits Directory, and through it MapCollection and Collection; the hierarchy rule lists what it inherits. Everything that the page of Directory says holds for a Properties, the entries read by upper-case name, the methods associated with names, unknown and the lists of the entries included; this page gives what differs and what is added.

The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. Names and values of the examples are strings, and the examples that use files create them under a distinctive name and delete them. The page says nothing about what load does with a file that cannot be read, other than one that does not exist.

The class

[class.properties.creation]

Properties declares the instance methods []=, getLogical, getProperty, getWhole, load, put, save, setLogical, setProperty and setWhole, and the class method load; its new is that of Directory (the new rule). The class method of and the other instance methods are those of Directory and the mixins. A properties object answers the same of and set operations, hasEntry, setMethod and unsetMethod as a directory (the inheritance rule).

p = .properties~new
own = '[]= GETLOGICAL GETPROPERTY GETWHOLE LOAD PUT SAVE SETLOGICAL',
  'SETPROPERTY SETWHOLE'
n = 0
do m over own~makearray(' ')
  if p~hasMethod(m) then n += 1
end
say p~class~id n p~class~superclass~id .properties~hasMethod('LOAD')
say p~hasMethod('HASENTRY') p~hasMethod('SETMETHOD') p~hasMethod('UNION')

Writing values

[class.properties.put]

put(value, name), [name] = value and setProperty(name, value) store a string at the name. A value that is not a string is replaced by its string value as the string-value rule says, which sends it request with STRING, so a number is stored as its digits, an object whose makeString answers a string is stored as that answer, and an array as the text that its makeString gives; .nil and an object with no makeString raise SYNTAX 93.938. An instance of a subclass of String is stored as its own characters (the deviation rule). The name is read as a string as for a directory (the index rule), and .nil as the name raises SYNTAX 88.909. The three answer nothing, and none of them sends put, []= or setProperty to the receiver. put and setProperty take exactly two arguments and []= is the assignment [name] = value: fewer raises SYNTAX 93.901, an omitted place before the last argument given raises SYNTAX 93.903, and a third argument raises SYNTAX 93.902. The count is checked first, then the value, then the name.

p = .properties~new
p~put('v1', 'a')
p['b'] = 7
p~setProperty('c', .made~new)
p~put(.array~of(1, 2), 'd')
do i over p~allIndexes~sort
  say i p[i]~class~id '['p[i]~changeStr('0a'x, '/')']'
end
call try 'p~put(.nil, "k")'
call try 'p~put(.plain~new, "k")'
call try 'p["k"] = .nil'
call try 'p~setProperty("k", .plain~new)'
call try 'p~put("x", .nil)'
call try 'p~put("x")'
call try 'p~put(, "x")'
call try 'p~setProperty("x")'
call try 'p~setProperty(, "x")'
call try 'p~put("x", "y", "z")'
call try 'p~put(.nil, .nil)'
call try 'p~setProperty(.nil, .nil)'
exit

[class.properties.getlogical]

getLogical(name, default) reads the value as getProperty does, with the same arguments, which it sends to the receiver, and answers 1 for the value 1 or true and 0 for 0 or false. The default is used when the name has no value and is checked in the same way, so it must be one of those four strings (or a logical value), or the error is raised; when the name has a value, the default is not looked at. [class.properties.getwhole]

[class.properties.setlogical]

Loading and saving

[class.properties.load.format]

load reads its source line by line as linein does (the line rule) and enters one property for each line that carries one. A line that is empty or holds only blanks and tab characters is skipped, and so is a line whose first characters after blanks and tab characters are --; a -- anywhere else is text. Any other line is split at its first =: the name is the text before it with the blanks and tab characters removed from both ends, and the value is all the text after it, blanks included. A line with no = is a name with the null string as its value, and a line that starts with = has the null string as its name. A later line with a name that an earlier line or the properties object already has replaces the value.

[class.properties.load]

The instance method load(source) reads the source as the class method does and adds what it reads to the receiver, replacing the values of names that it already has and leaving the others; it answers nothing. For each line that carries a property it then sends put to the receiver with the value and the name, in the order of the lines, so an override of put sees them and its checks apply. [class.properties.save]

save(target) writes one line name=value for each entry, each ended by a line feed, in an order that is not specified (the hash order rule); the name and the value are written as they are, a value that is not a string through the string-value rule, with no escaping, so a name that holds = or a value that holds a line feed does not load back as it was. target is the name of a file, whose old contents are replaced, a File object, treated the same, or an object that understands lineout, such as a Stream, which is written at its write position and is not closed. When the target is a name or a File, save first sends save to the receiver with a Stream made for it, and that message does the writing. The writing sends supplier to the receiver, and lineout with the line as the only argument to the target for each entry. The answer is nothing, and an object that does not understand lineout raises SYNTAX 97.1. It takes exactly one argument: none raises SYNTAX 93.901, a second raises SYNTAX 93.902.

Messages the methods send

[class.properties.sends]

The messages that Properties methods send to the receiver, to the values and to the source or target, are these. getProperty sends at with the name; getLogical and getWhole send getProperty with their own arguments; setLogical and setWhole send datatype to the value, and setProperty with the name and the text; setProperty, put and []= send nothing to the receiver; load and save send what the load rule and the save rule say, linein with no argument to a source that is not a name or a File and lineout with the line to a target that is not a name or a File. The methods put, setProperty, []= and the setters read a value that is not a string with request and the argument STRING (the put rule), and getWhole and save send request with STRING to a stored value that is not a string (the getWhole rule and the save rule). In the example each method of a subclass records its name, the number of its arguments and its first argument, and each call shows the records it caused.
