Deviations: D33, D78, D84, D109, D125

A Set holds members, each an object that is its own index: put stores an item and the item is the index it is found by, so a member occurs once however often it is put. Members are found as a table finds its indexes, by the hashCode and the == that they answer to. The class inherits MapCollection and SetCollection, and through them Collection; the hierarchy rule lists what it inherits. Unlike a table it declares its own set operations, which read their argument as a list of members and not as a list of entries.

A set has no unknown method: a message that the method search does not resolve raises NOMETHOD, as the error rule of the chapter says. Examples that show an error use a small routine try, as the builtin pages do. Where several members qualify for a method that answers one, which one it answers is not specified, and the examples then hold one member or sort the answers (the hash order rule).

The class

[class.set.creation]

Set declares the instance methods [], []=, allIndexes, allItems, at, empty, hasIndex, hasItem, index, intersection, isEmpty, items, makeArray, put, putAll, remove, removeItem, subset, supplier, union and xor, the init that new runs (the new rule) and the class methods new and of; the copy of Object copies a set as the copy rule says. The instance methods difference, disjoint and equivalent are those of Collection (one rule covers them). A set has no makeString, so it is not a string (the string rule), and no unknown, allAt, allIndex, removeAll or uniqueIndexes. Its superclasses are Object, MapCollection and SetCollection, in that order.

Making a set

[class.set.new]

new makes an empty set. Its optional argument is a hint for how large the set will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that Set supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

call try '.set~new("x")'
call try '.set~new(.nil)'

[class.set.of]

of(item, ...) answers a new set of the class that received it that holds the arguments, each member once, and with no argument an empty set. An argument that is omitted before the last one raises SYNTAX 93.903, and a trailing omitted argument counts for nothing. The method does not send new to the class and does not send put to the set: it sends init with no argument to the new object and stores the arguments itself, so an override of new or put in a subclass is not used. Two arguments are one member when they are equal as members are, so 1 and 1.0 are two.

s = .set~of('a', 'b', 'a', 1, 1.0, .nil)
say s~items s~hasItem('a') s~hasItem(1.0) s~hasItem(.nil) .set~of~items
x = .spy~of('p', 'q', 'p')

Members

[class.set.members]

A member is any object, .nil and the null string included, and the set stores the object that was put. A member is found by the lookup: hashCode answers the same string for the argument and for the stored object, and ==, sent to the argument with the stored object as argument, answers true. For an object that declares neither method that is the same object, and an Array is its own member only. A string is a member of its characters, compared by the strict comparison: case counts, a leading or trailing blank counts, and 5 and 5.0 are two members. A class that declares == has to declare hashCode so that equal objects hash alike, as the hash code rule says. When put finds an equal member, the set keeps the object it has as the index of the entry, and takes the new object as its item: at and allItems then answer the new object, and allIndexes and makeArray the old one.

s = .set~new
do x over .array~of('Key', 'KEY', 5, 5.0, ' a', '', .nil)
  s~put(x)
end
a = .array~of(1)
s~put(a)
say s~items s~hasItem('Key') s~hasItem('key') s~hasItem('5.0') s~hasItem('a')
say s~hasItem(a) s~hasItem(.array~of(1)) s~hasItem('') s~hasItem(.nil)
s~put(.eq~new('x', 'first'))
s~put(.eq~new('x', 'second'))
say s~items s~at(.eq~new('x', 'probe'))~tag
say s~allItems~items s~allIndexes~items
do i over s~allIndexes
  if i~isA(.eq) then say 'index' i~tag
end
do i over s~allItems
  if i~isA(.eq) then say 'item' i~tag
end

[class.set.members.sends]

at, [], hasIndex, hasItem, index, put, []=, remove and removeItem look a member up by sending hashCode to the argument, once, and then == to the argument with a stored object as the argument, for stored objects that have the same hash code, until one answers true; each of those is compared before the lookup gives up. Which further stored objects are compared, by == or hashCode, and how often, is not specified (the hash order rule); when the set is empty, the only message is hashCode. The very object that is stored is no exception to the == (the deviation rule). put and []= with an index first send == to the item with the index as argument (the put rule). In the example every member hashes to the same string, so each stored member is compared.

.local~log = .array~new
say 'empty:' .set~new~at(.k~new('p')) .local~log~makeString('L', ' | ')

Adding and reading members

[class.set.put]

put(item) and put(item, index) add the item and answer nothing; [index] = item is the same as put(item, index), and [] = item the same as put(item). An index may be given only as another name for the item: when one is, and the item is not the very object, == is sent to the item with the index as argument first, and an answer that is not true raises SYNTAX 93.949 and leaves the set unchanged. An index that is omitted counts for nothing. The methods take one or two arguments: none, or an omitted item, raises SYNTAX 88.901, and a third argument raises SYNTAX 93.902. The item may be any object, .nil included. The check of the index is made before the item is looked up (the lookup rule).

In the example MAKESTRING answers another text.

say .set~new(.sub~new('2'))~items
::class sub subclass string
::method makestring
  return 'other'

[class.set.deviation.125]

An answer of allItems or makeArray that is a List gives its items in list order, as the list rule says, for putAll, union, intersection, xor and subset. ooRexx reads it by the positions 1 up to its number of items, so in the example an item is missed and .nil is a member.

s = .set~new
s~putAll(.pk~new(.list~of('p', 'q', 'r')))
say s~items s~hasItem('p') s~hasItem('q') s~hasItem('r') s~hasItem(.nil)
say .set~of('q', 'r')~subset(.pk~new(.list~of('q', 'r')))
::class pk inherit collection
::method init
  expose answer
  use arg answer
::method allitems
  expose answer
  return answer
