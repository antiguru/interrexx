The interrexx Language Specification

Monitor

rexxref: Builtin Classes > Utility Classes > Monitor Class; Builtin Classes > Utility Classes > Monitor Class > current; Builtin Classes > Utility Classes > Monitor Class > destination; Builtin Classes > Utility Classes > Monitor Class > init; Builtin Classes > Utility Classes > Monitor Class > unknown

Deviations: D118, D124

A Monitor stands in for another object. A message that the monitor does not have a method for is sent on to the object that is the monitor's current destination, with the same name and the same arguments, and what that answers is what the monitor answers. The destination can be changed while the program runs, and put back to the one before: a program that holds a monitor, or that has made one the value of a name such as .output that other code reads, changes where the messages go without that code noticing. A monitor is transparent only for messages that it does not itself understand: the methods of Object are the monitor's own, and the rule on them says which messages are not forwarded. The forwarding is the unknown method, which the method search runs when it finds no method.

The class

[class.monitor.creation]

Monitor has the instance methods current, destination, init and unknown, besides the new that every class has. It may have private methods besides these; they are not part of this specification. Its only superclass is Object and it inherits no mixin class (the hierarchy rule). new is the one that Class supplies: it sends init the arguments of new, and answers an instance of the class that received it, so a subclass of Monitor makes instances of itself; methods that a subclass declares are found before unknown, so a message for which it has a method is not forwarded.

The destination

[class.monitor.init]

init sets the destination to its argument. It takes at most one argument (SYNTAX 93.902); the argument can be any object, strings, the empty string and .nil among them, and when it is omitted the destination is .nil. It replaces every destination that was set before, including those that destination put on top of the first, so that the destination that comes back after the last one has been dropped is .nil. init answers nothing. Because new sends init the arguments of new, new takes the same argument and raises the same error, and an instance made by new with no argument has no destination until one is set. A message that is forwarded while the destination is .nil raises SYNTAX 97.1, as the NOMETHOD rule says of a message that nothing understands.

a = .target~new('A')
b = .target~new('B')
m = .monitor~new
say (m~current == .nil) .monitor~new(a)~current~id
call try "m~hello"
call try ".monitor~new(a, b)"
call try "m~init(a, b)"
call try "m~init"
call try "m~init(.nil)"

say m~hello m~current~id
call try "m~init('')"
say '['m~current']' m~current~class~id
call try "m~init(a)"
r = m~destination(b)
call try "m~init(a)"
r = m~destination
say (r == .nil) (m~current == .nil)
exit

[class.monitor.destination]

destination changes the destination, and answers the one that is current afterwards. The destinations form a stack, with the one that init set at the bottom. With an argument, destination puts that object on top: from then on messages go to it, and the earlier destinations are kept below it. The argument can be any object, .nil and the empty string among them, and what destination answers is that same object. Without an argument it takes the top one off, so that the destination that was current before the last change is current again, and answers that one; when no destination is left under the one it took off it answers .nil, and the destination is .nil and stays so, for a further destination without an argument takes nothing more off and answers .nil again. A destination put on top after that is the only one. More than one argument raises SYNTAX 93.902. destination sends no message, not current and not init.

a = .target~new('A')
b = .target~new('B')

Forwarding

[class.monitor.unknown]

unknown(name, arguments) forwards a message. It is run by the method search for a message the monitor has no method for, with the name in upper case and the array of the arguments that the search builds, and it can be sent directly with the same two arguments. It sends the current destination a message with that name and the items of the array as its arguments, and answers what that message answers; when the message answers nothing, unknown answers nothing. The arguments are passed on as they were sent: an omitted argument stays omitted, so that the destination counts the arguments by the last one present, and a trailing omitted argument is not counted. A condition that the destination's method raises is raised for the message to the monitor in the same way, an error number and subcode included. When the destination does not understand the name, or is .nil, SYNTAX 97.1 is raised; and a method of the destination that is PRIVATE or PACKAGE is not available to the monitor, which is not the destination and has not the destination's package: the message raises SYNTAX 97.2 or 97.3 as it would for any other sender (the access rule). A method that the destination has on its class side is not reached. A destination that has an unknown method of its own gets that message in turn, with the name in upper case. Called directly, unknown needs both arguments (SYNTAX 93.901), takes no more (SYNTAX 93.902), and needs the name to be present (SYNTAX 93.903).

a = .target~new('A')
m = .monitor~new(a)
say m~hello(1, 2)
say m~hello(, 2)
say m~hello(1, , 3, )
say m~hello
say m~Hello(1) m~'hello'(1)
say m~unknown('hello', .array~of(7, 8))
call try "m~fail"
call try "m~priv"
call try "m~pk"
call try "m~classside"
call try "m~nosuchzz"
call try "m~silent"

call try "m~unknown"

[class.monitor.unknown.arguments]

The second argument of a direct unknown need not be an Array: it is any object, and it is sent request with ARRAY before anything is forwarded, as the unknown rule says. The items of what that answers, in order and with their holes, are the arguments of the forwarded message. A string answers an array of one item, itself, so that a string is one argument and the null string is none; a number, .true and a MutableBuffer are one argument each, as their strings; a List or a Set answers its items; and an object that answers no array to request, .nil and an Object among them, raises SYNTAX 98.946 and forwards nothing.

m = .monitor~new(.target~new)

call try "m~unknown('echo', '')"

[class.monitor.object]

Every instance method that Object defines (the Object page) is the monitor's own, so a message with the name of one is not forwarded: it answers as it would for any object, about the monitor and not about the destination. That includes class, copy, defaultName, hasMethod, isA, isInstanceOf, objectName and objectName=, send and sendWith, string and the comparison operators. A program that wants the destination's own answer to one of them sends it to current. send and sendWith send the message to the monitor itself, so they reach unknown for a name that the monitor has no method for. Which names a subclass or an enhanced monitor has methods for, besides these, is found by the method search in the usual way.

a = .target~new('A')
m = .monitor~new(a)
say m~class~id m~string m~isA(.monitor) m~isA(.target) m~isInstanceOf(.target)

[class.monitor.sends]

The messages that a monitor sends are the one that unknown sends to the destination, which the forwarding rule states, and that destination's unknown when it has to answer for a name. The monitor sends none to itself: unknown does not ask current for the destination, init and destination do not send each other, and a subclass that overrides current or destination sees them run only when the program sends them. The method unknown of a subclass that forwards with self~unknown:super(name, arguments) is found by the method search before the one of Monitor. The example overrides each message of a subclass and shows them from a forwarded message, destination and current.

.environment~log = .list~new
a = .target~new('A')
m = .logging~new(a)
say 'init:' .environment~log~makeArray~makeString('l', ' ')
.environment~log~empty
