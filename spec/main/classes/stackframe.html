The interrexx Language Specification

StackFrame

rexxref: Builtin Classes > Utility Classes > StackFrame Class; Builtin Classes > Utility Classes > StackFrame Class > arguments; Builtin Classes > Utility Classes > StackFrame Class > context; Builtin Classes > Utility Classes > StackFrame Class > executable; Builtin Classes > Utility Classes > StackFrame Class > invocation; Builtin Classes > Utility Classes > StackFrame Class > line; Builtin Classes > Utility Classes > StackFrame Class > makeString; Builtin Classes > Utility Classes > StackFrame Class > name; Builtin Classes > Utility Classes > StackFrame Class > string; Builtin Classes > Utility Classes > StackFrame Class > target; Builtin Classes > Utility Classes > StackFrame Class > traceLine; Builtin Classes > Utility Classes > StackFrame Class > type

Deviations: D0, D66

A StackFrame describes one level of the call stack of an activity: the main part of a program, a routine, a method, an internal routine or the text of an INTERPRET that was running when the frame was made. A program gets frames from the stackFrames method of RexxContext and from the condition object; it never makes one. A frame answers where its level was, what it was called with and what runs it, and it keeps answering after the level has ended.

The CALL, INTERPRET and SIGNAL instructions, the conditions and TRACE are specified in their own chapters; this page links their rules. Two Deviations touch frames, 0 for the indentation of a traceLine and 66 for the name of a frame, and the last section states them.

The class

[class.stackframe.creation]

StackFrame is a class whose only superclass is Object, and it inherits no mixin class (the hierarchy rule). Its instance side defines arguments, context, executable, invocation, line, makeString, name, string, target, traceLine and type, and no other method. The class method new raises SYNTAX 93.967 whatever the arguments are, so no program makes a frame. No instance method takes an argument, and one sent with an argument raises SYNTAX 93.902, copy included.

s = .stackframe~methods(.nil)
names = .array~new
do while s~available
  names~append(s~index)
  s~next
end
names = names~sort
do i = 1 to names~items by 4
  say names~section(i, min(4, names~items - i + 1))~makeString('l', ' ')
end
say .stackframe~superclasses~items .stackframe~superclass~id
call try '.stackframe~new'
call try '.stackframe~new(1)'
call try '.context~stackFrames[1]~type(1)'
call try '.context~stackFrames[1]~copy(1)'
exit
try:
  signal on syntax name bad
  interpret 'rr =' arg(1)
  say arg(1) '=> no error'
  return
bad: say arg(1) '=>' condition('o')~code
  return

[class.stackframe.copy]

copy answers a new frame that is not the receiver and has the same type, name and line. Every other method of the copy answers what the receiver's answers, the same objects included: the arguments, the context and the executable of the two are the same objects.

[class.stackframe.sources]

A frame comes from the array that stackFrames of a context answers or from the list that a condition's STACKFRAMES entry holds. In both the first frame is the level that was running, or that raised the condition, and each next one is the level that called the one before, with the main part of the program last. The array of a context has the indexes 1 and up and the list of a condition has the indexes 0 and up. The levels are those of the activity that asked, so the list of a message that another activity runs ends with the method that the message started. A condition answers the same list each time.

signal on syntax name h
call outer
exit
outer: procedure
  .o~new~m
  return
h:
  fs = condition('o')~stackFrames
  say fs~class~id fs~first fs~last fs~items (fs == condition('o')~stackFrames)
  do i over fs~allIndexes
    say i fs[i]~type fs[i]~line
  end
  .o~new~start('act')~result
exit
::class o
::method m
  say 1 + 'a'
::method act
  fs = .context~stackFrames
  say fs~class~id fs~first fs~last fs[1]~type fs[1]~name
  return 1

[class.stackframe.type]

type answers one of PROGRAM for the main part of a program, ROUTINE for a routine, METHOD for a method, INTERNALCALL for an internal routine, INTERPRET for the text of an INTERPRET and COMPILE for text that was being translated when a SYNTAX condition was raised. A frame of type COMPILE is the first of that condition's list. A built-in method that runs a program's code, such as send, is a level of type METHOD.

call ic
exit
ic:
  .o~new~send('go')
  return

  call dump

[class.stackframe.name]

name answers the name of the level. For PROGRAM it is the name of the package (the name rule of Package). For ROUTINE it is the name by which the routine was called: for a ::ROUTINE in upper case, for a routine that Routine~new made the name it was given. For METHOD it is the name of the method in upper case, which is the message name, and for INTERNALCALL the label in upper case. For INTERPRET it is the null string. A frame of type COMPILE has the name of the text that was being translated; for the text of an INTERPRET that is the name of the package.

call outer
.routine~new('anon', 'call dump')~call
.o~new~m
signal on syntax name h1
r = .routine~new('badone', 'x = = 1')
h1: f = condition('o')~stackFrames~firstItem
say f~type '['f~name']'
signal on syntax name h2
interpret 'x = = 1'
h2: f = condition('o')~stackFrames~firstItem
say f~type (f~name == .context~package~name)
exit
outer:
  call rt
  return

    else say f~type '['f~name']'
  end
  say '--'

[class.stackframe.line]

line answers the number of the line on which the clause that the level was running starts, and for an INTERPRET level the number of the line of the clause that holds the text, as the line of a trace line is. A frame is a snapshot of the moment it was made: the running code goes on, and the line of the frame's context, asked with line, moves with it. line answers .nil for a built-in method.

call r
exit
r:
  f = .context~stackFrames[1]
  say f~line .context~line f~context~line
  say f~line .context~line f~context~line
  g = .context~stackFrames[2]
  say g~line g~context~line
  .o~new~send('m')
  return
::class o
::method m
  say .context~stackFrames[2]~line~isNil .context~stackFrames[2]~type
  interpret 'say .context~stackFrames[1]~type .context~stackFrames[1]~line'

[class.stackframe.traceline]

traceLine, string and makeString all answer the same string, which is the trace line of the clause that the level was running: the number of its line in six columns, *-* and the clause, indented as the indentation rule says, which counts one level for each active internal call. Deviation 0 covers the indentation that a program reads back. The string of a built-in method's frame is seven blanks, *-*, a blank and Compiled method "NAME" with scope "Class"., with the method's name in upper case and the id of the class that defines it.

call show
do i = 1 to 1
  call show
end
call outer
call show 'multi',

  return
show:
  f = .context~stackFrames[2]
  say '['f~traceLine']' (f~string == f~traceLine),

  return

[class.stackframe.arguments]

arguments answers an array of the arguments that the level was given, as ARG with the option A answers for it: an omitted argument is a place with no item. The frame keeps the array, so asking again answers the same object, but it is a copy: changing it changes nothing the level sees and nothing that another frame of the level answers. A built-in method's frame holds the arguments of its message, and a frame of the main part of a program the arguments the program was started with.

call r 'a1', , 'a3'
exit
r:
  f = .context~stackFrames[1]
  a = f~arguments
  say a~class~id a~size a~items (a == f~arguments)
  a[1] = 'changed'
  a~append('x')
  say f~arguments~items arg(1) arg() (a == .context~stackFrames[1]~arguments),
      .context~stackFrames[1]~arguments[1]
  .o~new~send('m', 7, 8)
  return

::method m

[class.stackframe.context]

context answers the RexxContext of the level: for the first frame of a context's own stackFrames it is that context itself, and asking one frame again answers the same object. A built-in method's frame and a frame of type COMPILE have no context and answer .nil (the example of invocation shows the second). Once the level has ended, its context answers no message, as the active rule says, while the frame itself goes on answering.

call outer 'p', 'q'
exit
outer: procedure
  outvar = 'outer value'
  call inner
  return

  fs = .context~stackFrames
  say fs~items (fs[1]~context == .context) (fs[2]~context == fs[2]~context),

Deviations

[class.stackframe.deviation.0]

The traceLine of a frame is indented by block structure alone, as the indentation rule says of trace lines. ooRexx drops one level too many when a loop ends because its test failed, so the line of a clause after the loop stands one level short, as in the first line of the example below where ooRexx shows *-* call show at the margin.

do
  do i = 1 to 2
    nop
  end
  call show
end
call show
exit
show:
  f = .context~stackFrames[2]
  say '['f~traceLine']'
  return

[     5 *-*   call show]
[     7 *-* call show]

A SYNTAX 16.1 that arises in the text of an INTERPRET, because the label of a trap that SIGNAL ON set does not exist, has one frame, of type PROGRAM, and its name is the name of the package, as the INTERPRET rule states. ooRexx names that frame with the null string.

signal on syntax name e
signal on novalue name nolabel
interpret 'a = undefinedvar'
e: c = condition('o')
f = c~stackFrames~firstItem
say c~code c~stackFrames~items f~type (f~name == .context~package~name)
