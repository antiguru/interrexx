The interrexx Language Specification

List

rexxref: Builtin Classes > Collection Classes > List Class; Builtin Classes > Collection Classes > List Class > new (Class Method); Builtin Classes > Collection Classes > List Class > of (Class Method); Builtin Classes > Collection Classes > List Class > []; Builtin Classes > Collection Classes > List Class > []=; Builtin Classes > Collection Classes > List Class > allIndexes; Builtin Classes > Collection Classes > List Class > allItems; Builtin Classes > Collection Classes > List Class > append; Builtin Classes > Collection Classes > List Class > at; Builtin Classes > Collection Classes > List Class > delete; Builtin Classes > Collection Classes > List Class > empty; Builtin Classes > Collection Classes > List Class > first; Builtin Classes > Collection Classes > List Class > firstItem; Builtin Classes > Collection Classes > List Class > hasIndex; Builtin Classes > Collection Classes > List Class > hasItem; Builtin Classes > Collection Classes > List Class > index; Builtin Classes > Collection Classes > List Class > insert; Builtin Classes > Collection Classes > List Class > isEmpty; Builtin Classes > Collection Classes > List Class > items; Builtin Classes > Collection Classes > List Class > last; Builtin Classes > Collection Classes > List Class > lastItem; Builtin Classes > Collection Classes > List Class > makeArray; Builtin Classes > Collection Classes > List Class > next; Builtin Classes > Collection Classes > List Class > previous; Builtin Classes > Collection Classes > List Class > put; Builtin Classes > Collection Classes > List Class > remove; Builtin Classes > Collection Classes > List Class > removeItem; Builtin Classes > Collection Classes > List Class > section; Builtin Classes > Collection Classes > List Class > supplier

Deviations: D78, D109, D118

A List is an ordered collection that grows and shrinks at any point. Its entries are addressed by indexes that the list chooses and hands back when an item is added: an index names an entry for as long as the entry is in the list, whatever is inserted or removed around it, so it is a handle on the entry, not a position. The order of the entries is a separate matter, and the list keeps it. The class inherits OrderedCollection, and through it Collection; the hierarchy rule lists what it inherits.

The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. The page says nothing about an entry whose item was omitted in a put or an insert.

The class

[class.list.creation]

List declares twenty-six instance methods and two class methods, new and of. The instance methods are [], []=, allIndexes, allItems, append, at, delete, empty, first, firstItem, hasIndex, hasItem, index, insert, isEmpty, items, last, lastItem, makeArray, next, previous, put, remove, removeItem, section and supplier, and a copy that this page specifies (the copy rule). A list has no makeString, no toString, no size, no fill and no dimensions, and no method of its own that sorts: sort, sortWith, stableSort and stableSortWith are those of OrderedCollection, which sort a list through its makeArray, first, next and []= (the sort rule). The set operations and appendAll are those of the mixins, and one rule lists them.

own = 'AT PUT APPEND INSERT SECTION SUPPLIER REMOVEITEM FIRSTITEM'
n = 0

  if l~hasMethod(m) then n += 1

Making a list

[class.list.new]

new makes an empty list. Its optional argument is a hint for how large the list will grow and changes nothing the program can see; it is read as the index rule reads an index and must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees the hint, unlike the init of an array (the new rule).

l = .list~new
say l~items l~isEmpty l~first
say .list~new(0)~items .list~new(1000)~items .list~new(3, )~items
call try '.list~new(-1)'
call try '.list~new("x")'
call try '.list~new(.nil)'
call try '.list~new(1.5)'
call try '.list~new(1, 2)'
x = .watch~new(7)

exit

[class.list.of]

of makes a list that holds its arguments in the order given: the first is the first entry. An argument left out at the end counts for nothing, so of(1, ) holds one item; an argument left out before a given one raises SYNTAX 93.903. .nil is an item like any other. The result is an instance of the class that received the message. of sends init to the new object with no argument and not new, and adds the items itself: the append, insert and put of a subclass are not sent for them. The indexes are those that a fresh list hands out, the index rule says which.

l = .list~of('a', 'b', 'c')
say l~items l~allItems~makeString('L', ',') l~allIndexes~makeString('L', ',')
say .list~of~items .list~of('x', )~items .list~of(.nil, .nil)~items
call try '.list~of(1, , 3)'
call try '.list~of(, 1)'
x = .watch~of(1, 2)
say x~items
exit

Indexes

[class.list.indexes]

An index of a list is a whole number of 0 or more, chosen by the list when an entry is created and kept until the entry is removed. A method that takes an index reads it from its string value (the conversion rule) as a whole-number argument of a builtin is (the form rule, the digits rule): "1", ' + 1 ' and 1.0 are as good as 1, NUMERIC DIGITS plays no part, and anything that is not a whole number of 0 or more, .nil included, or that those rules refuse, raises SYNTAX 93.918. A valid index that names no entry is not an error for the methods that look entries up: at, next, previous, delete and remove answer .nil and hasIndex answers 0; the methods that must have an entry, put, insert and section, raise SYNTAX 93.918. When an entry is removed its index becomes free. A new entry takes the index that was freed most recently, when one is free, and otherwise the lowest whole number that has not been used since the list was made or last emptied. A list that only grows therefore hands out 0, 1, 2 and so on; empty makes the list start again at 0. The number of an entry never changes, wherever it is inserted. A copy has the same indexes, and the same state, as the list it is made from.

l = .list~new
a = l~append('a'); b = l~append('b'); c = l~append('c')
say a b c
l~remove(a)
l~remove(c)
say l~append('x') l~append('y') l~append('z')
say l~allIndexes~makeString('L', ',')
say l~allItems~makeString('L', ',')
m = .list~of('p', 'q')
m~empty
say m~append('r') m~append('s')
say m~at('1') m~at(1.0) m~hasIndex(' 1 ') m~hasIndex(7) (m~at(7) == .nil)

call try 'm~at(1000000000000000000)'
call try 'm~put("t", 9)'

exit

[class.list.put]

Messages the methods send

[class.list.sends]

No method that List declares sends a message to its receiver: an override of at, put, append or any other of the methods is never asked by another method, and [] and []= do not use at and put. The messages the methods do send go to other objects, and each has a rule of its own: init to the new object by new and of (the new rule, the of rule); == to the argument by removeItem, hasItem and index (the search rule). The sorts, which are not methods of the class, send messages to the receiver and to the array of makeArray, as their rule says. The methods string and copy of an instance and the set operations send what the pages that own them say. No argument is asked isA, and a string value is read as the conversion rule says. In the example a subclass has every method of List overridden to record its name, and each call records only its own.
