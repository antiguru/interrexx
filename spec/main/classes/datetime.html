A DateTime is one moment of the Gregorian calendar, from the first microsecond of 1 January 0001 to the last of 31 December 9999, that carries the offset of the time zone it is read in. Its methods answer the parts of the date and the time of day, write the moment in the formats of DATE and TIME and in ISO 8601 forms, make the moment that lies a given span away, and convert it to another zone. The class inherits Comparable and Orderable, which give it the comparison operators on top of its own compareTo; the span of time between two moments is a TimeSpan. The current moment and the host's time zone are not specified, so the examples build their instances from fixed values and give them an explicit offset wherever a result depends on one.

[class.datetime.value]

An instance holds a date and a time of day as the fields year (1 to 9999), month, day, hours, minutes, seconds and microseconds (0 to 999999), and an offset from UTC. The fields are the time as the people in that zone read it. No method changes an instance: every method that answers a different moment answers a new instance. Leap seconds do not exist, so a seconds value is at most 59, and a day has exactly 86400 seconds. The string value of an instance is its isoDate (the string rule); an instance written by say or joined to a string by || is that text, as the string-value rule says. An instance on which the init of DateTime never ran, because the init of a subclass does not forward to it, has the value of minDate (Deviation 131).

Offsets

[class.datetime.offset]

The offset of an instance is the distance of its zone east of UTC, in whole minutes from -900 to 900. The method offset answers it as a TimeSpan, so an instance in a zone 5 hours and 30 minutes east of UTC answers 05:30:00.000000 and one in a zone 90 minutes west answers -01:30:00.000000. Every place that takes an offset takes the same two forms: a number of whole minutes in that range, or a TimeSpan that is a whole number of minutes in that range. The argument is sent isA with the class TimeSpan; only a TimeSpan is then sent totalMicroseconds and is converted to minutes, and any other value is read as a number (the argument rule) and sent the messages that the sends rule lists. A value outside the range, a number that is not whole as the form rule and the digits rule read it (Deviation 130), such as 1.5, and a span that is not whole minutes raise SYNTAX 88.907 for new and, with a number or a span, for toTimezone, and SYNTAX 88.918 for today and for the from methods that read an offset, which are all but fromWeekNumberDate (it ignores the offset) and fromUtcIsoDate (it has none); a value that is no number at all gets the same code from new, today and those from methods, and what toTimezone raises for it is in the zone rule.

[class.datetime.offset.default]

An instance made without an offset gets the offset of the host's zone as it is when the instance is made: the number of microseconds that TIME('O') answers, as a span. It is one offset for every date: an instance for a date of summer and one for a date of winter get the same offset, the one the host has at the moment of the call. Which zone the host is in is not specified, so the examples compare with the offset of another instance or with TIME('O'). The class methods new, today and every from method take it, except fromUtcIsoDate, which takes the offset that its string gives, and minDate and maxDate, whose offset is 0. The methods that answer a moment of a new zone, toLocalTime and toUtcTime, are described with the zone rule. When the host's offset is not a whole number of minutes from -900 to 900, every method that takes the default offset fails: new and toLocalTime raise SYNTAX 88.907, and today and every from method other than fromUtcIsoDate raise SYNTAX 88.918.

Making an instance

[class.datetime.new]

new makes an instance and sends init to it with the arguments it received (the new rule); the init of DateTime takes up to eight arguments, and the number of them that are given, counted as the count rule says, picks the form. With no argument the moment is that of the host's clock, whose value is not specified. With one argument or two, the first is the number of microseconds from 00:00:00.000000 on 1 January 0001 to the moment, a whole number from 0 to 315537897599999999, and the second, if present, is the offset. With three arguments or four they are year, month and day, the time of day is 00:00:00.000000, and the fourth, if present, is the offset: the four-argument form is not the three-argument form with an hour. With from five to eight arguments they are year, month, day, hours and minutes, then seconds, microseconds and the offset, where an omitted one of these three is 0 (the offset: the default). Without an offset argument the instance has the default offset. An argument that the form needs and that is omitted raises SYNTAX 93.903; more than eight arguments raise SYNTAX 93.902.

[class.datetime.sends.new]

The class methods send new to the receiver, so a class that overrides its new sees them, and new sends init to the new instance with the arguments it got (the new rule); the init of DateTime sends nothing. minDate sends new with the four arguments 1, 1, 1 and 0, and maxDate with the eight arguments 9999, 12, 31, 23, 59, 59, 999999 and 0. today and every from method other than fromOrdinalDate and fromWeekNumberDate send new with two arguments: the number of microseconds from the start of 0001 to the moment, and the offset argument exactly as the caller gave it (a TimeSpan is not converted), or, without one, the default offset in minutes; fromUtcIsoDate, which has no offset argument, sends the offset of its string in minutes. fromOrdinalDate sends nothing to the receiver and answers a plain DateTime, whatever the receiver is. fromWeekNumberDate sends new with the three arguments year, 1 and 4, then sends that instance weeksInYear (which sends year), weekDay and addDays, and the answer of addDays is the result.
