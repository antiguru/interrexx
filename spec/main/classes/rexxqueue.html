RexxQueue

rexxref: Builtin Classes > Utility Classes > RexxQueue Class; Builtin Classes > Utility Classes > RexxQueue Class > new (Inherited Class Method); Builtin Classes > Utility Classes > RexxQueue Class > create (Class Method); Builtin Classes > Utility Classes > RexxQueue Class > delete (Class Method); Builtin Classes > Utility Classes > RexxQueue Class > exists (Class Method); Builtin Classes > Utility Classes > RexxQueue Class > open (Class Method); Builtin Classes > Utility Classes > RexxQueue Class > delete; Builtin Classes > Utility Classes > RexxQueue Class > empty; Builtin Classes > Utility Classes > RexxQueue Class > get; Builtin Classes > Utility Classes > RexxQueue Class > init; Builtin Classes > Utility Classes > RexxQueue Class > lineIn; Builtin Classes > Utility Classes > RexxQueue Class > lineOut; Builtin Classes > Utility Classes > RexxQueue Class > makeArray; Builtin Classes > Utility Classes > RexxQueue Class > pull; Builtin Classes > Utility Classes > RexxQueue Class > push; Builtin Classes > Utility Classes > RexxQueue Class > queue; Builtin Classes > Utility Classes > RexxQueue Class > queued; Builtin Classes > Utility Classes > RexxQueue Class > say; Builtin Classes > Utility Classes > RexxQueue Class > set

Deviations: D109, D135

A RexxQueue is an object that works with one of the external data queues, the lists of lines that are kept outside the program in a service and that the QUEUE and PUSH instructions fill and the PULL instruction empties. The object holds the name of a queue, adds lines to the queue and takes them out, and asks how many there are. Besides the instance methods the class has methods that make, open, delete and ask after a queue by its name. They are the same queues as those of the RXQUEUE function, and the rules that function states for the names of queues, for the queue SESSION and for a queue that does not exist hold here too. A program has a current queue that the instructions use; the object has a queue of its own, and the two are the same queue only when they have the same name. How programs and sessions share the queues is specified by the session rule and the child rule.

Note. The examples create a queue under a name that no other example uses and delete it when they are done, so they leave nothing behind. An example never waits for a line that nothing will add, because a program that does that does not end.

The class

[class.rexxqueue.creation]

RexxQueue has the class methods create, delete, exists and open, and the instance methods delete, empty, get, init, lineIn, lineOut, makeArray, pull, push, queue, queued, say and set, besides the methods that every class has, new among them. A class method is not an instance method and an instance method is not a class method, so the two delete methods do not meet. The class may have private methods besides these; they are not part of this specification. Its only superclass is Object and it inherits no mixin class (the hierarchy rule).

say .rexxqueue~id .rexxqueue~superclasses~items,
  .rexxqueue~superclass~id .rexxqueue~queryMixinClass
have = .set~new
s = .rexxqueue~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end
names = ('delete empty get init lineIn lineOut makeArray pull push queue',
  'queued say set')~makeArray(' ')
count = 0
do name over names
  if have~hasItem(name~upper) then count = count + 1

[class.rexxqueue.string]

The string value of a RexxQueue is the name of its queue in upper case: the class has no string method of its own, and the string of Object answers the objectName, which the init rule sets to the queue name and the set rule sets again to the name of the queue it switches to. The default name of the object stays a RexxQueue. A program may give the object another name with objectName= (the name rule); that changes the string value and nothing else, for the name of the queue that the object works with is get's answer.

q = .rexxqueue~new('spec_rq_Mixed_Case')
say q~string q~get q~defaultName
q~objectName = 'a nickname'
say q~string '|' q~get '|' q~objectName
say q~set('spec_rq_string_other') q~string q~get
say q~set('spec_rq_Mixed_Case') q~string
say q~delete

Making a queue object

[class.rexxqueue.new]

new is the new that Class supplies (the new rule): it makes an object of the class that received the message, so a subclass makes instances of itself, and sends it init with the arguments of new, in order. The queue that the object works with is therefore the business of init, and new with more than one argument raises SYNTAX 93.902, because init takes at most one. A subclass whose init does not reach the init of RexxQueue, by forward or by self~init:super, makes an object that is not connected to a queue (Deviation 135).

[class.rexxqueue.init]

init(name) connects the object to a queue and takes at most one argument (SYNTAX 93.902). It decides the name in one of three ways. With no argument the name is SESSION. With .nil it makes a queue whose name the service picks, as the class method create does with no argument, and uses that name; no program can know the name beforehand. With any other argument it sends the argument the message upper, and the answer is the name: a string in upper case, a number such as 12 or a MutableBuffer gives its upper-case string, and an object that does not understand upper, an Object or an Array for one, raises SYNTAX 97.1. For a name that was given, init then sends the class of the receiver the message open with the name, as the class method says: a queue of that name is kept as it is with its lines, or made when there is none. An init does not look at the answer of open, so a name that no queue can have raises no error here: the object is made, and the methods that need the queue fail later, as the missing queue rule says. At last init sets the objectName of the object to the name, as the string rule says. The messages that init sends are stated in the next rule.

a = .rexxqueue~new
b = .rexxqueue~new(.nil)
say a~get '|' (b~get~length > 0) (b~get \== 'SESSION')
say .rexxqueue~exists(b~get) b~delete .rexxqueue~exists(b~get)

[class.rexxqueue.init.sends]

init sends messages in this order. With a name given, upper goes to the argument, once and before anything else. With .nil, create goes to the class of the receiver with no argument, and then open with the name that create answered. With a name given, open goes to the class of the receiver, with the upper-case name. With no argument, nothing is sent to the class. Then objectName= goes to the receiver itself with the name. A subclass of RexxQueue therefore sees its own class-side create and open and its own objectName=. In the example the subclass overrides them and writes what they receive.

.environment~made = ''
say '-- named'
q = .spy~new('spec_rq_sends_init')
say '-- nil'
r = .spy~new(.nil)
say '-- none'
s = .spy~new
say '-- upper'
t = .spy~new(.shout~new)
say q~delete r~delete t~delete
::class spy subclass rexxqueue
::method create class
  say 'create' arg()
  .environment~made = self~create:super
  return .environment~made
::method open class
  if arg(1) == .environment~made~upper then
    say 'open the name that create answered'
  else say 'open' arg(1)
  forward class (super)
::method 'objectName='
  if arg(1) == .environment~made~upper then
    say 'objectName= the name that create answered'
  else say 'objectName=' arg(1)
  forward class (super)
::class shout
::method upper
  say 'upper'
  return 'SPEC_RQ_SENDS_UPPER'

[class.rexxqueue.create.class-side]

create(name) makes a queue and answers its name. It takes at most one argument (SYNTAX 88.922). With a name that no queue has, the queue gets that name and the answer is the name as it was given, in the case it was given in. When a queue of that name exists, or with no argument, the queue is made under a name that the service picks, which the answer reports, so the answer is a name of a new queue: the Create function states that. The name SESSION and a name that no queue can have (the queue name rule), the null string, a name with a blank or a -, and a name of more than 250 characters among them, make no queue and answer the null string, without an error. The name is read as the name rule says.

Adding lines

[class.rexxqueue.queue]

queue(line) adds one line at the end of the queue, so that it is taken after the lines that are there, and answers 0. line is the line, read as a string by the name rule; without it, or with an omitted place, the line is the null string. The method takes no other argument (SYNTAX 88.922). A line is kept as it is, with its case, its blanks and any characters it holds, a line end among them: one call adds one line, and a line end inside it does not split it. A queue that does not exist, the queue of a name that no queue can have included, cannot take the line: SYNTAX 48.1 is raised and the queue stays as it was. The QUEUE instruction adds a line to the queue of the program in the same order.
