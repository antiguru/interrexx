The interrexx Language Specification

MutexSemaphore

rexxref: Builtin Classes > Utility Classes > MutexSemaphore Class; Builtin Classes > Utility Classes > MutexSemaphore Class > new (Class Method); Builtin Classes > Utility Classes > MutexSemaphore Class > acquire; Builtin Classes > Utility Classes > MutexSemaphore Class > release; Builtin Classes > Utility Classes > MutexSemaphore Class > uninit

Deviations: D109, D136

A MutexSemaphore lets one activity at a time own something. An activity that is about to enter a part of the program that only one activity may be in at a time calls acquire; when it leaves it calls release. While one activity owns the semaphore, another that calls acquire waits for the owner to let go, or gives up after a timeout. An activity that owns the semaphore can acquire it again without waiting, and then has to release it as many times. This page states what each method answers and checks, how the count of acquisitions works and what a timeout may be. How activities are scheduled, and so which of several that wait gets the semaphore next, is specified in the environment chapter. The examples that use two activities start a message from the program and use event semaphores to force the order of what happens, so that nothing in their output depends on speed.

The class

[class.mutexsemaphore.creation]

MutexSemaphore has the instance methods acquire, release and uninit, and the class method new, besides the methods that every class has. It may have private methods besides these; they are not part of this specification. Its only superclass is Object and it inherits no mixin class (the hierarchy rule).

say .mutexsemaphore~id .mutexsemaphore~superclasses~items,
  .mutexsemaphore~superclass~id .mutexsemaphore~queryMixinClass
have = .set~new
s = .mutexsemaphore~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end
names = 'acquire release uninit'~makeArray(' ')
count = 0
do name over names
  if have~hasItem(name~upper) then count = count + 1
end

[class.mutexsemaphore.new]

new makes a semaphore that no activity owns, and answers an instance of the class that received it, so a subclass makes instances of itself. Owning

[class.mutexsemaphore.acquire]

acquire(timeout) gives the activity that calls it ownership, and answers 1, when no activity owns the semaphore and when the activity already owns it. It answers 0 when another activity owns it and keeps it for the whole timeout. The semaphore counts how many times its owner has acquired it: a call from the owner does not wait, adds one to the count and answers 1, and the semaphore becomes free only when release has taken the count back to zero. The timeout bounds the wait of a caller that does not get the semaphore at once. Omitted or below zero, there is no bound, so the answer can only be 1. Zero means no wait: the answer says whether the semaphore was free or the caller's already. Above zero it is a bound in seconds. When the owner lets go, one of the activities that wait gets the semaphore, which of them is not specified. The timeout is read as the next rule says, before the semaphore is looked at, so an invalid one raises its error whoever owns the semaphore. Ownership does not outlive the activity: when an activity ends, every count it held is dropped and the semaphore is free for others. In the first example one activity does all the calls, and in the second a message that the program starts owns the semaphore while the program calls.

say m~acquire m~acquire(0) m~acquire(0.05) m~acquire('0.05') m~acquire(-1)
say m~release m~release m~release m~release m~release m~release
say m~acquire(5) m~acquire(.timespan~fromSeconds(1)),
  m~release m~release m~release

[class.mutexsemaphore.release]

release answers 1 when the activity that calls it owns the semaphore, and takes one off the count of its acquisitions; when the count reaches zero the semaphore is free, and one of the activities that wait for it gets it. It answers 0 when the activity does not own the semaphore, because no activity does or because another does, and changes nothing. It takes no argument (SYNTAX 93.902) and sends no message. In the example the program owns the semaphore twice, a message that it starts releases it without owning it and answers 0, and only the program's own two releases free it.

[class.mutexsemaphore.copy]

copy answers a new semaphore that no activity owns, whatever the state of the original: the copy of a free semaphore is free, and so is the copy of one that an activity owns, any number of times. The original keeps its owner and its count (Deviation 136). From then on the two are separate: acquiring or releasing one does not change the other. The example copies a free semaphore.

f = .mutexsemaphore~new
j = f~copy
say j~release j~acquire(0) j~release
say f~acquire(0) f~release f~release

[class.mutexsemaphore.timeout]

The timeout is a number of seconds or a TimeSpan, and it is read before anything else is done, so an invalid one raises SYNTAX 88.902 whoever owns the semaphore. A string is a valid timeout when it is a number as the DATATYPE N rule reads it, so blanks at either end, a sign, a decimal point and an exponent are allowed; the empty string, a string of blanks and a string that is no number raise SYNTAX 88.902. An object that is neither a string nor a TimeSpan is replaced by its string value, as the conversion rule says, and that string is read in the same way; .nil, a DateTime and an object whose string value is no number, such as an instance of Object, raise SYNTAX 88.902. A TimeSpan is read through its totalSeconds, which is sent to it once, and a span that is negative means the same as a negative number. More than one argument raises SYNTAX 93.902. The example gives each form to a semaphore that nothing owns, and counts the acquisitions it made, to free the semaphore.

[class.mutexsemaphore.sends]

acquire sends the message totalSeconds to a timeout that is a TimeSpan, once and before it looks at the semaphore, and no other message to a TimeSpan; an object that is neither a string nor a TimeSpan is sent what the conversion rule says (Deviation 109 says that a string that is an instance of a subclass of String is read by its own characters). No method of the class sends a message to the semaphore itself: an override of acquire or release runs when the program sends that message and not because the other was. The first example overrides both methods and totalSeconds of a subclass of TimeSpan and shows what runs; the second gives a timeout whose class has its own request and makeString, and only request is sent.

say 'acquire:' x .environment~log~makeArray~makeString('l', ' ')

Cleaning up

[class.mutexsemaphore.uninit]

uninit frees what the semaphore holds. The interpreter may send it when the semaphore is reclaimed; whether and when is not specified. An uninit of a subclass replaces this one, so it frees the semaphore only by sending self~uninit:super. uninit takes no argument (SYNTAX 93.902) and answers nothing, so using its answer as a value raises SYNTAX 91.999. What a semaphore does for a message that a program sends it after a direct uninit, a second uninit included, is not specified.

.environment~log = .list~new
s = .tidy~new
s~uninit
say .environment~log~makeArray~makeString('l', ' ')

[class.mutexsemaphore.deviation.109]

A timeout that is an instance of a subclass of String is read by its own characters, and request, makeString and string are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING, so an override can change what is read. In the example the overrides answer a timeout of 0; they count their sends, and the string is read as 0.01 seconds without one.

[class.mutexsemaphore.deviation.136]

A copy of a semaphore is free whoever owns the original and however often. In the first example an activity owns the semaphore twice and the copy is free: its release answers 0, and releasing the original twice leaves it free. In the second a message that the program starts owns the semaphore when the program copies it: the program acquires the copy at once, and when the other activity ends, the original is free. ooRexx gives the copy the owner and the count of the original, so the first copy of the example releases twice, and the copy of the second stays owned by the activity that ended, and nothing can acquire it; the example is not run against it.

m = .mutexsemaphore~new
say m~acquire(0) m~acquire(0)
j = m~copy
say j~release j~release j~release
say m~release m~release m~release
