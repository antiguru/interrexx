The interrexx Language Specification

CommandHandler

rexxref: Builtin Classes > Utility Classes > CommandHandler Class; Builtin Classes > Utility Classes > CommandHandler Class > deregister (Class Method); Builtin Classes > Utility Classes > CommandHandler Class > environments (Class Method); Builtin Classes > Utility Classes > CommandHandler Class > handler (Class Method); Builtin Classes > Utility Classes > CommandHandler Class > handlers (Class Method); Builtin Classes > Utility Classes > CommandHandler Class > register (Class Method); Builtin Classes > Utility Classes > CommandHandler Class > command

Deviations: D109

A command that a program sends to an environment is run by whatever the environment is. CommandHandler is the mixin class for environments written in Rexx: an object whose class inherits it, registered under a name, receives every command that is sent to that name as a message, and answers with the return code of the command. The class methods register such an object, remove it, and list the environments of the interpreter, the native ones that run commands in the host's shell among them; the objects that stand for those are the NativeCommandHandler objects. While a command runs, the handler gets a CommandContext that describes it.

This page states the class, how a command reaches the method command of the handler and what the handler answers, and the class methods. The environment chapter specifies the environments of the interpreter, how a command to a name that no environment has fails and what the native environments do; this page says only where the class takes part. The examples register environments under names of their own, and use no environment that runs commands in the host.

The class

[class.commandhandler.creation]

CommandHandler is a mixin class: it has the one instance method command and the class methods deregister, environments, handler, handlers and register, besides the methods that every class has. Its superclass is Object, and it inherits no mixin of its own (the hierarchy rule). A class that inherits it gets the instance method command and the class methods too, so a program may send register to its own handler class as well as to CommandHandler, and all of them work with the same environments. A class method is not an instance method: an instance of such a class does not understand register. new sent to CommandHandler makes an instance, as it does for any class that is not abstract, and command sent to that instance is the abstract method that the command rule states. The class may have private methods besides these; they are not part of this specification.

say .commandhandler~id .commandhandler~superclasses~items,
  .commandhandler~superclass~id .commandhandler~queryMixinClass
h = .commandhandler~new
say h~class~id h~hasMethod('COMMAND') h~hasMethod('REGISTER')
say .commandhandler~hasMethod('REGISTER') .commandhandler~hasMethod('COMMAND')
say .echo~hasMethod('REGISTER') .echo~hasMethod('HANDLERS'),
  .echo~hasMethod('COMMAND')
say .echo~new~hasMethod('REGISTER') .echo~new~hasMethod('COMMAND')
say .echo~register('spec_ch_creation', .echo~new)~isNil
say .commandhandler~handler('spec_ch_creation')~class~id,
  .echo~handler('SPEC_CH_CREATION')~class~id
say .echo~deregister('spec_ch_creation')~class~id

  return 0

The method command

[class.commandhandler.command]

command(command, caller) is the method that a class implements to run commands. CommandHandler defines it as an abstract method: sent to an instance whose class has not replaced it, it raises SYNTAX 93.965, and so does a command that is sent to a handler like that. A command is therefore an ordinary message to the handler object, answered by the first command method that the method search finds for it, a subclass's before the class it extends, and command of a superclass reached with self~command:super as for any method. The arguments and what the method answers are stated in the dispatch rule and the return code rule.

.commandhandler~register('spec_ch_abstract', .lazy~new)

address spec_ch_sub 'abc'
say rc
x = .commandhandler~deregister('spec_ch_abstract')
x = .commandhandler~deregister('spec_ch_sub')

[class.commandhandler.dispatch]

When a command is sent to an environment name for which a handler is in use, by ADDRESS name expression or by a command clause while that name is the current environment, the handler is sent the message command with two arguments: the command, as the string that the command rule makes of the value of the expression, and a new CommandContext for this command. The message is sent from the activity that sends the command, and the clause that sent it waits for the answer. The name of the environment may be written in any case: the handler gets the same command either way, and the context names the environment as the environment rule says. A command that the handler sends from inside command, whichever environment it names, is dispatched by this same rule: it gets a context of its own, and one handler can be running several commands at once, one inside another. A value that is the null string is sent as a command, and arrives as the null string. In the example the handler registered under two names tells them apart by caller~environment, runs a command inside a command, and shows the arguments it was sent.

h = .count~new
x = .commandhandler~register('spec_ch_dispatch', h)
x = .commandhandler~register('spec_ch_other', h)
address spec_ch_dispatch 'first command'
address SPEC_CH_OTHER 'second' 1 + 2
address spec_ch_other ''
address spec_ch_dispatch .text~new
address spec_ch_dispatch
'a clause'
say 'rc' rc address()
address spec_ch_dispatch 'nest 2'
x = .commandhandler~deregister('spec_ch_dispatch')
x = .commandhandler~deregister('spec_ch_other')

[class.commandhandler.rc]

What command answers is the return code of the command: the object itself is the value of RC after the clause, a string, a number, any object or .nil, and a method that answers nothing leaves RC at 0. Whatever object command answers, a negative number included, the clause raises no condition for it, so a return code other than 0 from a handler is neither ERROR nor FAILURE, and .RS holds 0 after the command (the status rule); the answer is no more than a value. Only the methods of the context (raise and the rest) make a command raise one, and so does a native environment that the handler forwards the command to (the forwarding rule). How RC is assigned otherwise is stated in the return code rule.

x = .commandhandler~register('spec_ch_rc', .answers~new)
signal on error name caught
signal on failure name caught
do word over 'ZERO ONE NEGATIVE TEXT NOTHING NIL ARRAY BIG'~makearray(' ')
  address spec_ch_rc word
  say word 'rc' '<'rc'>' rc~class~id .rs
end
x = .commandhandler~deregister('spec_ch_rc')
exit
caught:
  say 'trapped' condition('c') rc

[class.commandhandler.conditions]

A condition that is raised in command and that the method does not trap reaches the code that sent the command, as a condition raised in any called code does: a SYNTAX error, a HALT, or any other condition raised by a RAISE in the method, which the code that sent the command traps as it would a condition raised at its own clause. An error in the method is therefore the error of the clause that sent the command, with its error number. The conditions that the command itself raises, by what the handler asks the context to raise, are stated with the context.

x = .commandhandler~register('spec_ch_conditions', .raiser~new)
call attempt 'syntax'
call attempt 'halt'
call attempt 'error'
call attempt 'user'
x = .commandhandler~deregister('spec_ch_conditions')
exit
attempt: procedure
  signal on syntax name s
  call on halt name c
  call on error name c
  call on user mine name c
  address spec_ch_conditions arg(1)
  say arg(1) 'went through, rc' rc
  return
s: say 'syntax' condition('o')~code
  return
c: say condition('c') condition('d') rc
  return

  use arg command, caller

Class methods

[class.commandhandler.register]

register(name, handler) makes handler the handler in use for the environment name and answers the handler that it covers: the one that was in use for the name before, or .nil when there was none. Both arguments are required (SYNTAX 93.901) and a third raises SYNTAX 93.902. The name is read as the name rule says, and is kept in upper case, so a handler is found by the name in any case; a name with a blank is allowed, and the null string and an object that is not a string raise SYNTAX 93.900. handler must be an object of a class that inherits CommandHandler: the object is asked isA with .CommandHandler as the argument, once, after the name was read, and it is accepted when the answer is true; .nil, a class and an object of another class raise SYNTAX 93.900. The handler it covers is not lost: it comes back into use when this one is removed by deregister, and handlers lists it. The same object can be registered more than once, under several names and under one name again. A handler is the object registered, not a copy. The registration belongs to the interpreter instance, and a name that is already the name of a native environment is covered like any other.

a = .echo~new('a'); b = .echo~new('b')
say .commandhandler~register('spec_ch_register', a)~isNil
say .commandhandler~register('Spec_Ch_Register', b)~tag
say .commandhandler~handler('SPEC_CH_REGISTER')~tag

[class.commandhandler.deregister]

deregister(name) removes the handler in use for the environment name, and answers it. The handler that it covered is in use again; when none is left, a command that names the environment finds nothing to run it and raises FAILURE with the return code 30, as the status rule shows for a name that has no environment. A name that is not the name of an environment, one that was already removed included, raises SYNTAX 93.900. The name is required (SYNTAX 93.901) and a second argument raises SYNTAX 93.902; it is read as the name rule says, and its case plays no part. deregister always takes the handler in use; there is no way to remove one that is covered by another. Registering the same handler again is allowed. The null string raises SYNTAX 93.900 as it does for register, although handler('') answers an environment (environments).

a = .echo~new('a'); b = .echo~new('b')

[class.commandhandler.handler]

[class.commandhandler.handlers]

handlers(name) answers a new Array of the handlers that are registered for the environment name, the one in use at index 1 and then the ones it covers, each covered one after the one that covers it, down to the oldest. The name is required (SYNTAX 88.901) and a second argument raises SYNTAX 88.922; it is read as the name rule says.

[class.commandhandler.environments]

environments answers a new StringTable of the environments of the interpreter instance. Its indexes are the names of the environments in upper case, and the item of each is the handler in use for it, the object that handler answers: an object of a class that inherits CommandHandler for an environment that a program registered, and a NativeCommandHandler for a native one. The environment SYSTEM, which runs commands in the host's shell, is among them. Which other native environments exist is not specified: it depends on the host, but the native environments include one under the null string, which register and deregister refuse. The table is a snapshot: a later register or deregister does not change it, and changing it does not change the environments. The method takes no argument (SYNTAX 88.922).

Reading names and what is sent

[class.commandhandler.name]

The name that register, deregister, handler and handlers take is read as a string, and the environment is the one with that name in upper case. A string is the name as it is. An object that is not a string, an instance of a subclass of String apart (the deviation rule), is replaced by what it answers to the message request: register and deregister send it with the argument String, and handler and handlers send it with the argument STRING, and the answer, when it is a string, is the name; the request of Object answers what makeString does, so an object that has makeString, an Array or a MutableBuffer is read through it. A number is read as the string that it is. An object that does not answer a string is no name: register and deregister raise SYNTAX 93.900 for it, and handler and handlers raise SYNTAX 88.909.

[class.commandhandler.register.sends]

register sends the message request with the argument String to a name that is not a string, and then isA with the class CommandHandler to the handler, each once and in that order; it sends nothing else, and a handler that does not answer true to isA is refused, whatever its class is. The handler does not get command or any other message when it is registered. In the example isA of a handler is overridden to say what it was asked.

Deviations

[class.commandhandler.deviation.109]

A name that register, deregister, handler or handlers takes and that is an instance of a subclass of String is read by its own characters, and request, makeString and string are not sent to it (Deviation 109). ooRexx sends such an instance request, with String from register and deregister and with STRING from handler and handlers, so an override can change the name that is read. In the examples the overrides would change the name; they count their sends, and the string is read as it is without one.
