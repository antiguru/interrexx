The interrexx Language Specification

Routine

rexxref: Builtin Classes > Fundamental Classes > Routine Class; Builtin Classes > Fundamental Classes > Routine Class > new (Class Method); Builtin Classes > Fundamental Classes > Routine Class > newFile (Class Method); Builtin Classes > Fundamental Classes > Routine Class > loadExternalRoutine (Class method); Builtin Classes > Fundamental Classes > Routine Class > []; Builtin Classes > Fundamental Classes > Routine Class > annotation; Builtin Classes > Fundamental Classes > Routine Class > annotations; Builtin Classes > Fundamental Classes > Routine Class > call; Builtin Classes > Fundamental Classes > Routine Class > callWith; Builtin Classes > Fundamental Classes > Routine Class > package; Builtin Classes > Fundamental Classes > Routine Class > setSecurityManager; Builtin Classes > Fundamental Classes > Routine Class > source; The Security Manager

Deviations: D41, D109, D111, D115, D118, D124, D134

A Routine object is a piece of code that is called with arguments and answers a value, as a routine of a program is. A ::ROUTINE directive makes one for each directive, and a program makes one of its own from source text with new, from a file with newFile, or from a native library with loadExternalRoutine. A routine object is called by the messages call, callWith and [], and every call is a call of an external routine: the code runs in a variable pool of its own, sees nothing of its caller's variables, and finds classes and routines through its package.

The page specifies the class methods that make a routine, the messages that call it and ask about it, and the security manager that a routine can be put under. The routine that a directive makes is specified by ::ROUTINE, the annotations by ::ANNOTATE, and the instruction that calls a routine by name by CALL. A routine is made from source in the way a method is, so the rules of the Method page for the source and the context apply to new and newFile here, and this page states what is its own. newFile takes its file as the newFile rule says, and the library of loadExternalRoutine is found as the library rule says; the examples here name a file that they create themselves, or a library that every installation has.

The examples that show an error use a routine try that sends the message in its argument and prints the answer, or the error code when the message raises one.

The class

[class.routine.creation]

A routine object made by new or newFile is called by sending it call, and holds the source it was made from. It has no annotations and belongs to a package of its own, as the context rule says for a method. A Routine object is an ordinary object otherwise, so it understands the methods of Object and has the default name a Routine. The class Routine has the superclass Object and no mixin class.

r = .routine~new('adder', 'use arg a, b; return a + b')
say r~class~id r~defaultName r~call(2, 3)
say r~source~items r~annotations~items r~package~class~id r~package~name
say .routine~superclass~id .routine~superclasses~items

Routine a Routine 5
1 0 Package adder
Object 1

new

[class.routine.new]

new makes a routine from a name, a source and a context, with the same arguments, the same checks, in the same order, and the same errors as the new of Method: the name and the source are required (SYNTAX 88.901), a name that gives no string, .nil among them, raises 88.909, a context that is not PROGRAMSCOPE, a Method, a Routine or a Package raises 40.904, and a source that does not translate raises its translation error, and the code does not run. The source is read as the source rule says, with the messages of the sends rule, and the context decides what the routine finds as the context rule says. The arguments from the fourth on are passed to init of the new object, and the class that received new is the class of the answer, as for a method. The name is the name of the routine's package.

r = .routine~new('who', 'return "I am" .context~executable~class~id')
say r~call r~package~name

newFile

[class.routine.newfile]

newFile makes a routine from the lines of a file, with the arguments, the checks, their order and the errors of the newFile of Method: the file name and an optional context, no third argument (SYNTAX 93.902), .nil or an object that gives no string as the name raises 88.909, a context that does not fit raises 40.904 before the file is looked for, and a file that cannot be read raises SYNTAX 3.1. The routine's package is named by the file name as it was given. Its source is the lines of the file before the first directive, except that a first line that begins with #! is not part of it, and the directives of the file still make the classes and routines of its package, which its code can name. call runs the lines before the first directive. The file is not searched for (the newFile rule). newFile sends init with no argument to the new object, and a subclass of Routine makes instances of itself.

loadExternalRoutine

[class.routine.loadexternalroutine]

loadExternalRoutine makes a routine object whose code is a routine of a native library, the same kind of routine that ::ROUTINE EXTERNAL declares. It takes a name and a descriptor, with the checks, the descriptor form and the errors of loadExternalMethod: the word LIBRARY in any case, the library, and optionally the entry in it, which is the name of the routine when it is left out. A third argument raises SYNTAX 93.902, a missing argument 88.901, a .nil argument or one that gives no string 88.909 and a descriptor of another form 99.917. When the library cannot be loaded or has no entry of that name, the answer is .nil. The answer is an instance of Routine also when a subclass received the message, and no init is sent. The routine can be called, with the arguments that the library routine takes, and its source is an empty array and its package is .nil. Where the library is searched for, and whether its name is case sensitive, is specified by the library rule.

p = .routine~loadExternalRoutine('pi', 'LIBRARY rxmath rxcalcpi')
say p~class~id p~call(5) p~callWith(.array~of(8)) p[3]
say p~source~items p~package~isNil

Methods

Calling the routine

[class.routine.call]

call runs the routine with its arguments and answers what it returns. The arguments are the arguments of the message, and the argument count is the position of the last one that is not omitted: an omitted place before it stays omitted for ARG and use arg, and omitted places at the end add nothing. The code runs as the code of an external routine does: it has variables of its own and cannot see those of the program that called it, the classes and routines it names are those of its package, and exit ends the routine and answers the value it gives. A routine that returns no value answers no value, so using the answer of its call as a term raises SYNTAX 91.999. A condition that the routine raises and does not trap reaches the sender of call as it would reach the caller of an external routine; the example shows 42.3 from a division by zero. A routine that was made by loadExternalRoutine calls the library routine with the arguments.

r = .routine~new('n', 'return arg() "<"arg(1)"><"arg(2)"><"arg(3)">"')
call try 'r~call'
call try 'r~call(1)'
call try 'r~call(, 2)'
call try 'r~call(1, , 3)'
call try 'r~call(1, )'
call try 'r~call(, )'
call try '.routine~new("n", "return arg() arg(1, ""e"")")~call(, "x")'
x = 'caller variable'

[class.routine.brackets]

r = .routine~new('n', 'return arg() "<"arg(1)"><"arg(2)">"')

say r[, 5] r~'[]'(, 5)
say r[] r~'[]'
say r~hasMethod('[]') r~hasMethod('CALL')
call try '.routine~new("n", "return 1/0")[]'

[class.routine.callwith]

callWith runs the routine as call does with the arguments that its one argument holds. The argument is required (SYNTAX 93.903) and a second raises 93.902. An instance of Array is used as it is. The security manager

[class.routine.setsecuritymanager]

setSecurityManager gives the package that holds the routine's code a security manager, or with no argument removes the one that package has, and answers 1 (the package rule); a routine that new or newFile made has a package of its own. It is a protected method. The manager can be any object, .nil as well, and it is not checked when it is set; .nil is an object like any other and is sent the checkpoints, which it does not understand (SYNTAX 97.1), so only a call with no argument removes the manager. The code of other packages, and of the packages that the code makes, is not under the manager. A manager that is set or removed while code of the package runs is taken up by the calls that start after the change, except for the name checkpoints LOCAL and ENVIRONMENT, which the run that is going on takes up at once (the run rule).

[class.routine.setsecuritymanager.method]

The METHOD checkpoint is offered when the code of the routine sends a message to a protected method, before the method runs. The directory holds OBJECT, the receiver, NAME, the upper case name of the method, and ARGUMENTS, an array of the arguments. A manager that answers 1 has run the message itself: the entry RESULT, when it is set, is what the message answers, and with no RESULT the message answers no value, so that using the answer raises SYNTAX 91.999. A manager that answers 0 lets the method run. A message to a protected method from code that is not under a manager runs the method, and so does a message to a method that is not protected.

r = .routine~new('agent', 'o = .box~new; return o~locked(1, 2) o~open')
r~setSecurityManager(.mgr~new)
say r~call
say .box~new~locked(1, 2)
exit
::class box
::method locked protected
  return 'locked ran'
::method open
  return 'open ran'
::class mgr
::method method
  use arg info
  say 'method' info~name info~object~class~id info~arguments~items
  info~result = 'replaced'
  return 1

method LOCKED BOX 2
replaced open ran
locked ran

r = .routine~new('agent', 'return .box~new~locked')
r~setSecurityManager(.mgr~new)
signal on syntax name bad
say r~call
exit
bad: say condition('o')~code

::method locked protected
  return 'locked ran'

[class.routine.deviation.111]
