Deviations: D34, D55, D58, D59, D62, D109, D135, D139, D140, D142

A Stream is an object that stands for a stream: the file, or the standard stream, that its name denotes. Its methods do what the stream built-in functions do, with the stream as the receiver in place of a name argument, and it has some that the functions have no counterpart for: the lines of a stream as an array or as a supplier, and the writing of the items of an array. This page states what is the method's own: how an object is made, the argument errors and the answers of the methods, and the messages that a method sends to its receiver and to its arguments, where a subclass or an argument can override them. The rules of the functions are linked, never repeated. A name that is one of the standard names denotes that standard stream, as for the functions; what the standard streams of a program are bound to when it starts, and the objects .input, .output and .error, are specified in the bindings rule. The examples create the files they use under names of their own, close every stream they open, and remove the files at the end.

The class

[class.stream.creation]

Stream is a subclass of InputOutputStream and it inherits no other class. It is a mixin class: queryMixinClass answers 1. It has the class method new, which every class has, and the instance methods arrayIn, arrayOut, charIn, charOut, chars, close, command, description, flush, init, lineIn, lineOut, lines, makeArray, open, position, qualify, query, say, seek, state, string, supplier and uninit. It may have private methods besides these; they are not part of this specification. It has no method makeString. It defines every method that InputStream, OutputStream and InputOutputStream define, so a message to a Stream never reaches the methods of those pages. An instance is not a string, so a string method such as left raises SYNTAX 97.1. A copy of an instance is a new stream that is not open.

[class.stream.new]

new is the new that Class supplies (the new rule): it makes an instance of the class that received it, a subclass included, and sends it init with the arguments of new. The instance is not open, and nothing is read or written until a method needs the stream; its state is UNKNOWN. init takes the name of the stream as its one argument. A missing argument raises SYNTAX 93.901 and a second one SYNTAX 93.902. A name that is a string is used as it is, with its blanks. The null string is a name too, though a stream with that name cannot be opened: opening it gives the ERROR state as for any name that is no file. (STREAM refuses a null name with SYNTAX 40.27, as its rule says; to the other functions the null string names the default stream, as the rule of the standard names says. A Stream with the null name denotes no standard stream.) A name that is not a string is read as the string value its makeString method answers, which is sent once, when the stream is made, and never again, so a later change in what the object answers does not change the name. An argument that has no makeString method, .nil among them, raises SYNTAX 93.938; a string method alone does not do. A MutableBuffer, an Array and a File have a makeString method, and the name of the stream is its answer.

[class.stream.args]

The arguments of a message are checked in this order, and the first error is the one raised. First comes the form of the arguments that a method reads before it counts them: a start, a line number or a count of charIn, lineIn, charOut and lineOut that is no whole number in the range that the arguments give raises SYNTAX 88.907, and a string to write that has no makeString method raises SYNTAX 88.909 (the strings rule); the option of open, lines, seek and position is read through makeString too, and one without it raises SYNTAX 88.909 (the objects rule).
