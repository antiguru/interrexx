The interrexx Language Specification

Directory

rexxref: Builtin Classes > Collection Classes > Directory Class; Builtin Classes > Collection Classes > Directory Class > new (Class Method); Builtin Classes > Collection Classes > Directory Class > []; Builtin Classes > Collection Classes > Directory Class > []=; Builtin Classes > Collection Classes > Directory Class > allIndexes; Builtin Classes > Collection Classes > Directory Class > allItems; Builtin Classes > Collection Classes > Directory Class > at; Builtin Classes > Collection Classes > Directory Class > empty; Builtin Classes > Collection Classes > Directory Class > entry; Builtin Classes > Collection Classes > Directory Class > hasEntry; Builtin Classes > Collection Classes > Directory Class > hasIndex; Builtin Classes > Collection Classes > Directory Class > hasItem; Builtin Classes > Collection Classes > Directory Class > index; Builtin Classes > Collection Classes > Directory Class > isEmpty; Builtin Classes > Collection Classes > Directory Class > items; Builtin Classes > Collection Classes > Directory Class > makeArray; Builtin Classes > Collection Classes > Directory Class > put; Builtin Classes > Collection Classes > Directory Class > remove; Builtin Classes > Collection Classes > Directory Class > removeEntry; Builtin Classes > Collection Classes > Directory Class > removeItem; Builtin Classes > Collection Classes > Directory Class > setEntry; Builtin Classes > Collection Classes > Directory Class > setMethod; Builtin Classes > Collection Classes > Directory Class > supplier; Builtin Classes > Collection Classes > Directory Class > unknown; Builtin Classes > Collection Classes > Directory Class > unsetMethod

Deviations: D29, D33, D78, D109, D118, D123, D124

A Directory maps string indexes to items. An index is a string compared in full and by its exact characters, so ab and AB are two indexes, and an item is any object. A directory can also hold methods: a method that setMethod associates with a name runs when the name is read, and so makes a computed entry; a method named UNKNOWN answers every read of a name that has no entry. The class inherits MapCollection, and through it Collection; the hierarchy rule lists what it inherits. Properties is its subclass, and StringTable is a sibling that has the same entry methods without the methods of a directory.

A directory also gives its entries a second face: a message for which the method search finds no method, such as d~name, reaches the unknown method of the class, which reads or sets the entry of that name in upper case (the unknown rule). The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. The page says nothing about which of two items equal to the argument removeItem removes (the hash order rule).

The class

[class.directory.creation]

Directory declares the instance methods [], []=, allIndexes, allItems, at, empty, entry, hasEntry, hasIndex, hasItem, index, isEmpty, items, makeArray, put, remove, removeEntry, removeItem, setEntry, setMethod, supplier, unknown and unsetMethod, the init that new runs (the new rule) and the class method new; the copy of Object copies a directory as the copy rule says. The class method of and the instance methods putAll, union, difference, intersection, xor, subset, disjoint and equivalent are those of the mixins (one rule lists them). A directory has no makeString: the message reaches unknown, so it answers the entry MAKESTRING, .nil when there is none, and a directory is not a string (the string rule).

Making a directory

[class.directory.new]

new makes an empty directory. Its optional argument is a hint for how large the directory will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that Directory supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

say .directory~new~items .directory~new(0)~items .directory~new(3, )~items

call try '.directory~new("x")'
call try '.directory~new(.nil)'

Indexes

[class.directory.indexes]

An index is read as a string: a string is used as it is, and any other object by the string-value rule, which sends it request with the argument STRING, so an object whose makeString answers a string is used through that answer, and an object that has neither gives SYNTAX 88.909, as .nil does. The index is stored as that string, and two indexes are the same when their characters are the same: case counts, 5 and 5.0 are different, and the null string is an index. A method of this page that takes a name reads it this way, at, [], put, []=, hasIndex, remove and the methods whose name is changed to upper case by the entry rule. An instance of a subclass of String is read by its own characters (the deviation rule).

Reading and writing entries

[class.directory.at]

at(name) and [name] answer the item stored at the index, and .nil when there is none. When the name is the name of a method that setMethod associated, the method runs, with the directory as self and no argument, and the answer is what it returns, so it is run again for each read, and .nil when it returns nothing. When there is neither an item nor a method and the directory has an UNKNOWN method, that method runs with the name as its only argument, as the name was given, and its answer is the answer of at. The methods take exactly one argument: none, or an omitted one, raises SYNTAX 88.901, and a second raises SYNTAX 93.902; the number of arguments is checked before the name is read.

d = .directory~new
d~put('item', 'k')
d~setMethod('calc', .method~new('', 'return self~class~id arg()'))
say d~at('k') d['k'] d~at('K') d~at('CALC') d~at('calc')
d~setMethod('unknown', .method~new('', 'return "none:" arg(1)'))
say d~at('missing') d['MISSING'] d~at('k')
call try 'd~at'
call try 'd~at(, "x")'
call try 'd~at("a", "b")'
call try 'd[]'
exit

Entries by upper-case name

[class.directory.entry]

entry(name), hasEntry(name), setEntry(name, item) and removeEntry(name) work like at, hasIndex, put and remove with the name changed to upper case first, so setEntry('abc', 1) stores the index ABC, and entry('abc') reads it, while at('abc') does not find it. entry falls back to a method and to the UNKNOWN method as at does, with the upper-case name as the argument of the latter. hasEntry is 1 when an item or a method has that name and does not count UNKNOWN; setEntry with the item omitted removes the entry, and with the item present stores it, replacing a method of that name. setEntry answers nothing and does not check the item. entry, hasEntry and removeEntry take exactly one argument, and setEntry one or two: a missing name raises SYNTAX 88.901, and one argument too many raises SYNTAX 93.902.

[class.directory.hasitem]

hasItem(item) answers 1 when some item is equal to the argument and 0 otherwise, and index(item) answers an index of such an item and .nil when there is none. The stored items are searched first. When none of them is equal, the methods are run one after the other, and the answer of each is compared before the next one runs, so a method runs only when nothing searched before it was equal, and at most once. The UNKNOWN method is not searched. Which index index answers when several items qualify is not specified (the hash order rule). Both take exactly one argument: none, or an omitted one, raises SYNTAX 93.903, and a second raises SYNTAX 93.902. .nil is an item like any other.

[class.directory.hasitem.sends]

hasItem, index and removeItem send == to the argument, once for each item that is searched, with that item as the argument, until one answers true, and send nothing else; the stored items are visited first, in an order that is not specified, and then the answers of the methods, in an order that is not specified either, so the number of messages is specified only when no item matches, as then every item is visited.
