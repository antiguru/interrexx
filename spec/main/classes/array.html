An Array is an ordered collection whose entries are addressed by positive whole numbers. Its indexes may have gaps, so an array can hold items at 1 and 5 and nothing between, and it may have more than one dimension, in which case an entry is addressed by one whole number for each dimension. The class inherits OrderedCollection, and through it Collection, and declares most of their methods itself; the hierarchy rule lists what it inherits.

The page follows the order of the rexxref entry: the class, the way indexes are read, the methods that read and write entries, the questions about the contents, the methods that make other collections, and the ones that sort or print. Examples that show an error use a small routine try, as the builtin pages do. No method that the class declares sends another message to its receiver; the sends rule lists the messages that methods do send, and to whom.

The class

[class.array.creation]

Array declares thirty-six instance methods and two class methods, new and of. The instance methods are [], []=, allIndexes, allItems, append, at, delete, dimension, dimensions, empty, fill, first, firstItem, hasIndex, hasItem, index, insert, isEmpty, items, last, lastItem, makeArray, makeString, next, previous, put, remove, removeItem, section, size, sort, sortWith, stableSort, stableSortWith, supplier and toString, and a copy that this page specifies (the copy rule). The set operations union, difference, intersection, xor, subset, disjoint and equivalent and the method appendAll are those of the mixins, and one rule lists them. Making an array

[class.array.new]

new makes an empty array. The arguments say how large the dimensions are expected to be, and they are hints only: the array grows as entries are put into it. With no argument the array has no dimension yet; its dimension is 0 and its size is 0, and the first put gives it as many dimensions as the put has indexes. With one or more arguments, each a whole number that is not negative, the array has one dimension for each argument, of that size, and its size is the product of them, though it holds no item (items is 0). One argument that is an Array of such numbers gives the same dimensions as arguments would; an instance of a subclass is not such an array. An argument that is not a whole number that is not negative raises SYNTAX 93.906, and so does an array of sizes that holds one, or an instance of a subclass; an omitted argument followed by a given one raises SYNTAX 93.903, while omitted arguments at the end count for nothing. A size of 0 is allowed and makes a dimension with no room: new(0) has dimension 1 and size 0. A size is read as the index rule reads an index.

a = .array~new
say a~dimension a~size a~items
b = .array~new(3)
say b~dimension b~size b~items
c = .array~new(2, 3)
say c~dimension c~size c~items c~dimensions~makeString('L', 'x')
d = .array~new(.array~of(2, 3, 4))
say d~dimension d~size
say .array~new(0)~dimension .array~new(0)~size .array~new(2, )~dimension

[class.array.of]

of makes a one-dimensional array that holds its arguments, the first at index 1, the second at index 2 and so on. An argument left out leaves its index without an item, and arguments left out at the end count for nothing, so of(1, , 3, ) has three indexes. of with no argument makes an empty array that has one dimension, unlike new. An argument that is .nil is an item like any other. The result is an instance of the class that received the message.

a = .array~of('x', , 'z', )
say a~size a~items a~dimension a~hasIndex(2)
b = .array~of
say b~size b~dimension
c = .array~of(.nil, .nil)
say c~items (c~at(1) == .nil)
say .array~of(, 'b')~first .array~of(, 'b')~size

Indexes

[class.array.indexes]

A method that takes an index takes it as one argument for each dimension, or as one Array that holds them all; at(2, 3) and at(.array~of(2, 3)) name the same entry. Only an instance of Array itself is such a list: an instance of a subclass is one argument like any other object. Each index is a whole number of at least 1, read from the string value of the argument (the conversion rule) as a whole-number argument of a builtin is (the form rule, the digits rule), so "2", ' + 2 ' and 2.0 are as good as 2 and NUMERIC DIGITS plays no part; an argument those rules refuse raises the error this rule names, not SYNTAX 40.12. The number of indexes must be the number of dimensions of the array: too few raise SYNTAX 93.925 and too many SYNTAX 93.926. An index that is not a whole number of at least 1 raises SYNTAX 93.907 when the array has one dimension, and SYNTAX 93.924 when it has more. No index at all, or an empty array of indexes, raises SYNTAX 93.901. An array that has no dimension yet (one made by new without arguments and not yet put into) has no entries, and a message that reads, with two or more indexes, answers as for an index that has no entry without checking them; with one index it is checked as for a one-dimensional array. Reading and writing entries

[class.array.at]

at(index) answers the item at the index, and .nil when the index has no item, whether the slot lies beyond the array or inside it. The indexes are read as the index rule says. [] is the same method under another name: a[i] is the message [] with the indexes as arguments, and a~"[]"(i) the same message written out. [class.array.put]

put(item, index) makes the item the entry at the index, replacing any item there, and answers no value. a[i] = v is the message []= with the item first and the indexes after, and it is put under another name. The method needs at least the item and one index: fewer arguments raise SYNTAX 93.901, and an omitted item raises SYNTAX 93.903; both come before any check of the indexes. The indexes are read as the index rule says. A put beyond the present size of a dimension makes the dimension as large as the index, and the array grows. The first put into an array that has no dimension yet gives it as many dimensions as it has indexes, each as large as its index. .nil is an item like any other. [class.array.append]

[class.array.insert]

An index beyond the highest index of the array is allowed: the item goes to the index after it. The size of the array becomes the larger of what it was and the highest index the insert uses, the new one's or that of an entry it moved, so it grows only when an entry is pushed past its last place. An omitted item, or no argument at all, makes the new slot empty, and the answer, the size and the moving of the entries after it are as for an item (the omitted item rule). The index is read as the index rule says, so an array of one index is accepted. The method takes one or two arguments: a third raises SYNTAX 93.902; an array of more than one dimension raises SYNTAX 93.954 whatever the index is, after the argument count has been checked. Sorting

[class.array.sort]

sort and stableSort put the items of the array in ascending order, in place, and answer the receiver; sortWith(comparator) and stableSortWith(comparator) do the same by the order the comparator gives. Items are compared by compareTo, which for strings is the string rule: 10 sorts before 9, and upper case before lower case. The comparator is any object that understands compare, and when it answers a negative number for two items the first sorts before the second, when it answers 0 they are equal, and when it answers a positive number the first sorts after. stableSort and stableSortWith keep items that are equal in their order; whether sort and sortWith do is not specified. The sorted items fill the slots from index 1 on in the order of the slots (in a multi-dimensional array the first dimension changing fastest), so an array whose items are not in the first slots, with an empty slot before an item, raises SYNTAX 98.975 before any comparison and stays as it was; empty slots after the items stay empty, and the size does not change. An array of fewer than two items is not compared; sortWith and stableSortWith then answer at once, before the slot check and without looking at the comparator, while sort and stableSort still make the slot check, so .array~of(, 5)~sort raises SYNTAX 98.975 and .array~of(, 5)~sortWith(.nil) does not. sort and stableSort take no argument: any raises SYNTAX 93.902. sortWith and stableSortWith take exactly one: none, or an omitted one, raises SYNTAX 93.903 and a second SYNTAX 93.902. An item or comparator that does not understand its message raises SYNTAX 97.1. The comparator's answer must be a whole number: another answer raises SYNTAX 26.903; the answer of an item's compareTo raises SYNTAX 26.902 in the same case.
