Validate

rexxref: Builtin Classes > Utility Classes > Validate Class; Builtin Classes > Utility Classes > Validate Class > classType (Class Method); Builtin Classes > Utility Classes > Validate Class > length (Class Method); Builtin Classes > Utility Classes > Validate Class > logical (Class Method); Builtin Classes > Utility Classes > Validate Class > nonNegativeNumber (Class Method); Builtin Classes > Utility Classes > Validate Class > nonNegativeWholeNumber (Class Method); Builtin Classes > Utility Classes > Validate Class > number (Class Method); Builtin Classes > Utility Classes > Validate Class > numberRange (Class Method); Builtin Classes > Utility Classes > Validate Class > position (Class Method); Builtin Classes > Utility Classes > Validate Class > positiveNumber (Class Method); Builtin Classes > Utility Classes > Validate Class > positiveWholeNumber (Class Method); Builtin Classes > Utility Classes > Validate Class > requestClassType (Class Method); Builtin Classes > Utility Classes > Validate Class > wholeNumber (Class Method); Builtin Classes > Utility Classes > Validate Class > wholeNumberRange (Class Method)

Deviations: D109

Validate is a set of class methods that check the arguments of a method written in Rexx: that an argument is a number, a whole number in a range, a position, a logical value or an instance of a class. A check that fails raises the SYNTAX condition that the interpreter itself raises for such a mistake, naming the argument, so that a method of the program refuses a bad argument the way the methods of the library do. A check that passes answers no value, except requestClassType, which answers the converted object.

Deviation 109 applies to every argument below that is read as a string or as a number.

The class

[class.validate.creation]

Validate is a class whose only superclass is Object, and it inherits no mixin class (the hierarchy rule). Its instance side defines no method, and its class side answers classType, length, logical, nonNegativeNumber, nonNegativeWholeNumber, number, numberRange, position, positiveNumber, positiveWholeNumber, requestClassType, wholeNumber and wholeNumberRange. new makes an object, which answers none of them: the methods are sent to the class.

v = .validate
say v~superclasses~items v~superclass~id v~class~id
list = 'classType length logical nonNegativeNumber nonNegativeWholeNumber',
  'number numberRange position positiveNumber positiveWholeNumber',
  'requestClassType wholeNumber wholeNumberRange nosuchcheck'
do n over list~makearray(' ')
  say n~upper v~hasMethod(n)
end
s = v~methods(.nil)
say s~available
o = v~new
say o~class~id
signal on syntax name bad
o~number('x', 5)
bad: say condition('o')~code

Arguments

[class.validate.arguments]

Every check takes the name of the argument as its first argument, the value as its second, and then its own further arguments. The name is only used in the error: it may be any string, a name or a text, and it is the first entry of the condition's ADDITIONAL array, whose other entries each rule below gives. The counts are fixed: two arguments for number and logical, two and an optional digits for the other number checks, three for classType and requestClassType, and four and an optional digits for the range checks. A call with fewer raises SYNTAX 93.901, one with more 93.902, and one that leaves out a required argument before the last one given 93.903; omitted arguments at the end count as not given. The ADDITIONAL array of the first holds the least number of arguments, that of the second the most, and that of the third the position of the first argument left out. The argument count is checked first, then digits, and the value last. Every value and bound is read as a string as the conversion rule says. A check that fails raises the SYNTAX error of its method, which the rules below give.

call t 'number', 'N', 'x'
call t 'number', 'my arg', 'x'
call t 'number', 'N'
call t 'number', 'N', 5, 6

call t 'numberRange', 'N', 5, , 9

call t 'numberRange', 'N', 5, 1, 9, 9, 9
call t 'wholeNumber', 'N', 'x', 0
call t 'wholeNumber', 'N', 'x', 5, 6
call t 'classType', 'N', 1
call u 'number("N", )'

[class.validate.digits]

[class.validate.number]

number accepts a string that is a number as DATATYPE with the option N says, and raises SYNTAX 88.902 for any other value, an object whose string value, read as the conversion rule says, is not a number included. positiveNumber also needs the value to be greater than zero (SYNTAX 88.926) and nonNegativeNumber to be zero or greater (SYNTAX 88.925); a value that is no number raises the error of the method asked, so 88.926 or 88.925. [class.validate.wholenumber]

wholeNumber accepts a number whose value, under digits, is a whole number and raises SYNTAX 88.903 for any other value: one with a fraction, one with more integer digits than digits allows, and a string that is no number. positiveWholeNumber also needs the value to be greater than zero (88.905), nonNegativeWholeNumber to be zero or greater (88.904), position to be greater than zero (88.912) and length to be zero or greater (88.911). [class.validate.range]

numberRange(name, number, min, max, digits) accepts a number from min up to and including max, compared under digits, and raises SYNTAX 88.907 for one that is no number and for a value that compares below min or above max as the < and > operators compare them. [class.validate.classtype]

[class.validate.classtype.sends]

classType sends the object isA with class and accepts it when the answer is 1. So the 88.914 that a class that is not a class raises, naming the argument class, is that of isA of Object, and an object whose own isA answers 1 is accepted whatever class is.
