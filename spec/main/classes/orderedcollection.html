OrderedCollection

rexxref: Builtin Classes > Collection Classes > OrderedCollection Class; Builtin Classes > Collection Classes > OrderedCollection Class > append (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > appendAll; Builtin Classes > Collection Classes > OrderedCollection Class > delete (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > difference; Builtin Classes > Collection Classes > OrderedCollection Class > first (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > firstItem (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > insert (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > intersection; Builtin Classes > Collection Classes > OrderedCollection Class > last (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > lastItem (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > next (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > previous (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > section (Abstract Method); Builtin Classes > Collection Classes > OrderedCollection Class > sort; Builtin Classes > Collection Classes > OrderedCollection Class > sortWith; Builtin Classes > Collection Classes > OrderedCollection Class > stableSort; Builtin Classes > Collection Classes > OrderedCollection Class > stableSortWith; Builtin Classes > Collection Classes > OrderedCollection Class > subset; Builtin Classes > Collection Classes > OrderedCollection Class > union; Builtin Classes > Collection Classes > OrderedCollection Class > xor

Deviations: D109, D118

OrderedCollection is the mixin class of the collections whose entries have an order of their own: the arrays, the lists, the queues and the circular queues. It inherits Collection and declares twenty methods of its own. The ones that walk and change a sequence, first, firstItem, last, lastItem, next, previous, append, insert, delete and section, are abstract, and the four sorts are written in terms of other messages. The rest are appendAll and the set operations union, difference, intersection, xor and subset, which replace the versions of Collection for a class that inherits this mixin. disjoint and equivalent are not replaced: they are the methods of that page, and they use the set operations of this one through the messages they send.

The set operations here treat the collection as a sequence that may repeat an item: a repeated item counts as many times as it occurs. They are built on messages that the receiver has to understand: removeItem, which no mixin defines, append, which this mixin declares abstract, and hasItem, which Collection defines. The examples use the class seq, which keeps its items in an array and declares init, string, append, removeItem, allItems, items, isEmpty and copy; hasItem it gets from Collection.

The class

[class.orderedcollection.creation]

OrderedCollection is a mixin class whose superclass is Collection, and queryMixinClass answers 1 for it (the mixin rule). new is not refused and makes an object of the class that received it, as the new rule says. The instance methods that the class declares are append, appendAll, delete, difference, first, firstItem, insert, intersection, last, lastItem, next, previous, section, sort, sortWith, stableSort, stableSortWith, subset, union and xor; there is no class method. A class that inherits the mixin gets these before the methods of Collection of the same name, and gets disjoint, equivalent and the rest from Collection.

c = .orderedcollection~new
say c~class~id c~class~queryMixinClass c~class~superclass~id
names = 'append appendAll delete difference first firstItem insert',
  'intersection last lastItem next previous section sort sortWith',
  'stableSort stableSortWith subset union xor'
n = 0
do m over names~makearray(' ')
  if c~hasMethod(m) then n += 1
end
say n c~hasMethod('DISJOINT') c~hasMethod('HASINDEX') c~hasMethod('OF')

Sorting

[class.orderedcollection.sort]

The methods sort, stableSort, sortWith and stableSortWith sort any receiver through other messages; a class that inherits the mixin and has no sorts of its own, such as List, uses them. They check the number of their arguments first: sort and stableSort take none, and an argument raises SYNTAX 93.902; sortWith and stableSortWith take exactly one, none raises SYNTAX 93.901 and a second SYNTAX 93.902, and the argument is not checked to be a comparator. sort sends stableSort to the receiver, and sortWith sends stableSortWith with its argument. stableSort sends makeArray to the receiver and sort to the answer; stableSortWith sends that answer sortWith with the comparator. Then the receiver is sent first, the sorted array size, and for each place from 1 to that size the array is sent [] with the place, the receiver []= with that item and the current index, and then next with that index, which gives the index for the next item. The receiver answers itself. A receiver whose makeArray reaches an abstract method, an instance of the mixin itself among them, raises SYNTAX 93.965.

Adding

[class.orderedcollection.appendall]

appendAll(source) adds every item of source to the end of the receiver, in the order the source gives them, and answers the receiver. The items are those that the source answers to allItems, an array or any collection. The source need not be a collection: any object that understands allItems is accepted, and an answer that is a string counts as one item. The answer of allItems is taken before the first append, so a collection can append its own items. The method takes exactly one argument: none raises SYNTAX 93.901 and a second raises SYNTAX 93.902. A source that does not understand allItems raises SYNTAX 93.948, and an answer of .nil raises SYNTAX 98.913; both are raised before anything is appended.

Set operations

[class.orderedcollection.operand]

The argument of union, difference, intersection, xor and subset is read as a list of items, and so is that of disjoint and equivalent through the methods that they send. The argument is asked isA with the class Collection (the isA rule). When that answers 1, whichever of the mixins the object has, it is sent allItems, with no argument. [class.orderedcollection.deviation.109]

An instance of a subclass of String that subset compares is read by its own characters, and REQUEST and MAKESTRING are not sent to it (Deviation 109). That reaches the answer of items of the copy, which 0 is compared with. ooRexx sends such an instance request with STRING or MAKESTRING, so an override of either can change what is read. In the example MAKESTRING answers other characters.

say .fake~new(.name~new('7'))~subset(.array~new)
::class name subclass string
::method makestring
  return '0'
::class fake inherit orderedcollection
::method init
  expose count
  use arg count
::method copy
  return self
::method removeitem
  nop
::method items
  expose count
  return count

0
[class.orderedcollection.deviation.118]

An instance of a subclass of List that appendAll or one of the operations that read a list gets as the answer of allItems is sent makeArray, so that its own makeArray is used, as the answer rule says for any collection. ooRexx uses the items such an instance holds and sends it no makeArray. In the example the subclass answers other items than it holds.

s = .seq~new
s~appendAll(.src~new(.llist~of('held')))
say s~items s~firstItem
s = .seq~new
say s~union(.src~new(.llist~of('held')))~items
::class llist subclass list
::method makearray
  say 'makearray sent'
  return .array~of('answered')
::class src inherit collection
::method init
  expose ans
  use arg ans
::method allitems
  expose ans
  return ans
