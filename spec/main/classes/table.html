Deviations: D33, D78, D84, D109

A Table maps indexes to items. Both are any objects: an index is found by the hashCode and the == that it answers to, so two indexes are one entry when they hash alike and compare equal, and a table holds at most one item for each index. The class inherits MapCollection, and through it Collection; the hierarchy rule lists what it inherits. Directory and StringTable are tables whose indexes are strings, IdentityTable is the table whose indexes are compared by identity, and Relation is the table that keeps several items for an index.

A table has no unknown method: a message that the method search does not resolve raises NOMETHOD, as the error rule of the chapter says. The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. The page says nothing about which of two items equal to the argument removeItem removes (the hash order rule).

The class

[class.table.creation]

Table declares the instance methods [], []=, allIndexes, allItems, at, empty, hasIndex, hasItem, index, isEmpty, items, makeArray, put, remove, removeItem and supplier, the init that new runs (the new rule) and the class method new; the copy of Object copies a table as the copy rule says. The class method of and the instance methods putAll, union, difference, intersection, xor, subset, disjoint and equivalent are those of the mixins (one rule lists them). A table has no makeString, so it is not a string (the string rule), and no unknown and no allAt.

end

Making a table

[class.table.new]

new makes an empty table. Its optional argument is a hint for how large the table will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that Table supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

say .table~new~items .table~new(0)~items .table~new(3, )~items
call try '.table~new(-1)'
call try '.table~new("x")'
call try '.table~new(.nil)'
call try '.table~new(1.5)'
call try '.table~new(1, 2)'
x = .watch~new(7)
call try '.watch~new("x")'
say .quiet~new("x", 2, 3)~items
exit

Indexes

[class.table.indexes]

An index is any object, .nil and the null string included, and is stored as it is: allIndexes answers the very objects that were stored. Two indexes are one entry when the lookup finds that hashCode answers the same string for both and that ==, sent to one with the other as argument, answers true. For an object that declares neither method that is the same object, and an Array is its own index only. A string is the index of its characters, compared by the strict comparison: case counts, a leading or trailing blank counts, and 5 and 5.0 are two indexes. An instance of a subclass of String that declares neither method is the index of its characters like any string. A class that declares == has to declare hashCode so that equal objects hash alike, as the hash code rule says. When a put finds the index already in the table, the entry keeps the index object it has and takes the new item.

t = .table~new
t~put('v1', 'Key')
t~put('v2', 'KEY')
t~put('v3', 5)
t~put('v4', 5.0)
t~put('v5', ' a')
t~put('v6', '')
t~put('v7', .nil)
a = .array~of(1)
t~put('arr', a)
say t~items t~at('Key') t~at('key') t~at(5) t~at('5.0') t~at('a') t~at('')
say t~at(.nil) t~at(a) (t~at(.array~of(1)) == .nil) t~at(.sub~new('Key'))
t~put('v8', .eq~new('x', 'first'))
t~put('v9', .eq~new('x', 'second'))
say t~items t~at(.eq~new('x', 'probe')) t~allIndexes~items
ix = t~allIndexes
do i over ix
  if i~isA(.eq) then say i~tag
end

[class.table.indexes.sends]

at, [], hasIndex, put, []= and remove look the index up by sending hashCode to the index argument, once, and then == to the index argument with a stored index as the argument, for stored indexes that have the same hash code, until one answers true; each of those is compared before the lookup gives up. Which further stored indexes are compared, by == or hashCode, and how often, is not specified (the hash order rule); when the table is empty, the only message is hashCode. The very object that is stored is no exception to the == (the deviation rule). In the example every index hashes to the same string, so each stored index is compared.

.local~log = .array~new
say 'empty:' .table~new~at(.k~new('p')) .local~log~makeString('L', ' | ')
calls = 't~at(.k~new("p"))|t[.k~new("p")]|t~hasIndex(.k~new("p"))',
  '|t~put("v2", .k~new("p"))|t[.k~new("p")] = "v2"',
  '|t~put("v3", .k~new("s1"))|t~remove(.k~new("s1"))'
do c over calls~makeArray('|')
  t = .table~new
  t~put('v1', .k~new('s1'))
  .local~log~empty
  interpret c
  say c '=>' .local~log~makeString('L', ' | ')
end
exit
::class k
::method init
  expose tag
  use arg tag
::method tag
  expose tag
  return tag
::method '=='
  expose tag
  use arg o
  .local~log~append('==' tag o~tag)
  return tag == o~tag
::method hashCode
  expose tag
  .local~log~append('hash' tag)
  return 'same'

Lists of the entries

[class.table.makearray]

allIndexes and makeArray answer a new Array of the indexes of the entries, and allItems a new Array of their items. They are instances of Array for a subclass receiver too, never the receiver, and do not follow later changes. They take no argument: one raises SYNTAX 93.902. The order is not specified (the hash order rule), and is the same for the three answers and for the supplier of one unchanged table, so the item at a position belongs to the index at the same position. The methods send no message to the table or to the indexes and items.

t = .many~new
do i = 1 to 40
  t~put('item'i, .array~of(i))
end
ix = t~allIndexes
it = t~allItems
bad = 0
do i = 1 to ix~items
  if t~at(ix[i]) \== it[i] then bad += 1
  if t~makeArray[i] \== ix[i] then bad += 1
end
say ix~class~id it~class~id t~makeArray~class~id ix~items it~items bad
a = t~allItems
t~put('x', 'extra')

Messages the methods send

[class.table.sends]

No method that Table declares sends a message to its receiver: an override of at, put or any other of the methods is never asked by another method, and [] and []= do not use at and put. The messages the methods do send go to other objects and have a rule each: init to the new object by new (the new rule); hashCode and == to the index argument by at, [], hasIndex, put, []= and remove (the lookup rule); == to the argument by hasItem, index and removeItem (the search rule). makeArray, allIndexes, allItems, supplier, copy, items, isEmpty and empty send nothing to the indexes and the items. The set operations send what the pages of the mixins say. In the first example a subclass has every method overridden to record its name, and each call records only its own; in the second the indexes and items record every message a program is likely to override.
