A Queue is an ordered collection that is addressed by position: the item at the head is at index 1, the next at index 2, and so on up to the number of items, so an index is where an item stands now, not a name for it. Adding an item at the head or in the middle, or taking one out, moves the items behind it to other indexes. The class inherits OrderedCollection, and through it Collection; the hierarchy rule lists what it inherits. CircularQueue is its subclass.

The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. The page says nothing about an entry whose item was omitted in an insert.

The class

[class.queue.creation]

Queue declares the instance methods [], []=, allIndexes, allItems, append, at, delete, empty, first, firstItem, hasIndex, hasItem, index, insert, isEmpty, items, last, lastItem, makeArray, next, peek, previous, pull, push, put, queue, remove, removeItem, section, size and supplier, a copy that this page specifies (the copy rule), and the class methods new and of. A queue has no makeString, no toString, no fill and no dimensions, and no method of its own that sorts: sort, sortWith, stableSort and stableSortWith are those of OrderedCollection, which sort a queue through its makeArray, first, next and []= (the sort rule). The set operations and appendAll are those of the mixins, and one rule lists them.

Making a queue

[class.queue.new]

new makes an empty queue. Its optional argument is a hint for how large the queue will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that Queue supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

q = .queue~new
say q~items q~isEmpty q~first
say .queue~new(0)~items .queue~new(1000)~items .queue~new(3, )~items
call try '.queue~new(-1)'
call try '.queue~new("x")'
call try '.queue~new(.nil)'
call try '.queue~new(1.5)'
call try '.queue~new(1, 2)'
x = .watch~new(7)
y = .watch~new
call try '.watch~new("x")'
say .quiet~new("x", 2, 3)~items
exit

[class.queue.of]

of makes a queue that holds its arguments in the order given: the first is at the head. An argument left out at the end counts for nothing, so of(1, ) holds one item; an argument left out before a given one raises SYNTAX 93.903. .nil is an item like any other. The result is an instance of the class that received the message. of sends init to the new object with no argument and not new, and adds the items itself: the append, queue, push, insert and put of a subclass are not sent for them.

Indexes

[class.queue.indexes]

An index of a queue is a whole number of at least 1, the position of an item counted from the head. A method that takes an index reads it from its string value (the conversion rule) as a whole-number argument of a builtin is (the form rule, the digits rule): "2", ' 2 ' and 2.0 are as good as 2, NUMERIC DIGITS plays no part, and an argument that those rules refuse, a number below 1, or .nil raises SYNTAX 93.907. An object that is not a string is read by its string value, so an array is read through its makeString: an array of exactly one such index gives that index, and an array with none or with more than one gives a string that is not an index and raises SYNTAX 93.907, as does a list, whose string value is not an index either. An index above the number of items is not an error for the methods that look an item up: at answers .nil, hasIndex answers 0, delete and remove answer .nil, next answers .nil, previous answers the last index and section an empty queue; insert and put raise a condition (the insert rule, the put rule). Where a method adds or removes an item in front of others, those others have other indexes afterwards, and the examples of the methods show it.

[class.queue.put]

put(item, index) replaces the item at the index and answers no value; the other items keep their indexes. q[i] = v is the message []= and the same as put. [class.queue.insert]

insert(item, index) adds the item as a new entry directly after the item at the index and answers the index of the new entry. An index of .nil makes the item the first, and an omitted index the last. Messages the methods send

[class.queue.sends]

No method that Queue declares sends a message to its receiver: an override of at, put, append, queue or any other of the methods is never asked by another method, and [] and []= do not use at and put. The messages the methods do send go to other objects, and each has a rule of its own: init to the new object by new and of (the new rule, the of rule), new and init by section (the section rule); == to the argument by removeItem, hasItem and index (the search rule). The sorts, which are not methods of the class, send messages to the receiver and to the array of makeArray, as their rule says. The methods string and copy of an instance and the set operations send what the pages that own them say. No argument is asked isA, and a string value is read as the conversion rule says. In the example a subclass has every method of Queue overridden to record its name, and each call records only its own.

own = '[] []= allIndexes allItems append at delete empty first firstItem',
  'hasIndex hasItem index insert isEmpty items last lastItem makeArray next',
  'previous put remove removeItem section supplier copy peek pull push queue',
  'size'
.local~log = .array~new
do m over own~makeArray(' ')
  src = "if .local~on then .local~log~append('"m"'); forward class (super)"
  .spy~define(m, src)
end
a = .spy~of('c', 'b', 'a')
calls = 'x = a[1]|a[1] = "x"|a~allIndexes|a~allItems|a~append("d")|a~at(1)',
  '|a~insert("e", 1)|a~hasIndex(1)|a~hasItem("q")|a~index("q")|a~isEmpty',
  '|a~items|a~first|a~last|a~firstItem|a~lastItem|a~makeArray|a~next(1)',
  '|a~previous(2)|a~put("y", 1)|a~section(1)|a~supplier|a~copy|a~peek|a~size',
  '|a~queue("k")|a~push("j")|a~pull|a~removeItem("q")|a~remove(1)',
  '|a~delete(1)|a~empty'
n = 0
extra = 0
.local~on = 0
do c over calls~makeArray('|')
  .local~log~empty
  .local~on = 1
  interpret c
  .local~on = 0
  n += 1
  if .local~log~items <> 1 then do
    extra += 1
    say c '=>' .local~log~makeString('L', ' ')
  end
end
say n 'calls,' extra 'sent more than one message to the receiver'

Deviations

[class.queue.deviation.78]

A search for an item with the very object that is stored, by hasItem, index or removeItem, sends that object's == as for any other item, so an object whose == answers false is not found even at its own entry. ooRexx finds the very object without sending it ==, and sends == only for the items before it. See Deviation 78.

.local~n = 0
x = .liar~new
c = .queue~new
c~append('a')
c~append(x)
c~append('b')
say c~hasItem(x) .n
.local~n = 0
say (c~index(x) == .nil) .n
.local~n = 0
say (.nil == c~removeItem(x)) c~items .n
::class liar
::method '=='
  .local~n += 1
  return 0

[class.queue.deviation.109]

An index or a count that is an instance of a subclass of String is read by its own characters, and REQUEST and MAKESTRING are not sent to it (Deviation 109). As an index, ooRexx sends such an instance request with STRING or MAKESTRING, so an override of either can change what is read. In the example MAKESTRING answers another index.

q = .queue~of('first', 'second')
say q~at(.num~new('1'))

  return '2'

[class.queue.deviation.121]

put with an index above the number of items raises SYNTAX 93.966 however far above it the index is, and the queue keeps its items. ooRexx raises 93.966 or 93.918 according to the storage the queue holds beyond its items, which its earlier history decides: an index just above the last item can answer either, and a much larger one answers 93.918.

q = .queue~of('a', 'b', 'c')
do i over .array~of(4, 5, 20, 50, 1000)
  call try 'q~put("x", 'i')'
end
say q~allItems~makeString('L', ',')
exit
