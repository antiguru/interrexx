A MutableBuffer holds a string of characters that a program changes in place. Where a String is a value, so that every operation answers a new string, a buffer is an object with an identity: append, insert, upper and the other changing methods alter the characters it holds and answer the buffer itself. Beside the characters a buffer has a size, the number of characters it can hold before it has to grow, which a program can read and set. A buffer is no String: it understands a part of the String methods, and for those it states only what differs, the rest being linked to the page that owns it.

The class

[class.mutablebuffer.creation]

MutableBuffer is a class whose only superclass is Object; it inherits no mixin class (the hierarchy rule), and it is not a subclass of String. It defines the instance methods of this page, and new is stated below. A message that names a String method the buffer does not define, such as left or abbrev, and an arithmetic operator sent to a buffer, raise SYNTAX 97.1 (the error rule). The comparison operators and the joining operators are covered by the comparison rule and the string value rule.

b = .mutablebuffer~new('abc')
say b~class~id b~isA(.string) b~isInstanceOf(.mutablebuffer)
do c over .mutablebuffer~superclasses
  say c~id
end
say b~hasMethod('APPEND') b~hasMethod('LEFT') b~hasMethod('ABBREV')
call try 'b~left(2)'
call try 'b + 1'
call try 'b~abbrev("a")'
exit

[class.mutablebuffer.new]

new makes a buffer from at most two arguments, and sends the new buffer init with the arguments after them (the new rule). The first argument, the text, is read for its string value as the argument rule says, and defaults to the null string; an object with no string value, .nil included, raises SYNTAX 88.909. The second argument, the size, is read after the first and must be a non-negative whole number, or the call raises SYNTAX 93.923; it defaults to 256 when it is omitted. A whole-number argument of a method of this class is read as that of a builtin is (the form rule, the digits rule), so NUMERIC DIGITS plays no part, and only the error code differs. The buffer holds the text and has the size given, except that a size smaller than the length of the text is raised to that length. A subclass receiver gets an instance of itself. Both arguments are checked before init is sent, so a failing new runs no init, and the reading of the first argument comes before the check of the second.

call show .mutablebuffer~new
call show .mutablebuffer~new('hello')
call show .mutablebuffer~new('hello', 10)
call show .mutablebuffer~new(, 40)
call show .mutablebuffer~new('hello', 2)
call show .mutablebuffer~new('hello', 0)
call show .mutablebuffer~new(copies('x', 300))
call try ".mutablebuffer~new('a', 'x')"
call try ".mutablebuffer~new('a', -1)"
call try ".mutablebuffer~new('a', 1.5)"
call try ".mutablebuffer~new(.nil)"
call try ".mutablebuffer~new(.nil, 'x')"
call try ".mutablebuffer~new('a', 1, 2)"
exit

[class.mutablebuffer.new.init]

The buffer already holds its text and has its size when init is sent, and init gets no argument unless new had more than two: it gets those after the second, in order. The init of Object takes no argument, so a call of new with a third argument raises SYNTAX 93.902 unless a subclass declares an init that takes it. An init of a subclass need not call its superclass: the buffer is complete without it. init sent to a buffer that exists accepts no argument either, and leaves it as it was.

call try ".keep~new('abc', 40)"
call try ".keep~new('abc', 40, 'x', 'y')"
call try ".skip~new('abc')~string"
call try ".keep~new('abc', 'x')"
call try ".mutablebuffer~new('abc', 5, 'x')"
b = .mutablebuffer~new('abc', 9)
b~init
say b~string b~getBufferSize
call try 'b~init(1)'
exit

[class.mutablebuffer.string]

string answers a String with the characters the buffer holds at that moment, and takes no argument: one raises SYNTAX 93.902. A string taken earlier does not follow later changes to the buffer. The string value of the buffer, which say, the joining operators and the arguments of the other methods use, is found as the string-value rule says, and is the same text, since a buffer answers makeString with its characters.

[class.mutablebuffer.makestring]

makeString answers a String with the characters of the buffer, as string does, and takes no argument (SYNTAX 93.902). The request of Object answers it for STRING, so a subclass that declares its own makeString decides what say b, b || x and a buffer given as an argument read, and an override of string changes only what string answers. request('ARRAY') answers an array, that of makeArray. Whether two calls answer one string object or two is not specified (Deviation 4).

[class.mutablebuffer.comparison]

A buffer compares as an object: =, ==, \=, \==, <> and >< are the methods of Object (the equality rule), which find two buffers equal only when they are the same buffer, however alike their characters are, and a buffer is never equal to a string when the buffer is the receiver. The other comparison methods, <, >, <=, >=, << and >> with their negations, are not defined, and raise SYNTAX 97.1. A string that is the receiver reads the string value of its argument, so 'abc' = b and 'abc' == b are true when the buffer holds abc (the string rules).

a = .mutablebuffer~new('abc')
b = .mutablebuffer~new('abc')
say (a = a) (a == a) (a = b) (a == b) (a \= b) (a <> b) (a \== b) (a >< b)
say ('abc' = a) ('abc' == a) (a = 'abc') (a == 'abc')
say ('abd' > a) ('abd' << a) ('abd' >> a)
call try 'rr = a < b'

exit

[class.mutablebuffer.copy]

copy answers a new buffer of the same class, holding the same characters and having the same size, with the object variables of the receiver copied as the copy rule says. The copy is independent: a change to either buffer does not reach the other, and the size of each grows by itself. copy sends no init and no other message, takes no argument (SYNTAX 93.902), and answers an instance of the class of the receiver, a subclass included.

Size

[class.mutablebuffer.size]

A buffer has a length, the number of characters it holds, and a size, the number of characters it can hold; the size is never smaller than the length. Every change that makes the buffer longer than its size raises the size to the larger of the new length and twice the old size; append makes one such change for each argument, in turn. No other method changes the size but setBufferSize, so deleting characters leaves it as it was. copy gives the copy the size of the original.

b = .mutablebuffer~new('abc', 5)
say b~length b~getBufferSize
b~append('de')
say b~length b~getBufferSize
b~append('f')
say b~length b~getBufferSize
b~append(copies('x', 20))
say b~length b~getBufferSize
b~delete(1, 20)
say b~length b~getBufferSize
b = .mutablebuffer~new
b~setText(copies('y', 300))
say b~length b~getBufferSize
b = .mutablebuffer~new('abcdefgh', 12)
b~setBufferSize(5)
say b~string b~length b~getBufferSize
b~setBufferSize(30)
say b~string b~length b~getBufferSize
b~setBufferSize(0)
say '<' || b~string || '>' b~length b~getBufferSize

[class.mutablebuffer.setbuffersize]

Changing the text

[class.mutablebuffer.append]

append appends the string value of each of its arguments, from left to right, and answers the buffer itself. At least one argument is required (SYNTAX 93.903), and an argument that is omitted before the last one present raises SYNTAX 93.903 too; trailing omitted arguments are ignored. Messages that a program can override

[class.mutablebuffer.sends]

No method of the class sends a message to the buffer it works on: not length, string, makeString, append, insert, setText, substr, delStr, getBufferSize, setBufferSize or any other, so that a subclass that overrides one of these changes only the calls that name it. new sends init as the init rule says and copy sends nothing. What a method sends to its arguments is the reading of their string values, once for each argument that is present and in the order of the arguments, each reading followed at once by the check of that argument: the first argument that fails raises its error and the arguments after it are not read. The reading is the string-value rule's: the argument is sent request with STRING, and the request of Object sends it makeString, so an argument that is a buffer of a subclass is sent both. append reads and appends one argument at a time. A call with too many arguments reads none. Nothing but that reading is sent to an argument. The first example prints, for each call, the messages that the subclass saw; the second passes objects that answer a string and log the reading, named by their first argument, and would log isA, string and class too; their request is that of Object. It prints the log in order, with the error that ended the call. The third example shows the request that comes before each makeString.

[class.mutablebuffer.deviation.4]

Whether two calls of string or of makeString answer one string object or two is not specified, and shows only through identityHash and the identity collections (Deviation 4). The characters are specified, and a string taken from a buffer never follows the buffer's later changes. ooRexx answers a new string at each call of makeString, where interrexx answers the same one.

b = .mutablebuffer~new('abc')
x = b~makeString
y = b~string
say (x == y) (x == 'abc') (x~hashCode == y~hashCode)
b~append('d')
say x b~makeString

[class.mutablebuffer.deviation.9]

A native routine that holds the address of the characters of a buffer keeps reading valid storage when the buffer grows, even across a collection (Deviation 9). In ooRexx a collection after the growth reclaims the old storage, and the routine then reads garbage. A program in Rexx sees only that the characters survive the growth, which the example shows: the buffer grows several times and still holds what was appended before.

b = .mutablebuffer~new('abc', 3)
do 5
  b~append(copies('x', 200))
end
say b~length b~substr(1, 6) b~substr(1001)
say b~string~length

[class.mutablebuffer.deviation.109]

An instance of a subclass of String that is given to a method of the buffer as a string, a number or a whole number, for the text of new, the size, a position, a length or the pad of the methods above, is read by its own characters, and REQUEST, MAKESTRING and STRING are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING and reads the answer, so an override can change what the method reads. In the example the subclass answers other strings from all three methods and counts the sends, and the instance n is the number 2, s the string ab, so the buffer is made from the characters ab, with size 2.

s = .shout~new('ab')
n = .shout~new('2')
b = .mutablebuffer~new(s, n)
say b~string b~length b~getBufferSize
b~append(s)
b~insert(s, n)
b[n] = s
say b~string b~length
say b[n] b~pos(s) b~substr(n, n)
say 'sends' .local~sent
