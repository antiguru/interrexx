Deviations: D78, D109, D118

Collection is the mixin class that all the collection classes have in common. It defines nineteen methods. Seven of them are abstract: they name what a collection has to be able to do, reading and writing an entry by its index and listing its indexes and items, and a class that inherits Collection declares them. The other twelve are written in terms of those seven and of the messages a collection answers for itself. They are the questions about an index, an item, the count and a supplier, and the set operations that combine two collections. A class that inherits only Collection gets all twelve working as the rules below say; a concrete class of the library may declare a method of the same name instead, and its page says what that method does.

The page specifies the methods in that order. Where a method sends a message that a program can override, its .sends rule gives the message, the receiver and the order, as the sends rule asks. The argument of a set operation is read by a rule of its own, shared by the seven operations. OrderedCollection declares its own versions of five of the set operations, and MapCollection its own makeArray; the pages of the concrete collections link to this page for what they do not declare.

The examples use the class box, a collection of strings in which the item and the index of an entry are the same string. It keeps its entries in a directory, answers the indexes and the items in sorted order, and declares put, remove and copy for the set operations; the rest it gets from Collection.

The class

[class.collection.creation]

Collection is a mixin class whose superclass is Object, and queryMixinClass answers 1 for it (the mixin rule). new is not refused: it makes an object of the class that received it, as the new rule says, and that object understands the nineteen methods of the class and no others beyond those of Object. A class that inherits Collection, or a subclass of such a class, understands them all and gets each from this page unless it or a class between it and Collection declares a method of the same name.

The abstract methods

[class.collection.abstract]

The methods [], []=, at, put, allIndexes, allItems and index are abstract. Sent to an object whose class has none of its own, each raises SYNTAX 93.965 whatever arguments the message has, none or too many included, and the raising comes before any check of the arguments, so that at with no argument raises 93.965 and not a missing-argument error (the abstract rule). The assignment c[i] = v is the message []=. A class that declares one of them answers the message itself. The methods that this page defines build on these: allIndexes and allItems are what hasIndex, hasItem, items, makeArray and supplier use, and put is what the set operations use to store.

call try 'c~at(1, 2, 3)'

The set operations

[class.collection.operand]

The argument of union, difference, intersection, xor, subset, disjoint and equivalent is read as a list of entries, and what is sent to it depends on what it is, which the object itself decides by its answers to isA (the isA rule). An ordered argument, one for which isA says it is an OrderedCollection, is sent allItems. Any other object for which isA says it is a MapCollection is sent supplier by union, intersection, xor and disjoint, and allIndexes by difference and subset. Every other object is sent makeArray. An object that is both counts as ordered. An element of an ordered or plain list is an index and an item at once; an entry of a map is its own index with its own item. disjoint reads its argument through intersection, and equivalent through subset. What is done with the answer is the subject of the list rule, the map rule and the answer rule.

[class.collection.operand.list]

The answer of allItems or makeArray is read as two arrays, the items and the indexes, and the operation takes the entries from position 1 of the items up to its size, an entry being the item at the position and the index at the same position, .nil when there is none. An answer that is an Array of that class itself is both arrays: it is read position by position, so an element is its own index, and a position that holds nothing is an entry whose item and index are .nil. Any other answer, an instance of a subclass of Array included, is sent makeArray twice, and the first answer is the items and the second the indexes; for a List, a Queue, a Set or a string the two are the same. An instance of a subclass of List is such an answer, and is sent makeArray like the instance of any other class that is not Array itself (Deviation 118). Messages that the operation sends to the entries are those of its own rule.
