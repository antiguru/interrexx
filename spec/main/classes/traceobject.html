The interrexx Language Specification

TraceObject

rexxref: Builtin Classes > Utility Classes > TraceObject Class; Builtin Classes > Utility Classes > TraceObject Class > activate (Class Method); Builtin Classes > Utility Classes > TraceObject Class > collector (Class Method); Builtin Classes > Utility Classes > TraceObject Class > collector= (Class Method); Builtin Classes > Utility Classes > TraceObject Class > counter (Class Method); Builtin Classes > Utility Classes > TraceObject Class > makeStringImpl (Class Method); Builtin Classes > Utility Classes > TraceObject Class > new (Class Method); Builtin Classes > Utility Classes > TraceObject Class > notify (Class Method); Builtin Classes > Utility Classes > TraceObject Class > notify= (Class Method); Builtin Classes > Utility Classes > TraceObject Class > option (Class Method); Builtin Classes > Utility Classes > TraceObject Class > option= (Class Method); Builtin Classes > Utility Classes > TraceObject Class > setMakeString (Class Method); Builtin Classes > Utility Classes > TraceObject Class > unsetMakeString (Class Method); Builtin Classes > Utility Classes > TraceObject Class > compareTo; Builtin Classes > Utility Classes > TraceObject Class > makeString

Deviations: D7, D50, D109

Every line that TRACE writes is first an object, a TraceObject: a StringTable whose entries describe the line, the code that produced it and the moment, and whose string value is the text of the line. The object, and not its text, is what the trace destination receives. The class lets a program choose how the text is formatted (the option), see every line as an object while the program runs (notify) or afterwards (collector), and replace the formatting altogether (setMakeString).

The class methods live on the class object, as the attributes of a singleton do: .traceobject~option = 'S' sets one. The instance methods are makeString and compareTo; everything else an instance answers is that of StringTable and its entries. This page links the rules of the TRACE instruction for what a trace line says and for where it goes. Deviation 7 covers the order in which concurrent activities' lines arrive, and Deviation 50 a line the destination refuses. Deviation 109 applies to every argument below that is read as a string.

The class

[class.traceobject.creation]

TraceObject is a class whose only superclass is StringTable; it inherits no mixin class of its own (the hierarchy rule), and no class of the library is its subclass. Its instance side defines compareTo and makeString. The class side answers activate, collector, collector=, counter, makeStringImpl, new, notify, notify=, option, option=, setMakeString and unsetMakeString. A subclass of TraceObject has class attributes of its own: its new counts with its own counter, from 0, sends append to its own collector, and its instances' makeString follows its own option and setMakeString. The interpreter makes the objects for trace lines with TraceObject itself, so the attributes of a subclass do not affect them.

t = .traceobject
say t~superclasses~items t~superclass~id t~subclasses~items
say t~isSubclassOf(.stringtable) t~isSubclassOf(.directory)
s = t~methods(.nil)
names = .array~new
do while s~available
  names~append(s~index)
  s~next
end
say names~sort~makeString('l', ' ')
list = 'ACTIVATE COLLECTOR COLLECTOR= COUNTER MAKESTRINGIMPL NEW NOTIFY',
  'NOTIFY= OPTION OPTION= SETMAKESTRING UNSETMAKESTRING NOSUCH'
do n over list~makearray(' ')
  say n t~hasMethod(n)
end

[class.traceobject.new]

new makes a TraceObject with three entries: NUMBER, the number of the object, which is the counter after the count has gone up by one, OPTION, the option at that moment, and TIMESTAMP, a DateTime. The interpreter makes the objects for trace lines in the same way and then adds more entries, as the entries rule says. When a collector is set, new sends it append with the new object. new takes at most one argument, the size hint that new of StringTable takes, with the same check: a value that is not a whole number of at least 0 raises SYNTAX 93.923, and two arguments raise SYNTAX 93.902. A new that raises makes no object: the counter does not go up and no collector receives append.

t = .traceobject
say t~counter
n = t~new
say n~class~id n~items t~counter n~allIndexes~sort~makeString('l', ' ')
say n~number n~option n~timestamp~class~id

[class.traceobject.lines]

A line of trace output is made like this. The interpreter makes the object with new, so that a collector sees it first, with only the three entries of new; it adds the other entries; a notify object then receives the complete object with append; and last the object is sent to the trace destination with lineout. The destination reads the line through makeString, which is what the string value of the object means for every use that needs a string. The same TraceObject is delivered to all three.

.traceoutput~destination(.sink~new)
a = .array~new
b = .array~new
.environment['COLLECTED'] = a
.environment['NOTIFIED'] = b
.traceobject~collector = .rec~new('collect', 'COLLECTED')
.traceobject~notify = .rec~new('notify', 'NOTIFIED')
trace r
x = 1
trace off
.traceobject~collector = .nil
.traceobject~notify = .nil
n = .traceobject~new
say 'say gives' '['n~~put('shown', 'TRACELINE')']' '['n~string']'
::class rec
::method init
  expose name key
  use arg name, key
::method append
  expose name key
  use arg o
  .environment[key]~append(o)
  .output~lineout(name 'append' o~items o~number)
::class sink
::method lineout
  use arg line
  a = .environment['COLLECTED']
  b = .environment['NOTIFIED']
  .output~lineout('destination' line~class~id '['line~makeString']',
    (line == a~lastItem) (line == b~lastItem))
  return 0

[class.traceobject.entries]

A traced line has the entries INTERPRETER, INVOCATION and THREAD, the numbers of the interpreter, the invocation and the activity of the traced code as RexxContext gives them, NUMBER, OPTION and TIMESTAMP as new makes them, TRACELINE, the text of the line in the N format, and STACKFRAME, a StringTable that describes the level that produced the line with the entries ARGUMENTS, EXECUTABLE, INVOCATION, LINE, NAME, TARGET, TRACELINE and TYPE, which answer what the StackFrame methods of the same names answer. A line traced in a method adds ATTRIBUTEPOOL, HASSCOPELOCK, ISGUARDED, RECEIVER and SCOPELOCKCOUNT, and the line that announces the method, flagged >I>, adds CALLERSTACKFRAME, the frame of the code that called it. A line that shows a variable being read or assigned adds VARIABLE, a StringTable with the entries NAME, VALUE and ASSIGNMENT, which is 1 for an assignment and 0 for a read. Which clause the STACKFRAME of the >I> line shows, in its LINE and its TRACELINE, and the values of HASSCOPELOCK and SCOPELOCKCOUNT of the lines that follow an EXPOSE in a method, are not specified. The example shows each set of entries once, with the first word of the line that has it.

.traceoutput~destination(.sink~new)
.traceobject~notify = .rec~new
trace i
x = 1
y = x + 1
call plain
z = .o~new~m
trace off
.traceobject~notify = .nil
exit

Class attributes

[class.traceobject.collector]

collector answers the object that is sent append with each TraceObject at the moment it is made, .nil when there is none, which is the setting at the start. collector= takes that object, any object, or .nil to stop the collecting. It takes exactly one argument: none raises SYNTAX 93.903 and two 93.902. A collector sees the object with the three entries of new only; the others are added afterwards and are there when the program reads the object later.

[class.traceobject.option]

option answers the setting that chooses the format of the trace lines, one of N, T, S, F and P, and N at the start. option= reads its argument as a string and keeps the first character in upper case if it is one of n, t, s, f or p, so that Normal, Thread, Standard, Full and Profiling or Probing can be written as words; the rest of the string is not examined. A string that does not begin with one of the five letters, the null string included, raises SYNTAX 93.914. option= takes no more than its first argument into account.

t = .traceobject
say t~option
do v over 'n Normal thread Standard FULL profiling probing tx'~makearray(' ')
  t~option = v
  say v '=>' t~option
end
call try '"x"'
call try '""'
call try '5'
call try '" s"'
say t~option
t~option = 'N'
exit

[class.traceobject.makestringimpl]

makeStringImpl answers the text of one TraceObject, which it takes as its one argument, in the format that the option names. With N it is the TRACELINE entry, or ? when the object has none. With T the number of the thread is put inside the flag of the trace line: after the first two characters of *-*, so that it reads *-1*, and likewise >>1>; this describes the lines that the interpreter makes, and where the number goes in any other text that a program sets as TRACELINE is not specified here. With S the line is preceded by [T, the thread number padded to three columns and at least one blank, I and the invocation number padded to two columns, ] and fifteen blanks. With F the prefix is [R, the interpreter number padded to four columns and at least one blank, T, the thread number in the same way, I, the invocation number padded to four columns, ] and eighteen blanks. With P the entry OPTION of the object chooses the format: a value equal, as the = operator compares, to N or P gives that of N, T that of T and S that of S, and any other value, the lower-case letters and the null string included, that of F; an object without an OPTION entry is formatted like N. The line of a method carries more fields in the prefix. makeStringImpl raises SYNTAX 93.901 with no argument, 93.902 with two and 93.924 for a string argument; the next rule gives the reading of the argument. A StringTable without entries gives ?.

t = .traceobject
do o over 'N T S F P'~makearray(' ')

[class.traceobject.makestringimpl.method]

When the object has an ATTRIBUTEPOOL entry, as every line traced in a method has, S and F write four more fields between the invocation number and the ]. The invocation number is then padded to two columns (S) or four (F) and followed by a blank. The first field is G when ISGUARDED is 1 and U when it is 0, then u when the method is guarded and HASSCOPELOCK is 0, g when it is unguarded and HASSCOPELOCK is 1, and a blank otherwise, then a blank. Next come A and the ATTRIBUTEPOOL value, padded to two columns (S) or four (F), and a blank; then L and the SCOPELOCKCOUNT value, padded to two columns (S) or three (F), and a blank; then * when HASSCOPELOCK is 1 and a blank otherwise, and a blank. One blank follows the ]. A missing ISGUARDED shows ? as the first field, and a missing SCOPELOCKCOUNT ? as its value; a missing HASSCOPELOCK shows ? in the place of the * and of the blank after it. An ISGUARDED or HASSCOPELOCK entry that is neither 0 nor 1 raises SYNTAX 34.901; the other two values are written as they are, whatever they hold.

[class.traceobject.deviation.7]
