A File holds a path, and its methods ask about or change the file or directory that the path names. The path may name something that does not exist: the methods look at the file system when they are called. The class also has methods that read and write whole files, search a list of directories for a file, and name the places where files live. The rules of this page are those of a Unix-like system, where the components of a path are separated by slashes, as QUALIFY assumes; the paths of other systems are not specified. Nor are the choices of the file system and the host: whether names that differ in case are different names, the home directory, the temporary directory, the size of a directory, how precisely a file keeps its times, and what the user may do with a file that the examples did not make. The examples make files and directories under names of their own, derive every expected value from what they made, and remove what they made. The class inherits Comparable and Orderable, and orders its instances by their absolute paths; the comparison operators of an instance are those of Orderable.

[class.file.creation]

Making a File

[class.file.new]

new sends init (the new rule). init takes a path and an optional dir. The path is read as a string argument: a File given as path is read by its makeString, which is its absolute path, and an argument with no string value raises SYNTAX 88.909. A call with no argument raises SYNTAX 93.901, one with a third argument 93.902, and one with dir and no path 93.903 (the argument rules). The path that the instance holds is made in these steps. First path and dir each lose their trailing slashes, but a lone slash keeps its slash: a//b/// is a//b, /// is /, and the empty string stays empty; slashes anywhere else are kept. Then, when dir is omitted or .nil, the path is the path that is left. Otherwise it is dir, a slash and path, where the slash is left out when dir ends in one or path begins with one, and where both supply one a single slash stands. A dir that is the empty string counts as a dir, so a with an empty dir is /a. A dir that is a File is read as its absolute path, and any other dir as a string argument, with the error that a path has. The text of the path is kept as it was written, apart from these steps: path (the path rule) answers it, and a File made with a relative path or dir is relative to the current directory when it is made (the absolute rule). init sent to an instance again changes that instance as new made it, and answers nothing.

The parts of a path

[class.file.name]
