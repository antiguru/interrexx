The interrexx Language Specification

CircularQueue

rexxref: Builtin Classes > Collection Classes > CircularQueue Class; Builtin Classes > Collection Classes > CircularQueue Class > of (Class Method); Builtin Classes > Collection Classes > CircularQueue Class > init; Builtin Classes > Collection Classes > CircularQueue Class > append; Builtin Classes > Collection Classes > CircularQueue Class > insert; Builtin Classes > Collection Classes > CircularQueue Class > intersection; Builtin Classes > Collection Classes > CircularQueue Class > makeArray; Builtin Classes > Collection Classes > CircularQueue Class > makeString; Builtin Classes > Collection Classes > CircularQueue Class > push; Builtin Classes > Collection Classes > CircularQueue Class > queue; Builtin Classes > Collection Classes > CircularQueue Class > resize; Builtin Classes > Collection Classes > CircularQueue Class > section; Builtin Classes > Collection Classes > CircularQueue Class > size; Builtin Classes > Collection Classes > CircularQueue Class > string; Builtin Classes > Collection Classes > CircularQueue Class > supplier; Builtin Classes > Collection Classes > CircularQueue Class > union; Builtin Classes > Collection Classes > CircularQueue Class > xor

Deviations: D78, D109

A CircularQueue is a Queue that has a size, fixed when it is made and changed by resize: it never holds more items than that. An item added to a full queue pushes another out at the opposite end, so a circular queue keeps the latest items, as a log of the last few commands does. Everything that this page does not specify is the behaviour of Queue: the indexes are positions from 1 at the head, and the methods that read, look up and remove items are those of the Queue page. The class inherits Queue, and through it OrderedCollection and Collection; the hierarchy rule lists what it inherits.

The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do.

The class

[class.circularqueue.creation]

CircularQueue declares the class method of and the instance methods init, append, insert, intersection, makeArray, makeString, push, queue, resize, section, size, string, supplier, union and xor, and a copy that this page specifies (the copy rule). All other methods are those of Queue (the Queue creation rule) and of the mixins; the rules below say where one of them behaves differently for a circular queue. A circular queue is a Queue: it has peek, pull and sort, and Queue has no resize and no makeString.

q = .circularqueue~new(3)
say q~class~id q~class~superclass~id q~isA(.queue) q~isA(.orderedcollection)
say q~hasMethod('RESIZE') q~hasMethod('MAKESTRING')
say .queue~new~hasMethod('RESIZE')
say .queue~new~hasMethod('MAKESTRING') .queue~new~hasMethod('SIZE')
say q~hasMethod('PEEK') q~hasMethod('PULL') q~hasMethod('SORT')

Making a circular queue

[class.circularqueue.new]

new needs the size of the queue: no argument raises SYNTAX 93.901 and a second one SYNTAX 93.902. The size must be a whole number from 0 to 999999999, read from its string value as a whole-number argument of a builtin is (the form rule, the digits rule): a negative number, a number that is not whole, text that is not a number and a number above that bound raise SYNTAX 93.906. A size of 0 makes a queue that holds nothing. A new queue is empty. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule); the checks are those of the init that CircularQueue supplies.

q = .circularqueue~new(3)
say q~size q~items q~isEmpty
say .circularqueue~new(0)~size .circularqueue~new(999999999)~size
say .circularqueue~new(' 3 ')~size '|' .circularqueue~new(3.0)~size
call try '.circularqueue~new'
call try '.circularqueue~new(-1)'
call try '.circularqueue~new("x")'
call try '.circularqueue~new(1.5)'
call try '.circularqueue~new(1000000000)'

call try '.circularqueue~new(.nil)'

[class.circularqueue.new.sends]

init first reads the string value of the size, as the conversion rule says, and then sends it < with the argument 0, reading the answer as a logical value: an answer that is neither 0 nor 1 raises SYNTAX 34.901. SYNTAX 93.906 is raised when < answered 1 or when the string value is not a whole number or is above 999999999; only < decides whether the size is below 0, so a size whose string value is -1 and whose < answers 0 is not refused. An object that does not understand <, .nil included, raises SYNTAX 97.1. The queue then keeps the very object it was given as its size, size answers it (the size rule), and its string value is read again each time a method compares the number of items with the size.

[class.circularqueue.of]

of makes a circular queue that holds its arguments in the order given, with the size that is the number of arguments, an argument left out before a given one counting, one left out at the end not. An item that was left out is the null string. The result is an instance of the class that received the message. of sends new to that class with the size as the only argument, which sends init as the new rule says, and then sends queue once for each argument, in order, with that argument, the null string for an omitted one, as the only argument. of with no argument makes a queue of size 0.

[class.circularqueue.size]

size answers the size of the queue: the object that new was given, or that resize was given last, as it was given, so that the size ' 3 ' is answered as ' 3 ' and 3.0 as 3.0. Adding items

[class.circularqueue.queue]

queue(item, option) adds the item at the tail and push(item, option) at the head. When the queue already holds as many items as its size, the item at the opposite end is taken out first: queue takes out the item at the head and answers it, push takes out the item at the tail and answers it; when nothing was taken out, both answer .nil. A queue of size 0 holds nothing. The option is Normal by default; one whose first character is U, in either case, is Unique: before the item is added, every item that is equal to it by the strict == is taken out, and when that made room nothing else is. Any other option, a null string and one that begins with a blank included, is Normal, and option is read as the option rule says. No argument at all raises SYNTAX 93.901; an omitted item before an option raises SYNTAX 93.903; a third argument raises SYNTAX 93.902.

q = .circularqueue~new(3)
say (q~queue('a') == .nil) (q~queue('b') == .nil) (q~queue('c') == .nil)
say q~queue('d') q~allItems~makeString('L', ',') q~items
say q~push('z') q~allItems~makeString('L', ',') q~items
say q~queue('e') q~push('f') q~allItems~makeString('L', ',')

call try 'q~push'

call try 'q~push(, "U")'

[class.circularqueue.queue.sends]

queue and push send, to the receiver, items and then, when the answer is greater than the size, pull for queue or, for push, items again and remove with the answer as the index. With the option Unique they send hasItem with the item first and, for as long as it answers true, removeItem with the item and hasItem again, and only then the items. The strict == of that search is the one of the Queue search rule: the first example shows the order. For the very object that is stored, see the deviation rule. The option is sent caselessMatchChar with the arguments 1 and u, whose answer is read as a logical value: neither 0 nor 1 raises SYNTAX 34.1, and an option that does not understand the message raises SYNTAX 97.1, .nil included. The second example shows these.

[class.circularqueue.append]

append(item) adds the item at the tail and answers its index, which is the number of items afterwards; a queue of size 0 holds nothing, and append then answers .nil. A full queue takes out the item at its head first, so the index is the size then. It takes exactly one argument: none raises SYNTAX 93.901, and a second raises SYNTAX 93.902. After the item is added, append sends items to the receiver, and pull when the answer is greater than the size.

say q~append('e') q~allItems~makeString('L', ',') q~last

[class.circularqueue.insert]

insert(item, index) adds the item directly after the item at the index, as the Queue insert rule says of any queue, and answers the index of the new item, which is the index it had when it was added. When that makes the queue hold more items than its size, the item at the tail is taken out afterwards: so an item that was added after the last item, by the omitted index or by the index of the last item, is taken out at once from a full queue, and the answer is then the index above the size. The receiver is sent items after the item is added, and when its answer is greater than the size last and then remove with the answer of last.

q = .circularqueue~of('a', 'b')
q~resize(4)
say q~insert('x', 1) q~allItems~makeString('L', ',')

Resizing

[class.circularqueue.resize]

resize(newSize, order) changes the size to newSize and answers newSize as it was given. When the queue holds more items than the new size, the surplus is taken out, from the head for the order Fifo, which is the default, and from the tail for Lifo, so that the other end is kept. [class.circularqueue.section]

section(start, count) answers a new circular queue of the same class as the receiver, made by new with the size count, whose items are read from the receiver by position: the first at index start, the next ones at the indexes after it, wrapping from the size to the index 1, so that a section that runs past the tail goes on at the head. The set operations

[class.circularqueue.set]

union, intersection and xor answer a new circular queue of the same class as the receiver, and the receiver is not changed. union(other) holds the items of the receiver followed by every item of the argument, so an item that both have is there twice; the size of the answer is the size of the receiver, or, when the receiver's number of items plus the argument's is greater, that number. intersection(other) holds the items of the argument in its order that the receiver has, each counting as often as the receiver has it, as the OrderedCollection rule says, and has the size of the receiver. xor(other) holds what the OrderedCollection rule says of the items that only one of the two has, receiver items first, and has the size of the receiver, or, when it holds more items, their number. difference, subset, disjoint, equivalent and appendAll are those of the mixins; difference answers a circular queue of the receiver's class and size, and appendAll answers the receiver and adds through append, so that the items that do not fit push the first ones out. The argument is read as the operand rule says, and each takes exactly one: none raises SYNTAX 93.901 and a second raises SYNTAX 93.902.

Copies

[class.circularqueue.copy]

copy answers a new circular queue of the same class as the receiver with the same size and the same items, so that neither sees the other's changes; the items are the same objects. As the Queue copy rule says, the variables of a subclass instance are copied as they are, and init is not sent. The method takes no argument: one raises SYNTAX 93.902.

q = .many~new(4)
q~queue('a'); q~queue('b'); q~queue('c')
q~tag = 'T'
c = q~copy
say c~class~id c~size c~items c~tag c~allItems~makeString('L', ',') (c == q)
c~queue('n'); c~queue('o')
say q~items c~items q~allItems~makeString('L', ',')
say c~allItems~makeString('L', ',')
call try 'q~copy(1)'
exit

Messages the methods send

[class.circularqueue.sends]

The methods that CircularQueue declares send these messages to the receiver: items, pull, last, remove, hasItem, removeItem, copy, allItems, [], makeArray and string, and items and at to the copy that makeArray and supplier make for the order Lifo; the rules above say which each one sends, in which order and with which arguments, and the set rule those of the three set operations. append, insert, push and queue add the item themselves: none of them sends append, queue or push to the receiver. Deviations

[class.circularqueue.deviation.78]

A search for an item with the very object that is stored, by hasItem, index or removeItem, sends that object's == as for any other item, so an object whose == answers false is not found even at its own entry. ooRexx finds the very object without sending it ==, and sends == only for the items before it. See Deviation 78.

.local~n = 0
x = .liar~new
c = .circularqueue~new(5)
c~append('a')
c~append(x)
c~append('b')
say c~hasItem(x) .n
.local~n = 0
say (c~index(x) == .nil) .n
.local~n = 0
say (.nil == c~removeItem(x)) c~items .n
::class liar
::method '=='
  .local~n += 1
  return 0

[class.circularqueue.deviation.109]

An index, a count, a size given to new or resize, or a delimiter that is an instance of a subclass of String is read by its own characters, and REQUEST and MAKESTRING are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING or MAKESTRING, so an override of either can change what is read.
