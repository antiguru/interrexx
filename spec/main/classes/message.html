A Message object is a message that has been written down as an object: a target, the name of a message and its arguments. A program makes one with new, or gets one from the start and startWith methods of Object, and then decides when the message is sent. It can send the message and wait for the answer, start it so that another activity runs it while the sender goes on, or start a copy of it. Afterwards the object keeps what the message answered, or the error that ended it, and a program can ask for them, wait for them, or be told when they are there.

The page specifies the class method that makes a message object, the methods that read what it holds, the methods that run it, the methods that wait for it, stop it or ask for a notification when it is done, and the three methods the class has because it implements the notification interfaces of MessageNotification and AlarmNotification. How an activity is scheduled, when a started message begins to run, and how it interleaves with the activity that started it is specified in the environment chapter. The examples on this page therefore show only results that no scheduling can change: they wait for a message with result or wait, or park the activity of the message on a guard that the example opens, before they print anything that depends on it. The methods that an example waits for, or that the waiting activity calls meanwhile, are UNGUARDED, so that the waiting activity and the activity of the message can both use the object (the guard rule).

The examples that show an error use a routine try that interprets the clause in its argument and prints the clause with the error code, or with the class of the answer when no error is raised.

[class.message.creation]

Message is a class whose superclass is Object and which inherits the mixin classes MessageNotification and AlarmNotification; it is not itself a mixin class. new

[class.message.new]

new(target, name, option, ...) makes a message object that has not been run. It needs at least two arguments: fewer raise SYNTAX 93.901, and an omitted target raises 88.901. The target is any object, .nil included. The name is checked next, after the target, as the send rule checks it: a string, or an array of two items, the name and a class that starts the search (the scoped send rule). A name that is not a string is read as the send rule reads it, through request with ARRAY; .nil and an object that answers .nil raise 93.972, an array of another size 93.946, an array whose first item is missing 88.901, an array with a first item that has no string value 88.909 and one with a second item that is not a class 88.914. The null string is a name. The option that follows is the third argument, which says how the remaining arguments are read, as the next rule states. With no option, the message has no arguments. The answer is the new object, and what the object holds is shown by messageName, target and arguments.

[class.message.new.options]

The option is a string whose first letter, in either case, is I (individual) or A (array); the other letters are not looked at, so Individual and array are options. Any other string, the null string, and a number raise SYNTAX 93.915, and an option that has no string value raises 88.909; the option is checked after the name. An omitted option with an argument after it raises 88.901. With I, every argument after the option is an argument of the message, in order, and an omitted place stays omitted; omitted places at the end add nothing to the count, as the count rule says, and an argument may be any object, .nil included. With A, the fourth argument is required (SYNTAX 93.901) and is the only argument that may follow: a fifth raises 93.902, also when the fourth is omitted. It holds the arguments of the message: it is an array, or an object that answers an array to the message request with the argument ARRAY, and the items of the array are the arguments in order. The message keeps a copy of the array, made when new runs, so that a change that the caller makes to the array afterwards does not reach the message, and the number of arguments is the position of the last item present, as the count rule says (Deviation 113). An object that answers no array, .nil and an array of more than one dimension among them, raises SYNTAX 88.913.

[class.message.new.sends]

new sends the message request with the argument ARRAY to the fourth argument of the option A, once, before it sends init, and uses the array that request answers. It sends no message to the target or to the arguments of I, and to the name only the request that the Object sends rule states, before the option is read.
