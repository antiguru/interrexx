The interrexx Language Specification

Supplier

rexxref: Builtin Classes > Utility Classes > Supplier Class; Builtin Classes > Utility Classes > Supplier Class > new (Class Method); Builtin Classes > Utility Classes > Supplier Class > init; Builtin Classes > Utility Classes > Supplier Class > allIndexes; Builtin Classes > Utility Classes > Supplier Class > allItems; Builtin Classes > Utility Classes > Supplier Class > available; Builtin Classes > Utility Classes > Supplier Class > index; Builtin Classes > Utility Classes > Supplier Class > item; Builtin Classes > Utility Classes > Supplier Class > next; Builtin Classes > Utility Classes > Supplier Class > supplier

Deviations: D118, D124, D135, D138

A Supplier walks over a series of entries, one at a time. An entry is an index and an item. The supplier method of every collection class answers a supplier that holds the entries of the collection; the page of each collection class says which entries those are and in what order. A program can also make a supplier of its own from two arrays, one for the items and one for the indexes. The loop DO WITH INDEX name ITEM name OVER collection walks the supplier of a collection (the loop rule). This page states the class: how a supplier is made, how it is read and advanced, what it answers at its end, and how copies and subclasses behave. The class StreamSupplier, a supplier over the lines of a stream, has a page of its own.

The class

[class.supplier.creation]

Supplier has the class method new and the instance methods allIndexes, allItems, available, index, item, next and supplier, besides the methods that every class has, and an instance method init that new sends. It may have private methods besides these; they are not part of this specification. Its only superclass is Object and it inherits no mixin class (the hierarchy rule). Its string value is that of any object that does not define string, a Supplier.

say .supplier~id .supplier~superclasses~items .supplier~superclass~id,
  .supplier~queryMixinClass
have = .set~new
s = .supplier~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end

end

Making a supplier

[class.supplier.new]

new(items, indexes) answers a new supplier of the class that received it, so a subclass makes instances of itself. It makes the object and then sends init the arguments of new, as the new rule says, so the arrays are read and checked by init, whatever the class. A subclass that declares its own init forwards to the init of Supplier with the two arrays; an instance whose init never reached that method raises SYNTAX 98.901 from every other method (Deviation 135).

s = .supplier~new(.array~of('a', 'b'), .array~of(10, 20))
say s~class~id s~index s~item

[class.supplier.init]

init(items, indexes) fills the supplier and puts it at its first entry. It checks in this order: more than two arguments raise SYNTAX 93.902 before anything is read; a missing first argument raises 93.903; the first argument is converted, as the next rule says, and an answer that is not accepted raises 98.913; a missing second argument raises 93.903; the second argument is converted the same way. So a call with one argument that cannot be converted raises 98.913, and one with an argument that can raises 93.903. Each answer must be an Array of one dimension, whatever its items; an answer that is .nil, a string or an array of more than one dimension raises 98.913, and so does any other kind of object, a Queue included (Deviation 124); the supplier then has as many entries as the first array has slots (the walking rules). init sent to a supplier that has been made already does the same again with new arrays and starts it over at its first entry; the arguments are checked then as they are by new, and the arrays that allItems or allIndexes collected before are dropped (Deviation 138).

[class.supplier.init.convert]

Each argument is converted by sending it request with the argument ARRAY (the request rule), the first argument before the second; nothing else is sent to either. An Array of one dimension answers itself, so the supplier holds that array and not a copy. An instance of a subclass of Array, a List and a String answer through their makeArray method (of Array, of List, of String) when they have one, so the supplier holds the array that method answers; a string gives an array of its lines. What the supplier holds is read by the walking methods directly, and nothing is sent to the arrays after init has returned. A request that answers an instance of a subclass of Array is accepted, and the supplier holds that instance.

Walking

[class.supplier.available]

available answers 1 when the supplier is at an entry and 0 when it has walked past the last one. A supplier starts at its first entry. The entries are numbered from 1 and their number is the number of slots of the items array (its size) at the moment of the call, so an array with empty slots has an entry for each of them, and a slot that is removed with delete at the end of the array takes its entry away. The supplier reads the arrays when it is asked, and does not copy them, so a change made to an array that the supplier holds shows in what it answers; the next rule gives the entry. The method takes no argument: any argument raises SYNTAX 93.902, also at the end.

a = .array~of('p', 'q')

say s~available
a~append('r')

[class.supplier.item]

item answers the item of the current entry: the item of the items array at the position of the entry, or .nil when that slot is empty. index answers the index of the current entry: the item of the indexes array at the same position, or .nil when that array has no item there, as it does when it is shorter than the items array. When the supplier is not available both raise SYNTAX 93.937. An argument raises 93.902 whether the supplier is available or not, before the error of the end.

The remaining entries as arrays

[class.supplier.allitems]

allItems answers an Array of the items of the entries from the current one to the last, in order, and allIndexes an Array of their indexes; an empty slot or a missing index is .nil, and the array has as many items as there are entries left. The answers are new arrays of the class Array, never the arrays the supplier holds. Both methods move the supplier to its end, so available answers 0 afterwards and index, item and next raise SYNTAX 93.937; for an instance of a subclass, the walk of the next rule leaves the supplier at the entry where available answered false. Whichever of the two is sent first collects both arrays, at the entry where the supplier was then; every later call of either answers the very same Array objects as the first (they compare equal under ==), and a later change to the arrays that the supplier holds does not change them. A copy of the supplier made after the first call answers them too. A supplier that has walked to its end with next and has had neither method sent answers empty arrays. Any argument raises 93.902.

s = .supplier~new(items, .array~of('a', 'b', 'c'))

[class.supplier.allitems.sends]

For a receiver whose class is Supplier itself the two methods send nothing. For an instance of a subclass they first send the receiver one private message of their own, which is not part of this specification, and then walk the remaining entries by messages to the receiver, so that an override of available, index, item or next takes part: while available answers true they send index, then item, then next, and when available answers false the walk ends. What index and item answer becomes the elements of the two arrays, whatever an override answers, and those arrays are the ones that every later call answers. An error raised by one of these messages ends the method with that error: an available that never answers 0 makes next raise 93.937, one that answers anything other than the string 0 or 1, even ' 1' or '1.0', raises 34.3, and an available, index or item that answers no value raises 91.999. The two methods send nothing to the arrays and nothing to the answers. A call that finds the arrays collected already sends the private message only, and the same messages are sent whichever of the two methods is the first call. [class.supplier.copy]

copy answers a new supplier of the same class as the receiver, at the same entry. The two are independent suppliers from then on, each with its own entry, but they hold the same arrays and not copies of them: what is put into an array shows in both. A copy made after allItems or allIndexes has been sent answers the same arrays as the receiver does.
