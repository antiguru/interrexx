A Package object is a unit of code that the interpreter loads: the program that a user runs, a file that ::REQUIRES loads, a source that new is given. It holds the source text, the classes, routines and unattached methods that its directives declare, the resources and annotations, the packages it imports and the namespaces it names them by, the initial settings of the numeric and condition options and of tracing, and the code that comes before its first directive, which is called its prolog. The classes and routines that its code can name are found through the package.

The page specifies the class methods that make a package and set the default options of the packages that are made afterwards, and the methods that ask a package what it holds, find a class, a routine or a namespace in it, add to it, and read or change its options. The directives that fill a package are specified by ::CLASS, ::ROUTINE, ::METHOD, ::REQUIRES, ::OPTIONS, ::RESOURCE and ::ANNOTATE, and the page links them instead of repeating them. A package's source is the source of a method or routine made in the way the Method page describes, and its rules for the source apply here where this page says so. The search for a file or a library that new, loadPackage, loadLibrary and findProgram start is specified by the required-file rule, the library rule and the program rule; the examples here name files that they create themselves, or a library that every installation has. The message a package sends to a security manager is specified on the Routine page, which also specifies the checkpoints.

The examples that show an error use a routine try that sends the message in its argument and prints the answer, or the error code when the message raises one. A message that answers .nil prints The NIL object.

The class

[class.package.creation]

A package is made by new, by the interpreter for the program that runs, by ::REQUIRES and by loadPackage, and the library classes belong to a package named REXX. A package made by new is an ordinary object otherwise: it has the default name a Package, and the class Package has the superclass Object and no mixin class. The package of the library, which .object~package answers, holds the classes of the library, is named REXX, has no source, and is found by findNamespace under that name from any package.

p = .package~new('first', 'return 5')
say p~class~id p~defaultName p~name p~source[1]
say .package~superclass~id .package~superclasses~items
rp = .object~package
say rp~name .array~package~name (rp == .string~package)
say rp~source~items rp~sourceSize rp~publicClasses~hasIndex('STRING')
say (p~findNamespace('REXX') == rp) (p~findNamespace('rexx') == rp)

[class.package.new]

new makes a package from a name and, optionally, a source and a context. The name is required (SYNTAX 88.901), and is a string or the string that its argument gives: an object that gives no string, .nil among them, raises 88.909. With a source, the name is only the name of the package, and the package is always a new object. With no source, the name is the name of a file, which new looks for and reads, as the file rule says, and there is no context: the arguments from the third on go to init. The context is the third argument. It is a Method, a Routine or a Package object, or omitted; any other value, .nil and PROGRAMSCOPE included, raises SYNTAX 93.953. The checks run in this order: the name, the context, the source (a source that is .nil raises 93.961), and then the source is translated, so that a source that does not translate raises its translation error, and new then installs the package as the install rule says. The arguments from the fourth on are passed to init of the new package, and so are the arguments from the third on when the source is omitted; the init of Object accepts none, and one argument raises SYNTAX 93.902 after the package is installed. A subclass of Package makes instances of itself. The answer is the new package.

say p~class~id p~name

[class.package.new.context]

The context decides which classes and routines the code of the package can name besides its own and those of the library. A package made with no context sees nothing of the package of the code that made it: a class name that it does not hold is the string of that name, and a routine that it does not hold raises SYNTAX 43.1. With a Package object as the context the package finds, after its own, the classes and routines that the context package finds, its own, those it imports and what its own context finds, and with a Routine or a Method it finds those of the package of that object. A context that is a Method or a Routine whose package is .nil, one that loadExternalMethod or loadExternalRoutine made, gives a package whose lookup through the context is not specified. The context package is not one of the importedPackages of the new package, and its classes and routines are not among the classes and routines of the new package.
