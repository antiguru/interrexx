The interrexx Language Specification

Ticker

rexxref: Builtin Classes > Utility Classes > Ticker Class; Builtin Classes > Utility Classes > Ticker Class > attachment; Builtin Classes > Utility Classes > Ticker Class > cancel; Builtin Classes > Utility Classes > Ticker Class > canceled/cancelled; Builtin Classes > Utility Classes > Ticker Class > init; Builtin Classes > Utility Classes > Ticker Class > interval

Deviations: D109, D119, D135

A Ticker is a repeating timer. It is made for an interval, a target that wants to hear of it and, if the program likes, an object to attach; at the end of every interval it sends its target triggered, until it is cancelled, and when it is cancelled it sends the target cancel. The target is an implementation of AlarmNotification, which states what the target is sent and when. A ticker is made as an Alarm is, with an interval in place of a time; it has no scheduledTime and no triggered of its own, and it asks for the target and the attachment as an alarm does. This page states how a ticker is made, what its interval may be and what its own methods answer. How the library runs a ticker beside the program, so at which times the target is reached and by which activity, is specified in the environment chapter, and so is whether a triggered that is still running delays the next one. The examples that wait use a guard that the target opens, and print nothing that varies with the clock.

The class

[class.ticker.creation]

Ticker has the instance methods attachment, cancel, canceled, cancelled, init and interval, besides the new that every class has. It may have private methods besides these; they are not part of this specification. Its only superclass is Object, it inherits no mixin class and is not itself a mixin class (the hierarchy rule), and so it is no implementation of AlarmNotification and cannot be the target of an alarm. new is the one that Class supplies: it sends init the arguments of new, which the next rule states, and answers an instance of the class that received it, so a subclass of Ticker makes instances of itself.

say .ticker~superclasses~items .ticker~superclass~id .ticker~queryMixinClass
have = .set~new
s = .ticker~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end
names = 'attachment cancel canceled cancelled'
names = (names 'init interval')~makeArray(' ')
count = 0
do name over names
  if have~hasItem(name~upper) then count = count + 1
end
say count 'of 6' have~hasItem('TRIGGERED') have~hasItem('SCHEDULEDTIME')
n = .note~new
a = .ticker~new(60, n)
b = .sub~new(60, n)

Making a ticker

[class.ticker.init]

new sends init(interval, target, attachment), and init sets the ticker up. It needs the first two arguments, so new with none or only the first raises SYNTAX 93.901 and an omitted first or second argument raises SYNTAX 93.903; a fourth argument raises SYNTAX 93.902. The checks of the arguments that are present are made in this order: first the target, which must be an implementation of AlarmNotification or SYNTAX 88.914 is raised, and then the interval, which raises SYNTAX 93.951 for every value that the rule below does not accept, except the very large ones for which it names other errors. So a target that is no implementation is reported even when the interval is wrong too, and a refused ticker is not set. attachment can be any object, and is .nil when it is omitted. The ticker is set when init ends normally. A subclass whose init does not send init to its superclass makes a ticker that is not set (Deviation 135).

n = .note~new
call try ".ticker~new"
call try ".ticker~new(60)"
call try ".ticker~new(, n)"
call try ".ticker~new(60, , 'x')"
call try ".ticker~new(60, n, 'x', 'y')"
call try ".ticker~new('abc', .nil)"
call try ".ticker~new('abc', n)"
call try ".ticker~new(60, n)"
call try ".ticker~new(60, n, .nil)"
call try ".ticker~new(60, n, .array~new)"
exit

[class.ticker.init.interval]

An interval that is a string is a number of seconds. It is read as a number as the DATATYPE N rule reads it, so blanks at either end are allowed and a decimal point or an exponent is too, and it has to be zero or more: a string that is no number, the empty string and a negative number raise SYNTAX 93.951. An interval that is a TimeSpan is that length, and must not be negative. An interval longer than the longest TimeSpan, 315537897599.999999 seconds, raises SYNTAX 40.19, whether it is positive or negative. A number of 10**12 or more, or of -10**12 or less, once it is rounded as said below, raises SYNTAX 88.903. Nothing else is an interval, so SYNTAX 93.951 is raised for a DateTime, for a string with a time of day such as 12:00:00, for .nil, for an array and for an instance of Object. The interval is kept to the microsecond: a longer fraction is cut off and not rounded, and the number is cut before its sign is checked, so -0.0000001 is an interval of zero; a number with more than 18 significant digits is first rounded to 18, so 1.999999999999999999 is 2 seconds. The number is read in full whatever the NUMERIC DIGITS setting. interval answers the interval, as the next rule says. The example makes tickers whose intervals are too long to end before they are cancelled.

n = .note~new
call try 'string " 90 "', ' 90 '
call try 'string 1.5e2', '1.5e2'
call try 'string +.5e3', '+.5e3'

call try 'string 1x', '1x'

call try 'string -0.0000001', '-0.0000001'
call try 'string 1.999999999999999999', '1.999999999999999999'

call try 'string -315537897600', '-315537897600'
call try 'string 1e12', '1e12'
call try 'string -1e12', '-1e12'

call try 'span of 600 s', .timespan~fromSeconds(600)
call try 'span of -600 s', .timespan~fromSeconds(-600)
call try 'DateTime', .datetime~new~addSeconds(600)
call try '.nil', .nil
call try 'array', .array~new
call try 'object', .object~new
numeric digits 3
call try 'digits 3', '123456.789'

[class.ticker.init.sends]

init sends messages that a program can override, in this order: first isA to the target, with AlarmNotification as its one argument, once; the answer decides whether the target is an implementation. Then, for an interval that is a TimeSpan, the span is sent sign, days and totalMicroseconds, once each and in that order, and for an interval that is a string nothing is sent (Deviation 109 covers a subclass of String). When the span is negative init stops after sign; the further messages that build the text of the error are not specified. A ticker that is refused for its target sends the interval nothing. init sends no message to the attachment, and none to the ticker itself, so an override of attachment or interval does not run. The example logs the sends of an override of each message in a subclass of TimeSpan.

.environment~log = .list~new
n = .note~new
ts = .span~fromSeconds(600)
.environment~log~empty
a = .ticker~new(ts, n)
say 'span:' .environment~log~makeArray~makeString('l', ' ')
.environment~log~empty
c = .ticker~new(600, n, .tracked~new)
say 'seconds:' .environment~log~makeArray~makeString('l', ' ')
.environment~log~empty

What the ticker answers

[class.ticker.interval]

interval answers a TimeSpan, the length of the interval that was set, and it takes no argument (SYNTAX 93.902). For an interval that was a TimeSpan it is a span equal to it (the compare rule); for a string it is that number of seconds, cut off to the microsecond. It does not change when the ticker is cancelled, and it sends no message.

[class.ticker.triggered]

The ticker sends its target triggered with itself as the argument at the end of each interval, until it is cancelled; the target's method is the one of the notification rule. How many times it is sent before a program cancels the ticker is not something the program can count on, as it depends on the times that the environment chapter specifies, so the example cancels from the method itself after the third, and shows that the ticker stops: the target is sent cancel once and nothing after it, even though the program waits for several more intervals. Unlike an alarm, a ticker has no method triggered of its own.

n = .note~new(3)
t = .ticker~new(0.02, n, 'tick')
n~awaitCancel
call syssleep 0.2
say n~log~strip
say t~canceled t~hasMethod('triggered')

Cancelling

[class.ticker.cancel]

cancel takes no argument (SYNTAX 93.902) and answers nothing, so using its answer as a value raises SYNTAX 91.999. Sent to a ticker that has not been cancelled it stops the ticker: no triggered is sent from then on, canceled answers 1, and the target is sent cancel with the ticker as its argument, as the notification rule says. The flag is already 1 when the target receives cancel. A second cancel of a ticker sends the target nothing (Deviation 119). A ticker that is cancelled from the triggered of its own target stops in the same way.

n = .note~new
a = .ticker~new(60, n, 'waiting')
a~cancel
n~awaitCancel
say n~log~strip
say a~canceled a~cancelled
n2 = .quiet~new
z = .ticker~new(60, n2)
y = .ticker~new(60, n2)
signal on syntax name e1
x = z~cancel
e1: say condition('o')~code
signal on syntax name e2
y~cancel(1)
e2: say condition('o')~code
y~cancel

Deviations

[class.ticker.deviation.109]

A string interval that is an instance of a subclass of String is read by its own characters, and request, makeString and string are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING, so an override can change what is read. In the example the overrides would make the interval -1; they count their sends, and the string is read as 60 seconds without one.

.environment~sent = 0
n = .note~new
t = .ticker~new(.digits~new('60'), n)
say t~interval 'sends' .environment~sent
t~cancel
::class note inherit AlarmNotification
::method triggered
  nop
::class digits subclass string
::method makestring
  .environment~sent = .environment~sent + 1
  return '-1'
::method request
  .environment~sent = .environment~sent + 1
  return '-1'

[class.ticker.deviation.119]

A second cancel of a ticker that was cancelled sends its target nothing, as the notification page states (Deviation 119). ooRexx sends the target cancel once or twice for it, depending on timing, so the example is not run against it; the target prints a line for each cancel it is sent.

n = .n~new
t = .ticker~new(60, n)
t~cancel
t~cancel
call syssleep 0.3
say 'done'
exit
::class n inherit alarmnotification
::method cancel unguarded
  say 'cancel sent'

cancel sent
done
[class.ticker.deviation.135]

A subclass of Ticker whose init does not send init to its superclass, by self~init:super or FORWARD, makes a ticker that is not set, and every instance method of the class other than init sent to it raises SYNTAX 98.901: attachment, cancel, canceled, cancelled and interval. ooRexx answers attachment, canceled, cancelled and interval of such a ticker without an error and raises SYNTAX 88.914 from its cancel.

o = .lazy~new
call try "o~attachment"
call try "o~cancel"
call try "o~canceled"
call try "o~cancelled"
call try "o~interval"
exit
try:
  signal on syntax name bad
  interpret arg(1)
  say arg(1) '=> no error'
  return
bad: say arg(1) '=>' condition('o')~code
  return

::method init
  nop
