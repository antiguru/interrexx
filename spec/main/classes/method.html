The interrexx Language Specification

Method

Deviations: D41, D109, D115, D118, D134

A Method object is the code of one method together with the facts that decide who may send it and how it runs: whether it is private, package-scope, protected or guarded, which class it belongs to, and the package whose classes and routines its code can name. A class holds its methods as Method objects, ::METHOD makes one for each directive, and a program makes one of its own from source text with new, from a file with newFile, or from a native library with loadExternalMethod.

The page specifies those three class methods, with the checks they make, the messages they send and what the new method may see, and the methods that ask or change what a method object is. The directive that makes a method object is ::METHOD, the annotations come from ::ANNOTATE, how a message finds a method is the method search, and the methods of Class that install a method object, define and setMethod, are on the pages of Object and Class. The messages every object understands are those of Object. newFile takes its file as the newFile rule says, and the library of loadExternalMethod is found as the library rule says; the examples here name a file that they create themselves, or a library that every installation has.

The examples that show an error use a routine try that sends the message in its argument and prints the answer, or the error code when the message raises one, as the pages of the other classes do.

The class

[class.method.creation]

A method object made by new or newFile is public, guarded and not protected, belongs to no class (its scope is .nil), has no annotations, and holds the source it was made from. It has no code that runs by itself: it runs when it is installed in a class or an object, and a message that finds it there runs its code. A Method object is an ordinary object otherwise, so it understands the methods of Object and has the default name a Method. The class Method has the superclass Object and no mixin class.

m = .method~new('greet', 'return "hello" arg(1)')
say m~class~id m~isGuarded m~isPrivate m~isPackage m~isProtected
say m~isAbstract m~isAttribute m~isConstant m~scope~isNil
say m~source~items m~annotations~items m~annotation('x')~isNil
say m~defaultName m .method~superclass~id .method~superclasses~items
.holder~define('GREET', m)
say .holder~new~greet('world')

Class methods

new

[class.method.new]

new makes a method object from a name, a source and a context. The name is required (SYNTAX 88.901), and is a string, or the string that its argument gives: an object that gives no string, .nil among them, raises 88.909, and a number is a name like any other string. The name becomes the name of the method's package, which package shows. The source is required too (88.901) and is read as the source rule says. The context is PROGRAMSCOPE in any case, or omitted, or a Method, a Routine or a Package object, and decides what the code can see, as the context rule says; another value raises 40.904. The checks run in this order: the name, the source, the context, and then the source is translated, so a source of .nil raises 93.961 whatever the context is, and a source that does not translate raises its translation error (35.1 for an invalid expression, 13.1 for an invalid character) after the context has been accepted, and new runs none of the code. The arguments from the fourth on are passed to init as the sends rule says. The answer is the new method object.

m = .method~new('greet', 'return "hello" arg(1)')
say m~class~id m~package~name m~source[1]
call try '.method~new()'
call try '.method~new("n")'

[class.method.new.source]

The source is one string, or an array of strings. A string is a single line of code, and the method's source is an array of that one line; a string is not split at line ends, and a line end character in a line, '0A'x, '0D'x or '1A'x, makes the translation raise SYNTAX 13.1, while a tab is an ordinary character. An empty string is a source of no lines. An array holds the lines in the order of its indexes. Each item is sent request with the argument STRING and the answer is the line: a string is its own line, a number is a line like any string, a MutableBuffer is the line of its text, and so is an instance of a subclass of String; an item that gives no string, .nil among them, or a hole that is followed by an item, raises SYNTAX 93.952. The answer is a line like any other, so an item whose answer has a line end, such as an array (its makeString joins its items with line ends), raises 13.1. An empty array is a source of no lines. A source that is neither a string nor an array is converted as the sends rule says; .nil raises 93.961. An instance of a subclass of String is such a source: it is not used as the one line that a string is, but is converted by its makeArray, so it is split at its line ends, and a null one is a source of no lines.

[class.method.new.sends]

new sends messages to its source and to the object it makes. A source that is not a string and not an array, and an instance of a subclass of String or Array, is sent request with the argument ARRAY; when that answers an array its items are the lines, read as the source rule reads an array. When it answers an object that is neither an array nor .nil, new raises SYNTAX 88.913 and sends no request with STRING (Deviation 115). An instance of a subclass of List is sent request as well (Deviation 118). When it answers .nil the source is sent request with the argument STRING: an answer that is a string is the one-line source, and for any other answer its objectName is the line, with no MAKESTRING or string message sent to it; .nil from both raises SYNTAX 93.961. A string that is an instance of String itself and an array that is an instance of Array itself are used directly, without a message. The request of Object sends makeArray for the argument ARRAY and makeString for STRING, as its rule says, so an object that declares makeArray or makeString is a source. When the method is made, new sends the new object the message init with the arguments of new from the fourth on, so that a subclass of Method that declares init receives them; the init of Object accepts none, and a fourth argument raises SYNTAX 93.902 after the source has been translated. The class that received new decides the class of the answer: a subclass of Method makes instances of itself.

[class.method.new.context]

The context decides which classes and routines the code of the method can name, as the classes and routines of a package do. The method has a package of its own, a new package named by the name argument, whose source is the source of the method. That package has no classes or routines of its own, and a name that it does not hold is looked up in the package of the context, among the classes and routines that package finds: its own, public or not, and the public ones of the packages it imports. With PROGRAMSCOPE, or with the argument omitted, that is the package of the code that sent new: the method sees the classes and routines of the program that made it. With a Package object it is that package, with a Routine or a Method object it is the package of that object, and the classes and routines of the program that sent new are no longer visible: a class name that is not found is the string of that name, and a routine that is not found raises SYNTAX 43.1. [class.method.setsecuritymanager]

setSecurityManager gives the package that holds the method's code a security manager, or with no argument removes the one that package has, and answers 1 (the package rule); a method that new or newFile made has a package of its own. It is a protected method. The manager is any object, .nil as well, and it is not checked when it is set: .nil is an object like any other, which is sent the checkpoints and does not understand them (SYNTAX 97.1), so only a call with no argument removes the manager. A second argument raises SYNTAX 93.902. While code of that package runs, the method and its internal routines among it, the actions that the checkpoint rules name are offered to the manager first (which code); the code of other packages that the method calls is not under the manager. A manager that was set before define installed the method stays with the installed method, as the example shows.

.k~define('GO', m)
say .k~new~go
say m~setSecurityManager
say .method~new('x', 'nop')~setSecurityManager(.nil)
call try 'm~setSecurityManager(1, 2)'
