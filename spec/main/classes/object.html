Object is the root of the class hierarchy: every class has it among its ancestors, so every object understands the methods of this page, and every class but those that Class~new makes understands its class method new. The page specifies each of them: what it accepts, in which order it checks, what it answers, and which messages it sends to its receiver or to its arguments, so that a class which overrides a method that another one sends can predict what happens.

The names that a program gives an object, its string value and its default name belong to the chapter index; the rules below link to them. How a message finds a method, and what setMethod and unsetMethod do to that search, belong to the method search. The examples that show an error use a small routine try that sends the message in its argument and prints either the answer or the error code, as the builtin pages do.

Class methods

[class.object.new]

The class method new makes an object of the class that received the message and sends it init with the arguments of new, as the new rule says. The arguments keep their places: an argument that is omitted in the middle of the list is omitted in the message to init, and omitted places at the end add nothing to the argument count, as the count rule says. The answer of new is the new object, whatever init answers. Every class that a directive, subclass or mixinClass made has this method, mixin classes and abstract classes included, and an abstract class refuses it as the abstract rule says. The class that Class~new makes is the one exception, and its page rule says what it answers.

[class.object.init]

[class.object.copy]

copy answers a new object of the same class. The copy has the object variables of the receiver, each holding the same object that the receiver's variable holds, so the copy is shallow, and it has the same methods, the receiver's own methods included, and the same name. The copy has its own table of the object's own methods, holding the same method objects, and the variables of those methods are copied as the others are, so a change to one object's own methods or to those variables does not reach the other. It does not send init, and takes no argument: with one it raises SYNTAX 93.902. A subclass of Object whose instances hold more than variables, as the collection classes do, defines its own copy on its page. A class object cannot be copied, as the copy rule says.

[class.object.setmethod]

setMethod gives the receiver a method of its own, as the object method rule says, and answers no value. It is private, with the restriction that the access rule gives. The first argument is the name and is required (SYNTAX 88.901); an object that is no string and whose request with the argument STRING answers no string raises 88.909.
