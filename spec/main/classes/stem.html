The interrexx Language Specification

Stem

rexxref: Builtin Classes > Collection Classes > Stem Class; Builtin Classes > Collection Classes > Stem Class > new (Class Method); Builtin Classes > Collection Classes > Stem Class > []; Builtin Classes > Collection Classes > Stem Class > []=; Builtin Classes > Collection Classes > Stem Class > allIndexes; Builtin Classes > Collection Classes > Stem Class > allItems; Builtin Classes > Collection Classes > Stem Class > at; Builtin Classes > Collection Classes > Stem Class > empty; Builtin Classes > Collection Classes > Stem Class > hasIndex; Builtin Classes > Collection Classes > Stem Class > hasItem; Builtin Classes > Collection Classes > Stem Class > index; Builtin Classes > Collection Classes > Stem Class > isEmpty; Builtin Classes > Collection Classes > Stem Class > items; Builtin Classes > Collection Classes > Stem Class > makeArray; Builtin Classes > Collection Classes > Stem Class > put; Builtin Classes > Collection Classes > Stem Class > remove; Builtin Classes > Collection Classes > Stem Class > removeItem; Builtin Classes > Collection Classes > Stem Class > request; Builtin Classes > Collection Classes > Stem Class > supplier; Builtin Classes > Collection Classes > Stem Class > toDirectory; Builtin Classes > Collection Classes > Stem Class > unknown

Deviations: D1, D68, D78, D109, D118, D124

A Stem is the collection that a stem symbol names: the value of a stem symbol is a Stem object, and the compound variables of the stem are its entries. An entry is a tail, a string, and the item stored at it; the stem also has a default, the value that every tail without an item has, and a name, which is the text that stands for the stem when it has no default. A Stem can be made without a variable, by new, and then behaves alike: the methods below read and write the same entries that s.tail reads and writes (the compound rule, the default rule). The class inherits MapCollection, and through it Collection; the hierarchy rule lists what it inherits.

A stem has an unknown method, and the page begins with what the other methods do; the unknown rule says what unknown does with the messages that no method answers. Examples that show an error use a small routine try, as the builtin pages do. The order in which the tails are listed is not specified, as the DO OVER rule says of a loop, and the examples then hold one tail or sort the answers (the order rule).

The class

[class.stem.creation]

Stem declares the instance methods [], []=, allIndexes, allItems, at, empty, hasIndex, hasItem, index, isEmpty, items, makeArray, put, remove, removeItem, request, supplier, toDirectory and unknown, and the class method new; the copy of Object copies a stem as the copy rule says. It has no init of its own: new makes the stem as the new rule says. The class method of and the instance methods putAll, union, difference, intersection, xor, subset, disjoint and equivalent are those of the mixins (one rule lists them). A stem has no makeString, and none of the comparison methods =, ==, \=, \==, <> and ><: a message with one of those names is passed on by the unknown rule. Its superclasses are Object and MapCollection, in that order.

s = .stem~new
n = 0
m = .stem~methods(.nil)
do while m~available
  n += 1
  m~next
end
say s~class~id n 'own methods' .stem~hasMethod('OF') s~hasMethod('OF')
do c over s~class~superclasses
  say c~id
end

say s~hasMethod('MAKESTRING') s~hasMethod('UNKNOWN') s~hasMethod('INIT')
say s~hasMethod('=') s~hasMethod('==') s~hasMethod('\=') s~hasMethod('\==')

Making a stem

[class.stem.new]

new makes an empty stem, with no default. Its first argument is the name: the text that the stem has as its value while it has no default, and the start of every tail that is read from it with no item. The name is the null string when it is omitted, and is not changed to end with a period. It must have a string value, found as the conversion rule says for a request that answers a string; an object whose request with STRING does not answer a string, .nil among them, raises SYNTAX 88.909 before init is sent. new then sends init to the new stem with the arguments that follow the name (the new rule). A stem has the init of Object, which takes no argument, so a second argument to new raises SYNTAX 93.902 when that init runs: after the init of a subclass has run, and not at all when the init of a subclass does not pass its arguments on.

s = .stem~new('abc.')
say s~string s['x'] s~items
say '['.stem~new~string']' '['.stem~new('')~string']' .stem~new(7)~string

call try '.tracked~new(.nil)'

say .quiet~new('Q.', 'x', 'y')~string .quiet~new(, 'x')~string'|'

Tails

[class.stem.tails]

The methods that take indexes take any number of them, and make one tail of them: each index argument is replaced by its string value, an omitted argument by the null string, and the strings are joined with a period between them, trailing omitted arguments being dropped. So s[1, 2] and s['1.2'] are the same tail, and s[1, , 3] is the tail 1..3. The tail is used as written: case counts, 01 and 1 are two tails, and blanks stay (the tail rule). An index that is not a string is replaced as the conversion rule says: the answer of its request with the argument STRING, and when that is not a string, of its string method; so .nil is the tail The NIL object. With no index at all the methods name the default of the stem and not a tail.

s = .stem~new('N.')
s['a'] = 1
s['A'] = 2
s['01'] = 3
s[1] = 4
s[1, 2] = 5
s[1, , 3] = 6
s['x.y'] = 7
s[.mk~new] = 8
s[.nil] = 9
say s~items s['a'] s['A'] s['01'] s[1] s['1'] s['1.2'] s[1, 2],
  s['1..3'] s['x', 'y']
say s[.mk~new] s['MK'] s[.nil] s['The NIL object']
say s~allIndexes~sort~makeString('L', ',')

Reading and writing items

[class.stem.at]

at(index, ...) and [index, ...] answer the item stored at the tail that the indexes make (the tails rule); when no item is stored there, the default of the stem; and when the stem has no default, the name of the stem followed by the tail, which is what the compound symbol would have as its value. With no index they answer the default, or the name when there is none. Reading stores nothing.

s = .stem~new('N.')
say s~at s[] s~at(1) s[1, 2] s~items
s['k'] = 'item'
say s~at('k') s['k'] s['K']
s[] = 'dflt'
say s~at s['K'] s['k'] s[3, 4] s~items

[class.stem.put]

put(item, index, ...) and [index, ...] = item store the item at the tail that the indexes make (the tails rule), replacing the item that was there, and answer nothing. The item may be any object, .nil included. With no index they store the item as the new default of the stem and remove every item from that same object, so the variable and every other reference to the stem see no entries. The item is required: none, or an omitted one, raises SYNTAX 93.903 for put.

s = .stem~new('N.')
s~put('one', 1)
s['two', 2] = 'x'
s[3] = .nil
say s~items s[1] s['two.2'] (s[3] == .nil) s~hasIndex(3)
s~put('d')
say s~items s[1] s~string
s[] = 'e'
say s~string s['zz']

Removing items

[class.stem.remove]

remove(index, ...) removes the item at the tail that the indexes make (the tails rule) and answers it, and answers .nil when no item is stored there; the tail then has the default again, or the derived name. With no index it removes the default and answers it, and answers the name of the stem when there is none, so that a second call answers the name. The other items stay.

s = .stem~new('N.')
s['a'] = 1
s['b', 'c'] = 2
say s~remove('a') (s~remove('a') == .nil) s~remove('b', 'c') s~items s['a']
s[] = 'd'
s['k'] = 'v'
say (s~remove('zz') == .nil) s~items

Lists of the items

[class.stem.makearray]

allIndexes and makeArray answer a new Array of the tails that have an item, as strings, and allItems a new Array of the items. The default is in neither. They are instances of Array for a subclass receiver too, never the receiver, and do not follow later changes. They take no argument: one raises SYNTAX 93.902. The order is not specified (the order rule), and is the same for the three answers and for the supplier of one unchanged stem, so the item at a position belongs to the tail at the same position. The methods send no message to the stem, makeArray excepted when it is asked through request, or to the items.

t = .many~new('N.')
do i = 1 to 40
  t['item'i] = .array~of(i)
end
t[] = 'dflt'
t['x', 'y'] = 'xy'
ix = t~allIndexes
it = t~allItems
bad = 0
do i = 1 to ix~items
  if t~at(ix[i]) \== it[i] then bad += 1
  if t~makeArray[i] \== ix[i] then bad += 1
end
say ix~class~id it~class~id t~makeArray~class~id ix~items it~items bad
a = t~allItems
t['extra'] = 'e'
say a~items t~items (ix == t~allIndexes)
call try 't~allIndexes(1)'
call try 't~allItems(1)'
call try 't~makeArray(1)'
exit
