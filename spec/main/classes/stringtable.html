The interrexx Language Specification

StringTable

rexxref: Builtin Classes > Collection Classes > StringTable Class; Builtin Classes > Collection Classes > StringTable Class > new (Class Method); Builtin Classes > Collection Classes > StringTable Class > []; Builtin Classes > Collection Classes > StringTable Class > []=; Builtin Classes > Collection Classes > StringTable Class > allIndexes; Builtin Classes > Collection Classes > StringTable Class > allItems; Builtin Classes > Collection Classes > StringTable Class > at; Builtin Classes > Collection Classes > StringTable Class > empty; Builtin Classes > Collection Classes > StringTable Class > entry; Builtin Classes > Collection Classes > StringTable Class > hasEntry; Builtin Classes > Collection Classes > StringTable Class > hasIndex; Builtin Classes > Collection Classes > StringTable Class > hasItem; Builtin Classes > Collection Classes > StringTable Class > index; Builtin Classes > Collection Classes > StringTable Class > isEmpty; Builtin Classes > Collection Classes > StringTable Class > items; Builtin Classes > Collection Classes > StringTable Class > makeArray; Builtin Classes > Collection Classes > StringTable Class > put; Builtin Classes > Collection Classes > StringTable Class > remove; Builtin Classes > Collection Classes > StringTable Class > removeEntry; Builtin Classes > Collection Classes > StringTable Class > removeItem; Builtin Classes > Collection Classes > StringTable Class > setEntry; Builtin Classes > Collection Classes > StringTable Class > supplier; Builtin Classes > Collection Classes > StringTable Class > unknown

Deviations: D29, D33, D78, D84, D109, D118, D124

A StringTable maps string indexes to items, as a Directory does, and has the same entry methods, but it holds nothing else: no method can be associated with a name, and there is no UNKNOWN method. An index is a string compared in full and by its exact characters, and an item is any object. The class inherits MapCollection, and through it Collection; the hierarchy rule lists what it inherits.

A message for which the method search finds no method, such as t~name, reaches the unknown method of the class, which reads or sets the entry of that name in upper case (the unknown rule). The page follows the order of the rexxref entry. Examples that show an error use a small routine try, as the builtin pages do. The page says nothing about which of two items equal to the argument removeItem removes (the hash order rule).

The class

[class.stringtable.creation]

StringTable declares the instance methods [], []=, allIndexes, allItems, at, empty, entry, hasEntry, hasIndex, hasItem, index, isEmpty, items, makeArray, put, remove, removeEntry, removeItem, setEntry, supplier and unknown, the init that new runs (the new rule) and the class method new; the copy of Object copies a string table as the copy rule says. The class method of and the instance methods putAll, union, difference, intersection, xor, subset, disjoint and equivalent are those of the mixins (one rule lists them). It has no setMethod and no unsetMethod of the kind a directory has (the method rule), and no makeString, so a string table is not a string (the string rule).

t = .stringtable~new
own = '[] []= ALLINDEXES ALLITEMS AT EMPTY ENTRY HASENTRY HASINDEX HASITEM',
  'INDEX ISEMPTY ITEMS MAKEARRAY PUT REMOVE REMOVEENTRY REMOVEITEM SETENTRY',
  'SUPPLIER UNKNOWN'
n = 0
do m over own~makearray(' ')
  if t~hasMethod(m) then n += 1

Making a string table

[class.stringtable.new]

new makes an empty string table. Its optional argument is a hint for how large the table will grow; no method that this page specifies answers differently for it. It must be a whole number that is not negative, or SYNTAX 93.923 is raised. A second argument raises SYNTAX 93.902, and omitted arguments at the end count for nothing. new sends init to the new object with the arguments it received, so a subclass's init sees them (the new rule). The checks are those of the init that StringTable supplies: they come after the init of a subclass has run, and a subclass whose init does not pass the arguments on is not refused for them.

say .stringtable~new~items .stringtable~new(0)~items
say .stringtable~new(3, )~items
call try '.stringtable~new(-1)'
call try '.stringtable~new("x")'
call try '.stringtable~new(.nil)'
call try '.stringtable~new(1.5)'
call try '.stringtable~new(1, 2)'
x = .watch~new(7)

exit

Indexes

[class.stringtable.indexes]

An index is read as a string, exactly as a directory reads it: a string is used as it is, any other object by the string-value rule, so an object whose makeString answers a string is used through that answer, and an object that has neither, .nil included, gives SYNTAX 88.909. The index is stored as that string, case counts, 5 and 5.0 are different indexes, and the null string is an index. An instance of a subclass of String is read by its own characters (the deviation rule). Every method of this page that takes a name reads it this way, those that change it to upper case afterwards included (the entry rule).

t = .stringtable~new
t~put('v1', 'Key')
t~put('v2', 5)
t~put('v3', .made~new)
t~put('v4', '')
say t~at('Key') t~at('KEY') t~at(5) t~at('5') t~at(5.0)

call try 't~at(.nil)'
call try 't~put("x", .plain~new)'
exit

[class.stringtable.entry]

[class.stringtable.unknown]

unknown(name, args) runs when the method search finds no method for a message. When the name does not end in =, it answers what entry of the name answers, and the arguments of the message are ignored; when it ends in =, it stores the first of the arguments at the name without the = with what setEntry does and answers nothing, so t~title = 'x' and t~name('y') set and read the entries TITLE and NAME. The message name can be any string. Neither entry nor setEntry is sent to the table by it. [class.stringtable.setmethod]

A string table has no setMethod and no unsetMethod of its own: the methods of those names that Object has are private (the private rule), and a message from outside the object does not reach them (the access rule). [class.stringtable.hasitem.sends]

The methods of the mixins

[class.stringtable.inherited]

The class method of and the instance methods putAll, union, difference, intersection, xor, subset, disjoint and equivalent are not declared by StringTable. of and putAll are those of MapCollection, and the others those of Collection; a string table is one of the collections they take as an argument, and the answers of the first four are instances of the class of the receiver. putAll stores with the put of the receiver. Messages the methods send

[class.stringtable.sends]

No method that StringTable declares sends a message to its receiver: an override of at, put, entry, setEntry or any other of the methods is never asked by another method, [] and []= do not use at and put, and unknown does not use entry and setEntry. The messages the methods do send go to other objects and have a rule each: init to the new object by new (the new rule); == to the argument by hasItem, index and removeItem (the search rule); request with STRING to a name that is neither a string nor an instance of a subclass of String (the index rule). The set operations send what the pages of the mixins say. In the example a subclass has every method overridden to record its name, and each call records only its own.
