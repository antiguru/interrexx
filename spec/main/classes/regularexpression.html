The interrexx Language Specification

RegularExpression

rexxref: Builtin Classes > Utility Classes > RegularExpression Class; Builtin Classes > Utility Classes > RegularExpression Class > new (Class Method); Builtin Classes > Utility Classes > RegularExpression Class > match; Builtin Classes > Utility Classes > RegularExpression Class > parse; Builtin Classes > Utility Classes > RegularExpression Class > pos; Builtin Classes > Utility Classes > RegularExpression Class > position

Deviations: D87, D88, D89

A RegularExpression holds a pattern and tells whether a string matches it, and where in a string it is found. The pattern language is small: literal characters, a single-character wildcard, repetition, alternatives, groups and sets of characters. The class is not preloaded. A program makes it available with ::requires "rxregexp.cls", and the package that file names is part of every installation; every example on this page does so. A traceback that runs through that file shows interrexx's own lines of it, their numbers and their text, not ooRexx's, and an error the package raises may be reported from another clause of it or from the caller (Deviation 89).

The page first states the class and how a pattern is read, then the grammar and what it matches, and last the matching calls. Characters are bytes: the pattern and the string are compared byte by byte, and no case is folded. A '00'x ends a pattern, and what match and pos answer for a string that contains one is not specified (the grammar rule gives the first).

The class

[class.regularexpression.creation]

RegularExpression has the class method new and the instance methods init, uninit, parse, match, pos and position, besides the methods that every class has. uninit is public (hasMethod('uninit') answers 1), but what it does is not part of this specification, except for the calls that follow it (Deviation 88). The class may have private and undocumented methods besides these; they are not part of this specification either. Its only superclass is Object and it inherits no mixin class (the hierarchy rule). new makes an instance of the class that received it, so a subclass makes instances of itself, and sends init the arguments of new (the new rule). A subclass that declares its own init forwards to this one, which holds the pattern. Until parse, match or pos has run, position answers the string !POS, also after a pattern was given to new.

re = .RegularExpression~new('ab')
say re~class~id re~class~superclass~id .RegularExpression~queryMixinClass
say re~hasMethod('uninit') re~hasMethod('position')
say re~position
re~match('ab')
say re~position
t = .tagged~new('x*', 'first')

[class.regularexpression.new]

new(pattern, mode) makes an expression. Both arguments are optional. A pattern that is omitted, or an omitted argument in its place as in new(, 'MINIMAL'), leaves the expression without a pattern; a pattern that is given is parsed as parse parses it, and an error in it raises SYNTAX 38.0 instead of an answer code, also for the empty pattern. The mode is MAXIMAL or MINIMAL in any case and nothing else: any other string, an abbreviation, a string with a blank around it and the empty string, raise SYNTAX 93.0. It chooses how a match is read; omitted, it is MAXIMAL. The arguments are read and checked as the argument rule says.

say .RegularExpression~new('a', 'minimal')~match('ab')
say .RegularExpression~new('a', 'Maximal')~match('ab')
say .RegularExpression~new(12)~match(12)
say .RegularExpression~new(, 'MINIMAL')~parse('a')

[class.regularexpression.args]

new, parse, match and pos check their arguments in one order, which is not the order of the count rule. First each argument that the method takes is checked from the left (the pattern and the mode of new and parse, the string of match and pos): a required one that is missing raises SYNTAX 88.901, and one that cannot be read as a string 88.909. Then the number of arguments is checked, one too many raising 88.922; an argument beyond the last one the method takes is not read. Then the mode is checked, 93.0, and only then the pattern, so that a bad pattern given to new raises 38.0 last. An argument that is not a string is converted by sending it request with STRING (the request rule); the request of Object answers what the object's makeString answers, and .nil when it has none. A string answer is used. An Array answer is read as its makeString answer, its items joined by line feeds. Any other answer, .nil included, raises SYNTAX 88.909, and the argument's string method is not used, unlike the builtins. So a number is its digits, and an Array argument is its items joined by line feeds.

[class.regularexpression.mode]

The mode decides what a match is when several are possible. In MAXIMAL mode a match is as long as it can be: match answers 1 only when the whole string matches the pattern, and pos finds the longest match at the leftmost place where there is one. In MINIMAL mode a match is as short as it can be: match answers 1 when the pattern matches a leading part of the string, the shortest one, and pos finds the shortest match at the leftmost place. The mode of an expression is the one given to new or the last one given to parse, and MAXIMAL before any was given.

text = '<p>one</p><p>two</p>'
big = .RegularExpression~new('<p>?*</p>')
small = .RegularExpression~new('<p>?*</p>', 'MINIMAL')
say big~match(text) big~position small~match(text) small~position
say big~pos(text) big~position small~pos(text) small~position
say big~pos('x'text'y') big~position
exit

Reading a pattern

[class.regularexpression.parse]

parse(pattern, mode) replaces the pattern of the expression and, when mode is given, its mode; without it the mode stays what it was. It answers a code: 0 when the pattern was read, and otherwise one of 1 to 6 that the next rule lists. The pattern is required. The arguments are checked as the argument rule says, and a mode that is not MAXIMAL or MINIMAL, in any case, raises SYNTAX 93.0. position answers how many characters of the pattern were read. When the code is 0 that is the length of the pattern, unless the text after a complete pattern was left unread, as the grammar rule says. When the code is not 0 the old pattern is gone and the expression matches every string: a later match answers 1 and pos answers 1, both with position 0.

re = .RegularExpression~new('ab', 'MINIMAL')
say re~match('abc') re~position
say re~parse('abc') re~position re~match('abc') re~position
say re~parse('abc', 'MAXIMAL') re~match('abcd') re~position
say re~parse('[') re~position
say re~match('zzz') re~position re~match('') re~position
say re~pos('zzz') re~position

[class.regularexpression.parse.codes]

The code of parse says what was wrong with the pattern. Code 1 is a symbol where none is allowed, or a pattern that ends where something has to follow: a pattern that is empty or starts with *, +, |, ), ], { or }, an empty group (), and an alternative with nothing in it, as in a|, a||b and (a|). Code 2 is a group that is not closed, as in (a. Code 3 is a set that is not valid or not closed: [, [a, [], [a- and [a-], a range that has no end, and a \ that ends the pattern inside a set, as in [a\. Code 4 is a pattern that ends after an escape outside a set, as in a\, or inside a count: a{ and a{3. Code 5 is a count that is not a number or is below 2, as in a{}, a{x} and a{1}, and a number too large for the pattern to be built. Code 6 is a symbolic name in a set that is not one of the defined names, or has no closing colon: [:foo:] and [:alpha]. position answers the number of characters before the one at fault, so 0 when the first character is at fault (*), 1 for () and 2 for a|*, and the length of the pattern when it ends where something has to follow ((a, a|, a\, [, [a, [a-c). Two kinds of error count differently. An error in a set other than a missing ], which is codes 3 and 6 and a \ that ends the pattern inside a set, counts the characters up to and including the [ ([] 1, xy[a-] 3, [a\ 1, xy[:foo:] 3), and so does a set that the pattern ends before its first member (q[^ 2). An error in a count, codes 4 and 5, counts those before its { (a{ 1, xyz{3 3, xyz{x} 3). The example shows it for a pattern of each kind.

re = .RegularExpression~new
patterns = .array~of('', '*', ')', '()', 'a|', '(a|)', '(a', '[', '[a', '[]')
patterns~appendAll(.array~of('[a-]', 'a\', 'a{', 'a{3', 'a{}', 'a{1}'))
patterns~append('a{x}')
patterns~appendAll(.array~of('[:foo:]', '[:alpha]', 'a|*', '[a-c', 'xy[a-]'))
patterns~appendAll(.array~of('[a\', 'xyz{3', 'xyz{x}', 'xy[:foo:]', 'q[^'))
do p over patterns
  say p~left(9) re~parse(p) re~position
end
exit

The pattern language

[class.regularexpression.grammar]

A pattern is one or more alternatives separated by |, and an alternative is one or more elements. An element is a character that stands for itself, the wildcard ?, a set in square brackets, or a group in parentheses, and it may be followed by one quantifier. Any character that is not special stands for itself, a blank, ., ^, $, -, : and , among them; case counts. ? stands for any one character. \ makes the character after it stand for itself, whatever it is; a \ that ends the pattern is error 4. An alternative may not be empty, and neither may a group. | separates whole alternatives: it ranks below joining elements, so ab|cd is ab or cd, and a group is how the choice is limited to part of a pattern. A * or + or {n} applies to the element before it. Reading stops, without an error, at a symbol that cannot continue a pattern that is complete: a ) with no group open, a second quantifier after a quantifier (a**, a+*, a{2}+), a ], or a } after an element; parse answers 0 and position says how many characters were read, so the rest is not part of the pattern and has no effect. Where an element is needed, such a symbol is error 1. A '00'x in the pattern ends it in the same way: what follows is not read, and position counts the characters before it.

re = .RegularExpression~new
say 'literals' re~parse('a b.c') re~match('a b.c') re~match('a bxc')
say 'case' re~parse('abc') re~match('ABC')
say 'wildcard' re~parse('a?c') re~match('abc') re~match('a-c') re~match('ac')
say 'escape' re~parse('a\?c\\') re~match('a?c\') re~match('abc\')
say 'colon' re~parse('a:b-c') re~match('a:b-c')
say 'plain' re~parse('a^b$c,d') re~match('a^b$c,d')
say 'alternatives' re~parse('ab|cd|e') re~match('ab') re~match('cd'),
  re~match('e') re~match('abcd')
say 'groups' re~parse('(a|b)(c|d)') re~match('ad') re~match('bc'),
  re~match('ab')
say 'nested' re~parse('((a)(b|(c)))') re~match('ab') re~match('ac')
say 'one char' re~match('a')
say 'stops' re~parse('ab)cd') re~position re~match('ab')
say 'stops' re~parse('a**') re~position re~match('aaa') re~match('a')
say 'stops' re~parse('a]b') re~position re~match('a')
say 'bytes' re~parse('?') re~match('é') re~parse('??') re~match('é')
say 'nul' re~parse('a'||'00'x||'b') re~position re~match('a')
say 'nul' re~parse('['||'a'||'00'x||']') re~position
say 'nul' re~parse('00'x) re~position

[class.regularexpression.grammar.repeat]

* after an element matches it any number of times, none included, + one or more times and {n} exactly n times. The count is read as a whole number from the text between the braces: blanks and the characters '09'x to '0d'x before it, and a sign, are allowed, it ends at the first character that is not a digit, and the text after it up to the } is ignored, so a{2,3} is a{2}. A count with no digit, or one below 2, is error 5, and so is one too large for the pattern to be built; how large that is is not specified. The element may be a character, ?, a set or a group, so ?* matches any string, the empty one included, and (ab){2} matches abab. A group that can match the empty string, as in (a*), may itself be repeated; Deviation 87 gives examples.

[class.regularexpression.grammar.set]

A set in square brackets matches one character that is one of its members. The members are characters, ranges and symbolic names. A ^ right after the opening bracket negates the set: it matches one character that is not a member; a ^ anywhere else is an ordinary member. A - between two characters makes a range. For a range the bytes count as numbers from -128 for '80'x up to 127 for '7f'x, so '80'x to 'ff'x come before '00'x. When the first character is not above the second, the range is all characters from the first to the second; when it is above, it is the characters above the second up to the first, so [d-a] is b, c and d. In a chain such as [a-c-e] the character that ends a range also starts the next one, so that set is a to e. A \ right after the - of a range is the end of the range and not an escape, and a - after a symbolic name starts a range at the closing colon of the name, which is left out when the end is above it: [:digit:-z] is the digits and the characters from ; to z. A [ inside a set is an ordinary member. A - that opens the set, or follows the ^ that opens it, is an ordinary member, and a - that ends the set is error 3. Inside a set the characters ?, *, +, |, (, ), {, } and . stand for themselves; \ makes the next character an ordinary member, which is how ], - and \ itself are members, and a : that is not preceded by \ begins a symbolic name. A set must have a member, and its closing bracket must be present: error 3.

[class.regularexpression.grammar.names]

A symbolic name in a set stands for a group of characters. A name is written between two colons and is read without regard to case; it may be mixed with other members, and [^:digit:] negates it. The names and what they stand for: alpha is the letters A to Z and a to z, lower is a to z, upper is A to Z, digit is 0 to 9, alnum is alpha and digit, xdigit is digit, A to F and a to f, blank is space and tab, space is '09'x to '0d'x and space, cntrl is '00'x to '1f'x and '7f'x, print is '20'x to '7e'x, graph is print without the space, and punct is print without the space, the letters and the digits. A : in a set that does not begin a name this way, such as the colon in [a:b], is error 6. A name outside a set is plain text: :alpha: is the seven characters.

re = .RegularExpression~new
names = 'alpha lower upper digit alnum xdigit blank space cntrl print'
names = names 'graph punct'
do name over names~makeArray(' ')
  re~parse('[:'name':]')
  hits = ''
  chars = .array~of('a', 'Z', '7', 'f', 'g', ' ', '09'x, '0a'x, '1f'x, '7f'x)
  chars~append('!')
  do ch over chars
    hits = hits re~match(ch)
  end
  say name~left(6) hits
end
say 'mixed' re~parse('[:digit:x]') re~match('x') re~match('5') re~match('y')
say 'negated' re~parse('[^:digit:]') re~match('x') re~match('5')
say 'case' re~parse('[:ALPHA:]') re~match('q')

say 'errors' re~parse('[a:b]') re~parse('[:]') re~parse('[:alpha'),
  re~parse('[:abc:]')
exit

Matching

[class.regularexpression.match]

match(string) answers 1 when the pattern matches the string as the mode says, and 0 when it does not, and position answers a number. When the answer is 1 the number is the length of the part of the string that matched: the whole string in MAXIMAL mode, the shortest leading part in MINIMAL mode. When it is 0 the number is the length of the longest leading part of the string that can still be the beginning of a match of the pattern, which is 0 when the first character already fails, and the length of the string when the string ended too early. The string argument is required; it is read and checked as the argument rule says.

re = .RegularExpression~new('ab?d')
say re~match('abcd') re~position
say re~match('abc') re~position
say re~match('abcde') re~position
say re~match('xbcd') re~position
say re~match('') re~position
say re~match('ab') re~position

exit

[class.regularexpression.pos]

pos(string) looks for the pattern in the string, and answers the position of the first character of the leftmost place where it matches, counting from 1, or 0 when there is none. position then answers the position of the last character of that match, so a match of n characters from position p ends at p+n-1, and an empty match, which a pattern that can match the empty string has at position 1, ends at 0. When there is no match both are 0. The match is the longest in MAXIMAL mode and the shortest in MINIMAL mode, and among matches that begin at one place only that place counts: the leftmost place wins over the length. The argument is checked as for match.

text = 'in 2016, 42 and 7'
re = .RegularExpression~new('[0-9]+')
b = re~pos(text)
say b re~position text~substr(b, re~position - b + 1)
mi = .RegularExpression~new('[0-9]+', 'MINIMAL')
b = mi~pos(text)
say b mi~position text~substr(b, mi~position - b + 1)
say re~pos('none') re~position
nul = .RegularExpression~new('b*')
say nul~pos('abb') nul~position nul~pos('') nul~position

[class.regularexpression.position]

Deviations

[class.regularexpression.deviation.87]

The pattern language is the one this page gives, and every call ends. ooRexx differs in many patterns; among them, it answers wrongly when a + is followed by a repeated element, as c+a*, which it does not match against cca, and when an alternative that begins with a repeated element is followed by another one, at the top or in a group: b*c|a is b*c or a, but ooRexx reads the second alternative as following the repeated element, so it finds ba. It does not end for a pattern that repeats a group that can match the empty string, such as (a*)*, for one that begins with a group whose first alternative can match the empty string and is followed by |, such as (c*|b)|d, and for a set with a range whose highest character, in the order of the set rule, is '7f'x, as in [a-'7f'x] and ['7f'x-'81'x], and it crashes on others, such as (c*|b)c|d. And for a count it cannot build, as in a{99999999999}, it uses memory until it is stopped, where interrexx answers code 5 from parse. None of the examples is run on ooRexx.
