The interrexx Language Specification

EventSemaphore

rexxref: Builtin Classes > Utility Classes > EventSemaphore Class; Builtin Classes > Utility Classes > EventSemaphore Class > new (Class Method); Builtin Classes > Utility Classes > EventSemaphore Class > isPosted; Builtin Classes > Utility Classes > EventSemaphore Class > post; Builtin Classes > Utility Classes > EventSemaphore Class > reset; Builtin Classes > Utility Classes > EventSemaphore Class > uninit; Builtin Classes > Utility Classes > EventSemaphore Class > wait

Deviations: D109

An EventSemaphore is a flag that activities can wait for. It is either posted or cleared. An activity that has to wait for something another activity does calls wait; the activity that does it calls post, and every activity that waits goes on. A semaphore that is posted lets wait return at once, until it is cleared again with reset. This page states what each method answers and checks, and what a timeout may be. How activities are scheduled, and so which of several waiters runs first after a post, is specified by the waiting rule of the concurrency chapter. The examples that use two activities start a message and wait on the semaphore from the program; the order of their output is forced by the semaphore itself.

The class

[class.eventsemaphore.creation]

EventSemaphore has the instance methods isPosted, post, reset, uninit and wait, and the class method new, besides the methods that every class has. It may have private methods besides these; they are not part of this specification. Its only superclass is Object and it inherits no mixin class (the hierarchy rule).

say .eventsemaphore~id .eventsemaphore~superclasses~items,
  .eventsemaphore~superclass~id .eventsemaphore~queryMixinClass
have = .set~new
s = .eventsemaphore~methods(.nil)
do while s~available
  have~put(s~index)
  s~next
end
names = 'isPosted post reset uninit wait'~makeArray(' ')
count = 0
do name over names
  if have~hasItem(name~upper) then count = count + 1
end
say count 'of 5'

[class.eventsemaphore.new]

[class.eventsemaphore.copy]

copy answers a new semaphore in the state the original is in: posted when it is posted, cleared when it is cleared. From then on the two are separate: a post or reset of one does not change the other, and a wait on one is not ended by a post of the other.

Waiting

[class.eventsemaphore.wait]

wait(timeout) answers 1 when the semaphore is posted, at the call or before the timeout ends, and 0 when the timeout ended with the semaphore still cleared. The timeout says how long the caller is prepared to wait. Omitted or below zero, there is no limit, so the answer is 1, except for a wait that a signal's HALT ends (Deviation 10). Zero is no wait at all, and the answer is the state at the call, as isPosted gives it. Above zero it is a limit in seconds. One post ends the wait of every caller that is waiting, however many there are; which of them runs on first is not specified. A call of wait that is released by post and one that finds the semaphore posted answer alike. The timeout is read before the semaphore is looked at, as the next rule says, so an invalid one raises its error even for a posted semaphore. In the example a message that the program starts posts after a short pause, and a second starts two waiters, one without a timeout and one with a long one that never ends before the post; the program waits for the post too, and prints what each answered, which the post forces to be 1 for all, and what wait(0) and a short timeout answer on a cleared semaphore.

e = .eventsemaphore~new
say e~wait(0) e~wait(0.05)
w1 = .message~new(e, 'wait')~~start
w2 = .message~new(e, 'wait', 'I', 30)~~start
w3 = .message~new(.poster, 'later', 'I', e)~~start
say 'blocking wait:' e~wait
say w1~result w2~result w3~result
say e~isPosted
say e~wait e~wait(0) e~wait(-1) e~wait(5)
e~reset
say e~isPosted e~wait(0.05)
p = .message~new(.poster, 'later', 'I', e)~~start
say p~result e~wait(30)

[class.eventsemaphore.wait.timeout]

The timeout is a number of seconds or a TimeSpan, and it is read before anything else is done, so an invalid one raises SYNTAX 88.902 whatever the state of the semaphore. A string is a valid timeout when it is a number as the DATATYPE N rule reads it, so blanks at either end, a sign, a decimal point and an exponent are allowed; the empty string, a string of blanks and a string that is no number raise SYNTAX 88.902. An object that is neither a string nor a TimeSpan is replaced by its string value, as the conversion rule says, and that string is read in the same way; .nil, a DateTime and an object whose string value is no number, such as an instance of Object, raise SYNTAX 88.902. A TimeSpan is read through its totalSeconds, which is sent to it once, and a span that is negative means the same as a negative number. More than one argument raises SYNTAX 93.902. The first example gives each form to a cleared semaphore with a short timeout, and to a posted one. In the second, a TimeSpan that is negative waits as long as a negative number does, until the post, which comes from another activity.

[class.eventsemaphore.wait.sends]

wait sends the message totalSeconds to a timeout that is a TimeSpan, once and before it looks at the semaphore, and no other message to a TimeSpan; an object that is neither a string nor a TimeSpan is sent what the conversion rule says (Deviation 109 says that a string that is an instance of a subclass of String is read by its own characters). No method of the class sends a message to the semaphore itself: an override of post, reset, isPosted or wait runs when the program sends that message and not because another of them was. The first example overrides each method and totalSeconds of a subclass of TimeSpan and shows what runs; the second gives a timeout whose class has its own request and makeString, and only request is sent.

Cleaning up

[class.eventsemaphore.uninit]

uninit frees what the semaphore holds. The interpreter may send it when the semaphore is reclaimed; whether and when is not specified. An uninit of a subclass replaces this one, so it frees the semaphore only by sending self~uninit:super. uninit takes no argument (SYNTAX 93.902) and answers nothing, so using its answer as a value raises SYNTAX 91.999. What a semaphore does for a message that a program sends it after a direct uninit, a second uninit included, is not specified.

.environment~log = .list~new
s = .tidy~new
s~uninit
say .environment~log~makeArray~makeString('l', ' ')

[class.eventsemaphore.deviation.109]

A timeout that is an instance of a subclass of String is read by its own characters, and request, makeString and string are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING, so an override can change what is read.
