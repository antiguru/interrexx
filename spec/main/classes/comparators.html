Deviations: D109

A comparator is an object that orders two others. It has one method, compare, which takes two objects and answers a number: negative when the first is to come before the second, 0 when the order does not tell them apart, and positive when the first is to come after. The sorting methods that take a comparator, such as sortWith, send it compare and need nothing else of it, so any object with such a method will do. This page describes Comparator and the seven classes below it: CaselessComparator, ColumnComparator, CaselessColumnComparator, DescendingComparator, CaselessDescendingComparator, InvertingComparator and NumericComparator. Each is made by new like any class; the compare of each hands the two objects to a method of the first or to a comparator that the instance holds, and says what it answers, so what a comparator answers for an object that is not a string depends on that object's own methods.

The classes

[class.comparators.creation]

Comparator is a mixin class (the mixin rule) whose only superclass is Object; each of the other seven classes is a mixin class whose only superclass is Comparator. Every one of the eight defines its own compare. ColumnComparator, CaselessColumnComparator, InvertingComparator and NumericComparator define init as well; the other four have the init of Object and take no argument in new, so that an argument raises SYNTAX 93.902 (the new rule). An instance of each of the eight can be made by new. An instance of one of them is not an instance of Comparable or Orderable, and a program's own comparator needs to inherit nothing: any class with a compare method works where a comparator is wanted.

names = 'Comparator CaselessComparator ColumnComparator',
  'CaselessColumnComparator DescendingComparator',
  'CaselessDescendingComparator InvertingComparator NumericComparator'
do n over names~makearray(' ')
  c = .environment~at(n~upper)
  line = n~left(28)
  do s over c~superclasses
    line = line s~id
  end
  say line~left(46) owns(c, 'compare') owns(c, 'init')
end

Comparator

[class.comparators.comparator.compare]

The compare of Comparator takes two arguments and sends compareTo to the first, with the second as its only argument, and answers what compareTo answers, unchanged and without examining it. So two strings are ordered by the string rule, two DateTime or two TimeSpan instances by theirs, and any other object by its own compareTo; a first argument that has no compareTo raises SYNTAX 97.1, and a second one that the compareTo of a string cannot read raises that method's error. A missing argument raises SYNTAX 93.901, an omitted first argument before a given second SYNTAX 93.903, and a third argument SYNTAX 93.902; the arguments are checked before anything is sent. Nothing is sent to the second argument by compare itself.

c = .comparator~new
say c~compare('a', 'b') c~compare('b', 'a') c~compare('b', 'b')
say c~compare('10', '9') c~compare(10, 9) c~compare('A', 'a')
say c~compare(.timespan~new(1), .timespan~new(2)),
  c~compare(.timespan~new(2), .timespan~new(1))
say c~compare(.pad~new(5), .pad~new(2)) c~compare(.pad~new('x'), 1)
call try 'c~compare("a")'
call try 'c~compare(, "a")'
call try 'c~compare'
call try 'c~compare("a", "b", "c")'
call try 'c~compare(.nil, "a")'
call try 'c~compare(.object~new, "a")'
call try 'c~compare("a", .nil)'
exit

The column comparators

[class.comparators.column.init]

init of ColumnComparator takes two arguments, start and length, and keeps them as they are: it examines neither, so that new accepts any two objects, including ones that no compare can use, and an invalid value shows only when compare is sent (the compare rule). init of InvertingComparator takes one argument, the comparator to invert, and keeps it as it is, without examining it: any object, .nil and a string included, is accepted by new, and a value that cannot be used shows only when compare is sent (the compare rule). The argument is required: new with none, or with an omitted one, raises SYNTAX 93.901, and a second argument raises SYNTAX 93.902. A later init sent to the instance replaces the comparator.

[class.comparators.inverting.compare]

The compare of InvertingComparator takes two arguments, sends compare with both of them to the comparator that init was given, sends the prefix - to the answer, and answers what that answers: the negated number, so that the order is the reverse of the one the held comparator gives. An answer of the held comparator that is no number raises the error of - for it, SYNTAX 41.1 for a string, and a held object that has no compare, .nil included, raises SYNTAX 97.1. [class.comparators.numeric.compare]

The compare of NumericComparator takes two arguments, subtracts the second from the first by sending - to the first with the second as its only argument, while NUMERIC DIGITS is the number given to init (the digits of the program that sent compare do not matter), and answers the sign of the difference: -1, 0 or 1. Two numbers whose difference is lost in the rounding to those digits are equal, so a comparator of 3 digits finds 1000 and 1001 equal and 1000 and 1010 not. A difference that is no number raises SYNTAX 93.943; a string that is no number raises SYNTAX 41.1; a first argument that has no - method raises SYNTAX 97.1. Argument errors are those of Comparator. The difference is read as a number as the argument rule reads one, so an object whose makeString or string answers a number is accepted, and the sign is that number's.

Sorting with a comparator

[class.comparators.sort]

The comparators are what sortWith and stableSortWith take (the sort rule), and the order they give is the one that their compare rules describe: Comparator the order of compareTo, in which for strings upper case comes before lower case and 10 before 9; CaselessComparator the same without regard to case; DescendingComparator and CaselessDescendingComparator the reverse of those; the two column comparators the order of the part of each string that starts at start, with items whose parts are equal keeping their order under stableSortWith; InvertingComparator the reverse of the comparator it holds; and NumericComparator the order of the numbers the items stand for. The example sorts the same items with each, by stableSortWith, so that items that compare as equal keep their places; 2e1 and 20.0 both stand for 20, and keep their order for NumericComparator.

w = .array~of('Rowan', 'elder', "hawk's eye", 'Birch', 'birch')
say show(w~copy~~stableSortWith(.comparator~new))
say show(w~copy~~stableSortWith(.caselessComparator~new))
say show(w~copy~~stableSortWith(.descendingComparator~new))
say show(w~copy~~stableSortWith(.caselessDescendingComparator~new))
say show(w~copy~~stableSortWith(.columnComparator~new(2, 3)))
say show(w~copy~~stableSortWith(.caselessColumnComparator~new(2, 3)))
say show(w~copy~~stableSortWith(.invertingComparator~new(.comparator~new)))
col = .columnComparator~new(2, 3)
say show(w~copy~~stableSortWith(.invertingComparator~new(col)))
n = .array~of(40, 8, 31, 6, 15, '2e1', 20.0)
say show(n~copy~~stableSortWith(.numericComparator~new))
say show(n~copy~~stableSortWith(.comparator~new))
exit

Messages that a program can override

[class.comparators.sends]

Each compare sends the messages below, in this order, and no other but those that NumericComparator sends in reading the difference: nothing is sent to the second argument or to the comparators themselves, nothing is sent to the first argument but what is listed, and no argument is asked isA. Comparator sends compareTo to the first argument with one argument, the second. CaselessComparator sends caselessCompareTo the same way. ColumnComparator sends compareTo, and CaselessColumnComparator caselessCompareTo, with three arguments: the second argument, start and length. DescendingComparator sends compareTo with one argument and then the prefix -, which is the message - with no argument, to the answer, and CaselessDescendingComparator does the same with caselessCompareTo. InvertingComparator sends compare with two arguments, the arguments it got, to the comparator it holds and then the prefix - to the answer. NumericComparator sends - to the first argument with one argument, the second. The answer of the last message of each is the answer of compare, except that NumericComparator answers the sign of it, reading it as a number as the argument rule says. The example gives the objects methods that log the messages they get, isA among them, and prints what each compare sent.

call p 'comparator', '.comparator~new~compare(.first~new, .second~new)'
call p 'caseless', '.caselessComparator~new~compare(.first~new, .second~new)'
call p 'column',,
  '.columnComparator~new(2, 3)~compare(.first~new, .second~new)'
call p 'caselesscolumn',,
  '.caselessColumnComparator~new(2, 3)~compare(.first~new, .second~new)'
call p 'descending',,
  '.descendingComparator~new~compare(.first~new, .second~new)'
call p 'caselessdescending',,
  '.caselessDescendingComparator~new~compare(.first~new, .second~new)'
call p 'inverting',,
  '.invertingComparator~new(.inner~new)~compare(.first~new, .second~new)'
call p 'numeric', '.numericComparator~new~compare(.first~new, .second~new)'
exit

Deviations

[class.comparators.deviation.109]

A string that a comparator reads from an argument is read by the string method that compare sends, and an instance of a subclass of String is read by its own characters, and REQUEST, MAKESTRING and STRING are not sent to it (Deviation 109). ooRexx sends such an instance request with STRING and then makeString, so an override can change what is read. In the example makeString and request of the subclass answer another string, and the instances still stand for their own characters.

.local~sent = 0
x = .digits~new('b')
say .comparator~new~compare('a', x) .comparator~new~compare('c', x)
say .caselessComparator~new~compare('B', x)
say .columnComparator~new(1, 1)~compare('ab', .digits~new('ba'))
say 'sends' .local~sent
::class digits subclass string
