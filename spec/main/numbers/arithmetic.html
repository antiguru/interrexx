The interrexx Language Specification

Arithmetic

ANSI: 7.4.2, 7.4.3, 7.4.4, 7.4.5, 7.4.10; rexxref: Numbers and Arithmetic > Arithmetic

Deviations: D53, D102

The arithmetic operators are the infix +, -, *, /, %, // and **, and the prefix + and -. Each reads its operands as numbers, works to the precision that NUMERIC DIGITS sets, and answers a new number. This page says how many digits an operation looks at in its operands, how it rounds, what each operator answers, and which errors an operation raises. How an answer is written is the business of the formats page, the size limits of the limits page, and the settings of the settings page. Where the operators stand in an expression is left to the expressions chapter.

Operands and precision

[num.arithmetic.operand]

Each operand of an arithmetic operator must be a number, and a string that is not one raises SYNTAX 41.1, as the use rule says. Both operands, and the operand of a prefix operator, are checked before the operator does anything else, so a bad operand wins over a zero divisor or any other error that the operator would otherwise find. The right operand of ** is the exception: it is the exponent and is checked by its own rule. A string whose exponent is out of range is not a number either.

signal on syntax name a
say 'ten' / 0
a: say condition('o')~code
signal on syntax name b
say 10 % 'x'
b: say condition('o')~code
signal on syntax name c
say -'1 2'
c: say condition('o')~code
signal on syntax name d
say 1 + ''
d: say condition('o')~code

[num.arithmetic.digits]

An operation works at NUMERIC DIGITS significant digits and rounds its result to that many, as the rounding rule of the builtins says and as the result rule applies to every operator. An operand is not rounded before the operation: it takes part with the digits it has, apart from the cut that the next two rules describe for the digits beyond DIGITS plus one. Under NUMERIC DIGITS 1 the product of 2 and 1.5 is therefore 3, where rounding 1.5 to 2 first would give 4, and rounding happens once, on the result.

numeric digits 1
say (2 * 1.5) (1.5 + 1.5) (6 / 4) (0.4 + 0.4)
numeric digits 3
say (1 / 3) (2 / 3) (100 / 3) (1000 / 3) (10000 / 3) (2.5 * 2.5)
numeric digits 12
say (1 / 3) (2 / 3) (1 / 7)

[num.arithmetic.cut]

Before *, /, % or // uses an operand that has more than DIGITS plus one significant digits, it cuts the operand to its first DIGITS plus one digits, counted from the first nonzero digit. The cut drops the later digits and does not round them. The digit kept beyond DIGITS takes part in the operation, so it shapes the digit on which the result is rounded. The two products and the two quotients below therefore differ from the exact ones, which would round to 4, 4, 1.0 and 0.32.

numeric digits 1
say (1.19 * 3) (1.19 * 3.19)
numeric digits 2
say (1.499 / 1.5) (2.999 / 9.5)

3 3
0.99 0.31
[num.arithmetic.addsub]

The result of + and - is rounded to DIGITS digits counted from the first digit of the operand whose first digit stands higher, and not from the first digit of the result. Let that higher digit stand at power of ten H, taking no account of an operand with the value zero. Both operands are first cut after the digit at H - DIGITS, which is one digit more than the rounding keeps. Their exact sum or difference is then rounded once, half up in magnitude, at the coarser of H - DIGITS + 1 and the DIGITS significant digits of that sum. So two close numbers can cancel down to zero, and a sum that carries into a new leading digit keeps one digit less after the point.

[num.arithmetic.prefix]

The prefix + and - round their operand to DIGITS significant digits as 0 + x and 0 - x would, and - also flips the sign. The operand is a number like any other, so a prefix applied to zero answers 0 without a sign. The sign of a number in a program is a prefix operator applied to the number without the sign, so a literal that is wider than DIGITS is rounded by its own sign before the operator beside it sees it.

numeric digits 3
say (-1.2345) (+2.4999) (-0.00012345) (+' 5.0 ') (-0) (-0.0)
numeric digits 1
x = '-1.5'
say (-1.5 + 2) (x + 2) (-1.5) x (+1.5) (+15)

Division

[num.arithmetic.divide]

/ answers the quotient of its operands, which are cut as the cut rule says, rounded to DIGITS digits. A dividend of zero answers 0, and the quotient has the trailing zeros removed. The quotient need not be whole, and a quotient with a repeating expansion is the first DIGITS digits of it, rounded.

say (1 / 3) (2 / 3) (10 / 4) (1 / 8) (6.0 / 3) (0 / 5) (-9 / 4) (7 / -2)
numeric digits 4
say (1 / 3) (2 / 3) (22 / 7) (1 / 80000) (12345 / 100) (1 / 800000000)

0.333333333 0.666666667 2.5 0.125 2 0 -2.25 -3.5
0.3333 0.6667 3.143 0.0000125 123.5 1.25E-9
[num.arithmetic.zero]

A zero divisor raises SYNTAX 42.3 for /, % and //, whatever the dividend is, zero included. A divisor is zero when it is a number of value zero, whatever its written form. The operand check comes first, as the last example shows.

signal on syntax name a
say 1 / 0
a: say condition('o')~code
signal on syntax name b
say 0 / 0
b: say condition('o')~code
signal on syntax name c
say 7 % 0.00
c: say condition('o')~code
signal on syntax name d
say 7 // '-0e5'
d: say condition('o')~code
signal on syntax name e
say 7 / 'x'
e: say condition('o')~code

[num.arithmetic.integer]

% answers the integer part of the quotient, its magnitude rounded down, with the sign of the quotient, and // answers what remains of the dividend after that many divisors are taken from it, which has the sign of the dividend and is rounded to DIGITS digits. Both cut their operands as the cut rule says before they divide. The integer part must fit in DIGITS digits, or % raises SYNTAX 26.11 and // raises SYNTAX 26.12, so a remainder is refused when the quotient it belongs to is too wide. A result of zero is 0 with no sign.

say (7 % 2) (-7 % 2) (7 % -2) (7 // 2) (-7 // 2) (7 // -2) (-7 // -2)
say (7.5 // 2) (-7.5 % 2) (0.5 % 1) (-0.5 // 1) (-0.5 % 1) (6 // 3) (6 % 3)
numeric digits 3

Powers

[num.arithmetic.exponent]

The right operand of ** must be a whole number of at most DIGITS digits, after it is rounded to DIGITS digits as exponent + 0 would round it, and its value may be negative. A string that is not a number at all, a number with a fraction after that rounding, and a number of more than DIGITS digits raise SYNTAX 26.8 where the other operators raise SYNTAX 41.1. The base is checked first, so a base that is not a number raises 41.1 even when the exponent is bad too.

[num.arithmetic.power]

A power answers the base raised to the exponent, rounded to DIGITS digits and written without the zeros that end its decimal places, as the trailing-zero rule says. Any base to the power 0 is 1, zero included, a base to a positive exponent is that many factors, and a base to a negative exponent is the reciprocal of the power with the exponent's magnitude. A negative base keeps its sign for an odd exponent. The base is cut to DIGITS plus one digits first, and the factors are multiplied under rounding of their own, so a power whose exact value does not fit in DIGITS digits may differ from that value rounded in its last digit, and this book does not specify which.

say (2 ** 10) (2 ** -3) ((-2) ** 3) ((-2) ** 2) (1.5 ** 2) (0 ** 3) (0 ** 0)
say (5.0 ** 1) (1.50 ** 2) (10 ** -2) (2.5 ** 0) (0.5 ** 3) (3 ** 20)

[num.arithmetic.power.error]

Only a zero base raises SYNTAX 42.903, and it does so for a negative exponent. A power raises SYNTAX 42.1 when the first digit of the base, at power of ten A, and the exponent N have a product A * N that is more than 999999999 in magnitude. The test is made before any digit is computed and does not look at the value, so it also refuses a power whose value is within the exponent range. A power that passes the test is computed. A product of the computation whose first digit stands above the range raises SYNTAX 42.901, whatever the sign of the exponent. The last digit of a product is not tested, so an intermediate value that is out of range only at its last digit raises nothing. The final result, which for a negative exponent is the reciprocal of the unrounded product, is tested as the power rule and the underflow rule say. A base such as 100 therefore raises 42.1 at an exponent for which 11 raises 42.901.

Errors in the multiplicative and additive operators

[num.arithmetic.range]

A result of +, -, * or / that is out of the exponent range raises the errors that the limits page gives, SYNTAX 42.901 for an overflow and SYNTAX 42.902 for an underflow, and the integer division operators raise the errors above for a result that is too wide. No operator answers a value outside the range, and the underflow rule says that a result that is too small is not replaced by zero.

signal on syntax name a
say 5e999999999 * 20
a: say condition('o')~code
signal on syntax name b
say 1e-999999999 / 10
b: say condition('o')~code
signal on syntax name c
say 1e999999999 % 7
c: say condition('o')~code

Lost digits

[num.arithmetic.lostdigits]

An operand of an arithmetic operator that has more digits than NUMERIC DIGITS raises the LOSTDIGITS condition, and so does the base of ** but not its exponent. The digits counted are those from the first nonzero digit to the last one written, so zeros that end the operand count, and the exponent and the zeros that start the operand do not. An operand of value zero has no digits. The condition is raised for the left operand first and only after both operands were found to be numbers, and the builtins raise no such condition. When the condition is not trapped the operation goes on with the digits it has, cut as the cut rule says. Both operands are checked for lost digits before the operator looks at their values, so a wide left operand raises LOSTDIGITS before SYNTAX 42.3 for a zero divisor of /, % and // (the zero rule) and before SYNTAX 26.8 for an exponent of ** that is a number but not a whole number of at most DIGITS digits (the exponent rule).

say 1234 + 1
signal on lostdigits name a
say 1234 + 1
a: say condition('c') condition('d')
signal on lostdigits name b
say 5 * 1.200
b: say condition('d')
signal on lostdigits name c
say 99 * 1000

say 1234 * 5678
d: say condition('d')

Deviations

[num.arithmetic.deviation.53]

A divisor that is wider than NUMERIC DIGITS raises LOSTDIGITS even when the dividend is zero, and the description of the condition is the text of the operand as it was written, whichever operator produced the condition. ooRexx does not check the divisor when the dividend is zero and answers 0. It describes the operand of *, /, %, // and ** and the operand of a prefix operator by its value, written as the notation rule writes a result under the settings in force, with every digit kept and none rounded, so 1234.50 becomes 1.23450E+3. An operand whose last digit stands at the units is written without an exponent however wide it is. It keeps the text as written for the operands of +, - and the comparisons.

numeric digits 3
signal on lostdigits name a
say 0 / 1.234
a: say condition('d')
z = '1.234E3'
signal on lostdigits name b
say -z
b: say condition('d')
signal on lostdigits name c
say z * 1
c: say condition('d')
signal on lostdigits name d
say 1 * '1234.5'
d: say condition('d')

[num.arithmetic.deviation.102]

When LOSTDIGITS is trapped, an operand that is wider than NUMERIC DIGITS raises it before the operator checks a zero divisor or an exponent that is not a whole number. ooRexx checks the right operand first and raises SYNTAX 42.3 or SYNTAX 26.8 instead.
