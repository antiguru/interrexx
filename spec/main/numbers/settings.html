The interrexx Language Specification

Numeric settings

ANSI: 8.3.15; rexxref: Numbers and Arithmetic > Arithmetic > Precision

Three settings steer every numeric operation: NUMERIC DIGITS, NUMERIC FUZZ and NUMERIC FORM. They are not arguments of the operations and no number carries them, so the same expression gives different answers under different settings. This page says what each setting controls, how it is checked when a program changes it, and which part of a program a change reaches. The syntax of the NUMERIC instruction that changes a setting belongs to the instructions chapter, and the examples here use it only in its plain form, numeric digits expression and its two siblings.

What the settings control

[num.settings.effect]

NUMERIC DIGITS is the count of significant digits that arithmetic and numeric comparison keep, and it is also read by the builtins that round their numbers. NUMERIC FUZZ is the count of those digits that a numeric comparison ignores, so it acts only on comparison: every numeric comparison, the end test of a DO loop included, and the comparisons of the builtins that pick a number. NUMERIC FORM decides only how an exponent is written in a result that needs one, as the notation rule says. Each setting has a default that a program starts with: 9, 0 and SCIENTIFIC, unless a directive of the package gives another value. The builtins DIGITS, FUZZ and FORM answer the setting in force where they are called.

say digits() fuzz() form()
say (1 / 3) (12345678 * 1000) (1.0004 = 1) (1.006 = 1)
numeric digits 4
numeric fuzz 1
numeric form engineering
say digits() fuzz() form()
say (1 / 3) (12345678 * 1000) (1.0004 = 1) (1.006 = 1)
say (1.0004 + 1) (1.0004 - 1)
numeric digits 3
do i = 100 to 103.5
  last = i
end
say last

[num.settings.written]

A setting acts when an operation runs and never afterwards. A string that an operation answered keeps the digits and the notation it was written with, and a later change of a setting leaves it as it is, even though a later operation that uses it works under the new setting. This is the rule that a number is a string applied to settings.

numeric digits 3
x = 1 / 3
y = 12345 + 0
numeric digits 9
say x y (x + 0) (x * 3) (x * 3.0) (y + 0)
numeric digits 3
numeric form engineering
say x y (y + 0) (y * 1)

0.333 1.23E+4 0.333 0.999 0.9990 12300
0.333 1.23E+4 12.3E+3 12.3E+3

Changing a setting

[num.settings.digits]

The value that NUMERIC DIGITS sets must be a whole number of at least 1 and of at most as many digits as the setting in force, after it is rounded to that many digits as value + 0 would round it. Any other value raises SYNTAX 26.5, a value that is not a number, a fraction, zero and a negative number among them, and the setting stays as it was. The check is made under the old setting, so a setting of 2 cannot be changed to a value of 100, while a setting of 3 can be changed to 999. Writing no value returns the setting to its default. The new setting must stay above NUMERIC FUZZ, or the instruction raises SYNTAX 33.1 as the fuzz rule says.

numeric digits 20
say digits()
numeric digits 1e1 + 5
say digits()
numeric digits 3
numeric digits 999.4
say digits()
numeric digits 2
numeric digits 99
say digits()
numeric digits 2
signal on syntax name a
numeric digits 100
a: say condition('o')~code digits()
signal on syntax name b
numeric digits 0
b: say condition('o')~code digits()
signal on syntax name c
numeric digits 2.5
c: say condition('o')~code digits()
signal on syntax name d
numeric digits 'x'
d: say condition('o')~code digits()
signal on syntax name e
numeric digits -3
e: say condition('o')~code digits()

[num.settings.fuzz]

The value that NUMERIC FUZZ sets must be a whole number of at least 0 and of at most as many digits as NUMERIC DIGITS, after it is rounded to that many digits. Any other value raises SYNTAX 26.6, and so does a value that is not a number, and the setting stays as it was. A value that is not below NUMERIC DIGITS raises SYNTAX 33.1, and so does a return of NUMERIC DIGITS to its default when that default is not above the fuzz. NUMERIC FUZZ with no value returns the setting to its default.

numeric digits 20
numeric fuzz 15
signal on syntax name a
numeric digits
a: say condition('o')~code digits() fuzz()
signal on syntax name b
numeric fuzz 2.5

Where a setting reaches

[num.settings.block]

A setting belongs to the routine that is running and not to a block of it. A NUMERIC instruction in the body of a DO loop, an IF or a SELECT changes the setting for the rest of the routine, including the clauses after the block, and a trapped condition that transfers control to a label of the same routine finds the setting as it was. A condition raised inside an internal routine whose trap names a label of the calling routine runs that label with the settings of the routine where the condition was raised, as the last lines of the example show.

numeric digits 4
numeric fuzz 1
do 2
  numeric digits 5
end
if 1 then numeric fuzz 2
select
  when 1 then numeric form engineering
  otherwise nop
end
say digits() fuzz() form()
signal on syntax name h
x = 'a' + 1
h: say condition('o')~code digits() fuzz() form()
signal on syntax name k
call inner
k: say condition('o')~code digits() fuzz() form()
exit
inner: procedure
  numeric digits 3
  numeric fuzz 0
  numeric form scientific
  x = 'a' + 1
  return

5 2 ENGINEERING
41.1 5 2 ENGINEERING
41.1 3 0 SCIENTIFIC
[num.settings.call]

The scope rules of DIGITS, FUZZ and FORM say which routines start from the caller's settings and which from the defaults of their package. An internal routine changes only its own settings, and the caller has its own again when the routine returns, whether the routine is written with PROCEDURE or not. The value that the routine returns is a string like any other, written under the routine's settings, and the caller finds it as it was written.

numeric digits 4
numeric fuzz 1
numeric form engineering
call inner
say digits() fuzz() form()
say outer() digits() (1 / 3)
numeric digits 9
say passed(1 / 3)
exit
inner: procedure
  numeric digits 12
  numeric fuzz 0
  numeric form scientific
  say digits() fuzz() form() (1 / 3)
  return
outer:
  numeric digits 3
  return 1 / 3
passed: procedure
  return arg(1) digits() (arg(1) + 0)

4 1 ENGINEERING
