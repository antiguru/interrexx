The interrexx Language Specification

Search

rexxref: Functions > Search Order; Functions > Search Order > Locating External Rexx Files; Directives > ::REQUIRES

A program names code that lives outside it in four ways: a call of a routine that the program does not define, a ::REQUIRES directive, a program name on the command line, and a library name. This page specifies how each is found: the places that are searched and their order, the extensions that are added to a name, how the case of a name matters, what a repeated search finds again, and what a program called by name leaves behind in the program that called it.

The page states the behavior of a Linux host. The names of the places depend on the host: / separates the parts of a path, : separates the entries of REXX_PATH and PATH, and a file name is case sensitive.

Note. The test harness runs each example from one working directory. interrexx runs it without a program file. ooRexx runs it as a file with the extension .rex in that directory. So no example depends on the directory or the extension of its own program: where one matters, the example writes a calling file of its own. An example that needs a directory builds one, and uses names that no host has. The examples set REXX_PATH and PATH with VALUE, change the current directory with DIRECTORY, and put them back. The rules about the rexx command are tested by the recorded runs of the command in rust/crates/interrexx/tests/rexx_command/cases, which run interrexx and ooRexx on the same words from a directory of known programs and compare what they write and their status; each such rule is cited there.

Which names are searched

[env.search.kinds]

These situations search for what a name stands for, and newFile takes a file without a search. A call of a routine that nothing in the program, no required package and no built-in function answers to searches for a file, a registered function and a macro, in the order of the order rule. A ::REQUIRES directive without LIBRARY, and the methods new and loadPackage of Package when they are given only a name, search for a file of Rexx code as the required-file rule says. findProgram of Package searches for a file in the way of a routine call (its rule). The command rexx searches for the program it is told to run, as the program rule says. newFile of Method and of Routine takes the file as it is named and searches for nothing (its rule). A library name is searched as the library rule says. A search that finds nothing is the error of the situation: SYNTAX 43.1 for a call (the name is shown in upper case when it was written as a symbol, as CALL says), 43.901 for a ::REQUIRES and for new and loadPackage (the file rule), and 3.901 for the command (its rule).

call try 'call a3zqkindsx'
call try 'r = a3zqkindsx()'
call try 'r = .package~new("a3zqkindsx")'
call try 'r = .package~new("a3zqk1", .array~of("::requires ""a3zqkindsx"""))'
call try 'r = .package~new("a3zqk2", "nop")~loadPackage("a3zqkindsx")'
call try 'r = .routine~newFile("a3zqkindsx")'
say .package~new('a3zqk3', 'nop')~findProgram('a3zqkindsx')~isNil
say .package~new('a3zqk4', 'nop')~loadLibrary('a3zqkindsx')
exit
try: signal on syntax name e
  interpret arg(1)
  say arg(1) '=> ok'
  return
e: say arg(1) '=>' condition('o')~code
  return

The places

[env.search.places]

A name that is not a path, as the next rule says, is looked for in these places, in this order: the directory of the file that holds the code that makes the call; the current directory; each directory that the environment variable REXX_PATH lists, in its order; and each directory that PATH lists, in its order. The directory of a caller is skipped when the caller has no file: the code of a package made from source text and the string that rexx -e runs have none, and the command rexx has no caller at all. The code of a routine of a file has the directory of that file, wherever it is called from, so a routine that a required package supplies looks first beside the package's own file; the caller rule gives an example. REXX_PATH and PATH are read at the time of each search, and list their directories separated by colons; a directory that does not exist or has no such file adds nothing, a directory that is not absolute is read from the current directory, and a variable that is not set lists none. In the example, the files of the same name stand in the places one after another, and each call finds the first place that has a file; the last lines make the entries of REXX_PATH relative to the current directory.

d = directory()
do n over .array~of('a3zqpl', 'a3zqpl/rp1', 'a3zqpl/rp2', 'a3zqpl/pp')
  call sysmkdir n
end
oldrp = value('REXX_PATH', d'/a3zqpl/nonesuch:'d'/a3zqpl/rp1:'d'/a3zqpl/rp2', -
  'ENVIRONMENT')
oldp = value('PATH', , 'ENVIRONMENT')
call value 'PATH', d'/a3zqpl/pp:'oldp, 'ENVIRONMENT'
call show 'none'
call put 'a3zqpl/pp/a3zqwhere.rex', 'PATH'
call show 'PATH'
call put 'a3zqpl/rp2/a3zqwhere.rex', 'REXX_PATH second'
call show 'REXX_PATH 2'
call put 'a3zqpl/rp1/a3zqwhere.rex', 'REXX_PATH first'
call show 'REXX_PATH 1'
call put 'a3zqwhere.rex', 'current directory'
call show 'current'
call sysfiledelete 'a3zqwhere.rex'
call directory 'a3zqpl'
call value 'REXX_PATH', 'rp2:rp1', 'ENVIRONMENT'
call show 'relative'
call directory d
call value 'REXX_PATH', oldrp, 'ENVIRONMENT'
call value 'PATH', oldp, 'ENVIRONMENT'
do n over .array~of('pp', 'rp1', 'rp2')
  call sysfiledelete 'a3zqpl/'n'/a3zqwhere.rex'
  call sysrmdir 'a3zqpl/'n
end
call sysrmdir 'a3zqpl'
exit
put: call sysfiledelete arg(1)
  call lineout arg(1), 'return "'arg(2)'"'
  call lineout arg(1)
  return
show: signal on syntax name e
  call a3zqwhere
  say arg(1)':' result
  return
e: say arg(1)':' condition('o')~code
  return

Names that are paths

[env.search.names]

A name that begins with a slash is an absolute path, and is looked for there and nowhere else. A name that begins with ./ or ../ is a path from the current directory, and is looked for there and nowhere else: neither the directory of the caller nor REXX_PATH nor PATH is tried for it. Any other name, one with slashes inside it such as sub/name included, is joined to each place of the places rule in turn. The extensions and the case of the following rules apply to the name of every kind.

d = directory()
call sysmkdir 'a3zqnm'
call sysmkdir 'a3zqnm/rp'
call sysmkdir 'a3zqnm/rp/sub'
call put 'a3zqnm/rp/a3zqplain.rex', 'plain'
call put 'a3zqnm/rp/sub/a3zqdeep.rex', 'deep'
oldrp = value('REXX_PATH', d'/a3zqnm/rp', 'ENVIRONMENT')
call show 'plain', 'a3zqplain'
call show 'dot', './a3zqplain'
call show 'absolute', d'/a3zqnm/rp/a3zqplain'
call show 'sub', 'sub/a3zqdeep'
call show 'dot sub', './sub/a3zqdeep'
call directory 'a3zqnm/rp/sub'
call show 'dotdot', '../a3zqplain'
call show 'dotdot sub', '../sub/a3zqdeep'
call directory d
call value 'REXX_PATH', oldrp, 'ENVIRONMENT'
call sysfiledelete 'a3zqnm/rp/sub/a3zqdeep.rex'
call sysfiledelete 'a3zqnm/rp/a3zqplain.rex'
call sysrmdir 'a3zqnm/rp/sub'
call sysrmdir 'a3zqnm/rp'
call sysrmdir 'a3zqnm'
exit
put: call sysfiledelete arg(1)
  call lineout arg(1), 'return "'arg(2)'"'
  call lineout arg(1)
  return
show: signal on syntax name e
  call (arg(2))
  say arg(1)':' result
  return
e: say arg(1)':' condition('o')~code
  return

Extensions

[env.search.extension]

A name that has a period in its last part, the part after the last slash, names a file, and no extension is added to it. Any other name is tried with each of these endings in turn, and the first ending for which a file is found in some place ends the search: the endings come before the places, so that a file that has an earlier ending in a later place is found before a file that has a later one in an earlier place. The endings are, in order: .cls, only for the required-file search; the extension of the file that holds the calling code, from the last period of the last part of the file's name, when that part has one; .REX; .rex; and no ending at all. A call, findProgram and the command rexx leave the .cls out, and the command has no calling file. In the example, a file a3zqxc.xyz calls a routine, and the files of that name are taken away one by one: the routine is found with the ending xyz, then REX, then rex, then with none. The file with the ending .cls stays to the end and is never found by the call. A second caller, a3zqxd, has no extension, and so has no ending of its own to add: it finds .REX first, and the file that has the extension xyz is not tried for it. A name with a period, a3zqpd.x, finds the file of that name and not a3zqpd.x.REX or a3zqpd.x.rex, and finds nothing when that file is gone.

call put 'a3zqex.cls', 'cls'
call put 'a3zqex.xyz', 'xyz'
call put 'a3zqex.REX', 'REX'
call put 'a3zqex.rex', 'rex'
call put 'a3zqex', 'none'
call lineout 'a3zqxc.xyz', 'return a3zqex()'
call lineout 'a3zqxc.xyz'
call lineout 'a3zqxd', 'return a3zqex()'
call lineout 'a3zqxd'
say 'with extension:' a3zqxc.xyz()
say 'without:' a3zqxd()
call sysfiledelete 'a3zqex.xyz'
say 'with extension:' a3zqxc.xyz()
say 'without:' a3zqxd()
call sysfiledelete 'a3zqex.REX'
say 'with extension:' a3zqxc.xyz()
call sysfiledelete 'a3zqex.rex'
say 'with extension:' a3zqxc.xyz()
call sysfiledelete 'a3zqex'
signal on syntax name e
say 'with extension:' a3zqxc.xyz()
e: say condition('o')~code
call put 'a3zqpd.x', 'as named'
call put 'a3zqpd.x.REX', 'with REX'
call put 'a3zqpd.x.rex', 'with rex'
say 'period:' 'a3zqpd.x'()
call sysfiledelete 'a3zqpd.x'
signal on syntax name e2
say 'period:' 'a3zqpd.x'()
e2: say 'period:' condition('o')~code
call sysfiledelete 'a3zqpd.x.REX'
call sysfiledelete 'a3zqpd.x.rex'
call sysfiledelete 'a3zqex.cls'
call sysfiledelete 'a3zqxc.xyz'
call sysfiledelete 'a3zqxd'
exit

  call lineout arg(1), 'return "'arg(2)'"'

  return

Case

[env.search.case]

A file name is tried in two forms, the name as it was written and the whole name in lower case, directories included; the extension that is added is never changed. The two forms come after the extensions and before the places, so that for each ending the written form is tried in every place before the lower-case form is tried in the first. A call written as a symbol is written in upper case (the call rule), and so finds a file of the name in lower case. A name that is spelled in neither form as the file is, a3zqmixed for a file A3zqMixed.rex or a3zqUp/A3zqIn for a file a3zqUp/a3zqin.rex, finds nothing. In the example, a caller that has no extension of its own, so that it adds no ending of its own, calls the names. A3ZQCS finds the file of its lower-case form and A3zqMixed the file of its own spelling. A3zqOrd finds the file a3zqord.REX, because the ending .REX is tried before .rex, although the file A3zqOrd.rex is of the written form. A directory is lower-cased with the name. For A3ZQCR the written form is found in REXX_PATH although the lower-case form is in the current directory, and for A3ZQCW the written form in the current directory is found before the lower-case form in REXX_PATH.

d = directory()
call sysmkdir 'a3zqsd'
call sysmkdir 'a3zqUp'
call sysmkdir 'a3zqcr'
call put 'a3zqcs.rex', 'lower'
call put 'A3zqMixed.rex', 'mixed'
call put 'a3zqord.REX', 'lower REX'
call put 'A3zqOrd.rex', 'mixed rex'
call put 'a3zqsd/a3zqinsd.rex', 'in the lower directory'
call put 'a3zqUp/a3zqin.rex', 'in a mixed directory'
call put 'a3zqcr/A3ZQCR.rex', 'upper in REXX_PATH'
call put 'a3zqcr.rex', 'unused'
call put 'a3zqcr/a3zqcw.rex', 'lower in REXX_PATH'
call put 'A3ZQCW.rex', 'upper in the current directory'
call lineout 'a3zqcl', 'parse arg n'
call lineout 'a3zqcl', 'signal on syntax name e'
call lineout 'a3zqcl', 'call (n)'
call lineout 'a3zqcl', 'return result'
call lineout 'a3zqcl', 'e: return condition("o")~code'
call lineout 'a3zqcl'
old = value('REXX_PATH', d'/a3zqcr', 'ENVIRONMENT')
say a3zqcl('A3ZQCS')
say a3zqcl('A3zqMixed')
say a3zqcl('a3zqmixed')
say a3zqcl('A3zqOrd')
say a3zqcl('A3ZQSD/A3ZQINSD')
say a3zqcl('a3zqUp/A3zqIn')
say a3zqcl('A3ZQCR')

call value 'REXX_PATH', old, 'ENVIRONMENT'
do f over .array~of('a3zqcs.rex', 'A3zqMixed.rex', 'a3zqord.REX', -
    'A3zqOrd.rex', 'a3zqsd/a3zqinsd.rex', 'a3zqUp/a3zqin.rex', -

  call sysfiledelete f

call sysrmdir 'a3zqUp'
call sysrmdir 'a3zqcr'
exit

The directory of the caller

[env.search.caller]

The directory that comes first in the places belongs to the file that holds the code of the call, and not to the program that started the run or to the code that called that file. A file that was found in a place and called as a routine looks first beside itself, a file that it calls looks beside that file in turn, and a directory in a name such as sub/name is joined to the directory of the file that makes the call. In the example, the file a3zqcdm.rex stands in a directory that is not the current directory, and finds a file beside itself that the current directory lacks. A file a3zqtwo.rex stands both beside it and in the current directory, and it finds the one beside it, while the program of the example finds the other. The file a3zqcdm.rex calls a file in a directory below its own, and that file finds the files of its own directory and not the files beside its caller. The program of the example, which stands in the current directory, does not find the file of a3zqsib.

call sysmkdir 'a3zqcd'
call sysmkdir 'a3zqcd/a3zqsub'
call put 'a3zqcd/a3zqsib.rex', 'beside the caller'
call put 'a3zqcd/a3zqtwo.rex', 'the directory of the caller'
call put 'a3zqtwo.rex', 'the current directory'
call put 'a3zqcd/a3zqsub/a3zqunder.rex', 'beside the callee'
f = 'a3zqcd/a3zqcdm.rex'
call sysfiledelete f
call lineout f, 'return a3zqsib() "/" a3zqtwo() "/" "a3zqsub/a3zqdown"()'
call lineout f
f = 'a3zqcd/a3zqsub/a3zqdown.rex'
call sysfiledelete f
call lineout f, 'return a3zqunder() "/" safe("a3zqsib")'
call lineout f, '::routine safe'
call lineout f, '  signal on syntax name e'
call lineout f, '  call (arg(1))'
call lineout f, '  return result'
call lineout f, 'e: return condition("o")~code'
call lineout f
say 'a3zqcd/a3zqcdm.rex'()
say a3zqtwo()
signal on syntax name e
