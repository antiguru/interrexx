The interrexx Language Specification

Command environments

rexxref: General Concepts > Commands to External Environments > Environment; Useful Services > The RXQUEUE Filter

Deviations: D11, D93, D146, D147, D148, D149

A command that a program sends goes to an environment, which runs it and answers with a return code. The commands page specifies what is sent and how RC and .RS are set, the ADDRESS instruction chooses the environment and redirects its streams, and the conditions chapter specifies ERROR and FAILURE. This page specifies the environments that the interpreter has on Linux and what they do with a command: which program runs it and with what, the return codes they answer, what the command starts with, the commands that the interpreter does itself, and the rxqueue filter through which a command puts lines on the program's queue. CommandHandler and NativeCommandHandler are the classes of the environments, and a handler written in Rexx gets CommandContext, CommandInput and CommandOutput objects for a command that it runs.

The examples start commands that every Linux host has: the shell's own commands, echo, printf, cat and cd. An example that changes the current directory, HOME, PATH or the queue puts it back.

The environments

[env.commands.names]

A program has eleven command environments, which CommandHandler~environments lists under these names: SYSTEM, COMMAND, SH, BASH, BSH, KSH, CSH, TCSH, ZSH, PATH and the null string. They are all NativeCommandHandler objects. The case of a name plays no part (the setting rule). A command sent to any other name raises FAILURE with the return code 30 (the status rule), and sets nothing that its redirections name.

do n over .commandhandler~environments~allIndexes~sort
  say '['n']' .commandhandler~handler(n)~kind
end

'echo not run'

Running a command

[env.commands.shell]

The environments SYSTEM, COMMAND, SH and the null string run a command with the program /bin/sh, given the two arguments -c and the command string, so that the string is one argument and the shell reads it. BASH does the same with /bin/bash, and BSH, KSH, CSH, TCSH and ZSH with the program of that name in /bin, in lower case. The interpreter waits for the shell to end and answers its exit status as the return code (the return code rule). A shell that the host does not have cannot be run, and the command raises FAILURE with the return code 127 (the failure rule).

do n over .array~of('system', 'command', 'sh', '')
  address value n
  'echo "$0"'
end

[env.commands.shell.string]

What the shell does with the string is the shell's business, not the interpreter's: it reads blanks, quotes, ;, |, &&, variables, $(( )), redirections and a line feed that separates two commands as it does in a script, and the return code is that of the last command it ran. The variables of the Rexx program are not variables of the shell, which sees only the environment variables. The string is not changed, and a string that holds nothing but blanks runs nothing and answers 0. Which characters the string may hold beyond those that a string argument of a program can hold is the host's business, except that a NUL is not run.

address system
x = 'rexx'
'echo "a   b" | cat; x=shell; echo $x $((6 * 7)); printf "[%s]" 1 2 3; echo'
'echo l1' || '0a'x || 'echo l2'
'echo ${x:-unset}'
'   '
say 'blank' rc

[env.commands.deviation.146]

A command string that holds a NUL character is not run in any native environment: the command raises FAILURE with the return code 127, and nothing of the string runs. This is Deviation 146: ooRexx cuts the string at the NUL and runs the part before it, so that there the shell gets only echo ran; echo "a from the first command of the example, refuses it as a syntax error and answers 2 (ERROR, nothing printed), and the second command runs printf ran.

f: say condition('c') rc

[env.commands.path]

The environment PATH runs no shell. It cuts the command string into words as the words rule says, looks for the program named by the first word and runs it with the other words as its arguments. A first word that holds a slash names the program itself; any other is searched for in the directories of the environment variable PATH, as the variable stands when the command is sent, so that a change by VALUE is seen. An empty entry of PATH, and a PATH that is the null string, stand for the current directory. When PATH has no value, the host's default list of system directories is searched, which does not hold the current directory. A file that cannot be run, or a directory, is passed over and the search goes on. A string with no word, a program that is not found, and a program named with a slash that cannot be run raise FAILURE with the return code 127. The interpreter answers the exit status of the program as the return code, the same way as for a shell.

e = 'ENVIRONMENT'
address path
'echo one two'
say rc

'echo not found'

say rc
call value 'PATH', old, e

say rc

'   '

[env.commands.path.words]

The words of a command for PATH are separated by blanks and tabs, and any number of them separate two words. A word that begins with a double quote ends at the first double quote that is followed by a blank, a tab or the end of the string, and the two quotes are not part of it; it may hold blanks, any other double quote, and line feeds. A word of this kind that is never closed ends with the string. Every other character belongs to a word as it is, a single quote, a backslash, a dollar sign, a tilde, a star, ;, |, > and a line feed among them, so that nothing is expanded and no redirection or pipe exists. A double quote inside a word that does not begin with one is an ordinary character.

The return code

[env.commands.rc]

The return code of a command that a shell or a program ran to its end is its exit status, a whole number from 0 to 255: an exit with another number gives the number modulo 256. It is set in RC as the return code rule says, and a nonzero one raises ERROR, 127 raising FAILURE. A shell answers the status of the command it ran last, so a command that the shell could not find is the 127 of the shell, and which codes other than 127 a shell uses for a command that it cannot run is the shell's business.

address system
do c over .array~of('exit 0', 'exit 7', 'exit 255', 'exit 256', 'exit 300',,
    'true', 'false', 'test -d /a4zq_none', '(exit 4)', 'a4zq_none_cmd')
  c
  say c '->' rc .rs
end

[env.commands.rc.signal]

A shell or a program that a signal ended has no exit status, and its return code is the number of the signal with a minus sign, -9 for the signal KILL, -15 for TERM and -1 for HUP. The command raises ERROR, and .RS is 1. A shell that runs a program which a signal ended answers the status 128 plus the signal number for it, as a shell does, and that is an exit status. This is the same for all environments.

What a command starts with

[env.commands.start]

A command starts in the current directory of the program as DIRECTORY leaves it, with the environment variables of the program as VALUE leaves them, and with the standard input, output and error of the program, unless a redirection of the ADDRESS instruction replaces them. What the command itself changes, its current directory, its variables and what it exports, ends with it and is not seen by the program: the commands that the interpreter does itself are the exception.

[env.commands.deviation.148]

A command has the standard input, output and error of the program as its descriptors 0, 1 and 2. No descriptor that the interpreter opens for its own work is open in it. One that the interpreter was started with is passed on as the host passes it, so that the example, whose second interpreter is started with none, lists only these three and the 3 that ls opens to list them. Commands the interpreter does itself

[env.commands.inprocess]

A command that the shell would run in a process of its own, and whose effect would end with that process, is run by the interpreter in the program instead, so that its effect is the program's. These are the commands cd, export, set and unset, in lower case, when all of the following hold. The string begins with the word, directly followed by a blank and an argument, or, for cd, by nothing or by blanks only. It has none of the characters ;, &, |, < and >. It is sent as a command clause or by an ADDRESS instruction with a command to a native environment, any of those that the first rule names, PATH included. Which shell that environment runs, and whether the host has that shell, plays no part. The environment may also be reached under another name it was registered with, or by a handler that forwards the command with command. No WITH applies to it: its clause has none, and no earlier ADDRESS instruction with WITH and no command has given the environment one, even one that names only NORMAL. Any other string is run as the environment runs every command, by a shell or, for PATH, as a program that is searched for, in a process whose effect on the program ends with it, so that a leading blank, a tab for the blank, a capital letter, or a ; sends the string that way. A command that the interpreter does itself writes nothing, and its return code is set as the rules of the four commands say.

[env.commands.cd]

cd makes the directory its argument names the current directory of the program, as DIRECTORY does, and answers 0. The argument is the rest of the string after the blanks that follow cd; with no argument the directory is the value of the environment variable HOME, read as any other argument is: unlike DIRECTORY with ~, a value that does not start with a slash is taken from the current directory. When the argument as written begins with ~, the tilde is read before anything else. A ~ alone, or followed by a slash or a blank, stands for the value of HOME, which is then read as the rest of the argument is, its double quotes and backslashes dropped, but not read again for a ~. After a slash the rest of the argument follows as usual; after a blank the rest is not read. A ~ followed by a name, which runs to the first slash or to the end of the argument, stands for the home directory of the user of that name in the host's user database. When there is no such user, the command is not done by the interpreter: the string goes to the shell, as any other string does. A ~ that is not the first character of the argument as written, and one that a quote or backslash comes before, is an ordinary character. In the rest of the argument every double quote is dropped, even one that nothing closes, and so is a backslash, the character after it being kept. Nothing else is read: a blank at the end is part of the name, as is a -, a single quote, a dollar sign or a star. A name that does not start with a slash is taken from the current directory. When HOME is the null string, cd with no argument fails as below, and a ~ that stands for HOME stands for nothing, so that cd ~ and cd ~/ make / current and cd ~/x makes /x current. When the directory cannot be made current, the command answers the number that the host gives the error, as Linux numbers them: 2 when there is no such directory, 20 when a part of the name is not a directory, 13 when permission is refused. It raises ERROR as every nonzero return code does, and leaves the current directory as it was.

[env.commands.export]

export and set, given an argument, set an environment variable of the program, as VALUE does (the variables rule), and answer 0. The name is the text from the blanks that follow the word to the first =, and the value is all that follows that =, to the end of the string, blanks and quotes included. A string without = sets nothing, and neither does one whose name is empty, export =3 for one, which answers 0 (the deviation rule). Within the value each $ starts a reference: the characters after it up to the next /, : or $, or the end of the string, are the name of an environment variable, and the reference is replaced by the value of that variable, or by nothing when there is none; the character that ended the name stays. Neither the name nor the reference follows the rules of the shell, so that ${NAME} is a reference to a variable whose name has braces in it. A ~ in the value is an ordinary character. export and set with no argument are run by the shell.

The queue and the filter

[env.commands.rxqueue.filter]

rxqueue is a program of the interpreter's installation that a command finds by its name, as it finds any program. It reads its standard input and puts the lines on a queue of the program that ran the command, which makes it the way for a command to hand lines to the program: a command whose output is piped into rxqueue leaves its lines in the queue when it ends. That queue is the program's SESSION queue, the one that PUSH, QUEUE, QUEUED and PULL work on until RXQUEUE sets another (the get rule), and the lines are put on it as the rules of its options say. A line of the input ends at a line feed, or at a carriage return followed by a line feed; a carriage return that no line feed follows also ends a line, and the character after it begins the next line and belongs to it whatever it is, so that a second carriage return directly after the first is text of the next line, not the end of an empty one; text after the last line end is a line, an empty line is a line, and input with no character puts none. The text is not changed, so that case, blanks, tabs and control characters stay as they are; only PULL changes the case, as its rule says. A line is cut after its first 65472 characters, and the rest of it up to its end is lost. The filter ends with the status 0 when it did its work, and the status of a pipeline that ends in it is its status, as for any pipeline of a shell. The other statuses are in the rules below. The text that it writes when it fails goes to its standard output, and this book does not specify it.

[env.commands.rxqueue.options]

rxqueue takes at most one option and at most one queue name, in either order. An option is / or - directly followed by FIFO, LIFO or CLEAR, in any letter case, and is the whole word; an abbreviation is not an option. The option /FIFO, which is the default, puts each line at the end of the queue, so that the lines come out in the order of the input after what the queue held. /LIFO puts each line at the front as it is read, so that the lines come out in the reverse order of the input and before what the queue held. /CLEAR removes every line of the queue, reads no input and puts nothing on the queue. A word that begins with / or - and is not one of these options, a second option, and a second name are errors in the call: rxqueue writes a usage text, puts nothing on the queue and answers the status 0.

[env.commands.rxqueue.name]

The queue that rxqueue works on is the queue that its name word names, and the name need not be written in the case that the queue was created with (the case rule). [env.commands.rxqueue.session]

A program starts with the environment variable RXQUEUESESSION set, before its first clause, to 0x followed by lower-case hexadecimal digits. The value names the program's SESSION queue for rxqueue and for a Rexx program that a command starts. A command inherits it with the other variables, as the start rule says, and that is how the filter and a child program reach the queue. The interpreter sets it once, at the start.
