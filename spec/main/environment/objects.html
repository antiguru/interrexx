Environment objects

Deviations: D144

A program reaches the objects that the language provides through environment symbols: a period followed by a name, such as .output, .true or .array. The value of such a symbol is found by a lookup that this page specifies: first which objects exist and what they are, then the places the lookup goes through and their order, and last what a program may change. The lookup that reads the symbol is the environment rule of the lexical chapter; the order in which it consults the places is the rule of this page.

Two directories hold most of the objects. .environment holds the objects that the whole program can reach, and .local the ones that belong to one interpreter instance, such as the standard streams. A program adds its own objects to them as it adds entries to any other Directory.

Note. Each interpreter instance has its own .environment (Deviation 85). A program that rexx runs has one instance, and so has every example in this book.

The directories

[env.objects.directories]

.environment and .local are each a Directory, the same object every time the symbol is read. .environment holds an entry ENVIRONMENT for itself and an entry LOCAL for .local, so that the symbols .environment and .local are found in .environment like every other. .local holds neither of those entries. An entry is read with the methods of Directory, by its name in upper case, and the entries of this page are the ones that exist before the program changes anything.

say .environment~class~id .local~class~id (.environment == .environment),
    (.local == .local)
say (.environment~at('ENVIRONMENT') == .environment)
say (.environment~at('LOCAL') == .local)
say .local~hasIndex('LOCAL') .local~hasIndex('ENVIRONMENT')

What .environment holds

[env.objects.entries]

.environment holds the class objects of the classes chapter, each under its class name in upper case, with three differences: RegularExpression is not among them, because it belongs to a package that a program requires; the class RexxInfo is not, because its name is the index of the one RexxInfo object; and ArgUtil is (the rule on it). The entries that are not classes are NIL, TRUE, FALSE, ENDOFLINE, REXXINFO, LOCAL and ENVIRONMENT, and there are no others. .true is the string 1, .false the string 0, and .endofline the string of the one character '0A'x, the line end of the platform. .nil is the object that stands for the absence of an object (isNil answers 1 for it). .rexxinfo is the one RexxInfo object (its rule). The example prints the class entries in rows, after checking that the upper case id of each is its index, and then the entries that are none.

others = .array~new
row = ''
do i over .environment~allIndexes~sort
  o = .environment~at(i)
  if \o~isA(.class) then others~append(i)
  else do
    if o~id~upper \== i then say 'id differs:' i
    if length(row i) > 78 then do
      say row~strip
      row = ''
    end
    row = row i
  end
end
say row~strip
say others~makeString('l', ' ')

What .local holds

[env.objects.local]

.local holds, when a program starts, the five monitors INPUT, OUTPUT, ERROR, TRACEOUTPUT and DEBUGINPUT, each a Monitor; the three streams STDIN, STDOUT and STDERR, each a Stream; STDQUE, a RexxQueue; and SYSCARGS, an Array. The symbols .input, .output, .error, .traceoutput, .debuginput, .stdin, .stdout, .stderr, .stdque and .syscargs are found there. .syscargs is the array of the command line arguments that follow the program name; a program started without any has none, as the example shows, and the syscargs rule says how a command line becomes those arguments.

do i over .local~allIndexes~sort
  say i~left(12) .local~at(i)~class~id

[env.objects.bindings]

The monitors start out connected to each other and to the streams: the current destination of .output is .stdout, that of .error is .stderr, that of .input is .stdin, that of .traceoutput is the monitor .error and that of .debuginput is the monitor .input, each the same object and not a copy (the rule on current). A message that a monitor has no method for goes to its current destination (the forwarding rule), so a destination that a program sets on .error is also where the trace lines go, as the trace rule says for .traceoutput. .stdque is the RexxQueue of the queue SESSION.

say (.output~current == .stdout) (.error~current == .stderr),
    (.input~current == .stdin) (.traceoutput~current == .error),
    (.debuginput~current == .input)

The order of the lookup

[env.objects.search]

A program that reads the environment symbol .name gets the first object that the following places answer to the name, taken in upper case, and the symbol's own text when none does (the last rule of this section). The places, in order, are: the three fixed symbols .nil, .true and .false; the classes that the code can see, beginning with those its own package declares; the local directory of the package that holds the code; .local; .environment; and the symbols .line, .context, .methods, .routines, .resources and .rs, which the interpreter answers for the code that reads them. The rules that follow state each step. In the example, .zqa is found as a class, .zqb in .local although .environment has it too, .zqc in .environment, and .zqd nowhere.

.local~zqa = 'in local'
.environment~zqa = 'in environment'
.local~zqb = 'in local'
.environment~zqb = 'in environment'
.environment~zqc = 'in environment'
say .zqa~id '|' .zqb '|' .zqc '|' .zqd
::class zqa

ZQA | in local | in environment | .ZQD
[env.objects.search.fixed]

The symbols .nil, .true and .false always answer the .nil object, the string 1 and the string 0. A program that stores an entry of the same name in .local or .environment, or that declares a class of that name, changes that entry and that class and nothing else: the entry is still there to read with at, and the symbol still answers the fixed object.

.environment~nil = 'N'
.local~true = 'T'
.environment~false = 'F'
say .nil~isNil .true .false
say .environment~nil .local~true .environment~false
say .environment~at('TRUE') .environment~hasIndex('TRUE')

[env.objects.search.classes]

A name is looked up among the classes that the code can see before any directory is: the classes of its package, the public classes of the packages it requires, and the classes of the class library, in the order that the class rule and findClass give. A library class is found whatever .local and .environment hold under its name, and it stays found when the entry is removed from .environment; a class that the package itself declares hides a library class of the same name.

[env.objects.search.symbols]

.line, .context, .methods, .routines, .resources and .rs are looked up last. An entry of one of those names in the local directory of the package, in .local or in .environment, and a class of the name, is the value of the symbol, and the interpreter's own answer is given only when none exists. The interpreter answers .line with the same number as .context~line and .context as the context rule says. The rules for .methods (the floating methods), .routines (the table of routines), .resources (the resource rule) and .rs (the command status) say when each exists; when it does not, the symbol is not found and has its own text. [env.objects.search.name]

The name that is looked up is the characters after the period, in upper case, and the lookup is by that exact index: an entry whose index has a lower case letter is not found by any symbol, because the symbol's name has none. A period inside the name is part of it, so .my.name looks up the index MY.NAME, which is also how .environment~my.name reads it. A name that nothing holds is not an error and does not raise NOVALUE (the rule).

.environment['mixed'] = 'lower index'
.environment['MIXED2'] = 'upper index'
.environment['MY.NAME'] = 'dotted'
say .mixed .Mixed2 .my.name .MY.name

What a program may change

[env.objects.change.entries]

A program may add to .local and .environment an entry of any name and any object, replace an entry, and remove one, with the methods of Directory. The symbol then finds the object, the new one after a replacement and the one below it, or none, after a removal, as the order above says. The entries that the language put there are entries like the others, except where a rule of this page says that a symbol does not read them: the classes of the library, and .nil, .true and .false.

.local~zqx = 'first'
say .zqx
.local~zqx = .array~of(1, 2)
say .zqx~items
.local~remove('ZQX')
say .zqx
.environment~endofline = 'eol'
say .endofline

[env.objects.change.scope]

An entry that a program adds or changes is seen by everything that runs in the same interpreter instance afterwards: by the code of other packages and by the other activities. The local directory of a package is not shared (its rule). In the example, a package that the program makes reads .zqenv and .zqloc and sets .zqfrom, which the main program reads, and the method of a started message reads .zqenv and sets .zqact.

.environment~zqenv = 'env'
.local~zqloc = 'loc'

Where input and output go

Note. The monitors in .local are the one place through which the language reads and writes the standard streams, so a program that gives one a new destination, or that puts another object in its place, changes what other code reads and writes without that code noticing. The rules below state which messages the language sends to each of these objects. The examples use a spy, an object that logs the name of each message it is sent and answers a value of its own.

[env.objects.streams]

A stream builtin whose name denotes the standard output, error or input stream does not use the stream: it sends a message to the OUTPUT, ERROR or INPUT entry of .local, whichever the name denotes, whatever the builtin does. CHAROUT, LINEOUT, CHARIN, LINEIN, CHARS and LINES send the message of their own name with the builtin's arguments after the name, as given, so a call with none sends none; LINES sends its option, and NORMAL when the call gives none. STREAM sends STATE for the option S or none, DESCRIPTION for D, and COMMAND with the command for C. The builtin answers what the object answers, except LINES: unless its option is C, and then it answers what the object answers, it answers 0 when the string value of the answer is a number equal to zero and 1 otherwise, whether that value is a number or not, and whether the answer is a string or another object (Deviation 144). A message that a program sends to .stdout, .stderr or .stdin itself is not redirected. In the example, one spy answers 3 to every message, and the log shows the name of each message with the number of its arguments and the arguments themselves.

s = .spy~new
.output~destination(s)
.error~destination(s)
.input~destination(s)
call lineout
call charout
a = lineout(, 'x', 1)
b = charout('STDOUT', 'y', 2)
c = lines('STDERR')
d = chars('stderr:')
e = linein('STDERR')
f = charin('STDERR')
g = lineout('STDIN', 'z')
h = charout('stdin:', 'w')
i = stream('STDOUT', 'c', 'query exists')
j = stream('STDIN')
k = stream('STDERR', 'd')
.output~destination
.error~destination
.input~destination
say s~log~makeString('l', '0a'x)
say a b c d e f g h i j k

  log = .array~new

::method unknown
  expose log
  use arg name, args

[env.objects.queue]

[env.objects.deviation.144]
