The interrexx Language Specification

::ATTRIBUTE

::ATTRIBUTE name [GET | SET] [CLASS] [PUBLIC | PRIVATE | PACKAGE] [GUARDED | UNGUARDED] [PROTECTED | UNPROTECTED] [ABSTRACT | EXTERNAL spec | DELEGATE var]

rexxref: Directives > ::ATTRIBUTE

::ATTRIBUTE declares the accessor methods of an object variable: a getter that returns the variable and a setter that assigns it, or only one of the two. A directive with no code of its own generates both methods, and a directive with GET or SET takes the code of that one method from its section. The options that set who may send the messages and how they are guarded are the ones of ::METHOD, and this page names them without restating them. What a method object does once it exists, and the methods of Class that add one to a class, belong to the classes chapter.

The generated methods

[dir.attribute.create]

::ATTRIBUTE with no GET and no SET declares two methods of the class that the most recent ::CLASS declared: a method of the attribute's name and a method of that name followed by an equals sign. The first takes no argument and returns the value of the object variable of that name, which is the variable's own name, spelled as the name rule gives it, while it is unset. The second takes exactly one argument and assigns it to the variable; it is what a message assignment obj~name = value sends, and it returns no value, so a message whose result is used raises SYNTAX 91.999. An extra argument raises SYNTAX 93.902 and a missing one 93.903. A clause after the directive is refused as the section rule says. The form of ::METHOD with the keyword ATTRIBUTE declares the same two methods.

o = .box~new
say o~size
o~size = 4
say o~size
say o~peek
call try 'say o~size(1)'
call try 'o~"SIZE="()'
call try 'o~"SIZE="(1, 2)'
call try 'say o~"SIZE="(1)'
src = .array~of('::class k', '::attribute a', 'say 1')
signal on syntax name e
p = .package~new('spec-dir-attribute-create', src)
e: say condition('o')~code
exit
try:
  signal on syntax name e2
  interpret arg(1)
  return
e2: say arg(1) '=>' condition('o')~code
  return

[dir.attribute.name]

The name is a symbol or a string. As the names rule says, a symbol names the variable in upper case and a string names it exactly as written, so the variable of ::attribute "Mixed" is not the one that the symbol mixed names in an EXPOSE, and while it is unset the getter answers Mixed. The messages mixed and mixed= still reach the methods, because the lookup of a method by name ignores case. A name that cannot be the name of a variable, such as a string with a blank or a number, raises SYNTAX 99.925, and a directive whose name is missing or is neither a symbol nor a string raises 19.914. Both are found when the program is read.

o = .box~new
o~"Mixed" = 5
o~lower = 6
say o~mixed o~lower
say o~peek
o2 = .box~new
say o2~mixed
call try '::attribute "a b"'

GET and SET

[dir.attribute.getset]

GET declares only the getter and SET only the setter, so that the two can have different options. GET and SET together raise SYNTAX 25.925. A GET or SET directive without a keyword of the kind group (ABSTRACT, EXTERNAL, DELEGATE) that has a section takes the section as the code of its method, with the directive clause left out, and without a section it declares the generated method. In the code of a setter the argument is the value that name = value assigned, and the variable is reached through EXPOSE as in any method.

o = .box~new
o~size = 3
say o~size o~peek
o~tag = 'abc'
say o~tag
o~note = 7
say o~note
signal on syntax name e
o~count = 1
e: say condition('o')~code

[dir.attribute.options]

The keywords after the name are GET, SET, CLASS, PUBLIC, PRIVATE, PACKAGE, GUARDED, UNGUARDED, PROTECTED, UNPROTECTED, ABSTRACT, EXTERNAL and DELEGATE, in any case and in any order. The groups and the rules about them are those of ::METHOD, except that ATTRIBUTE is not a keyword and GET and SET make a group of their own: a word that is none of the keywords, a keyword repeated or a second keyword of one group raises SYNTAX 25.925. The access, guarding and protection options apply to every method that the directive declares, as access, guarding and protection say for a method. A GET and a SET directive for one name may therefore differ: a public getter and a private setter make an attribute that others read and only the object itself writes.

Class attributes

[dir.attribute.class]

CLASS makes the declared methods class methods, as it does for ::METHOD, and the variable that they reach is an object variable of the class object. An instance does not see the methods, and an attribute of the same name without CLASS reaches a different variable, so a class and its instances can hold a value each under one name. CLASS requires a ::CLASS directive before it, and without one the directive raises SYNTAX 99.905.

.box~count = 3
say .box~count
o = .box~new
say o~count
o~count = 'mine'
say o~count .box~count
call try 'say o~tally'

Names that are taken

[dir.attribute.duplicate]

A class declares one method of a name, and a second declaration of one of the attribute's method names in the same class raises a SYNTAX error when the program is read. The names are the getter's name and the setter's name with the equals sign, so a GET directive and a SET directive of one name do not collide, while two of the same half, or a plain directive and a GET or SET one, do. The code is that of the later directive: 99.931 for an attribute, 99.902 for a ::METHOD and 99.932 for a ::CONSTANT. An attribute with CLASS and one without it are two methods of different kinds, so they do not collide.

[dir.attribute.delegate]

DELEGATE takes the name of an object variable as a symbol, as it does for ::METHOD, and forwards the message of each method that the directive declares to the object that the variable holds. [dir.attribute.external]

EXTERNAL takes the operand that ::METHOD describes and declares the method or methods from a native library. A missing operand, or one that is not a string, raises SYNTAX 19.905, and a string that does not start with the word LIBRARY or has too many words raises 99.917. A library that cannot be loaded raises 98.903, and a library that loads but has no method entry of the given name raises 90.998. Both are raised when the section of the directive ends, so a clause in the section is refused first, as the section rule below says. How they are ordered against the faults of other directives is the subject of the rule for external methods.

call try '::attribute a external'

The section

[dir.attribute.section]

A directive that declares the generated methods takes no code, and any clause after it that is not a null clause raises a SYNTAX error when the program is read. The code is 99.937 after a directive with neither GET nor SET, whatever its kind keyword. After GET or SET it is 99.940 with ABSTRACT, 99.935 with EXTERNAL and 99.947 with DELEGATE. GET or SET with no kind keyword is the form whose section is code, so no clause is refused there. Comments and blank lines between the directive and the next one are null clauses.

call try '::attribute a', 'say 1'
call try '::attribute a abstract', 'say 1'
