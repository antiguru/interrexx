The interrexx Language Specification

::METHOD

::METHOD name [CLASS] [PUBLIC | PRIVATE | PACKAGE] [GUARDED | UNGUARDED] [PROTECTED | UNPROTECTED] [ATTRIBUTE | ABSTRACT | EXTERNAL spec | DELEGATE var]

rexxref: Directives > ::METHOD

Deviations: D105

::METHOD declares a method. Its section, the clauses up to the next directive, is the method's code, and the method belongs to the class of the most recent ::CLASS directive. A ::METHOD before any ::CLASS belongs to no class. This page specifies the name of a method, the options that set who may send it and how it is guarded, the forms that have no code of their own, and the method that belongs to no class. What a method object does once it exists, and the methods of Class that add one to a class, belong to the classes chapter.

The method and its name

[dir.method.create]

The section of a ::METHOD is the code of an instance method of the class that the most recent ::CLASS declared, and the directive clause itself is not part of it. The method runs with SELF as the object it was sent to, and it reads and writes the object's variables through EXPOSE. The most recent ::CLASS is the one that counts even when other directives, such as a ::ROUTINE, come between. A method with no clause in its section returns no value, so a message whose result is used raises SYNTAX 91.999. The code is a unit of its own: a label or variable of another section is not known in it.

o = .counter~new
say o~add(2) o~add(3)
say o~total
o~empty
signal on syntax name e
x = o~empty
e: say condition('o')~code

  return 'a routine between'

  expose n
  use arg step
  if \datatype(n, 'W') then n = 0
  n += step
  return n

  expose n

[dir.method.name]

The name of a method is a symbol or a string, and the name rule gives the name, so ::method "Mixed" is found by mixed and by MIXED. A string may hold any characters, so it can name an operator method such as "+"; a symbol cannot, and a ::method followed by something that is not a symbol or a string raises SYNTAX 19.902. A class declares one method of a name: a second ::METHOD of the same name, in any case, raises SYNTAX 99.902. An instance method and a class method of the same name are two methods.

Options

[dir.method.options]

The keywords after the name are CLASS, PUBLIC, PRIVATE, PACKAGE, GUARDED, UNGUARDED, PROTECTED, UNPROTECTED, ATTRIBUTE, ABSTRACT, EXTERNAL and DELEGATE, in any case and in any order. A method names at most one keyword of each of these groups: access (PUBLIC, PRIVATE, PACKAGE), guarding (GUARDED, UNGUARDED), protection (PROTECTED, UNPROTECTED) and the kind of code (ABSTRACT, EXTERNAL, DELEGATE), and CLASS and ATTRIBUTE at most once each. ATTRIBUTE goes with any one keyword of the kind group. A word that is none of the keywords, a keyword repeated or a second keyword of one group raises SYNTAX 25.902. EXTERNAL and DELEGATE take an operand, and the other keywords do not. The errors of the directive are found when the program is read. A clause after an ATTRIBUTE method raises the error that the attribute rule gives, except with DELEGATE, where it raises the error of the delegate rule.

call try '::method m private package'

[dir.method.access]

PUBLIC is the default, and a public method accepts a message from any sender. A PRIVATE method, an instance method or a class method, accepts a message only from a method whose SELF, the sender, is the class that declares it or a subclass of it, or is an instance of one of those; a class that inherits a mixin class counts as a subclass of it. The sender may be another object, so objects of one class can send each other private messages, and a class method of the class can send a private instance method. A message from the prolog, from a routine, or from a method of an unrelated class raises SYNTAX 97.2. The test is on SELF, not on the class whose method runs, so a method of a superclass that runs with an instance of the superclass as SELF cannot send a private method of a subclass, and the same method running with an instance of the subclass as SELF can. A PACKAGE method accepts a message from any code of the package that declares it and from no other package, which raises SYNTAX 97.3. A message sent with START is checked as a Deviation states.

[dir.method.guard]

A method is guarded unless UNGUARDED says otherwise, and the instruction page of GUARD says what that means: a guarded method starts with the exclusive use of its object's variables, and an unguarded one does not. An unguarded method can therefore run while another method holds the guard. GUARDED may be written, and it is the same as writing no option.

log = .array~new
o = .box~new(log)
h = o~start('hold')
do until o~inside; end
g = o~start('probe')
u = o~start('quick')
u~result
o~release
h~result; g~result
say log~makestring('l', ' ')
exit
::class box
::method init
  expose log inside go
  use arg log
  inside = .false
  go = .false
::method hold
  expose log inside go
  inside = .true
  do until go; end
  log~append('hold-end')
::method probe guarded
  expose log
  log~append('probe')
::method quick unguarded
  expose log
  log~append('quick')
::method inside unguarded
  expose inside
  return inside
::method release unguarded
  expose go
  go = .true

[dir.method.protected]

Methods without code of their own

[dir.method.attribute]

ATTRIBUTE declares two methods at once and takes no code: a method of the given name that returns the value of the object variable of that name, and a method name= that assigns its one argument to the variable and returns no value, so that a message whose result is used raises SYNTAX 91.999. The object variable is named as the directive spells the name: a symbol gives it in upper case, and a string as written, so an attribute that a lower-case string declares is not the variable that an EXPOSE of the symbol names. The access, guarding and protection options apply to both methods, and so does CLASS, which makes them class methods. An unset variable returns its own name as spelled. The first method takes no argument, and the second takes exactly one: SYNTAX 93.902 for an extra argument and 93.903 for a missing one. A clause after the directive that is not a null clause raises SYNTAX 99.934, found when the program is read, because the directive has no section; that holds for ATTRIBUTE with ABSTRACT too, which declares both methods abstract, and for ATTRIBUTE with EXTERNAL, which looks for its library as the external rule says. ATTRIBUTE with DELEGATE raises 99.946 instead, as the delegate rule says.

[dir.method.external]

EXTERNAL names a method that a native library supplies, and takes no code. Its operand is a string whose first word is LIBRARY, in any case, followed by the name of the library and optionally one more word, the entry in it. A missing operand, or one that is not a string, raises SYNTAX 19.905. A string that does not have that form, whose first word is another word, or that has no library name or more than two words after LIBRARY, raises 99.917; both are found when the program is read. A clause after the directive that is not a null clause raises 99.936. A library that cannot be loaded raises SYNTAX 98.903 when the directive's section ends, which is before the next directive is read. It therefore comes before every fault raised when the package is installed and before a fault found when a later directive is read, while a fault found when an earlier directive is read comes first, and a clause in the section raises 99.936 and not 98.903. With ATTRIBUTE the library is looked for in the same way, and a clause after the directive raises 99.934, as the attribute rule says. How a library is searched for, and which routine of it the method runs, are not specified here.

[dir.method.delegate]

DELEGATE takes the name of an object variable as a symbol and no code. A message sent to the method is forwarded, with its arguments, to the object that the variable holds, as if the section were expose var followed by forward to(var). The operand must be a symbol, and a missing operand or a string raises SYNTAX 20.926; a symbol that cannot name a variable raises 99.925. A clause after the directive that is not a null clause raises 99.946. All three are found when the program is read.

o = .front~new(.target~new)
say o~hello(1)
say o~size
call try '::method m delegate'
call try '::method m delegate "d"'
call try '::method m delegate 1'
exit

Methods of no class

[dir.method.floating]

A ::METHOD that comes before every ::CLASS belongs to no class, and the package keeps it as a method object of its own. The environment symbol .METHODS holds a table of the package's floating methods, whose indexes are the method names in upper case, and a lookup in it is by exact index, so .methods['greet'] is the .nil object. The symbol exists only in a package that has a floating method; for any other package it is the symbol's own text. Each package has its own table. A floating method may not use CLASS, which raises SYNTAX 99.905, and a name declared twice raises 99.902, as the methods of a class do.

say .methods~items
say .methods~allindexes~sort~makearray~makestring('l', ' ')
.box~define('GREET', .methods['GREET'])
say .box~new~greet('world')
say .methods['greet'] .methods['GREET']~class~id

exit

[dir.method.deviation.105]

A message sent with START is checked for PRIVATE and PACKAGE access as the same message sent directly by the code that starts it. A method of a class may start a private method of its own class, code of a package may start a PACKAGE method of that package, and a PACKAGE method started from another package raises SYNTAX 97.3. ooRexx raises 97.2 for every started private message and 97.1 for every started PACKAGE message, whichever code starts it.

::method open unguarded
