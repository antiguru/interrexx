The interrexx Language Specification

::OPTIONS

::OPTIONS option ...

rexxref: Directives > ::OPTIONS

Deviations: D103

::OPTIONS sets the defaults that the code of its package starts with. The defaults are the three NUMERIC settings, the TRACE setting, whether a routine takes the NUMERIC settings of its caller, the way that six conditions are raised, and whether the prolog runs when another package requires this one. The settings themselves are specified with NUMERIC and TRACE, and the conditions with their own pages in the conditions chapter. This page specifies the form of the directive, what each option sets, and how far it reaches.

The directive

[dir.options.syntax]

The words after ::OPTIONS are options. An option is a keyword, in any case, followed by its value, except PROLOG and NOPROLOG, which stand alone. Any number of options may be written in any order, on one directive or on several. When an option of one kind occurs twice, in one directive or in two, the one that stands later in the text wins, and options of different kinds all stay in force. A directive with no option does nothing. A word that is no keyword of an option, which a second value after a keyword also is, raises SYNTAX 25.924. The directive takes no code of its own: a clause after it that is not a null clause raises SYNTAX 99.916, as the section rule says. The faults are found when the program is read, so as the read rule says a program file with one writes nothing and exits with 256 minus the error number, 231 for 25.924.

src = .array~of('say digits() fuzz() form()', -
  '::options digits 23 form engineering', -
  '::options fuzz 3 digits 15', -
  '::OPTIONS Digits 11')
p = .package~new('spec-dir-options-syntax', src)
src = .array~of('say digits() fuzz() form()', '::options', '::options ;')
p = .package~new('spec-dir-options-syntax2', src)
call try '::options bogus'
call try '::options 5'
call try '::options "digits" 5'
call try '::options digits 5 6'
call try '::options form engineering digits 5'
call try '::options prolog 5'
call try '::options digits 5', 'say 1'
exit

[dir.options.scope]

The options of a package are the starting values of all its code. They reach the prolog, every ::ROUTINE and every method of the package, wherever the directive stands in the file, so that code written before the directive has them too. The NUMERIC and TRACE settings that they give are the defaults of the package that DIGITS, FUZZ and FORM name: a NUMERIC instruction without a value returns the setting to them. A NUMERIC or TRACE instruction changes only the setting of the code that runs it, as the scope rule says, and the next routine or method that starts is not affected. An internal routine and the text of an INTERPRET take the setting of the code that runs them, as the scope rules of the settings say, and not the option. The instruction TRACE with no value sets N, not the option, as the bare form says.

say 'prolog' digits() fuzz() form() trace()
call internal
say 'routine' r()
say 'method' .box~new~m()
numeric digits 20
numeric fuzz 3
numeric form scientific
trace n
say 'changed' digits() fuzz() form() trace()
call internal
say 'routine' r()
numeric digits
numeric fuzz
numeric form
trace
say 'reset' digits() fuzz() form() trace()
interpret 'say "interpret" digits()'
exit
internal: say 'internal' digits() fuzz() form() trace(); return

[dir.options.package]

The options of a package belong to the code that is written in it. They do not reach the code of a package that this one requires, and the options of a required package do not reach the code that requires it. A routine of one package that another package calls starts with the options of the package that holds the routine, as the scope rule says for the NUMERIC settings.

f = 'spec-dir-options-lib.tmp'
call sysfiledelete f
call lineout f, '::options digits 15 fuzz 3 form engineering'
call lineout f, '::routine libr public'
call lineout f, '  return digits() fuzz() form()'
call lineout f
src = .array~of('say "main" digits() fuzz() form()', -
  'say "lib" libr()', -
  '::requires "'f'"', -
  '::options digits 6')
p = .package~new('spec-dir-options-main', src)
call sysfiledelete f

main 6 0 SCIENTIFIC
lib 15 3 ENGINEERING

The numeric options

[dir.options.numeric]

DIGITS, FUZZ and FORM set the NUMERIC settings that the code of the package starts with. DIGITS and FUZZ take a symbol or a string that the NUMERIC instruction would accept as its value, so that "7", 05, 1e2 and 5.0 are whole numbers. A value that is not a whole number of at least 1 raises SYNTAX 26.5 for DIGITS, and one that is not a whole number of at least 0 raises 26.6 for FUZZ. A symbol is never looked up as a variable. A missing value, or one that is not a symbol or a string, such as a sign or parentheses, raises 19.917 for DIGITS and 19.918 for FUZZ. FORM takes the symbol SCIENTIFIC or ENGINEERING in any case, and no abbreviation. A missing value or a string raises SYNTAX 20.925, and any other symbol 25.11. The faults are found when the program is read.

call try '::options digits "7" fuzz 05'
call try '::options digits 1e2'
call try '::options digits 5.0'
call try '::options digits abc'
call try '::options digits 1.5'
call try '::options digits 0'
call try '::options digits -1'
call try '::options digits (5)'
call try '::options digits'
call try '::options fuzz abc'
call try '::options fuzz -1'
call try '::options fuzz'
call try '::options form Engineering'
call try '::options form sci'
call try '::options form "scientific"'
call try '::options form'
exit

[dir.options.fuzz]

The two settings must stay apart: after each DIGITS or FUZZ is processed, DIGITS must exceed FUZZ, or the directive raises SYNTAX 33.1, as the fuzz rule says for the instruction. The check is made on the value that the other setting holds at that point, which is its default of 9 or 0 until an option sets it, and it is made after every option, so the order of the options matters. The error is found when the program is read.

call try '::options fuzz 8'
call try '::options fuzz 9'
call try '::options digits 4'
call try '::options digits 5 fuzz 5'
call try '::options digits 5 fuzz 4'
call try '::options fuzz 8 digits 10'
call try '::options digits 10 fuzz 8 digits 8'
call try '::options digits 10 fuzz 8', '::options digits 7'
call try '::options digits 24', '::options fuzz 21', '::options digits 21'
exit

[dir.options.inherit]

NUMERIC INHERIT makes a routine or a method of the package start with the three NUMERIC settings of the code that calls it, and NUMERIC NOINHERIT, which is the default, makes it start with the options and defaults of its own package. The word after NUMERIC must be INHERIT or NOINHERIT, and the last of the two in text order is used. A missing word, or a string, raises SYNTAX 20.935, and any other symbol 25.935, found when the program is read. With INHERIT the settings that DIGITS, FUZZ and FORM give still start the prolog, but a ::ROUTINE or a method does not use them. A routine of a package with INHERIT that a caller from another package calls takes the settings of that caller.

numeric fuzz 1

say 'main' digits() fuzz() form()

The trace option

[dir.options.trace]

TRACE sets the tracing setting that the prolog, every routine and every method of the package start with. Its value is a word that the TRACE instruction accepts, chosen by its first letter, so that Off and O are alike, and a letter that is not valid raises SYNTAX 24.1, which a string with a blank before the letter does too. A missing value, a sign and a parenthesis raise 19.919. The empty string is accepted and starts the code with N. The directive is stricter than the instruction in one respect: a number is not a setting and raises 24.1. The setting is what TRACE() returns when the code starts, and a TRACE instruction changes it for the running code only, as the scope rule says. A question mark before the letter is accepted, and what interactive tracing does is specified in the debugging chapter. What TRACE() returns when the code starts after a question mark with no letter after it is ?N, as the Deviation states.

call try 'o'
call try 'Off'
call try 'normal'
call try 'N'
call try '"n"'
call try 'x'
call try '3'
call try '""'
call try '-1'
call try '+'
call try '(n)'
call try '" n"'
call try ''
exit

The condition options

[dir.options.condition]

ERROR, FAILURE, LOSTDIGITS, NOSTRING, NOTREADY and NOVALUE each take the value SYNTAX or CONDITION; NOVALUE takes ERROR as well, with the meaning of SYNTAX. CONDITION is the default and leaves the condition as the conditions chapter specifies it. SYNTAX makes the condition that no trap answers raise a SYNTAX condition instead, with these codes: 98.970 for ERROR, 98.971 for FAILURE, 98.972 for LOSTDIGITS, 98.973 for NOSTRING, 98.974 for NOTREADY and 98.986 for NOVALUE. The clause that raised it ends there as the SYNTAX rule says, and RC is 98 in the trap that catches it. Without a trap the program ends as the rule for an untrapped SYNTAX says, with exit status 158. A FAILURE raised as SYNTAX is not passed on to the ERROR trap, as the second example shows. A FAILURE that no trap answers, which the untrapped rule would ignore, is answered as ERROR here, so with ERROR SYNTAX it raises 98.970 when FAILURE is left at CONDITION, as the third example shows. A missing value or a string raises SYNTAX 20.929 and any other symbol 25.927, ERROR for an option other than NOVALUE among them, both when the program is read.

call try 'error'
call try 'failure'
call try 'lostdigits'
call try 'nostring'
call try 'notready'
call try 'novalue'
exit
try:
  which = arg(1)
  signal on syntax name e
  select
    when which = 'error' then address system 'exit 3'
    when which = 'failure' then address nosuchenv 'echo x'

    when which = 'nostring' then say 'a' || .nstr~new
    when which = 'notready' then say linein('nosuchfile.zzz')
    when which = 'novalue' then say undefinedvar
  end
  say which 'went on'
  return
e: say which condition('o')~code rc
  return

[dir.options.condition.trap]

A trap still answers the condition with its own name: with SIGNAL ON, CALL ON or the ANY trap on, the condition is raised as ERROR, FAILURE, LOSTDIGITS, NOSTRING, NOTREADY or NOVALUE and not as SYNTAX, and the answering trap is the one that the choice rule picks. The option applies only while the trap instructions have left the condition alone: a SIGNAL or CALL instruction that turns the trap of the condition ON or OFF, or the trap of ANY, ends the option for that condition for the rest of the routine or method in which it ran, so that an OFF condition is ignored again. A CALL instruction does so for ERROR, FAILURE and NOTREADY, the conditions of the option that CALL can trap, and CALL ON or OFF of ANY does so for these three only: for LOSTDIGITS, NOSTRING and NOVALUE the option stays in force. An internal routine takes this state from its caller, and the instructions that it runs end the option for its own code only, so that its caller still has the state it had when the routine returns. A SIGNAL or CALL in the text of an INTERPRET ends the option for the code that runs the INTERPRET. A ::ROUTINE and a method start without the state, and the option applies there afresh. A SYNTAX condition that the option raises is an ordinary one, which SIGNAL ON SYNTAX answers.

The prolog option

[dir.options.prolog]

PROLOG and NOPROLOG decide what a ::REQUIRES of the package does with its prolog: with PROLOG, the default, the prolog runs, and with NOPROLOG it is skipped, so that a package of routines and classes can be required without its start-up code. The last of the two in text order is used. The installation of the package is not affected, so its routines and classes exist all the same. The program that was started runs its prolog whatever the option says. Loading the text of a package with the Package class follows the same rule as a requirement, as the first example shows. The option acts on a package that is required or loaded as a package only: a file that a program calls as an external routine runs its code from the start, whatever the option says, as the third example shows.

f = 'spec-dir-options-pro1.tmp'
call sysfiledelete f
call lineout f, 'say "prolog of one"'
call lineout f, '::options noprolog'
call lineout f, '::routine one public'
call lineout f, '  return "one"'

call lineout f, '::method activate class'
call lineout f, '  say "activate kone"'
call lineout f
