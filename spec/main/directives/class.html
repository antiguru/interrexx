The interrexx Language Specification

::CLASS

::CLASS name [METACLASS m] [SUBCLASS s | MIXINCLASS s] [PUBLIC | PRIVATE] [ABSTRACT] [INHERIT i ...]

rexxref: Directives > ::CLASS

Deviations: D32, D114

::CLASS declares a class. The class comes into being when the package is installed, before the prolog runs, and the methods that the ::METHOD directives after it declare belong to it until the next ::CLASS. This page specifies the name of the class, the options that place it in a hierarchy and make it visible to other packages, and the order in which the classes of a package are made. What a class object does once it exists, the methods of Class such as new, id and superclass among them, is specified in the classes chapter; the examples here use those methods only to show what the directive made.

The class and its name

[dir.class.create]

::CLASS creates one class, named by a symbol or a string, and the class is reachable from every code of the package as the environment symbol that is a period followed by its name, from the point that the installation rule gives. The class's id is the name that the name rule gives, and .shown and .SHOWN are one class. A class declared with no SUBCLASS or MIXINCLASS option is a subclass of Object, and a class is a mixin class only when MIXINCLASS says so. A program may declare a class named like a built-in one, and its own then hides the built-in one in every code of the package.

say .plain~superclass~id .plain~new~class~id
say .Shown~id .ALSO~id .also~id
say .array~new~hi .array~new~class~id
::class plain
::class Shown
::class "Also"
::class array
::method hi
  return 'my array'

Object PLAIN
SHOWN Also Also
my array ARRAY
[dir.class.duplicate]

A package may declare a class name once. A second ::CLASS that names it again raises SYNTAX 99.901, whatever the case of either spelling, whether the directive is a symbol or a string and whether the first one was PUBLIC. The error is found when the program is read, as the directive rule says for the other faults of the text.

call try '::class Foo', '::class FOO'
call try '::class Foo', '::class "Foo"'
call try '::class Foo public', '::class foo private'
call try '::class Foo', '::class Bar'
exit
try:
  signal on syntax name e
  src = .array~new
  do i = 1 to arg()
    src~append(arg(i))
  end
  p = .package~new('spec-dir-class-dup', src)
  say src~makestring('l', ' / ') '=> ok'
  return
e: say src~makestring('l', ' / ') '=>' condition('o')~code
  return

::class Foo / ::class FOO => 99.901
::class Foo / ::class "Foo" => 99.901

::class Foo / ::class Bar => ok

Options

[dir.class.options]

The keywords after the name are METACLASS, SUBCLASS, MIXINCLASS, PUBLIC, PRIVATE, ABSTRACT and INHERIT, in any case. They may stand in any order, except that INHERIT takes every word that follows it as the name of a class, so it comes last. Each of the four groups METACLASS, SUBCLASS or MIXINCLASS, PUBLIC or PRIVATE and ABSTRACT may appear once. A word that is none of the keywords, a keyword repeated, and a keyword that excludes one already given, such as PRIVATE after PUBLIC or SUBCLASS after MIXINCLASS, raise SYNTAX 25.901. METACLASS, SUBCLASS, MIXINCLASS and INHERIT without a name after them raise 19.906, 19.907, 19.913 and 19.908, and a ::CLASS with no name raises 19.901. Every one of these is found when the program is read.

call try '::class a public private'
call try '::class a public public'
call try '::class a mixinclass object subclass object'
call try '::class a abstract abstract'
call try '::class a frob'
call try '::class a inherit m public'
call try '::class A SubClass Object Public Abstract'
call try '::class a public abstract subclass object metaclass class'
call try '::class'
call try '::class a metaclass'
call try '::class a subclass'
call try '::class a mixinclass'
call try '::class a inherit'
exit
try:

    '::class m mixinclass object'))

e: say arg(1) '=>' condition('o')~code
  return

[dir.class.visibility]

A class is private unless PUBLIC says otherwise. A private class is known only to the package that declares it. A public class is also known to every package that requires the package, directly or through a chain of ::REQUIRES, and a class name is looked up first among the classes that the package declares, then among the public classes of the packages it requires, taking the first of those in the order of the ::REQUIRES directives. The order is depth first: a required package contributes its own public classes, then those it makes visible by its own ::REQUIRES, and all of these come before the classes of the next ::REQUIRES directive of the requiring package. A private class of a required package does not hide a public class of the same name that the package makes visible. When none of these has the name, the lookup goes on with the classes of the class library and then the directories, in the order of the rule of the environment chapter: a library class is found before an entry of .local or .environment, and a class object that the program has stored in .local or .environment is found when no class has the name. The same lookup finds the class that SUBCLASS, MIXINCLASS, METACLASS and INHERIT name. A name that no step finds is the environment symbol's own text, and the options that need a class raise the error that their rule gives.

The hierarchy

[dir.class.subclass]

SUBCLASS names the class's superclass, by a symbol or a string that the lookup of the visibility rule resolves. The new class inherits the instance methods and the class methods of the superclass, and the class that the program names may be a built-in one. A name written with a leading period is looked up as written: subclass .object looks for a class named .OBJECT, which no ::CLASS declares unless it spells its own name that way, so the built-in Object is not found. A name that is found nowhere raises SYNTAX 98.909 when the package is installed, and a class that is its own superclass, directly or through the classes it names, raises 98.911.

call try '::class a subclass array'
call try '::class a subclass "String"'
call try '::class a subclass .object'
call try '::class a subclass nosuchsuperclass'
call try '::class a subclass a'
call try '::class a subclass b', '::class b subclass a'
exit

[dir.class.mixin]

MIXINCLASS makes the class a mixin class and names its superclass as SUBCLASS does, so that the name is required. Only a mixin class may be inherited by INHERIT, which takes a list of class names, and the classes of the list are inherited in the order written. INHERIT of a class that is not a mixin class raises SYNTAX 98.942. A class that appears twice in the list, or is both the superclass and in the list, raises 98.944. A class that would become its own ancestor through INHERIT, itself included, raises 98.911. The class that MIXINCLASS names for a mixin class that is inherited must be the superclass of the inheriting class or one of the superclass's ancestors, or INHERIT raises SYNTAX 98.943 when the package is installed. When that class is itself a mixin class, the test applies to the class its own MIXINCLASS names, and so on down to the first class that is not a mixin class. A mixin class can itself be a subclass and inherit other mixin classes.

call try '::class c inherit m1 m2'
call try '::class c inherit plain'
call try '::class c inherit m1 m1'
call try '::class c subclass m1 inherit m1'
call try '::class c inherit c'
call try '::class m3 mixinclass m1 inherit m2'
exit

[dir.class.search]

A message sent to an instance finds its method by looking first at the methods the class itself declares and then at those of the classes it descends from through SUBCLASS and INHERIT, in the order that the order rule of the method search gives; the first method found runs. When the superclass and its ancestors inherit no mixin classes and each class that INHERIT names is a mixin class whose MIXINCLASS option names Object and that inherits none itself, as in the example, that order is the class, its superclass and the superclass's ancestors other than Object, the mixin classes in the order written, and Object last. A superclass then hides a method of a mixin class that the subclass inherits, and an earlier mixin class hides a later one. A mixin class with another base class, and a class that more than one listed class reaches, stand where the base rule and the shared-class rule say.

o = .c~new
say o~who o~only1 o~only2 o~deep o~own
::class s0
::method deep
  return 's0 deep'
::class s subclass s0
::method who
  return 's who'
::method only1
  return 's only1'

  return 'm1 who'
::method only1
  return 'm1 only1'

  return 'm1 only2'
::method deep
  return 'm1 deep'
::class m2 mixinclass object
::method only2
  return 'm2 only2'

[dir.class.metaclass]

METACLASS names a class that is a subclass of Class, and the instance methods of that class become class methods of the new class, so that they answer messages sent to the class itself. A class method that the new class declares with the CLASS option hides a metaclass method of the same name, and both hide a class method that the new class inherits. A subclass has its superclass's metaclass unless it names its own. A metaclass name that is found nowhere raises SYNTAX 98.908, where SUBCLASS, MIXINCLASS and INHERIT raise 98.909. A name that is found and is not a subclass of Class raises SYNTAX 99.927 when the package is installed, after the classes created before it have received INIT as the failure rule says, and a metaclass that is the class itself raises 98.911. A new of the METACLASS that answers an object that is not a class raises SYNTAX 98.900 when the package is installed (Deviation 114).

say .k~hello .k~both
say .sub~hello .sub~both .sub~metaclass~id

[dir.class.abstract]

ABSTRACT marks the class as one that has no instances of its own: the NEW method that Class supplies raises SYNTAX 98.989 for it, before any INIT runs, and a class method NEW that the abstract class declares itself runs instead. A class that has the abstract class as a superclass, or that inherits it, is not abstract unless it says so, and makes instances. A class can be abstract and a mixin class at once.

Order of creation

[dir.class.forward]

A class may name a class that the package declares further on, in SUBCLASS, MIXINCLASS, METACLASS or INHERIT. The classes are created in text order, except that a class waits until every class it names has been created, and is then created at once, before the next class in the text. The order of creation is the order in which the classes receive their INIT and ACTIVATE messages, as the installation rule says. A class that names itself, directly or through the classes it names, raises SYNTAX 98.911 before any class of the package is created, so that no INIT has run, not even for the classes that come before it in the text and take no part in the cycle.
