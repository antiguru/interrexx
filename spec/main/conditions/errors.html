The interrexx Language Specification

Error numbers

ANSI: 8.2.1, 8.4, 8.4.1; rexxref: Conditions and Condition Traps > Condition Information > The Special Variable RC; Error Numbers and Messages

Every fault that raises the SYNTAX condition has an error number. The number says what kind of fault it is, so that a program can answer a kind of error without reading a message. This page specifies how a number is built, what a program sees of it, and what each of the numbers means. It does not list the subcodes: the pages that raise an error name its subcode, and the texts of the messages are not specified, as the error rule of the conventions says. The numbers run from 3 to 99, and the numbers in that range that name no kind of fault are the ones that ERRORTEXT answers with the null string, as its rule lists them.

How a number is built

[cond.errors.scheme]

An error number has two parts, a major number and a subcode written after a point without leading zeros: 40.3, 93.924. How a trap reads the two parts, and why a program tells faults apart by the whole code, is the business of the code rule; this page owns what the major numbers mean. SIGL is set as the SIGL rule says. An error that no SIGNAL trap answers ends the program with the exit code 256 minus the major number, as the untrapped rule says, and the subcode does not enter it. The error of a fault in the text that is read before the program runs is no condition at all, as the reading rule says.

rc = 'unset'
signal on syntax name e
say 'one'
x = 1 + 'a'
e: say condition('o')~code rc sigl
say word(translate(condition('o')~code, ' ', '.'), 1) == rc

one
41.1 41 4
1
[cond.errors.subcodes]

The subcodes of an error number are named on the pages of the clauses and functions that raise it, in the rule that names the fault. This page names a subcode only to show a kind of error.

call try 'x = left("abc", -2)'
call try 'x = copies("ab", -2)'
call try 'x = d2c(-1)'
call try 'x = "abc"~substr(0)'
exit

  interpret arg(1)
e: o = condition('o')
  say left(arg(1), 26) o~code o~rc

The numbers

Each entry gives the major number, a short label, constructs that raise it with the full code, and a rule of this book that raises it where one is written. The grouping is by the usual kind of fault, and a number may have subcodes of another kind. The examples run the listed constructs and print the code that the trap reads.

Faults in the form of the text

These faults are usually found in the text of a clause, and a clause that is a directive or part of a block can raise them too. A fault in the text of a program is found when the program is read, and in the text of an INTERPRET when it runs, as the reading rule says.

Faults in the values and the flow

These faults are found while a clause runs, because a value or the state of the program does not fit the clause.

[cond.errors.run]

The numbers below usually name a fault that the values or the flow of control cause, at the clause that meets it.

  • 16, jump to a missing label: signal nolabelhere 16.1, signal value 'zz' 16.1; rule.
  • 17, misplaced PROCEDURE: procedure 17.1; rule.
  • 24, unknown TRACE setting: trace x1 24.1; rule.
  • 26, value that is no whole number: numeric digits 'a' 26.5, numeric digits 0 26.5, numeric fuzz -1 26.6, x = 2 ** 1.5 26.8; rule.
  • 28, LEAVE or ITERATE with no target: leave 28.1, iterate 28.2, leave nosuchzz 28.3, iterate nosuchzz 28.4; rule.

  • 40, argument count or value refused: x = abs() 40.3, x = abs(1, 2) 40.4, x = left('abc', 'q') 40.12, x = random(5, 1) 40.33; rule, rule.
  • 41, arithmetic on a non-number: x = 1 + 'a' 41.1, x = -'a' 41.1, x = 'a' % 2 41.1; rule.
  • 42, arithmetic with no result: x = 9 // 0 42.3, x = 1e999999999 * 10 42.901, x = 1e-999999999 / 10 42.902, x = 0 ** -1 42.903; rule.

Faults of the interpreter and its services

[cond.errors.system]

The numbers below usually name a fault that is neither in the text nor in a value of the program: the interpreter that cannot start the program or go on, a program that is stopped, and a request to the system that fails.

  • 3, a program file that does not exist: 3.901, with the exit status 253.
  • 4, a HALT that no trap answers: raise halt 4.1; rule.
  • 11, parentheses or calls nested beyond the limit; rule.
  • 48, a request to the system that fails: call rxqueue 'Set', 'nosuchq' followed by queue 'x' 48.1; rule.

The number 3 comes before any clause runs, so no trap sees it. The numbers 5, 39 and 49 name states that this book does not tie to a clause: how much a program can ask for before 5 is raised, how complex an expression can be before 39, and what 49 reports are not specified. A RAISE HALT is a deterministic way to reach 4.

exit

  interpret arg(1)
  say arg(1) '=> none'
  return
e: say left(arg(1), 40) condition('o')~code
  return
gone: call rxqueue 'Set', 'spec_errors_no_such_queue'
  return

Faults of messages, objects and directives

[cond.errors.objects]

The numbers from 88 up usually name faults of messages, of objects and of directives.

  • 88, argument value refused: x = filespec('N') 88.901, x = .directory~new~put(1) 88.901, x = charin(, 0, -1) 88.907; rule.
  • 89, USE target of the wrong kind: use arg a, 'b' 89.1, use arg (a) 89.1; rule.
  • 90, EXTERNAL entry that is not there: ::routine r external 'registered nonezz' 90.999; rule.
  • 91, message term with no result: say 'a' .m~new~bar 'b' 91.999; rule.
  • 93, argument value refused: x = left('abc', -2) 93.923, x = copies('ab', -2) 93.906, x = 'abc'~substr(0) 93.924, x = d2c(-1) 93.927, x = .array~new('x') 93.906, x = stream('nofile_zz', 'c', 'bogus') 93.914; rule.
  • 97, message that is not answered: x = 'a'~foo 97.1, x = .nil~foo 97.1, .m~new~p 97.2; rule, rule.
  • 98, fault of a running clause or directive: raise propagate 98.918, ::class a subclass nosuchzzclass 98.909, ::routine r external 'library nonezz' 98.903; rule, rule.
  • 99, fault in a directive or its place: ::routine zz 99.914, expose x 99.908, forward to (.nil) 99.923, use local a 99.915, ::class a (twice) 99.901; rule.

The numbers 40, 88 and 93 all refuse arguments, and which of them a builtin or a method raises is named on its own page. The number 92 belongs to a platform interface that this book does not specify, so no rule or example raises it. The numbers 98 and 99 differ in when the fault is found: 99 is a fault of form found when the text is read, and 98 is a fault found when the clause or directive takes effect. A directive in the text of an INTERPRET is no directive, so it raises 99 there.

call try "x = filespec('N')"

call try "use arg (a)"

try:

  interpret arg(1)
  say left(arg(1), 44) '=> none'
  return
e: label = arg(1)
  if arg(2, 'E') then label = arg(2)
  say left(label, 44) condition('o')~code
  return

The directive constructs run as the source lines of a package, so that the fault is found when the package is built.

call pk "::requires 'nonexistent_spec_errors_zz.rex'"
call pk "::routine r external 'registered nonezz'"
call pk "::routine r external 'library nonezz'"
call pk "::class a subclass nosuchzzclass"
call pk "::class a", "::class a"
exit
pk:
  signal on syntax name pe
  src = .array~new
  do i = 1 to arg()
    src~append(arg(i))
  end
  p = .package~new('n', src)
  say arg(1) '=> none'
  return
pe: say left(arg(1), 44) condition('o')~code
  return

The numbers 91 and 97.2 need a class to hold the method, so their example is a program of its own.

signal on syntax name e1
say 'a' .m~new~bar 'b'
e1: say condition('o')~code
signal on syntax name e2
.m~new~p
e2: say condition('o')~code
::class m
::method bar
  return
::method p private
  return
