The interrexx Language Specification

Condition information

ANSI: 8.4.1, 9.5.3; rexxref: Conditions and Condition Traps > Condition Information; Conditions and Condition Traps > Condition Information > Condition Object

When a trap answers a condition, the interpreter records what it knows about the condition, and the code that the trap reaches can read it. The record holds the name of the condition, the kind of the trap, its state, a description, and an object that some conditions carry. It is read with the CONDITION builtin, which owns what each option answers, and as a condition object, a directory with one entry for each piece of information. The trap also sets the variables RC and SIGL, and an error that no trap in the code that raised it answers goes on to the code that called it. This page specifies the record, the condition object, the two variables and that journey, and the traps page specifies when a trap answers.

The record

[cond.information.record]

When a SIGNAL trap or a CALL trap answers a condition, the condition is recorded for the code that the trap reaches: the label's code for a SIGNAL trap, and the routine that a CALL trap calls. The record holds the name of the condition, the instruction of the trap, SIGNAL or CALL, the state of the trap, the description and the additional object, which CONDITION answers with its options. The scope rule of CONDITION also says which code holds a record and how long it stays. A condition that no trap answers records nothing: it is ignored, or it becomes a SYNTAX condition, as the untrapped rule says.

x = undefinedvar
'exit 3'
say '['condition('c')']' (condition('o') == .nil)

[cond.information.argument]

A CALL trap calls its routine with one argument, the condition object of the condition that it answers, so ARG() is 1 there and ARG(1) is a directory with the entries of the entries rule. A SIGNAL trap passes no argument: ARG() at its label is what it is at any other place of the code, which is the arguments of the routine that holds the label. That directory is the condition object itself, and none of the copies that the object rule of CONDITION says CONDITION('O') answers is the argument. The options C, D, I and A of CONDITION read the current entries of the object itself, so a change that the routine makes to its argument shows in what they answer, and in the entries of a copy made after it. The option S reads no entry, and the status rule says what it answers.

The condition object

[cond.information.object]

The condition object is a directory with these entries, whose names are in capital letters. CONDITION, DESCRIPTION, INSTRUCTION and ADDITIONAL are the entries that the object rule of CONDITION names. PACKAGE is the package that holds the code that raised the condition, and PROGRAM its name. POSITION is the number of the line on which the clause that raised the condition starts, in that code, and a NOTREADY that the interpreter raised has none. PROPAGATED is 1 when the condition left the level that raised it and 0 otherwise, as the propagated rule specifies. STACKFRAMES and TRACEBACK are lists with one item for each active level of code at that time, the main program's included, and the text of a traceback line is not specified. ADDITIONAL is present for a SYNTAX, NOMETHOD, NOSTRING or NOTREADY that the interpreter raised. A condition that a RAISE instruction raised has POSITION, and has ADDITIONAL exactly when the instruction gave one, whatever the name of the condition, as the options rule of RAISE says. The exception is a SYNTAX, which always has an ADDITIONAL array, empty when the instruction gave none, as the SYNTAX rule of RAISE says. SYNTAX adds CODE, the error number with its subcode as 41.1, RC, its major number, ERRORTEXT, the text of the error that the ERRORTEXT builtin answers for RC, and MESSAGE, the text with the details of this occurrence. ERROR and FAILURE have RC, the return code of the command. The texts of the messages are not specified, and the entry RESULT is not specified here.

[cond.information.library]

A level that runs a method of the class library, the code of package REXX, has a line number that is not specified. That holds for POSITION of a condition that was raised there, for the line of its StackFrame, for the number in its traceback line and for the line that the report of an error names. The number of such levels between the level that sent the message and the level that raised the condition is not specified either, so the number of items of STACKFRAMES and TRACEBACK is not specified where library levels are among them. The code and subcode of an error that a library method raises are specified, as the page of the class says; its text is not, as the object rule says for every message.

[cond.information.library.trace]

The trace line of a level that runs a method of the class library, and so each such entry of TRACEBACK, holds no text of the class library's code. [cond.information.context]

In a trapped condition's code, .CONTEXT~CONDITION answers a new directory that holds the same entries as CONDITION('O'), and .nil when the code holds no record. The variables RC and SIGL

[cond.information.rc]

Before control reaches the code of a trap, the trap sets RC for some conditions. After a SYNTAX condition it is the major number of the error, so 35 for 35.1, and it equals the RC entry of the object. After ERROR and FAILURE it is the return code of the command, which the command rule already sets. Every other condition leaves RC as it was.

[cond.information.sigl]

When a trap answers a condition, SIGL is the number of the line on which starts the clause that was running in the code of the trap, in the level that the trap belongs to. A level is the main program or a running routine, method or internal routine. When the condition is raised in the level whose trap answers, the clause is the one that raised it, and when it is raised deeper, in a level that has no trap of its own, the clause is the one that called that level. A clause that spans several lines counts at its first, and the clause of an INTERPRET is the INTERPRET instruction, not a clause of its text. The POSITION entry is the line of the clause that raised the condition, in the code that raised it, so it differs from SIGL when the condition was raised in a deeper level that has no trap. The SIGL of a CALL trap is set as the CALL trap rule says.

From the code that raised it to its caller

[cond.information.propagate]

A SYNTAX condition that is raised in a level where no trap answers it, as the choice rule decides, ends the clause that raised it, and then the clause of the level that called this one, so that no clause of the first level runs on, and is raised again at the clause that made the call, in the level above: a CALL, a function call, a message term or a message instruction. A level above whose trap answers ends the chain there, and the code of the trap runs in that level, with the record and the object of the original condition: POSITION names the line where the error was found, and STACKFRAMES lists the active levels as they were then. A level that does not answer passes the condition on, up to the main program, where an untrapped condition ends the program as the SYNTAX rule says. A level that starts with every trap OFF, a ::ROUTINE or a method, passes it on until it switches a trap on, and an internal routine does when its copy of the trap states has no trap that answers.

[cond.information.propagated]

The PROPAGATED entry of the object that the trap sees is 1 when the condition left the level that raised it, which is the case for a SYNTAX that reached a caller from a ::ROUTINE, from a method or from an internal routine, and after a RAISE with PROPAGATE. It is 0 for a condition that the level which raised it answers, a SYNTAX or a user condition alike.

signal on syntax name t
call r
t: say 'routine' condition('o')~propagated
signal on syntax name v
say .o~new~m
v: say 'method' condition('o')~propagated
signal on syntax name w
x = 1 % 0
w: say 'same level' condition('o')~propagated
exit
::routine r
  x = 1 % 0
::class o
::method m
  x = 1 % 0

routine 1
method 1
same level 0
[cond.information.propagated.internal]

An internal routine that switched the trap off passes the condition on in the same way, and the object that its caller sees has 1.

signal on syntax name v
call iq
v: say 'caller' condition('o')~propagated condition('o')~code
exit
iq: procedure
  signal off syntax
  x = 1 % 0

caller 1 42.3

signal on syntax name v
call i1
v: say 'caller' condition('o')~propagated condition('o')~code
exit
i1: procedure
  signal off syntax
  call i2
  return
i2: procedure
  signal off syntax
  x = 1 % 0

caller 1 42.3
[cond.information.propagate.only]

Only a SYNTAX condition is passed on. Any other condition is answered or ignored in the level that raised it, by the trap states that level has, so a trap that the level above set for itself does not see it. An internal routine has a copy of the trap states of its caller, as the scope rule says, so a trap that its caller switched on does answer a condition raised in the routine, and it does so in the routine, not in the caller. A HALT or NOMETHOD that nothing answers becomes a SYNTAX condition first, as the untrapped rule says, and that one is passed on.

signal on novalue name nv
address system
call on error name er
say 'main' r()
exit
nv: say 'nv in main' sigl
er: say 'er in main'; return
::routine r
  x = unsetvar
  'exit 3'
  return 'r done'

main r done

signal on novalue name nv
address system
call on error name er
say 'main' r()
say 'after'
exit
nv: say 'nv' sigl; return 'from nv'
er: say 'er' sigl rc; return
r:
  'exit 3'
  say 'back in r'
  x = unsetvar
  say 'not reached'
  return 'r done'

er 10 3
back in r
nv 12
main from nv
after
