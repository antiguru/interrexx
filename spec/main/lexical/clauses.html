The interrexx Language Specification

Clauses

ANSI: 6.2.1.1, 6.2.3, 6.3.2; rexxref: General Concepts > Structure and General Syntax

A clause is the unit that the interpreter runs: a sequence of tokens that ends at a semicolon, which the reader supplies at most line ends. This page says where a clause ends, which clauses do nothing, how a label is recognized, how a line is continued, and how the first tokens of a clause decide whether it is a label, an assignment, an instruction or a command. The line ends of this page are those of a program file. The text given to INTERPRET has no line ends, so only a semicolon and the end of the text end a clause there, and examples of INTERPRET here hold no line end.

[lex.clauses.end]

A clause ends at a semicolon, at a line end, or at the end of the program. A semicolon inside a string or a comment ends nothing. A line end inside a comment ends nothing either, and neither does a line end after a continuation character. Several clauses may share a line when semicolons separate them.

say 1; say 2; say ';' /* ; */
say 3
say 4 /* a comment
   across lines */ ; say 5
say 6

[lex.clauses.null]

A clause with no tokens is a null clause. Blank lines, lines that hold only comments and repeated semicolons are null clauses, and a null clause does nothing. Where an instruction is required after THEN, ELSE or OTHERWISE, the null clauses in between are passed over and the next clause that has tokens is that instruction.

; ;

[lex.clauses.implied]

The keywords THEN, ELSE and OTHERWISE end the clause they are in, so that the instruction after one may follow on the same line with no semicolon. They have this effect only where they are keywords: THEN after the expression of IF or WHEN, and ELSE and OTHERWISE as the first token of a clause that is not an assignment. Anywhere else they are ordinary symbols. In the expression of IF or WHEN, outside parentheses and brackets, THEN is never a symbol, so if then = 1 then raises SYNTAX 35.929, while if (then = 1) then reads the variable.

if 1 then say 'a'; else say 'b'
if 0 then say 'c'
else say 'd'
select; when 0 then say 'e'; otherwise say 'f'; end

then = 5; else = 6; otherwise = 7
say then else otherwise
if (then = 5) then say 'g'

Labels

[lex.clauses.label]

A clause that holds only a symbol or a string and a colon is a label. Blanks and comments may stand before the colon, and the colon implies a semicolon, so another clause, or another label, may follow on the same line. A label does nothing when it is reached. A symbol label is read in upper case, and a string label keeps its characters as written, so a label written as a lower-case string is not found by a name that is written as a symbol. Any kind of symbol is a label, a number and a symbol that starts with a period included. When two labels have the same name, the first is the one that is found. The colon makes a label before it can make an assignment, so x: = 3 is the label x followed by the clause = 3, which raises SYNTAX 35.1 when the program is read, so that the program produces no output and ends with the exit code 221. A label inside a DO, IF or SELECT body raises SYNTAX 47.2, 47.3 or 47.4 when the program is read, and a label in the text given to INTERPRET raises SYNTAX 47.1.

go : /* c */ say 'a'
1: say 'b'

Continuation

[lex.clauses.continuation]

A comma or a minus sign that is the last token on a line, followed by nothing but blanks, tabs and comments, continues the clause on the next line. The character acts as a blank, and the line end implies no semicolon. A comment after it may span lines, and the line end after the comment is the one that counts. The next line is joined whole, so when it is empty the clause ends at its line end. At the end of a program, the character just ends the clause. A -- is a line comment and not a continuation, and a minus sign that is not the last token is an operator.

say 1,
    2
say 3,    /* c */   -- c
    4
say 5 -
    6
say 7 - -
    8

[lex.clauses.continuation.comma]

A comma that continues a line is not an argument separator: it is replaced by a blank like any other continuation. To continue a call after a separator, the separator is written first, so that the comma at the end of the line is the continuation. Two commas in a row at the end of a line are a separator and a continuation.

          2)
say right('a', 3,,
          '-')

What a clause is

[lex.clauses.kinds]

A clause that is not a null clause or a label is an assignment, an instruction or a command, and the first tokens decide which. If the first token is a symbol and the second is =, the clause is an assignment, and if the second is one of the assignment operators of the operator rule, such as +=, it is an extended assignment. Otherwise, if the first token is a symbol that is an instruction keyword, the clause is that instruction. A clause whose first token is a symbol and whose second token is == raises SYNTAX 35.1 when the program is read, and so does a clause of the form term[...] == or term~name ==. A clause of the form term[...] = expression or term~name = expression is a message assignment, and a clause that is a single message term, such as o~tell or o~~tell, is a message instruction. Neither is a command. Any other clause is a command.

signal on failure name f
address nosuch
say = 'assigned'
say say
say(2)
'a command'
f: say condition('d')

[lex.clauses.assignment.op]

The tokens += -= *= /= %= //= and **= for the arithmetic operators, ||= for concatenation and &= |= and &&= for the logical operators start an assignment too, when a symbol comes first. x op= expression assigns the result of x op (expression), so the whole expression is evaluated before the operator is applied. The characters of the token may be separated as those of any operator may be.

x //= 2; say x
x = 2; x **= 3; say x

[lex.clauses.keyword]

When a clause is not an assignment and its first token is a symbol without a period that is the name of an instruction, in either case, the clause is that instruction. The keyword may be followed directly by a parenthesis, a quote mark or a sign. A symbol with a period, as say.1 is, is not a keyword. The instructions and their keywords are the subject of the instructions chapter.

[lex.clauses.command]

A clause that is not a label, an assignment or an instruction is a command. The string that its expression evaluates to is sent to the current environment. How that is done is the business of the ADDRESS instruction, and here only the recognition matters.
