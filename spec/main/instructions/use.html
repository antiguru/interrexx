  27. 15. Deviations

The interrexx Language Specification

USE

USE [STRICT] ARG [target [= default]] [, ...] | USE LOCAL [name]...

rexxref: Keyword Instructions > USE

Deviations: D71

USE has two unrelated forms. USE ARG takes the arguments of the running program, routine or method and stores the argument objects themselves in variables, where ARG and PARSE ARG make strings of them and cut them up with a template. USE STRICT ARG is the same with a check of the number of arguments. USE LOCAL is for methods only and decides which of the method's variables are its own. This page specifies the targets and defaults of USE ARG, the strict form and the errors of both forms. How the arguments are counted and read is the matter of the ARG builtin.

USE ARG

[instr.use.arg]

The targets of USE ARG are filled from left to right. The target in position n receives argument n, as an object, without any change: it is not converted to a string, its case stays, and a collection is the same collection that the caller passed. A target for which no argument was passed, because the caller passed fewer arguments or left that position empty, is dropped, so a variable it had before is unset. An argument beyond the last target is ignored. The clause may run again, and it reads the arguments the call was made with, not the current values of the variables. A target can be a simple symbol, a compound symbol or a stem symbol, or it can be left empty, which skips its argument and sets nothing.

call show 1, 2, 3
call show 'a'
call show
call show , 'b'
call show 1, , 3, 4
call take .array~of('x', 'y'), 'Mixed Case', 12
exit
show:
  use arg x, y, z
  say 'x=' || x 'y=' || y 'z=' || z symbol('x') symbol('y') symbol('z') arg()
  return
take:
  use arg a, b, c
  a = 'changed'
  use arg again
  say again~class~id again~items b c + 1
  return

[instr.use.compound]

The tail of a compound target is resolved when that target is filled, with the values its variables have at that moment, as for an assignment to the symbol. A target to the left that set a variable of the tail therefore counts. The argument is stored under the resulting name.

k = 5
call fill 'v1', 'v2'
say c.1 c.5
call chain 7, 'second'
say d.7
exit
fill:
  use arg c.1, c.k
  return
chain:
  use arg t, d.t
  return

v1 v2
second
[instr.use.stem]

A stem symbol as a target receives the argument as the stem. When the caller passed a stem, as in call s st., the target is that stem, not a copy, so the routine's assignments to it are the caller's. When the argument is not a stem, the target is a new stem that has the argument as its default value, as assigning a value to a stem does.

st.1 = 'one'
call change st.
say st.1 st.2
exit
change: procedure
  use arg sub.
  say sub.1
  sub.2 = 'two'
  return

one
one two

call plain 'str'
exit
plain:
  use arg s.
  say s.1 s.xyz s.~class~id
  return

str str Stem
[instr.use.message]

A target can be a message term, such as obj~name or arr[1], whose object is a variable that has a value, one that an earlier target of the clause set included. The argument is then sent as the assignment of that term, as the message assignment rule describes, so it sets the attribute or the item. The message terms are evaluated in order, and a message term whose argument is missing is skipped: it sends nothing and changes nothing.

o = .thing~new
arr = .array~new
arr[2] = 'keep'
call fill o, arr, 'v1', 'v2'
say o~name arr[1] arr[2]
call fill o, arr
say o~name arr[1] arr[2]
call fill o, arr, 'w1'
say o~name arr[1] arr[2]
exit
fill:
  use arg obj, ar, obj~name, ar[1]
  return

::attribute name

[instr.use.reference]

A target written with a < before its name is an alias of a variable of the caller. The caller passes the variable as a reference, a < or a > before its name in the call (the reference rule), and the target is then the same variable: a value read through it is the caller's, and an assignment changes the caller's variable. The target needs a reference as its argument, and a plain value raises SYNTAX 88.928. The argument must not be omitted, which raises SYNTAX 88.931. The alias name must not be a variable of the routine that has a value, or the clause raises SYNTAX 98.995. A default after a reference target raises SYNTAX 99.950 when the program is read. The reference that such an argument passes is a VariableReference (its page).

v = 'orig'
call s <v
say v
call try 'plain'
call try
call taken <v
exit

  return

  has = 'a value'
  use arg <has
  say 'ok'
  return
e: say arg() 'args =>' condition('o')~code
  return

[instr.use.default]

A target can be followed by = and a default. When the argument for that position was not passed, the target takes the value of the default, which is evaluated at that moment and only then, after the targets to its left have been filled. An argument of the null string is passed, so it replaces the default. The default is a literal string, a constant symbol such as a number, an environment symbol such as .nil, or an expression in parentheses. Any other text after the = raises SYNTAX 35.1 for a variable symbol and 35.930 for something that is not a single term or has no term at all.

n = 0
call s 1
call s 1, 2
call s , 'x', ''
call bad 'a = b'
call bad 'a = 1 + 2'
call bad 'a ='
call bad 'a = (1 + 2)'
exit

  return

  return 'tick' n

  return

USE STRICT ARG

[instr.use.strict]

USE STRICT ARG fills the targets as USE ARG does, after it has checked the number of arguments. A target with no default is required, and a target with a default is optional, so the number of arguments passed must not be smaller than the number of required targets, and must not be greater than the number of targets. A position that is left empty counts, but trailing positions left empty do not, in the sense of the ARG builtin. A required position that is left empty is a third fault. In a program, an internal routine or an external routine the three faults raise SYNTAX 40.3, 40.4 and 40.5; in a method they raise SYNTAX 93.901, 93.902 and 93.903. A required target may follow an optional one: the count must still reach it. Without a target the clause demands no argument at all.

call s
call s 1
call s 1, 2
call s 1, 2, 3
call s , 2
call none
call none 1
call late 1, 2
call late 1, 2, 3
exit

  say arg() 'ok' a b
  return

  use strict arg
  say arg() 'ok'
  return
late: signal on syntax name e
  use strict arg a, b = 'B', c
  say arg() 'ok' a b c
  return
e: say arg() 'args =>' condition('o')~code
  return

[instr.use.ellipsis]

Three periods after the last target of a USE STRICT ARG mean that more arguments may follow, so the upper limit of the count is lifted and the lower limit stays. The arguments beyond the targets are not stored, and the routine reads them with the ARG builtin. The three periods are accepted after USE ARG without strict too, where they change nothing. They must be the last item of the clause: a target after them raises SYNTAX 99.930.

call s 1
call s 1, 2, 3, 4, 5
call s 1, , 3
call s

USE LOCAL

[instr.use.local]

USE LOCAL reverses the division of a method's variables. With it every variable of the method is an object variable, as if it were exposed, except the names the clause lists, which are the method's own. A listed name can be a simple or a stem symbol; a stem lists every compound variable of it. The special variables RC, RESULT, SIGL, SELF and SUPER are never object variables, whatever USE LOCAL lists. A USE LOCAL with no name leaves only these local. The EXPOSE rule says what an object variable is.

o = .box~new
say o~a
say o~b
say o~c
::class box
::method a
  use local keep st.
  keep = 'local'
  st.1 = 'local too'
  shared = 'object'
  call sub
  return symbol('result') symbol('sigl') symbol('keep') symbol('st.1')
sub:
  return 'r'
::method b
  use local
  return symbol('shared') symbol('keep') symbol('st.1') symbol('result'),
    symbol('sigl')
::method c
  use local
  return symbol('shared') shared

[instr.use.local.place]

USE LOCAL must be the first instruction of a method, with only comments and null clauses before it. Any other instruction before it, a label, a USE ARG, an EXPOSE or a second USE LOCAL included, and a position inside a DO or an IF, raise SYNTAX 99.910 when the program is read. An EXPOSE after it raises 99.907, since it is not the first instruction. USE ARG may follow it. In the main program or a routine, USE LOCAL as the first instruction raises SYNTAX 98.993 when it runs, and the text of an INTERPRET raises 99.915 when the INTERPRET runs. A name that is a compound symbol raises 99.948, one that starts with a digit 31.2, and a comma, a string, a parenthesis or an = where a name should be 20.927.

Errors of the clause

[instr.use.syntax]

A fault in the form of the clause is raised when the program is read. USE with no word after it, and USE with a word that is not ARG, STRICT or LOCAL, raise SYNTAX 25.905. STRICT that is not followed by ARG raises 25.929. Two targets that follow each other with no comma raise 46.902. A target that starts with a digit raises 31.2, one that starts with a period 31.3, and a string or a parenthesis in a target's place 89.1. The text of an INTERPRET raises the same errors when the INTERPRET runs.

call try 'use'
call try 'use foo a'
call try 'use strict a'
call try 'use strict arg a b'
call try 'use arg 1'
call try 'use arg .a'
call try 'use arg "x"'
call try 'use arg (a)'
exit
try:
  signal on syntax name e
  interpret arg(1)
  say arg(1) '=> ok'
  return
e: say arg(1) '=>' condition('o')~code
  return

use arg 1 => 31.2
