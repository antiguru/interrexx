The interrexx Language Specification

RAISE

RAISE condition [DESCRIPTION expr] [ADDITIONAL expr | ARRAY (expr, ...)] [RETURN [expr] | EXIT [expr]]

rexxref: Keyword Instructions > RAISE

Deviations: D65

RAISE raises a condition on purpose, and it also ends the code that runs it. The condition is raised in the code that called the code that ended, so the instruction is how a routine or a method reports an event to its caller, whose traps answer it as they answer any condition. SYNTAX and the main program are the exceptions, and so is the text of an INTERPRET with RETURN; this page specifies them. The instruction names the condition, carries the values that the condition object holds, and chooses whether the code ends as RETURN or as EXIT does, which also decides who is the caller.

This page specifies the form of the clause, what each option sets, where the condition is raised for each kind of code, what happens when no trap answers, and the PROPAGATE form that raises a trapped condition again. What a trap does, and what a program reads from a condition, belong to the conditions chapter, and the rules here link the ones they use.

The clause

[instr.raise.form]

RAISE is followed by a condition word: ERROR, FAILURE, HALT, LOSTDIGITS, NOMETHOD, NOSTRING, NOTREADY, NOVALUE, PROPAGATE, SYNTAX or USER, in any case. ERROR and FAILURE then take a code, SYNTAX takes a number and USER takes a name, and the other words take nothing. The options come after that, in any order, each at most once: DESCRIPTION and an expression, ADDITIONAL and an expression or ARRAY and a parenthesized list of expressions (the two are one option, so a clause has at most one of them), and RETURN or EXIT with an optional expression (again one option). The code, the number and the expression of an option are each one term: a literal string, a constant symbol, an environment symbol or an expression in parentheses. A variable symbol is not a term here, so its value is written in parentheses. A RETURN or EXIT that has no expression ends the clause: any option after it is read as its expression. ANY is not a condition word, because the names rule says that nothing raises it.

call on user alpha name h
call on user beta name h
call on error name h
call on notready name h
signal on syntax name s
do i = 1 to 5
  call ('R'i)
end
exit
h: say 'h' condition('c') '['condition('d')']',
     condition('o')~hasindex('ADDITIONAL')
  return
s: say 'syntax' condition('o')~code
  exit
::routine r1
  RAISE USER Alpha
::routine r2
  raise user beta additional ('x') description 'two words'
::routine r3
  raise error 5 description ('a' || 'b') additional (.nil)
::routine r4
  raise notready description 'late' array (1, 2) return
::routine r5
  raise user alpha return 'v' description 'rv'

[instr.raise.errors]

A RAISE clause that breaks the form is an error found while the program is read. Nothing is raised: the clause is not part of a program that runs, as the reading rule says, and the same error is an ordinary SYNTAX condition in the text of an INTERPRET. The error is 20.914 when nothing follows RAISE, 25.906 when the word after it is not a condition word, 20.915 when USER has no symbol after it, and 35.1 when a code or number is missing or is not a term, or when a RETURN or EXIT without an expression is followed by another option, which it then reads as its expression. A missing expression after DESCRIPTION or ADDITIONAL is 35.922 or 35.923, and an ARRAY without its opening parenthesis is 35.924. An ARRAY list whose parenthesis is not closed is 36.901. The options that appear twice are 25.908 for DESCRIPTION, 25.909 for ADDITIONAL or ARRAY together, whichever two they are, and 25.911 for RETURN or EXIT together. Any other word after the options is 25.907.

What each condition takes

[instr.raise.condition]

Each condition word raises the condition of that name, and the clause sets what the condition word takes. ERROR and FAILURE take a code, which is any string: the text of the literal, of the constant symbol in upper case, or of the value of the parenthesized expression, with no check that it is a number. The code is the value that RC has in the code that answers the condition, as the rule for RC says. The RC entry of the condition object holds the code itself: when the parenthesized expression is an object that is not a string, the entry holds that object, and so does the variable RC in the code of the trap. The user conditions take a name, which the name rule specifies. HALT, LOSTDIGITS, NOMETHOD, NOSTRING, NOTREADY and NOVALUE take nothing, and the condition has the entries that the entries rule lists for a condition that an instruction raised.

names = 'HALT LOSTDIGITS NOMETHOD NOSTRING NOTREADY NOVALUE'
do w over names~makearray(' ')
  call go w
end
call go 'ERROR 12'
call go 'FAILURE 13'
call go 'USER plain'
exit

  return

[instr.raise.number]

The number of RAISE SYNTAX is a major error number from 1 to 99, which may be followed by a point and a subcode from 0 to 999. It is read from the text of the value, and the digits after the point are one whole number, so 40.3, 40.003 and 040.03 are the error 40.3, and 40.030 is the subcode 30. A number without a point is the error of that number with the subcode 0. The CODE entry of the condition holds the number as m.n, and the RC entry holds the major number. A number of digits, or of digits, a point and digits, that no error has raises SYNTAX 98.941. The null string, a minus sign, a letter that is not the exponent of a number, a second point, a point with no digit on one side of it, a major number outside 1 to 99 and a subcode above 999 raise SYNTAX 33.904. The text of any other form, such as a number with a plus sign, with blanks in it or with an exponent, is not specified. The error 33.904 is a fault of the clause itself, so it is raised in the code that holds the RAISE, as an error found at that clause would be, whichever option ends the clause. The error 98.941 is a SYNTAX condition that the clause raises, like the condition that the clause names: it goes where the RETURN rule puts it, and with EXIT where the EXIT rule puts it.

[instr.raise.syntax]

A SYNTAX condition that RAISE raised holds, besides CODE and RC, the description that DESCRIPTION gave, which is the null string without it. Its ADDITIONAL entry is always an array, whatever the clause gave: the array is empty when the clause has neither ADDITIONAL nor ARRAY, it is the array of ARRAY's values, and it is the value of ADDITIONAL made an array, where an array stays as it is, a string becomes an array of one item and a list becomes an array of its items. The null object .nil and an instance of the class Object cannot be made an array, and an ADDITIONAL with such a value raises SYNTAX 98.939 in the raising code, as the SYNTAX rule says; whether an object of any other class is converted is not specified. The values of the array are what the message of the error names, and the text of the message is not specified. Every other condition has the entry only when the clause gave one, as the rule for the options says.

[instr.raise.additional]

ADDITIONAL gives the object of the ADDITIONAL entry, any object, and ARRAY gives an array of the values of its list, whose items may be omitted, and which may be empty. A condition that neither option accompanies has no ADDITIONAL entry, except SYNTAX, which always has one. The entry is what CONDITION('A') answers. An ADDITIONAL that holds the null object .nil is still present. An ADDITIONAL belongs to the clause that gave it: a RAISE that no trap answers leaves nothing for the condition that is raised next.

[instr.raise.order]

The expressions of the clause are evaluated before anything is raised, in the code that holds the RAISE and with its variables, in a fixed order that does not depend on the order of the options: the code or the number first, then the DESCRIPTION expression, then the ADDITIONAL expression or the ARRAY list from left to right, and last the RETURN or EXIT expression. A name of a user condition is not evaluated. When the number of a RAISE SYNTAX is not valid, the number is checked as soon as it is evaluated, and the error 33.904 of the number rule is raised before the DESCRIPTION, ADDITIONAL, ARRAY, RETURN and EXIT expressions are evaluated.

call on error name h
call on user foo name h
call one

[instr.raise.exit]

[instr.raise.interpret]
