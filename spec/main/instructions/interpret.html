The interrexx Language Specification

INTERPRET

INTERPRET expression

ANSI: 6.3.2.62, 8.3.10; rexxref: Keyword Instructions > INTERPRET

Deviations: D51, D66, D76

INTERPRET evaluates an expression and runs the string that results as instructions, at the place where the INTERPRET stands. The instructions of the text are those of the clause's own routine, method or program: they read and assign its variables, take its arguments and use its settings. The text is program text without a file around it, so it has no lines and no labels, and it must hold only whole constructs. This page specifies what the text may hold, how it is run, how control leaves it and what errors it raises.

Running the text

[instr.interpret.run]

INTERPRET evaluates its expression, takes the string value of the result and runs it as a sequence of clauses, from the first to the last. When the last has run, the clause after the INTERPRET runs. The text may hold any instruction, including another INTERPRET, and the instruction may be written in any case, over any number of clauses separated by semicolons. The expression is an ordinary expression, so a text is often built from pieces.

slot = 'total'
interpret slot '= 6 * 7'
say total
interpret 'p = 1; q = p + 1'
say p q
interpret 'say' 1 + 1
interpret 'do 2; say "loop"; end'
interpret 'interpret "z = 9"'
say z

[instr.interpret.empty]

A text that holds no clause, because it is the null string, blanks, one or more comments or a bare semicolon, does nothing. An INTERPRET with no expression after the keyword raises SYNTAX 35.912, which a program file raises when it is read, so that it runs nothing and exits with 221. An error in the expression is raised before any text is read.

interpret ''
interpret '   '
interpret '/* only a comment */'
interpret '-- a line comment'
interpret ';'
say 'nothing happened'
signal on syntax name e
interpret 1 / 0
e: say condition('o')~code
call try 'interpret'
exit

  interpret arg(1)
  say 'ok' arg(1)
  return

  return

Scope

[instr.interpret.scope]

The text runs in the scope of the code that holds the INTERPRET. A variable that the text sets is set for the code after the INTERPRET, a variable that the text drops is dropped, and the text reads the arguments of the routine through ARG and PARSE ARG. In a method, the text sees the object variables that the method exposed and the method's SELF. A NUMERIC setting that the text makes stays in force for the code after the INTERPRET, and so does an ADDRESS setting.

numeric digits 12
interpret 'numeric digits 5; v = 1 / 3'
say digits() v
call sub 'one', 'two'
say digits() v
o = .box~new
o~go
exit
sub:
  interpret 'say arg(1) arg(2) arg()'
  interpret 'parse arg p, q; w = p || q; numeric digits 3'
  say p q w digits()
  interpret 'drop p'
  say symbol('p') symbol('w')
return
::class box
::method init
  expose n
  n = 5
::method go
  expose n
  interpret 'n = n + 1; say n self~class~id'
  say n

Translation and running

[instr.interpret.whole]

The text is read as a whole before its first clause runs. An error of the kind that a program file raises when it is read, such as an expression that cannot be read, an unterminated string or comment, a label, a directive or an unbalanced construct, is raised before any clause of the text runs, so the clauses before the faulty one do nothing. An error that a clause raises when it runs, such as a zero divisor or a missing routine, is raised when that clause runs, and the clauses before it have run.

call try 'say "first"; say 2 +'
call try 'say "first"; say "open'
call try 'say "first"; say 1 2 )'
call try 'say "first"; end'
call try 'say "first"; x = 1 / 0'
call try 'say "first"; call nosuchroutine'
call try 'say "first"; signal nolabel'
call try 'say "first"; if 2 then nop'
exit
try:
  signal on syntax name e
  interpret arg(1)
  say 'ok' arg(1)
  return
e: say condition('o')~code '<=' arg(1)
  return

[instr.interpret.lines]

The text has no line ends. A line feed or a carriage return in it, which is what a program file would read as the end of a line, raises SYNTAX 13.1 when the text is read, and so does a result that the conversion makes into several lines, such as an Array. A -- comment therefore runs to the end of the whole text and hides what follows it, even after a semicolon, and a comma at the very end of the text is accepted.

call try 'say 1' || '0a'x || 'say 2'
call try 'say 1' || '0d'x || 'say 2'
call try 'say 3 -- c; say 4'
call try 'say 5,'
call try 'interpret .array~of("say 6", "say 7")'
exit

[instr.interpret.complete]

Every DO, IF and SELECT that the text opens must end inside it, and the text may not hold the end of a construct that began outside it. A simple DO with no END raises SYNTAX 14.1, a SELECT with no END 14.2, and a loop with no END 14.5. An IF with no THEN raises 18.1, a THEN with no instruction after it 14.3 and an ELSE with none 14.4. An END with no construct to end is a part out of place, and so is an END that would close a loop around the INTERPRET. A THEN, an ELSE, a WHEN and an OTHERWISE with no IF or SELECT before it are too. Complete constructs run as they do in a program.

interpret 'if 1 then say "t"; else say "e"'
interpret 'select; when 0 then say 0; otherwise say "o"; end'

Leaving the text

[instr.interpret.transfer]

An instruction of the text that moves control moves it for the code that holds the INTERPRET. A RETURN returns from that routine or method with its value, or ends the program, and the clauses after the INTERPRET do not run. An EXIT does what it would do where the INTERPRET stands, as the EXIT rules say. In the main program and in an internal routine of it, it ends the program with its value as the exit code. In a method or a ::ROUTINE, it ends only that unit, and the value goes to the sender or the caller as the rule for a unit says. A SIGNAL to a label of the program leaves the text and any active DO, IF or SELECT, and sets SIGL to the number of the line of the INTERPRET clause, as it would for a SIGNAL written there.

say f(5)
call sub
say 'sigl' sigl result
interpret 'signal lab; say "no"'
say 'not run'
lab: say 'at lab' sigl
say 'method' .box~new~run
say 'routine' later()
interpret 'exit 3'
say 'not run'
f: interpret 'return arg(1) * 2'
say 'not run'
sub: return 'from sub'
::class box
::method run
  interpret 'exit "from method"'
  say 'not run'
::routine later
  interpret 'exit "from routine"'
  say 'not run'

[instr.interpret.loop]

A LEAVE or ITERATE in the text refers to a loop that the text itself holds. A loop of the code around the INTERPRET is out of reach: the instruction raises SYNTAX 28.1 for a LEAVE and 28.2 for an ITERATE with no name, and 28.3 and 28.4 when the instruction names a loop, even in the body of a loop. A simple DO group is not a loop, as the LEAVE rule says. The text may not hold a PROCEDURE, an EXPOSE, a USE LOCAL, a GUARD, a FORWARD or a REPLY. Each page says what it raises there. In the example, an EXPOSE and a REPLY raise when the text is read, so that no clause of the text runs.

Errors

[instr.interpret.error]

An error in the text is a SYNTAX condition raised at the INTERPRET clause. SIGL is the number of the line on which that clause begins, whichever line of the text the error is in and however many lines the clause spans. A program that does not trap the condition ends with the exit code that the error gives, as for any other error.

interpret 'say 1; x = 1 / 0'

[instr.interpret.deviation.76]

The condition object of a SYNTAX error that arises while the text is translated names the package that holds the INTERPRET. The object that its PACKAGE method answers is the one that .context~package answers in the code. In ooRexx the object is another package that has the same name.

signal on syntax name e
interpret 'say 1 +'
e: c = condition('o')
say c~code (c~package == .context~package)

[instr.interpret.deviation.51]

Inside the text, .RS and .CONTEXT~RS answer the same value: the return code that a command in the text has just set. In ooRexx the method answers the value that the caller had before the INTERPRET until the text ends, and .RS answers the new value at once.

'true'
interpret '"false"; say .rs .context~rs'
say .rs .context~rs

[instr.interpret.deviation.66]

A trap that SIGNAL ON enabled, and whose label does not exist, raises SYNTAX 16.1 when its condition occurs, as the conditions chapter specifies. When the condition occurs in the text of an INTERPRET, the condition has one stack frame, of the type PROGRAM, and its name is the name of the program. In ooRexx the name of that frame is the null string.
