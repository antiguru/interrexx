The interrexx Language Specification

ADDRESS

ADDRESS [name | VALUE expression | (expression)] [command] [WITH redirection]

ANSI: 6.3.2.21, 8.3.1; rexxref: Keyword Instructions > ADDRESS

Deviations: D52

ADDRESS chooses the environment that receives the commands of a program, and it can also send a single command to another environment, and redirect where a command reads its input and writes its output. This page specifies the forms of the instruction and the redirections. The environment that is current, the name that the ADDRESS function answers, the swap of the current and the previous environment and the scope of both across calls are specified with that function, and the page links them. What a command is, how it is evaluated and sent and what its return code is belong to the commands page. The environments that exist, other than the one that runs commands in the host's shell, belong to the environment chapter.

The examples use the name system for that shell and, in a few, names of environments that do not exist, because the result of the instruction shows in the ADDRESS function.

The forms

[instr.address.form.name]

ADDRESS name makes name the current environment, and the environment that was current the previous one, as the swap rule says. The name is one symbol or one string, and the function's name rule says which characters it has. A symbol is not looked up as a variable. The instruction sends no command.

system = 'other'
address system
say address()
address Foo.Bar
say address()

SYSTEM
FOO.BAR
[instr.address.form.value]

ADDRESS VALUE expression takes the value of the expression as the name, as the function's name rule says. The expression is what follows VALUE, up to a WITH that is not inside parentheses, so a variable named with cannot end it and ADDRESS VALUE WITH has no expression. The word VALUE may be left out when the expression starts with a parenthesis, so that ADDRESS (expression) is the same instruction; the expression is then what follows, up to that WITH, and not only the part in parentheses.

x = 'dyn'
address value x 'env'
say '['address()']'
address (x 'foo')
say '['address()']'
address (x) 'bar'
say '['address()']'
call try "address value 'a' with"
call try "address value ('a' with)"
call try "address value 'a' || with"
call try "address value with"
exit
try: procedure
  signal on syntax name e
  interpret arg(1)
  say arg(1) '->' '['address()']'
  return
e: say arg(1) '->' condition('o')~code
  return

[dyn foo]
[dyn bar]
address value 'a' with -> 20.933
address value ('a' with) -> [a WITH]
address value 'a' || with -> 35.1
address value with -> 35.914
[instr.address.form.bare]

ADDRESS with nothing after it swaps the current and the previous environment, as the swap rule says. It sends no command.

address first
address second
address
say address()
address value 'third' with output normal
say address()
address
say address()

[instr.address.command]

ADDRESS name expression has a symbol or a string for the name, and whatever follows it, up to a WITH that starts a redirection, is an expression. It is evaluated as the expression of a command is, and its value is sent to the named environment as one command. The current environment and the previous one stay as they were, so the function answers the same name after the command. RC is set as the commands page says. An error in the expression raises that error and sends nothing.

address first
address system 'exit 2'
say rc address()
address "system" 'exit' 1 + 2
say rc address()
signal on syntax name e
address system 'exit' + 1
e: say condition('o')~code address()

2 FIRST
3 FIRST
41.1 FIRST

Redirection

[instr.address.with.syntax]

A clause of the forms above may end with WITH and one to three redirections, in any order, each introduced by INPUT, OUTPUT or ERROR and each used at most once. The redirection is then one of NORMAL; STEM followed by a stem symbol, which ends in a period; or STREAM or USING followed by an expression in parentheses, a string, a constant symbol or an environment symbol, where STREAM names a stream. A plain variable symbol after STREAM or USING is not one of these. OUTPUT and ERROR may put APPEND or REPLACE before STEM, STREAM or USING, and replace is meant when neither is written. The keywords may be in any case. The word WITH directly after ADDRESS is the name of an environment and not the keyword, so ADDRESS WITH OUTPUT NORMAL sends the command OUTPUT NORMAL to the environment WITH.

address first
i.0 = 1
i.1 = 'z'
address system 'cat' with Error stem e. OUTPUT append stem o. input stem i.
say o.0 o.1
address with output normal
say rc address()

1 z

[instr.address.with.normal]

NORMAL is no redirection: the command reads and writes the program's own standard input, output and error, as a command does with no redirection at all.

address system with output stem o.
address system 'echo kept' with output normal
say symbol('o.1')

kept
LIT
[instr.address.with.stem]

STEM name. reads or writes the lines of a stem. For input, the stem's 0 tail holds the number of lines and the tails 1 to that number hold them. For output and error, a replace clears every tail of the stem, keeps the default value of the stem, and then sets the tails 1 and up and the tail 0, which holds the number of lines. An append keeps the stem and numbers the lines after the number that its 0 tail holds. A line is the text up to a line end, without it; a carriage return directly before a line feed is not part of the line, text after the last line end is a line, and an empty line is kept. An input line that holds a line feed is sent as it is, and the command reads it as two lines.

address system 'echo a; echo; echo c d' with output stem b.
say b.0 '['b.1']' '['b.2']' b.3
o.0 = 3
o.3 = 'old'
address system 'echo m' with output stem o.
say o.0 o.1 symbol('o.3')

say a.0 a.1 e.0 e.1
i.0 = 2
i.1 = 'l1'
i.2 = 'l2'
address system 'cat' with input stem i. output stem o.
say o.0 o.1 o.2
o.0 = 5
address system 'echo n' with output append stem o.
say o.0 o.6
address system 'printf "p\r\nq"' with output stem c.
say c.0 c2x(c.1) c2x(c.2)
j.0 = 1
j.1 = 'u' || '0a'x || 'v'

say c.0 c.1 c.2

[instr.address.with.stem.count]

The 0 tail of an input stem is the number of lines, a whole number of zero or more, in any form that the whole-number form allows and whose value is whole: 1.0, 1e0, +1 and ' 1 ' are 1. A 0 tail that was not assigned raises SYNTAX 98.998, and the default value of the stem does not count as an assignment. One that is not a whole number of zero or more raises SYNTAX 26.904; so does a count too large to be a number of lines, such as one of twenty digits. The NUMERIC DIGITS setting plays no part, and the error is not the SYNTAX 40.12 of the digits rule. A count of 0 sends nothing, and a tail from 1 to the count that is not set sends the stem's own default value, which for a stem that was never assigned is the stem's name with its period. For an append, a 0 tail that was not assigned, or that holds only the default value of the stem, counts as 0; any other 0 tail is checked as for input, and SYNTAX 26.904 is raised for a bad one.

[instr.address.with.stream]

STREAM names a stream by the name that the stream functions take. An output or error stream is written with the lines of the command, and a replace empties it first. A command with an input stream reads the lines of the stream.

[instr.address.with.using]

For output and error, USING names the object that receives the lines. An ordered collection, an Array, a List, a Queue or a subclass of one, gets each line by the message APPEND, after it is emptied, by the message EMPTY, when the redirection is a replace. A RexxQueue object gets each line by the message QUEUE. A Stem object, an object of the Stem class itself and not of a subclass, is written as STEM writes a stem: a replace clears it and sets the tails 1 and up and 0, and an append numbers the lines after its 0 tail. A stream object, an object of an OutputStream or InputOutputStream class (a .Stream among them), gets each line by LINEOUT; it takes neither REPLACE nor APPEND, and either raises SYNTAX 98.997. Any other object, a string, .nil, a Set, a Directory, a Bag, a MutableBuffer, an object of a subclass of Stem, an object of an InputStream class that is not also an OutputStream, and an object of a class of the program that has an APPEND method of its own, raises SYNTAX 98.996 when the command is about to be sent, whether or not the command would have written anything.

address system 'echo b1' with output append using (a)

[instr.address.with.using.input]

For input, USING names the source of the lines. A string is one line, and so is a MutableBuffer, by its string value. A Stem object, of the Stem class itself, is read as STEM reads a stem. [instr.address.with.once]

A redirection written on a clause with a command applies to that command and to no other. The streams the clause does not name keep what they had, which is the setting of the earlier clauses.

[instr.address.with.set]

A clause with a redirection and no command sets the redirection of the environment that it names, and makes that environment current as ADDRESS name does. The commands sent to that environment from then on use the setting, until another such clause names the same environment. It sets all three streams at once: a stream the clause does not name goes back to NORMAL. A name without WITH makes an environment current with the setting it last had, or with none when it never had one, and the swap of the current and the previous environment brings an environment back with its setting. The environment is the same whatever the case of its name. The setting of one environment does not touch the commands that another receives. The stem, the stream expression or the USING expression is kept as it was written and is evaluated again when each command is sent, in the variables of the code that sends it.

address system with output stem b.

[instr.address.with.error]

Syntax that does not fit the forms is found when the program is read, so a program file with one writes nothing and ends with the return code of the error. The subcodes show in INTERPRET text. SYNTAX 35.914 is VALUE with no expression. SYNTAX 20.933 is WITH with nothing after it, and SYNTAX 20.932 is STEM with no stem symbol. SYNTAX 25.933 is a word that is not a type where the type is due, among them APPEND or REPLACE before NORMAL or before an input type, and the end of the clause; SYNTAX 25.930, SYNTAX 25.931 and SYNTAX 25.932 are INPUT, OUTPUT and ERROR named twice, and SYNTAX 25.934 is a word where INPUT, OUTPUT or ERROR is due. SYNTAX 35.935 is STREAM or USING with no expression, and SYNTAX 35.1 is a plain variable symbol after either.

Scope

[instr.address.scope]

The redirections of the setting rule have the scope that the current environment has, and the scope rules of the function say it. An internal routine starts with the caller's redirections, a stem it names is the one in its own variables, and the caller has its own redirections back when the routine returns. A routine with PROCEDURE and no EXPOSE therefore fills a stem of its own and leaves the caller's stem as it was. A method, and a ::ROUTINE, starts with none, so its commands read and write the program's own streams. Code run by INTERPRET shares them.

address system with output stem o.
call plain
say 'A' o.0 o.1
call inherit
say 'B' o.0 o.1
say .o~new~m
say 'C' o.0 o.1
interpret "'echo int'"
say 'D' o.0 o.1
call plain2
'echo back'
say 'E' o.0 o.1
call hid
say 'F' o.0 o.1
exit

  'echo plain'
  address system with output normal
  'echo plainnormal'
  return
inherit: procedure expose o.
  'echo inherit'
  return
hid: procedure
  'echo h'
  say 'hid' o.0 o.1
  return
plain2:
  address system with output stem p.
  'echo plain2'
  return

::method m

Deviations

[instr.address.deviation.52]

When a write of a command's output or error raises a condition, as the message APPEND to a collection or LINEOUT to a stream object may, the condition is raised whatever return code the command answered. ooRexx raises it only when the command answered 0, and ends the clause with the return code otherwise. The example shows the interrexx output; ooRexx shows ok 1.

signal on syntax name e
address system 'echo x; exit 1' with output using (.bad~new)
say 'ok' rc
exit
e: say 'caught' condition('o')~code rc
