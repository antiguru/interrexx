The interrexx Language Specification

DO

DO [LABEL name] [COUNTER name] [repetitor] [conditional]; instructions; END [name]

ANSI: 6.3.2.12, 8.3.6; rexxref: Keyword Instructions > DO

Deviations: D1, D25, D26, D38, D47, D118

DO opens a block of instructions that ends at a matching END. Without anything after the keyword it groups the clauses so that they stand where the language expects one instruction. With a repetitor, a condition, or both, it runs the block again and again: a number of times, for ever, with a variable that steps through a range, or once for each item of a collection. This page specifies each form, the order in which the parts of the clause are evaluated, the tests that end a loop, the value that the control variable has afterwards, and the errors. LOOP is the same instruction under another keyword, and LEAVE and ITERATE steer a loop from inside.

The clause has one of these shapes, where each part in brackets is optional. The LABEL and COUNTER phrases come first, in either order. Then comes at most one repetitor, which is a count, FOREVER, name = expression with TO, BY and FOR phrases, name OVER expression, or WITH with an INDEX and an ITEM phrase and OVER expression. Then comes at most one WHILE or UNTIL phrase. The block follows, and END closes it.

Groups

[instr.do.group]

A DO with nothing after the keyword, or with only a LABEL phrase, is a simple group. The interpreter runs the clauses between the DO and its END once, in order, and no variable changes because of the DO. A group lets several clauses stand in the place of one, as the branch of an IF does. It is not a loop, so a LEAVE or an ITERATE with no name does not see it, as the LEAVE rule says, while a LEAVE that names its label does leave it.

x = 1
if x = 1 then do
  say 'one'
  say 'still the first branch'
end
else say 'two'
do; say 'bare'; end
do label blk
  say 'labelled'
  leave blk
  say 'skipped'
end blk
say 'done'

Counts and endless loops

[instr.do.count]

DO expression runs the block a fixed number of times. The expression is evaluated once, when the DO is reached, and its value is the number of passes, so a later assignment to a variable of the expression changes nothing. The value must be a whole number that is not negative. It may be written with a decimal point or an exponent when that is its value, and it must be below 10 to the power of NUMERIC DIGITS however it is written: at DIGITS 5, 9.9999e4 is a count and 1e5 is not. No count may reach 10 to the power of 18, whatever DIGITS is. Any other value raises SYNTAX 26.2. A count of zero runs no pass and does not raise an error. When LOSTDIGITS is trapped, a count written with more than DIGITS digits raises that condition before the error, if any, as the lost-digits rule describes for an operand.

do n
  n = 1
  say 'pass'
end
do 0
  say 'never'
end

do 1e1; k = k + 1; end

[instr.do.forever]

DO FOREVER has no end test of its own, so the block runs until a LEAVE, an EXIT, a RETURN, a SIGNAL or an error ends it. It may be followed by a WHILE or an UNTIL phrase, which the condition rules cover. Anything else after FOREVER raises SYNTAX 27.901, because the clause is read before it runs. LOOP with nothing after it is the same endless loop.

n = 0
do forever
  n = n + 1
  if n = 4 then leave
end
say n
do forever while n < 6
  n = n + 1
end
say n
call try 'do forever forever; end'
call try 'do forever 2; end'
call try 'do forever to 2; end'
exit

Controlled loops

[instr.do.control]

DO name = initial [TO limit] [BY step] [FOR count] is a controlled loop. The three phrases come in any order after the initial expression, each at most once, and a repeated phrase raises SYNTAX 27.902. The interpreter evaluates the initial expression and then the phrases in the order written, each exactly once, and only after all of them does it assign the initial value to the control variable. A phrase therefore sees the variables as they were before the loop, even name itself, and nothing the block does to a variable of a phrase affects the loop. A missing STEP is 1. A missing LIMIT means that no limit ends the loop, and a missing COUNT means that no count does. A control variable written as a string is not specified.

do i = f('init', 1) to f('to', 3) by f('by', 1) for f('for', 5)
  say 'body' i
end
say '--'
do i = f('init', 1) for f('for', 2) to f('to', 9) by f('by', 1)
  say 'body' i
end
say '--'
i = 3
do i = 1 to i + 2 by i - 1
  say 'i' i
end
say '--'

[instr.do.control.check]

The interpreter checks each value when it has evaluated that expression, and before it evaluates the next, so the first fault in the written order is the one that is reported. The initial value, the LIMIT and the STEP must be numbers, and the first that is not raises SYNTAX 41.1. The COUNT must be a value that the count rule accepts, and raises SYNTAX 26.3 when it is not. The initial value is taken as the prefix + would answer it, so it is rounded and written like the result of an operation: blanks go, an exponent is written out as a result would show it, and the digits are cut to NUMERIC DIGITS, but a trailing zero after the point stays.

[instr.do.control.step]

After each pass the interpreter adds STEP to the control variable, with the rules of addition at the current NUMERIC settings, and then decides whether to run another pass. No pass runs when FOR has counted out. No pass runs either when the control variable has passed LIMIT, which for a STEP that is zero or positive means that it is greater, and for a negative STEP that it is smaller. The comparison is a numeric one, so NUMERIC FUZZ applies to it. A STEP of zero is treated as a positive one, so it never moves the variable and ends the loop only through FOR, a condition, a LEAVE, or an initial value beyond LIMIT. The test happens before the first pass too, so a loop can run no pass at all.

do i = 5 to 1 by -2; say i; end
do i = 3 to 1; say 'never' i; end

[instr.do.control.after]

When the loop ends, the control variable holds the value that it last had. If a pass ran to its end and the step and the tests ended the loop, that is the value after the last step, which is one step beyond the last value that the block saw. If a LEAVE ended the loop, it is the value the block saw. If the tests ended the loop before the first pass, it is the initial value. A WHILE that fails ends the loop with the stepped value, and an UNTIL that holds ends it before the step, so it keeps the value of the last pass.

do i = 1 to 3; end; say i
do i = 1 to 3; leave; end; say i
do i = 5 to 1; end; say i
do i = 1 for 2; end; say i
do i = 1 to 3 while i < 2; end; say i
do i = 1 to 3 until i = 2; end; say i

[instr.do.control.body]

The control variable is an ordinary variable that the block can read and assign. The step adds to the value that the variable has then, so an assignment in the block moves the loop, and a value that is not a number, or a variable that was dropped, raises SYNTAX 41.1 at the step. When the control variable is a compound symbol, its tail is worked out again each time that the loop uses the variable, from the values of the tail variables at that moment, so the block can change which variable the loop steps.

do i = 1 to 5
  say i
  if i = 2 then i = 4
end
say 'end' i

Collections

[instr.do.over]

DO name OVER expression runs the block once for each item that a collection yields, and assigns the item to name before the pass. The expression is evaluated once, before name is assigned, and the loop sends it the message MAKEARRAY, whatever the class of the object is: an instance of a subclass of List is sent it as any other collection is (Deviation 118). The items are those of the Array that comes back, in its order, and they are taken when the loop starts, so a change to the collection during the loop does not add, remove or alter an item that the loop visits. An Array yields its items in index order and skips an index that holds none, and a List and a Queue yield theirs from first to last. A String yields its lines, so a null string yields none. A Stem, a Directory and a Table yield their indexes, which for a Stem are the tails of the existing compound variables, and a Set yields its members. The order of those four is not specified, as Deviation 1 says for a Stem and Deviation 33 for the others. A collection that yields nothing leaves name as it was, and otherwise name holds the last item after the loop.

a = .array~of('x', 'y', 'z')
do e over a
  say e
end
say 'e' e
do e over .list~of(1, 2)

[instr.do.with]

DO WITH INDEX name ITEM name OVER expression runs the block once for each entry of a collection, and assigns the index and the item of the entry. The two phrases come in either order, and one or both may be left out. With neither, the loop is an OVER loop that assigns nothing: it behaves as the OVER rules say, and the sentences below about SUPPLIER do not apply to it. With INDEX or ITEM, the loop sends the value of the expression the message SUPPLIER and walks the Supplier that comes back, assigning the index first and the item after it, so that a variable named by both ends up holding the item. The entries are taken when the loop starts. A FOR phrase limits the number of entries as it does in an OVER loop. A phrase repeated raises SYNTAX 27.902. WITH starts this form only when INDEX, ITEM or OVER follows it, and such a clause with no OVER raises SYNTAX 27.904. An object that does not answer SUPPLIER raises SYNTAX 97.1, and an answer that is not a Supplier raises SYNTAX 98.994.

a = .array~of('x', 'y', 'z')
do with index ix item it over a
  say ix it
end
do with item it index ix over a for 2
  say ix it
end
do with index ix over a
  say 'index' ix
end
do with index i item i over a
  say 'same' i
end
do with over a
  say 'bare'
end

Conditions

[instr.do.while]

A WHILE phrase ends the loop when its expression is false. It is tested before every pass, after the step and the LIMIT and FOR tests of a controlled loop and after the item of an OVER or WITH loop was assigned, so the expression sees the control variable of the pass that it guards. A WHILE that is false the first time runs no pass. The expression must be a logical value, and a value that is not 0 or 1 raises SYNTAX 34.3. The list form WHILE a, b follows the list rule of IF: the expressions are evaluated from left to right up to the first that is false, and an expression that is evaluated and is not 0 or 1 raises SYNTAX 34.6. WHILE and UNTIL cannot both appear in one clause, and the attempt raises SYNTAX 27.1.

Counting passes

[instr.do.counter]

A COUNTER phrase names a variable that holds the number of the current pass. The variable is set to zero before the expressions of the repetitor are evaluated, so they can read it, and then to 1, 2, and so on at the start of each pass, once the tests have decided that the pass runs. A test of WHILE therefore sees the number of the previous pass. An assignment to the variable in the block does not disturb the count, which the loop keeps itself, so the next pass sets the variable again. After the loop the variable holds the value that the last pass left in it: the number of that pass unless the block assigned the variable. The phrase belongs to a loop and not to a simple group, and a COUNTER on a DO with nothing else raises SYNTAX 27.905. The name may be a compound symbol, and it comes before any repetitor.

Labels and the end of a block

[instr.do.label]

A LABEL phrase gives the block a name that LEAVE, ITERATE and END can use. The name is the label when the block has a LABEL phrase, and otherwise the control variable of a controlled loop or of an OVER loop. A block with neither has no name. The interpreter compares a name to the names in those clauses without regard to case, and a compound symbol matches by its text, without working out the tail. Once a block has a LABEL, the name of its control variable no longer names it, so LEAVE, ITERATE and END have to use the label. When two active blocks have the same name, the name means the innermost. The phrase works on every form, a simple group included. It comes before any repetitor, and in either order with COUNTER. A LABEL phrase does not create a label for CALL or SIGNAL. A LABEL with no symbol after it, or with a string there, raises SYNTAX 20.918.
