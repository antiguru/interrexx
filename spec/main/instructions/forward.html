The interrexx Language Specification

FORWARD

FORWARD [TO expr] [MESSAGE expr] [ARGUMENTS expr | ARRAY (expr, ...)] [CLASS expr] [CONTINUE]

rexxref: Keyword Instructions > FORWARD

FORWARD sends again the message that started the running method, with parts of it changed: the object that receives it, the name, the arguments, or the class where the search for the method starts. It is the way for a method to hand its work to another object or to the method it overrides. Without CONTINUE the running method is over once the message has been sent, and the answer of the forwarded message is the answer of the first one. This page specifies the options, what is kept of the original message, what comes back and where errors go, the places where FORWARD may stand, and the errors of the clause.

The message that is sent

[instr.forward.options]

The options may come in any order, and each may be given once. TO gives the object that receives the message, and without it the receiver is the object that received the original message. MESSAGE gives the name of the message, which is its string value made upper case, and without it the name is the one of the original message. ARGUMENTS gives the arguments, and ARRAY gives them as a list of expressions in parentheses, where an expression left out is an argument that is left empty, and without both the arguments are the ones the original message had. CLASS gives a class at which the search for the method starts, so that the methods of the classes below it are passed over, and without it the search starts at the class of the receiver. CONTINUE is described by its own rule. TO, MESSAGE, ARGUMENTS and CLASS are followed by a literal string, a constant symbol such as a number, an environment symbol such as .nil, or an expression in parentheses. A variable symbol there is not enough.

f = .front~new
say f~hello('x', 'y')
say f~named('p', 'q')
say f~mixed('p', 'q')
say f~withArgs('z')
say f~withArray
say f~noArgs('k')

[instr.forward.nullname]

A message name that is the null string is accepted, whether it is written as a literal such as ('') or comes from a variable that holds the null string. The message with that name takes exactly one argument and answers the string value of the receiver followed by the string value of that argument. A FORWARD that sends it with no argument raises SYNTAX 93.903, and one that sends it with two or more raises 93.902, so the literal and the variable behave alike and only the number of arguments decides. Because the forwarding method has ended, a trap in the method does not see the error: the sender of the original message does. With CONTINUE the method is still running, and its own trap sees it. The arguments are those that the rule for the original message names unless ARGUMENTS or ARRAY gives others.

call try '.box~new~lit'
call try ".box~new~lit('a')"
call try ".box~new~var('b')"
call try ".box~new~lit('a', 'b')"
call try '.box~new~var'
call try ".box~new~later('c')"
call try ".box~new~later('c', 'd')"
call try '.box~new~later'
exit

  return
e: say arg(1) '=>' condition('o')~code
  return

[instr.forward.original]

When the arguments are not given, the forwarded message carries the arguments that the original message had when the method was entered, in the same positions, with the positions that the caller left empty still empty. The method's own variables do not change that: an assignment to a variable that USE ARG filled does not change what is forwarded. When no receiver is given, the message goes to the object itself, so a name or a class that differs from the original is needed to stop the message from coming back to the method. A FORWARD that sends the same message to the same object with the same class again sends the original message unchanged, so the method runs again and forwards again; what happens then is not specified.

d = .derived~new
say d~holes(, 'two', , 'four')
say d~keepOrig('orig1', 'orig2')
say d~viaSelf('q')

    else s = s i'=-'
  end
  return s
::method name

::method keepOrig

  forward message 'recv'
::method viaSelf

[instr.forward.arguments]

The value of ARGUMENTS is turned into the list of arguments by sending it the message MAKEARRAY, so an array supplies its items, an empty array no argument, and an item that is missing in an array is an argument that is left empty. A string that is not null and has no line ends is one argument, the null string supplies none, a string of several lines has one argument for each line, and a list supplies its items. A value that cannot be made into an array raises SYNTAX 98.946.

t = .target~new
call try 'array', .array~of(1,,3)
call try 'empty', .array~new
call try 'string', 'a b c'
call try 'null', ''
call try 'lines', 'x'||'0a'x||'y'
call try 'list', .list~of(1, 2)
call try 'nil', .nil
call try 'object', .object~new
exit

[instr.forward.class]

CLASS is the class at which the search for the method starts, so a method of the receiver's own class, or of a class between, is passed over when the class named is above it. The class must be one that the receiver is an instance of: the class of the receiver itself, one of its superclasses or a mixin class that it inherits. A class of the program that the receiver does not belong to raises SYNTAX 93.957, and a value that is not a class raises SYNTAX 88.914. A common use is forward class (super) to run the method that the running one overrides.

What comes back

[instr.forward.end]

Without CONTINUE the running method ends when the message has been sent, so the clauses after the FORWARD do not run. The answer of the forwarded message is the answer of the original message, and when it has none the original has none. A condition that the forwarded message raises is raised in the caller of the method, not in the method: a trap in the method does not see it. If the receiver has no method of that name, the message is an error in the caller in the same way.

d = .d~new
say d~answer
signal on syntax name e
say d~plain
say 'not reached'
e: say 'caller saw' condition('o')~code
::class d
::method answer
  forward to ('abcde') message 'length'
  say 'not run'
::method plain
  signal on syntax name h
  forward to ('abc') message 'nosuch'
  say 'not run'
h: return 'method trapped'

5
caller saw 97.1
[instr.forward.continue]

With CONTINUE the running method does not end: it goes on with the clause after the FORWARD when the forwarded message has been answered. The answer is assigned to RESULT, and when the message has no answer RESULT is dropped, as after a message instruction. A condition that the forwarded message raises is raised in the running method, where a trap can see it. The running method returns its own value, as any method does.

d = .d~new
say d~after
say d~dropped
say d~trapped
::class d
::method after
  forward to ('abc') message 'reverse' continue
  return 'after:' result
::method none
  return
::method dropped
  forward message 'none' continue
  return 'result is' symbol('result')
::method trapped
  signal on syntax name h
  forward to ('abc') message 'nosuch' continue
  return 'not reached'
h: return 'method trapped' condition('o')~code

Where FORWARD may appear

[instr.forward.method]

FORWARD works in the code of a method, anywhere among its own clauses, in a DO, an IF or a SELECT as well. In the main program, in a routine of a ::ROUTINE directive and in an internal routine, including one that a method calls, it raises SYNTAX 98.947 when it runs. The text of an INTERPRET raises SYNTAX 99.923 when the INTERPRET runs, so no clause of the text runs.

o = .box~new
say o~deep
call try 'main'
call try 'internal'
call try 'routine'
say 'inside =>' o~inside
exit
try:
  what = arg(1)
  signal on syntax name e
  if what = 'main' then forward to ('abc') message 'length'
  if what = 'internal' then do; call lab; return; end
  if what = 'routine' then call r
  say what '=> ok'
  return
e: say what '=>' condition('o')~code
  return
lab:
  forward to ('abc') message 'length'
::routine r
  forward to ('abc') message 'length'
::class box
::method deep
  do 1
    if 1 then forward to ('abcd') message 'length'
  end
  return 'never'
::method inside
  signal on syntax name h
  interpret "forward to ('abc') message 'length'"
  return 'no'
h: return condition('o')~code

Errors of the clause

[instr.forward.syntax]

A fault in the form of the clause is raised when the program is read. An option given twice raises SYNTAX 25.917 for TO, 25.922 for MESSAGE, 25.921 for CLASS, 25.919 for CONTINUE, and 25.918 for ARGUMENTS and ARRAY together or either one twice. A word that is not an option, or an item after the last option, raises 25.916. An option with no expression raises 35.925 for TO, 35.927 for MESSAGE, 35.926 for ARGUMENTS, 35.928 for CLASS and 35.924 for ARRAY, which also needs its expressions in parentheses. A variable symbol where an expression is wanted raises 35.1, and a parenthesis that is not closed 36.901. FORWARD with no option at all is accepted.
