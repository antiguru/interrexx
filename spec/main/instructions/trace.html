The interrexx Language Specification

TRACE

TRACE [setting | VALUE expression | (expression)]

ANSI: 6.3.2.85, 8.3.26; rexxref: Keyword Instructions > TRACE; Keyword Instructions > TRACE > The Format of Trace Output

Deviations: D0, D7, D50

TRACE chooses how much of a running program the interpreter reports, and the report is a stream of lines in a fixed format. This page specifies the forms of the instruction, when a new setting takes effect, where the lines go and what each kind of line looks like. The nine settings, what the TRACE function answers and how a setting is scoped across calls belong to the TRACE function, and this page links them instead of repeating them.

The examples that show trace lines first send them to standard output with .traceoutput~destination(.output), because the lines go to the error stream otherwise, and the examples are checked on standard output only.

The forms

[instr.trace.form.name]

TRACE followed by one symbol or one string takes it as the setting. A symbol is never looked up: whatever the variable of that name holds, its own characters, in either case, are the setting. A setting is chosen by its first letter after the prefix, as the letter rule says, so a whole word such as Results does as well as R, and the string 'a' does as well as A.

r = 'I'
trace r
say trace()
trace 'a'
say trace()
trace Results
say trace()
trace "Normal"
say trace()
trace off
say trace()

[instr.trace.form.value]

TRACE VALUE expression evaluates the expression and takes its value as the setting, with the same choice by first letter. A value that is not a string is converted as a string argument says, and .nil is not a setting. VALUE may be left out when the expression starts with a parenthesis, or with an operator character other than +, -, = and ~, so TRACE (expression) is the same instruction; the expression is then the rest of the clause, as it is after VALUE. TRACE = expression is an assignment to the variable TRACE, and TRACE~name a message instruction, as the kinds rule says; neither sets a trace setting. A null value is the setting N. The expression ends the clause, so TRACE VALUE 'l' 'x' takes the value l x, which is the setting L.

r = 'I'
trace value r
say trace()
trace value 'a' || 'c'
say trace()
trace (r)
say trace()
trace ('E')
say trace()
trace value ''
say trace()
trace value 'l' 'x'
say trace()

[instr.trace.form.bare]

TRACE with nothing after it sets N, and so does the null string in any form of the instruction. Where interactive tracing is on, a setting is ignored, as the instruction rule of the function says, except in a line typed at a stop (the rule there); a number in the program still raises the error of the number rule.

[instr.trace.form.interactive]

A question mark before the setting, or alone, turns interactive tracing on or off in the way of the prefix rule: TRACE ? alone flips it and leaves the letter. In the program the instruction cannot turn interactive tracing off, which the function can; in a line typed at a stop it can (the rule there). What a stop reads and what each kind of line does is specified in the debugging chapter; a program run with no input at all goes on after each stop.

say trace()
call trace '?'
say trace()

say trace()

[instr.trace.number]

A setting that is a whole number, written as a symbol, as a string or as the value of an expression, with a sign and blanks around it as a number may have, raises SYNTAX 24.901 in the program. In a line typed at a stop it has a meaning, as the debugging rule says. A value that is not a whole number is not numeric here and is judged by the letter rule as any other, so 1.5 raises SYNTAX 24.1, as does .5. A sign directly after TRACE, followed by one symbol or string, makes a signed number of it: a whole number raises SYNTAX 24.901, and any other operand raises SYNTAX 26.7. A parenthesis after the sign raises SYNTAX 35.1, and data after the number raises SYNTAX 21.906. A sign alone is no number: TRACE - is the bare form, and TRACE + and a second sign after the first raise SYNTAX 35.1.

call try '1.5'
call try '.5'
exit

[instr.trace.syntax]

Data after the setting, other than the expression of VALUE or the rest of a clause that starts as the value rule says, raises SYNTAX 21.906. VALUE with no expression raises SYNTAX 35.916. Both are found when the program is read, so a program file that has one writes nothing and ends with the return code of the error, and the subcode shows only in INTERPRET text.

When it takes effect

[instr.trace.effect]

A clause is traced with the setting that was in force when it began. The TRACE clause itself is therefore traced under the old setting and not the new one: TRACE R after N shows nothing, and TRACE N after R is the last line shown. The setting is in force from the next clause on.

.traceoutput~destination(.output)
trace r
x = 1
trace n
x = 2

     3 *-* x = 1
       >>>   "1"
     4 *-* trace n
[instr.trace.scope]

The instruction changes the setting that the TRACE function reports and changes, and the setting has the same scope: an internal routine starts with the caller's setting and the caller has its own back when the routine returns, wherever the routine changed it.

trace r
call sub
say 'caller' trace()
exit
sub:
  say 'sub' trace()
  trace i
  say 'sub' trace()
  return

sub R
sub I
caller R

Where the lines go

[instr.trace.destination]

Every trace line is written by sending the message LINEOUT to the object that the environment symbol .TRACEOUTPUT holds, with one argument, an object whose string value is the line without a line end. The .TRACEOUTPUT object is a monitor, and by default it writes to the error stream, so a program that traces shows nothing on its standard output. A program sets another destination with the message DESTINATION to .TRACEOUTPUT: any object that understands LINEOUT will do, and .OUTPUT sends the lines to standard output.

trace r
x = 1
say 'done'

done

The format of a line

[instr.trace.line]

A line that shows a clause has the line number right-aligned in six columns, a blank, the flag *-*, a blank, the indentation and the text of the clause. The line number is the program line on which the clause starts, and clauses that share a line share its number. A clause run by INTERPRET carries the line number of the INTERPRET clause, and its text is the text of the string.

.traceoutput~destination(.output)
trace r
x  =  3
y = x + 4 ; z = 'a'  'b'
-- 5
-- 6
-- 7
-- 8
-- 9
w = 10

     3 *-* x  =  3
       >>>   "3"
     4 *-* y = x + 4 ;
       >>>   "7"
     4 *-* z = 'a'  'b'
       >>>   "a b"
    10 *-* w = 10
       >>>   "10"

.traceoutput~destination(.output)
trace r
interpret 'x = 1; y = 2'

     3 *-* interpret 'x = 1; y = 2'
       >>>   "x = 1; y = 2"
     3 *-* x = 1;
       >>>   "1"
     3 *-* y = 2
       >>>   "2"
[instr.trace.text]

The text of a clause is shown as it was written, from its first token on: the blanks between tokens are kept, a comment between tokens is kept, a comment before the first token and a line end are not, and a clause that ends with a semicolon shows the semicolon. A comment before that semicolon is shown, and one after it is not. A comment after the last token on its line, with no semicolon after it, is kept. A clause that ran over several lines, by a continuation or by a comment, is shown on one line with the line ends removed, the comma of a continuation and the blanks that begin the next line kept, and carries the number of its first line. The text of an IF or WHEN clause ends before THEN, so it keeps the blanks that stood before THEN.

trace r
/* lead */ a  =  1 /* mid */ + 2 ;
b = 3 +,
    4
c = 5   /* tail */

       >>>   "3"
     4 *-* b = 3 +,    4
       >>>   "7"
     6 *-* c = 5   /* tail */
       >>>   "5"

[instr.trace.result]

A line that shows a value is written below the line of its clause, with seven blanks, a three-character flag, a blank, the indentation of the clause, two more blanks and the value in double quotation marks. Blanks inside the quotes are the value's own. The tab '09'x, the line feed '0A'x and the carriage return '0D'x are shown as themselves, every other byte below '20'x is shown as ?, and the bytes from '20'x up, '7F'x and 'FF'x among them, are shown as themselves. A value that is not a string is shown as its string value.

What a setting lists

[instr.trace.setting.clauses]

Under A every clause is shown, before it runs, and nothing else about it. R shows the same clauses and below each of them the final value of its expression, with the flag >>>. I shows in addition every step of the evaluation, with the flags that the tag rule lists. O shows nothing. The TRACE clause that ends a setting is shown under the setting it ends, as the effect rule says.

.traceoutput~destination(.output)
call work 'A'
say '--'
call work 'R'
say '--'
call work 'I'
say '--'
call work 'O'
exit

[instr.trace.setting.commands]

A command is shown by A, R and I with the rest of the clauses, and three more settings show commands and nothing else. C shows each command before it runs. E shows a command that raised ERROR or FAILURE, F shows one that raised FAILURE, and N shows what F shows. A shown command is followed by a line with the flag >>> that holds the command string that was sent, and by a line with the flag +++ that holds RC(n) and the return code, when the command raised one of the two conditions; the return code is 30 when the environment does not exist. Which commands raise the conditions is specified with the commands page.

exit

The tags

[instr.trace.tags]

The flag of a value line says what produced the value. Under R the value lines carry >>>, the final value of an expression, a value that a PARSE, ARG, PULL or USE instruction took from its source, and the value that a routine returns to its caller; a message instruction and a message assignment write no value line. The flag >K> marks, under R and I, the value of a keyword's expression in DO, NUMERIC, PARSE, RAISE, FORWARD, GUARD, SIGNAL VALUE and TRACE with a value, and a redirection of an ADDRESS command; it is shown as the keyword and its value. ADDRESS VALUE and OPTIONS write only >>>. >R> is a variable reference that USE ARG took, shown as "V" => "W", and is written under R and I. The +++ line of a command is the other kind of line of this setting. The other flags belong to I alone. >L> is a literal and >V> the value of a variable, shown as NAME => "value". >C> is a compound variable whose tail was substituted, shown as the substituted name, as in S.K => "S.1", >E> an environment symbol, and >N> a symbol qualified by a namespace, shown as NS:C => "The C class". >O> is the result of a binary operator and >P> that of a prefix operator, each shown as the operator and its result, >F> the result of a function call and >M> that of a message, shown as the name and the result, and >A> an argument of a call or of a message. >=> is an assignment, shown as NAME <= "value", and >.> a value that a placeholder period of a template took. Names are shown in upper case.

Indentation

[instr.trace.indent]

The text of a clause is indented by two blanks for each level of nesting. A level is added inside a DO group or loop, after THEN or ELSE, after WHEN or OTHERWISE, and for each active internal call. THEN, ELSE, WHEN and OTHERWISE are shown on a line of their own, one level in from the IF or SELECT, and the clause after them one level further. DO, SELECT and the IF clause stand at the level of their surroundings, and the END that closes a DO or a SELECT stands there too. The lines of values are indented by the level of their clause and two blanks more. The label of an internal routine and the clauses of its body are shown one level deeper than the CALL that started it.

.traceoutput~destination(.output)
trace r
n = 2
do
  if n = 2 then do
    select
      when n = 1 then nop
      otherwise
        m = n
    end
  end
  call f
end
exit
f:
  i = 1
  return

     3 *-* n = 2
       >>>   "2"
     4 *-* do
     5 *-*   if n = 2 
       >>>     "1"
     5 *-*     then
     5 *-*       do
     6 *-*         select
     7 *-*           when n = 1 
       >>>             "0"
     8 *-*           otherwise
     9 *-*             m = n
       >>>               "2"
    10 *-*         end
    11 *-*       end
    12 *-*   call f
    15 *-*     f:
    16 *-*     i = 1
       >>>       "1"
    17 *-*     return
    13 *-* end
    14 *-* exit

Concurrent activities

[instr.trace.concurrent]

Each activity traces with its own setting and its own indentation, and the lines of one activity reach the destination in the order that activity wrote them. How the lines of two activities that trace at the same time are interleaved is not specified, as Deviation 7 says.

sink = .sink~new
.traceoutput~destination(sink)
m = .worker~new~start('run')
trace r
a1 = 1
a2 = 2
trace n
m~result
.traceoutput~destination(.output)
say 'main:'
do l over sink~lines
  if pos('*-* a', l) > 0 then say word(l, 1) word(l, 3)
end
say 'worker:'
do l over sink~lines
  if pos('*-* b', l) > 0 then say word(l, 1) word(l, 3)
end
::class sink
::method init
  expose lines
  lines = .array~new
::method lines
  expose lines
  return lines
::method lineout
  expose lines
  use arg l
  lines~append('' || l)
  return 0
::class worker
::method run
  trace r
  b1 = 1
  b2 = 2
  trace n
  return 1

6 a2

[instr.trace.deviation.50]

When the destination refuses a line by raising a condition, the condition is the same as in ooRexx, but a clause may do its own work before the line that refuses is written.
