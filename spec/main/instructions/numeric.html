The interrexx Language Specification

NUMERIC

NUMERIC {DIGITS [expression] | FUZZ [expression] | FORM [SCIENTIFIC | ENGINEERING | [VALUE] expression]}

ANSI: 6.3.2.66, 8.3.15; rexxref: Keyword Instructions > NUMERIC

NUMERIC changes one of the three settings that steer arithmetic: the number of digits kept, the number of digits a comparison ignores, and the notation of an exponent. The meaning of each setting, the values it accepts, its default and the part of the program that a change reaches belong to the numeric settings, and this page does not repeat them. It specifies the syntax of the instruction, when its expression is evaluated, what leaving the expression out means, the forms of FORM, and the errors of the clause.

DIGITS and FUZZ

[instr.numeric.value]

NUMERIC DIGITS and NUMERIC FUZZ take an optional expression. The expression is an ordinary one, so it may use operators, variables and function calls, and it is evaluated before the setting changes, with the setting in force. Its value is then checked and stored as the DIGITS and the FUZZ rules say. A comma after the expression is not refused when the program is read; the clause then fails as a value that the setting does not accept, 26.5 for DIGITS and 26.6 for FUZZ. The keywords may be written in any case, and a comment may stand between the words.

numeric digits 5 + 5
say digits()
numeric digits digits() * 2
say digits()
Numeric /* now */ DIGITS 3
say digits()
numeric digits 100 + 0.4
say digits()
numeric fuzz 1 + 1
say fuzz()
signal on syntax name e
say 'before'
numeric digits 5, 6
say 'not reached'
e: say condition('o')~code digits()

[instr.numeric.default]

NUMERIC DIGITS or NUMERIC FUZZ with no expression returns the setting to its default, which is 9 for DIGITS and 0 for FUZZ unless the package names another one, as DIGITS and FUZZ say. The clause ends at the semicolon or the line end that follows the keyword.

numeric digits 20
numeric fuzz 3
numeric digits; numeric fuzz
say digits() fuzz()

9 0

FORM

[instr.numeric.form]

NUMERIC FORM has four shapes. The symbol SCIENTIFIC or ENGINEERING, in any case, names the form to set. The keyword VALUE followed by an expression sets the form to the value of the expression. VALUE may be left out when the first token of the expression is not a symbol, as with a string or a parenthesis. With nothing after FORM the form returns to its default. The value of an expression has to be exactly SCIENTIFIC or ENGINEERING, in capitals, with no blanks round it and no abbreviation.

numeric form engineering
say form()
numeric form Scientific
say form()
f = 'ENGINEERING'
numeric form value f
say form()
numeric form ('SCIENTIFIC')
say form()
numeric form value 'ENG' || 'INEERING'
say form()
numeric form
say form()
numeric form 'ENGINEERING'
say form()

[instr.numeric.form.error]

A value that is not exactly one of the two words raises SYNTAX 25.11 when the instruction runs, and the form stays as it was. Lower case, mixed case, blanks round the word, an abbreviation and a number are all such values. Any other symbol directly after FORM, a variable or a number included, is refused with 25.11 when the program is read, and its value is never looked at.

call try "numeric form 'engineering'"
call try "numeric form value 'Engineering'"
call try "numeric form value ' ENGINEERING '"
call try "numeric form value 'ENG'"
call try "numeric form value 5"
call try "numeric form value nosuch"
call try "numeric form + 1"
call try "numeric form nosuch"
exit
try:
  signal on syntax name e
  numeric form scientific
  interpret arg(1)
  say arg(1) '=>' form()
  return
e: say arg(1) '=>' condition('o')~code form()
  return

Errors

[instr.numeric.syntax]

A fault in the form of the clause is raised when the program is read, so no clause runs: 20.905 for NUMERIC alone or followed by something that is not a symbol; 25.15 for a symbol that is not DIGITS, FUZZ or FORM; 21.911 for anything after SCIENTIFIC or ENGINEERING; and 35.917 for FORM VALUE with no expression. A fault in the expression is the error of the expression, such as 35.1 for an operator with nothing after it. A value that the setting does not accept is raised when the instruction runs, with the error that the settings rules give: 26.5, 26.6 or 33.1. An INTERPRET raises the same errors when it runs.

say 'before'
numeric

call try 'numeric'
call try "numeric 'digits' 5"
call try 'numeric foo'
call try 'numeric forms scientific'
call try 'numeric form engineering extra'
call try 'numeric form scientific 1'
call try 'numeric form value'
call try 'numeric digits 5 +'
call try 'numeric digits 5 6'
call try 'numeric fuzz 1 2'
call try 'numeric digits nosuch'
call try 'numeric digits 0'
call try 'numeric fuzz 9'
exit
try:
  signal on syntax name e
  numeric digits 9
  numeric fuzz 0
  interpret arg(1)
  say arg(1) '=> ok'
  return
e: say arg(1) '=>' condition('o')~code
  return
