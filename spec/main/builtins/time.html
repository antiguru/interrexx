The interrexx Language Specification

TIME

TIME([option [, [string] [, informat]]])

ANSI: 9.8.5; rexxref: Functions > Built-in Functions > TIME

TIME answers a time of day. With no string it answers the current local time, or the reading of an elapsed-time clock that the program can start and reset; with a string it reads a time written in one format and writes it in another. The current time changes from moment to moment, so the examples of this page convert fixed times, or check only the form of the current time and how its formats agree with each other, and the elapsed-time clock is checked against pauses and not against figures.

Arguments

[bif.time.args]

TIME takes up to three arguments and requires none: option, string and informat. The argument count is checked by the builtin call rules: a call with more than three arguments raises SYNTAX 40.4, and a call with only omitted places counts as a call with no arguments. TIME does not run as a String method: sending the message TIME to a string raises SYNTAX 97.1. option and informat name formats by their first letter.

say time('C', '13:05:09') time(, '13:05:09') time('N', '13:05:09', 'N') time('N', '13:05:09', )
signal on syntax name a
say time('N', '13:05:09', 'N', 1)
a: say condition('o')~code
signal on syntax name b
say '13:05:09'~time
b: say condition('o')~code

1:05pm 13:05:09 13:05:09 13:05:09
40.4
97.1
[bif.time.default]

An omitted option is N, and so is an omitted informat. A call with no string answers the current time, in the format option names; a call with a string is a conversion.

say time(, '07:08:09') time('N', '07:08:09') time(, '07:08:09', 'N')
say (time() == time('N')) (length(time()) == 8)

Formats written

[bif.time.out.clock]

Three options write the time of day as hours, minutes and seconds. N writes hh:mm:ss, with the hour from 00 to 23, and L writes hh:mm:ss.uuuuuu, which adds six digits for the microseconds. C writes h:mmam or h:mmpm, a civil time: the hour is from 1 to 12 with no leading zero, the minutes have two digits and the seconds are not written. The hour 0 is 12 with am, the hours 1 to 11 have am, the hour 12 is 12 with pm, and the hours 13 to 23 are 1 to 11 with pm.

say time('N', '00:00:00') time('N', '09:08:07') time('N', '23:59:59')
say time('L', '09:08:07') time('L', '09:08:07.5', 'L') time('L', '23:59:59.999999', 'L')
say time('C', '00:00:00') time('C', '00:59:59') time('C', '01:00:00') time('C', '11:59:59')
say time('C', '12:00:00') time('C', '12:59:59') time('C', '13:00:00') time('C', '23:59:59')

[bif.time.out.counts]

Three options write the time of day as a count since midnight: H the whole hours, M the whole minutes and S the whole seconds. Each is written with no leading zero, point or exponent, as 0 for zero, and a part of a unit that is not complete is dropped, never rounded. NUMERIC DIGITS plays no part.

say time('M', '00:00:59') time('M', '01:00:00') time('M', '23:59:59')
say time('S', '00:00:01') time('S', '01:00:00') time('S', '23:59:59')

[bif.time.out.stamp]

Two options write a count that includes the date. F writes the number of microseconds since the start of 1 January 0001, and T the number of seconds since the start of 1 January 1970, which is negative before it. T is F divided by 1000000, rounded down, less 62135596800. A string read with the informat C, H, L, M, N or S has no date, so its date is 1 January 0001: F is then the time of day in microseconds, and T is that time of day in seconds less 62135596800, a negative number. NUMERIC DIGITS plays no part in how they are written.

say time('F', '00:00:00') time('F', '00:00:01') time('F', '23:59:59.999999', 'L')
say time('T', '00:00:00') time('T', '00:00:01') time('T', '23:59:59.999999', 'L')

The current time

[bif.time.current]

A call with no string answers the current time in the local time zone, in the format option names, as of the moment the clause reads the clock. Every format of the current time is the same time: converting the current time in L form to N, C, H, M, S or L gives what that option gives for the current time. F and T include the date, and F with its whole days taken off is what the conversion of the L form gives for F.

numeric digits 20
say (time('N') == time('N', time('L'), 'L')) (time('C') == time('C', time('L'), 'L')),
    (time('H') == time('H', time('L'), 'L')) (time('M') == time('M', time('L'), 'L')),
    (time('S') == time('S', time('L'), 'L')) (time('L') == time('L', time('L'), 'L'))

    (time('T') == date('T'))

The time zone

[bif.time.zone]

The current time of every format is that of the local time zone, and the option O writes how far that zone is from UTC: a whole number of microseconds, positive east of UTC and negative to the west, and less than a day. F and T are local like the rest: the UTC reading of F is F - O. A call that gives O with a string reads the string as usual and answers the same offset, except with the informat O, whose answer is the offset that the string gives. This book does not specify which time zone a program runs in. The zone is read with the clock, at the clause's moment. A program that changes it, as by setting TZ with VALUE in the environment, has the new zone at the next reading of the clock: in the same clause when no DATE or TIME call came before the change there, and from the next clause otherwise.

o = time('O')

[bif.time.in.text]

[bif.time.in.number]

The informats H, M, S, F and T read a count: hours, minutes or seconds since midnight, or the number of microseconds or seconds that F and T write. The string may have any form of a number, such as 5, 5, +5, 5.0 and 5e0, and NUMERIC DIGITS does not apply. A string whose value is a whole number is read as that number, however many leading or trailing zeros it has, and the number must be in the range given below. A string whose value is not a whole number raises SYNTAX 40.19 when it has at most nine significant digits for H, M and S, or at most 18 for F and T, its significant digits being those from the first digit that is not 0 to the last digit that is not 0. This book does not specify whether a string with more significant digits, whose value is not a whole number, is accepted, nor what it then reads as. H must be from 0 to 23, M from 0 to 1439 and S from 0 to 86399. F must be from 0 to 315537897599999999 and T from -62135596800 to 253402300799, which are the instants from 1 January 0001 to 31 December 9999. An F or T names a date and a time, and a format other than F or T keeps only the time of day; F and T keep both.

[bif.time.in.truncate]

A conversion answers the earliest time that fits the string. A part of the time that the string gives and the format of the answer has no place for is dropped, never rounded: N, C, H, M and S drop the microseconds, C, H and M drop the seconds as well, and H drops the minutes. [bif.time.in.offset]

The informat O reads a whole number of microseconds, as the informats F and T read their counts, as an offset from UTC. The elapsed-time clock

[bif.time.elapsed.start]

The options E and R read an elapsed-time clock, which starts at the first call of E or R in the code that owns the clock. That call answers 0, and the clock then counts time from it. Other options do not start the clock and are not affected by it, and neither is DATE.

x = time('N') time('L') time('F') time('O') date('S')
call syssleep 0.3
say time('R')
call syssleep 0.3
say time('E') >= 0.25

0
1
[bif.time.elapsed.value]

After the clock has started, E answers the time since the start or the last reset in seconds with a fraction of six digits: whole seconds with no leading zeros, a point, and the six digits of the microseconds, 0.300268 and 12.000001 being examples. The figure is written whatever NUMERIC DIGITS is.

numeric digits 3
x = time('E')
call syssleep 0.3
e = time('E')
say datatype(e, 'N') (e >= 0.25) verify(e, '0123456789.') countstr('.', e) (pos('.', e) > 1),
    (length(e) - pos('.', e)) (left(e, 1) \== '0' | pos('.', e) == 2)
call syssleep 1.1
e = time('E')
say (e >= 1.35) verify(e, '0123456789.') countstr('.', e) (length(e) - pos('.', e)) (left(e, 1) \== '0')

[bif.time.elapsed.reset]

R answers what E would, and also resets the clock: the next call of E or R counts from the moment of this call.

x = time('R')
call syssleep 0.4
parse value resets() with a b
m = time('E')
/* m counts on through the label's reset; without the reset, b would include a */
say (a >= 0.35) (b >= 0.35) (a + b < m + 0.2)
exit
resets:
a = time('R')
call syssleep 0.4
return a time('E')

[bif.time.elapsed.scope]

The clock belongs to the code that runs. A program shares its clock with the code that INTERPRET runs in it. A routine of the same program that CALL or a function call runs, a label of the program, begins with a copy of its caller's clock as it stands at the call, running if the caller's is and not started if not, and what it does to its copy is not seen by the caller. A ::ROUTINE, a method and a message sent with START each begin with no clock, which their first call of E or R starts.

call starter
call syssleep 0.3
say 'caller of a label that started a clock' kind(time('E'))
call syssleep 0.3
say 'label' kind(inside())
say 'main' kind(time('E'))
say 'routine' kind(outside())
say 'method' kind(.o~new~m)
say 'start' kind(.o~new~start('m')~result)

m = time('E')
/* m counts on through the label's reset; if INTERPRET had a clock of its own, e would include y */
say 'interpret' kind(y) (y + e < m + 0.2)
exit

The order of the checks

[bif.time.order]

A call is checked in this order, and the first failure is the one raised: the argument count; a missing string that an informat needs (40.5); the options E and R with a string (40.29); the letter of informat; the string itself (40.19); and, last, the letter of option.

signal on syntax name a
say time('X', 'junk', 'Q', 1)
a: say condition('o')~code
signal on syntax name b
say time('E', , 'N')
b: say condition('o')~code
signal on syntax name c
say time('E', 'junk', 'Q')
c: say condition('o')~code
signal on syntax name d
say time('X', 'junk', 'Q')
d: say condition('o')~code
signal on syntax name e
say time('X', 'junk')
e: say condition('o')~code
signal on syntax name f
say time('X', '13:05:09')
f: say condition('o')~code

Note. The ANSI draft (9.8.5) has neither the options F and T nor the informats F, O and T, and it raises SYNTAX 40.29 for O as well as E and R as option with a string, where ooRexx answers the offset. The reference manual describes an error when the system clock is set back below the start of the elapsed-time clock, and one for an elapsed time of more than nine digits of seconds; this book specifies neither.
