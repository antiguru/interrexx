  5. 4. Deviations

The interrexx Language Specification

RIGHT

RIGHT(string, length [, pad])

ANSI: 9.3.18; rexxref: Functions > Built-in Functions > RIGHT

Deviations: D4

RIGHT answers the last length characters of a string, adding pad on the left when the string runs out.

Arguments

[bif.right.method]

RIGHT is a builtin that runs as a String method, and string, its first argument, is the receiver; length and pad become the message's arguments, in that order. string is a string, length is a length, and pad is a pad. The arguments are checked in the order the conventions give, and the argument count by the builtin call rules: two are required and three is the most. Like LEFT and unlike SUBSTR, RIGHT does not default length: it is a required argument, so a call without it fails by the call rules, with SYNTAX 40.3 when nothing follows its place (too few) and SYNTAX 40.5 when a pad does (missing).

say right('hi  yo', 8) '|' 'abc'~right(5, '.')
signal on syntax name a
say right('abc')
a: say condition('o')~code
signal on syntax name b
say right('abc', 2, '.', 1)
b: say condition('o')~code
signal on syntax name c
say right('abc', , '.')
c: say condition('o')~code
signal on syntax name d
say right('abc', 'x')
d: say condition('o')~code
signal on syntax name e
say right('abc', -1)
e: say condition('o')~code
signal on syntax name f
say right('abc', 2, '..')
f: say condition('o')~code
signal on syntax name g
say right('abc', -1, '..')
g: say condition('o')~code
signal on syntax name h
say right()
h: say condition('o')~code

  hi  yo | ..abc
40.3
40.4
40.5
40.12
93.923
40.23
40.23
40.3
[bif.right.pad.default]

When pad is omitted, it is the blank, '20'x.

say '['right('ab', 4)']' '['right('ab', 4, )']'

[  ab] [  ab]

The result

[bif.right.result]

RIGHT returns a string of exactly length characters. When string has length characters or more, the result is its last length characters. Otherwise the result is string preceded by length less LENGTH(string) copies of pad.

say '['right('ab   c', 7)']' '['right('xy zw', 4)']' '['right('7', 3, '0')']'
say '['right('abc', 3)']' '['right('abc', 1)']' '['right('abc', 4, '.')']'

[ ab   c] [y zw] [007]
[abc] [c] [.abc]
[bif.right.length.zero]

When length is 0, the result is the null string, for every string. pad is still checked, as a pad always is.

say '['right('abc', 0)']' '['right('', 0)']' '['right('abc', '-0', '.')']'
signal on syntax name a
say right('abc', 0, '')
a: say condition('o')~code

[] [] []
40.23
[bif.right.empty]

When string is the null string, the result is length copies of pad.

say '['right('', 3)']' '['right('', 3, '*')']'

[   ] [***]
[bif.right.bytes]

RIGHT cuts and pads by character, one byte each, and copies every byte of string that stays unchanged: whitespace, control characters and '00'x are characters like any other, in string and as pad.

say c2x(right('0061'x, 4, '00'x)) c2x(right('c3a9'x, 1))

00000061 A9
[bif.right.large]

A length that is a whole number below 10**18 is valid, and a length of 10**18 or more raises SYNTAX 40.12 like any whole number that is too large. The caller's NUMERIC DIGITS setting plays no part.

numeric digits 3
say '['right('abc', 1E1)']'
signal on syntax name a
say right('abc', 1000000000000000000)
a: say condition('o')~code

[       abc]
40.12

Note. Whether, when and with which code RIGHT fails for a length whose result cannot be held in memory is not specified.

Deviations

[bif.right.deviation.4]

interrexx does not specify whether the answer of RIGHT is the same object as another string of equal value: as string itself, when the call returns all of it unchanged as right(s, length(s)) does, or as an equal string produced some other way, such as the literal 'abc'. Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'ab' || 'c'
say (right(s, 3) == s) (right('xabc', 3) == 'abc')
