The interrexx Language Specification

SUBSTR

SUBSTR(string, n [, length] [, pad])

ANSI: 9.3.21; rexxref: Functions > Built-in Functions > SUBSTR (Substring)

Deviations: D4

SUBSTR selects a run of characters from a string by position, and pads the run when it reaches past the end of the string.

Arguments

[bif.substr.method]

SUBSTR is a builtin that runs as a String method, and string, its first argument, is the receiver. string is a string, n is a position, length is a length, and pad is a pad. The arguments are checked in the order the conventions give, and the argument count by the builtin call rules: two are required and four is the most.

signal on syntax name a
say substr('abc', 0)
a: say condition('o')~code
signal on syntax name b
say substr('abc', 2, -1)
b: say condition('o')~code
signal on syntax name c
say substr('abc', 1, 2, '..')
c: say condition('o')~code
signal on syntax name d
say substr('abc', 1, 1, '.', 1)
d: say condition('o')~code

[bif.substr.length.default]

When length is omitted, it is the number of characters of string at position n and after it: LENGTH(string) - n + 1 when n is at most LENGTH(string), and 0 otherwise.

say '['substr('abcde', 2)']' '['substr('abcde', 5)']',
    '['substr('abcde', 6)']' '['substr('abcde', 100)']'

[bcde] [e] [] []

Note. The ANSI draft (9.3.21) computes the omitted length as LENGTH(string) + 1 - n and repeats that many times, so for n two or more past the end its count is negative and its definition raises SYNTAX 26.2 from inside the builtin. This page follows ooRexx, where the reference manual says the rest of the string is returned and positions past the end select nothing, so the result is the null string.

[bif.substr.pad.default]

When pad is omitted, it is the blank, '20'x.

say '['substr('xyz', 3, 3)']'

[z  ]

The result

[bif.substr.result]

SUBSTR returns a string of exactly length characters. Its character at position i, for each i from 1 to length, is the character of string at position n + i - 1 when string has a character there, and pad otherwise. So the result is the characters of string from position n on, at most length of them, followed by as many copies of pad as make up the length.

say '['substr('abcdef', 2, 3)']' '['substr('abcdef', 4, 5, '.')']',
    '['substr('abcdef', 1, 6)']'

[bif.substr.past-end]

When n is greater than LENGTH(string), no character of string is selected: the result is length copies of pad, and the null string when length is omitted. This holds for every n past the end that passes its check.

say '['substr('abc', 4, 2, '*')']' '['substr('abc', 999999999999999999, 3, '*')']',
    '['substr('abc', 4)']'

[bif.substr.length.zero]

When length is 0, the result is the null string, for every n that passes its check. pad is still checked, as a pad always is.

say '['substr('abc', 2, 0)']' '['substr('abc', 10, 0, '*')']'

say substr('abc', 2, 0, '')

[bif.substr.empty]

When string is the null string, every position is past its end, so the result is length copies of pad, or the null string when length is omitted.

say '['substr('', 1)']' '['substr('', 1, 3)']' '['substr('', 5, 2, '-')']'

[bif.substr.bytes]

SUBSTR selects and pads by character, one byte each, and copies every byte unchanged: whitespace, control characters and '00'x are characters like any other, in string and as pad.

say c2x(substr('61000962'x, 2, 4, '00'x))

Deviations

[bif.substr.deviation.4]

interrexx does not specify whether the result of SUBSTR is the same object as another string of equal value: as string itself, when the call returns all of it unchanged as substr(s, 1) does, or as an equal string produced some other way, such as the literal 'abc' beside substr('abcdef', 1, 3). Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'abc' || 'def'
say (substr(s, 1) == s) (substr('abcdef', 1, 3) == 'abc')
