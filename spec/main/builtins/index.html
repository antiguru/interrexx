The interrexx Language Specification

Built-in functions

ANSI: 9.2.1; rexxref: Functions > Built-in Functions

Deviations: D4

This chapter has a page for each builtin function, and each page specifies the function call. The rules here hold for every builtin call; the pages link to them, and to the conventions, instead of restating them.

A page's syntax line names the arguments in order. A name in square brackets is an optional argument; every other argument is required. The number of names on the line is the most arguments the builtin takes, and the number of required ones is the fewest.

[bif.index.call.count]

The argument count of a call is the position of the last argument in it that is not omitted. Omitted places at the end of the list therefore add nothing to the count, and a call with only omitted places counts as a call with no arguments, a count of 0.

say substr('abc', 2, , ) word('a b', 2, , , )

bc b
[bif.index.call.too-few]

A call whose argument count is less than the number of required arguments raises SYNTAX 40.3.

signal on syntax name a
say substr('abc')
a: say condition('o')~code
signal on syntax name b
say substr('abc', )
b: say condition('o')~code
signal on syntax name c
say word(, , )
c: say condition('o')~code

[bif.index.call.too-many]

A call whose argument count is greater than the number of arguments on the syntax line raises SYNTAX 40.4, whatever the values of the arguments, and even when the arguments before the last are omitted.

Words

[bif.index.words.split]

The builtins that count words split a string into words the same way. A word is a run of one or more characters, none of them whitespace, that has whitespace or an end of the string on each side. The words of a string are numbered from 1, left to right. Whitespace before the first word, between two words and after the last belongs to no word, so the null string and a string of only whitespace have no words. Every other character, line feed and '00'x among them, can be part of a word.

say words(' a'||'09'x||'b  c ') words('') words('  '||'09'x)
say word('one  two', 2) c2x(word('a'||'0a000c'x||'b c', 1))

3 0 0
two 610A000C62

Note. The ANSI draft (9.3.26 and the other word builtins) separates words by a set of blank characters that it leaves to the configuration: the blank and any others the configuration names. ooRexx fixes that set as the blank and the horizontal tab, and so does this book.

[bif.index.words.number]

Where a word builtin's page calls an argument a word number, that argument is a position that counts words: the word number n names word n of the string as the word rule numbers them. A word number greater than the number of words in the string is not an error, for every value that passes its check; it names no word, and the builtin's page says what the builtin answers then.

say '['word('a b', 3)']' wordindex('a b', 3) wordlength('a b', 999999999999999999),
    wordpos('a', 'a b', 3)
signal on syntax name e
say wordindex('a b', 0)
e: say condition('o')~code

[] 0 0 0
93.924

Answers that are counts

[bif.index.count.answer]

WORDINDEX, WORDLENGTH, WORDPOS and VERIFY each answer a count: of characters or of words, or a position, which counts characters or words up to the one it names. A builtin that answers a count writes it as a whole number in decimal digits only: no sign, no leading zero, no period and no exponent, and 0 for zero. The caller's NUMERIC DIGITS setting plays no part, so the answer is exact however many digits it has.

numeric digits 3
say wordindex(copies(' ', 1000) || 'a', 1) wordlength(copies('z', 1234), 1),
    wordpos('y', copies('x ', 1200) || 'y') wordpos('q', 'a b')
say verify(copies('a', 1200) || 'b', 'a') verify(copies('a', 1300), '', 'N', 1234),
    verify('ab', 'ab')

1001 1234 1201 0
1201 1234 0

Note. The reference manual does not say how these answers are written or whether NUMERIC DIGITS applies to them; this rule matches ooRexx.

[bif.index.count.answer.deviation.4]

interrexx does not specify whether the answer of a builtin that answers a count is the same object as another string of equal value: as an equal number the program already holds, such as the start argument of a call that answers it, or a literal such as '1201', or the equal answer of another call. Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

w = copies('x ', 1200) || 'y'
n = 1200 + 1
say (wordpos('y', w, n) == n) (wordindex(copies(' ', 1200) || 'a', 1) == '1201'),
    (wordlength(copies('z', 1201), 1) == wordpos('y', w))
v = copies('a', 1300)
say (verify(v, '', 'N', n) == n) (verify(copies('a', 1200) || 'b', 'a') == '1201')
