The interrexx Language Specification

Built-in functions

ANSI: 9.2.1; rexxref: Functions > Built-in Functions

Deviations: D4, D98, D99, D101

This chapter has a page for each builtin function, and each page specifies the function call. The rules here hold for every builtin call, except that a builtin whose page links the native call rule follows that rule in place of the rules for the number of arguments, and also for the conversion of an object that is not a string, which has no fallback to STRING there. The pages link to these rules, and to the conventions, instead of restating them.

A page's syntax line names the arguments in order. A name in square brackets is an optional argument; every other argument is required. The number of names on the line is the most arguments the builtin takes, and the number of required ones is the fewest.

[bif.index.call.count]

The argument count of a call is the position of the last argument in it that is not omitted. Omitted places at the end of the list therefore add nothing to the count, and a call with only omitted places counts as a call with no arguments, a count of 0.

bc b

Words

[bif.index.words.split]

The builtins that count words split a string into words the same way. A word is a run of one or more characters, none of them whitespace, that has whitespace or an end of the string on each side. The words of a string are numbered from 1, left to right. Whitespace before the first word, between two words and after the last belongs to no word, so the null string and a string of only whitespace have no words. Every other character, line feed and '00'x among them, can be part of a word.

say words(' a'||'09'x||'b  c ') words('') words('  '||'09'x)
say word('one  two', 2) c2x(word('a'||'0a000c'x||'b c', 1))

3 0 0
two 610A000C62

Note. The ANSI draft (9.3.26 and the other word builtins) separates words by a set of blank characters that it leaves to the configuration: the blank and any others the configuration names. ooRexx fixes that set as the blank and the horizontal tab, and so does this book.

[bif.index.words.number]

Where a word builtin's page calls an argument a word number, that argument is a position that counts words: the word number n names word n of the string as the word rule numbers them. A word number greater than the number of words in the string is not an error, for every value that passes its check; it names no word, and the builtin's page says what the builtin answers then.

say '['word('a b', 3)']' wordindex('a b', 3) wordlength('a b', 999999999999999999),

[bif.index.count.answer]

A builtin whose page links this rule answers a count: of characters, of words or of occurrences, or a position, which counts characters or words up to the one it names. Such a builtin writes it as a whole number in decimal digits only: no sign, no leading zero, no period and no exponent, and 0 for zero. The caller's NUMERIC DIGITS setting plays no part, so the answer is exact however many digits it has.

numeric digits 3
say wordindex(copies(' ', 1000) || 'a', 1) wordlength(copies('z', 1234), 1),
    wordpos('y', copies('x ', 1200) || 'y') wordpos('q', 'a b')
say compare(copies('a', 1500) || 'b', copies('a', 1500) || 'c') countstr('a', copies('a', 1500))
say verify(copies('a', 1200) || 'b', 'a') verify(copies('a', 1300), '', 'N', 1234),
    verify('ab', 'ab')

1501 1500
1201 1234 0

Note. The reference manual does not say how these answers are written or whether NUMERIC DIGITS applies to them; this rule matches ooRexx.

[bif.index.count.answer.deviation.4]

interrexx does not specify whether the answer of a builtin that answers a count is the same object as another string of equal value: as an equal number the program already holds, such as the start argument of a call that answers it, or a literal such as '1201', or the equal answer of another call. Through identityHash, or as a key of an IdentityTable, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

w = copies('x ', 1200) || 'y'

    (wordlength(copies('z', 1201), 1) == wordpos('y', w))
v = copies('a', 1300)
say (verify(v, '', 'N', n) == n) (verify(copies('a', 1200) || 'b', 'a') == '1201')

[bif.index.bit.args]

Note. B2X, C2D, C2X, D2C, D2X, X2B, X2C and X2D convert between the characters of a string, a number written in decimal, and a string of hexadecimal or binary digits. The rules below are the ones that more than one of them follows; a function's page links the ones it uses and states the rest.

[bif.index.conv.digits]

In an argument that is a string of binary digits, the digits are 0 and 1. Streams

Note. The input and output builtins read and write streams. A stream is a source of characters, a destination for them, or both: a file, or one of the three standard streams. The rules here hold for every stream builtin; the pages link to them instead of restating them. The examples keep their files in the current directory under names of their own, and delete them.

[bif.index.stream.name]

A stream builtin names its stream with a string, its name argument. For a file the name is the file's name, taken from the current directory when it is not absolute (see Deviation 34). While the stream is open, a name denotes the same stream, whichever stream builtin it is given to, so what one builtin writes another reads. This holds in the main program and in one call of a method, and in the routines that either of them calls. Each call of a method has streams of its own, which a routine called from it shares, so a name that the method uses is not the stream that the main program, a routine called from the main program or another call of the method uses under that name.

[bif.index.stream.transient]

[bif.index.stream.open]

A stream builtin opens its stream when it first uses it, and the program does no opening of its own. A file is opened for reading and for writing, each as far as the file allows; an operation that the file does not allow has the NOTREADY outcome that its page gives. A file that does not exist is created by a write, and a read of it creates nothing: it finds no characters and raises the NOTREADY condition. [bif.index.stream.positions]

A file that is open has two positions in it, counted in characters from 1: the read position, where the next read starts, and the write position, where the next write starts. [bif.index.stream.lifetime]

A stream stays open, with its positions, until the program closes it or ends. The streams that a call of a method opened are closed when the call returns, so what the call wrote is in the file then. What it wrote to a name that the code which called it also has open is not specified. CHAROUT given only a name closes a stream; the pages of the other stream builtins name their forms. The next use of a closed name opens the stream again: the read position is at the start and the write position at the end of the data, and the characters written before the close are in the file. A standard stream is closed in the same way, by CLOSE and by CHAROUT or LINEOUT given neither a string nor a start or line: its state is then UNKNOWN, and the next stream builtin that reads from it, writes to it, counts what is left in it (CHARS or LINES) or opens it opens it again on the same input or output, so that later reads and writes carry on. ooRexx differs, as Deviation 98 says.

[bif.index.stream.lifetime.deviation.98]

A close of a standard stream is a logical one, as for a file: the lifetime rule holds for the standard input, output and error too. A call of CHAROUT or LINEOUT that gives neither a string nor a start or line, and either no stream name or the name of a standard stream, writes nothing, answers 0 and closes the stream, and the later output of the program is written as usual. [bif.index.stream.notready]

A call that cannot read, or write, as many characters as it was asked to raises the NOTREADY condition. That happens at the end of the data, when the stream cannot be opened, and when a write fails. condition('D') in a trap for it is the name of the stream, and condition('C') is NOTREADY. For a file the name is the spelling that the first call to name the stream gave. A later call that names the same file in another way, such as ./x for x or an absolute path, gets that spelling again, until a CLOSE ends the stream. For the standard input it is STDIN, whatever the spelling of the name in the call and also when the call gave none. The condition is not an error: when it is not trapped, or after a CALL ON trap returns, the call goes on and answers what its page says. A trap by SIGNAL ON NOTREADY abandons the clause that raised it, like any other condition.
