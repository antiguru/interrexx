The interrexx Language Specification

X2D

X2D(hex_string [, n])

ANSI: 9.6.11; rexxref: Functions > Built-in Functions > X2D (Hexadecimal to Decimal)

Deviations: D4

X2D answers the number that a string of hexadecimal digits writes, in decimal. With a length n it reads the digits as a signed number of n hexadecimal digits.

Arguments

[bif.x2d.method]

X2D is a builtin that runs as a String method, and hex_string, its first argument, is the receiver; n becomes the message's argument. hex_string is a string of hexadecimal digits and n is a length. The argument count is checked by the builtin call rules: one is required and two is the most.

say x2d('ff') 'ff'~x2d 'ff'~x2d(2)
signal on syntax name a
say x2d()
a: say condition('o')~code
signal on syntax name b
say x2d(, 1)
b: say condition('o')~code
signal on syntax name c
say x2d('a', 1, 1)
c: say condition('o')~code

255 255 -1
40.3
40.5
40.4
[bif.x2d.digits]

hex_string may have whitespace between its digits and not at its ends, and may be null. The errors those rules give are those of a hexadecimal string: SYNTAX 93.933 for a character that is not a digit, SYNTAX 93.931 for whitespace at an end and SYNTAX 93.976 for a gap at a place that is not a multiple of 2 digits from the end. A sign is not a digit, so a negative number cannot be written in hex_string.

say x2d('1 ff') x2d('1' || '09'x || 'ff') x2d('')
signal on syntax name a
say x2d('1g')
a: say condition('o')~code
signal on syntax name b
say x2d('ff ')
b: say condition('o')~code
signal on syntax name c
say x2d('f f')
c: say condition('o')~code
signal on syntax name d
say x2d('-1')
d: say condition('o')~code

511 511 0
93.933
93.931
93.976
93.933
[bif.x2d.errors]

The checks of the call run in this order: the argument count; the form of n as a whole number, SYNTAX 40.12; the sign of n, SYNTAX 93.923; then the digits of hex_string; and last the number of digits of the answer, SYNTAX 93.935. A negative n is therefore raised even when hex_string has a character that is not a digit or the answer would not fit, and a non-whole n before that.

signal on syntax name a
say x2d('zz', 'x')
a: say condition('o')~code
signal on syntax name b
say x2d('zz', -1)
b: say condition('o')~code
signal on syntax name c
say x2d('ffffffffff', -1)
c: say condition('o')~code
signal on syntax name d
say x2d('zz')
d: say condition('o')~code
signal on syntax name e
say x2d('ffffffffff')
e: say condition('o')~code

40.12
93.923
93.923
93.933
93.935

The result

[bif.x2d.unsigned]

Without n, the answer is the sum, over the digits of hex_string, of the digit's value times 16 to the power of the number of digits after it, and is never negative. A letter is read in either case, whitespace does not count as a digit and leading zeros change nothing.

say x2d('0') x2d('f') x2d('FF') x2d('0ff') x2d('1 00') x2d('aBcD') x2d('8000')

0 15 255 255 256 43981 32768
[bif.x2d.signed]

With n, the digits are read as a signed number of n hexadecimal digits: the answer is negative when the leftmost bit of the digits, made n long by dropping some on the left or adding 0 digits there, is set, which is when the leftmost digit is 8 or more. Padding with 0 means that a string shorter than n is never negative, and that only the last n digits of a longer one matter.

say x2d('a7', 2) x2d('a7', 3) x2d('c4d9', 2) x2d('c4d9', 3) x2d('c4d9', 4)
say x2d('8', 1) x2d('7', 1) x2d('f', 2) x2d('ffff', 1) x2d('f ff', 2),
    x2d('8000', 4)

-89 167 -39 1241 -15143
-8 7 15 -1 -1 -32768
[bif.x2d.n.default]

When n is omitted, the leftmost bit does not make the number negative: every string is read as a number with no sign. An omitted n is not an n of the number of digits: with that n a string whose leftmost digit is 8 or more is negative.

say x2d('80') x2d('80', ) x2d('ff') x2d('ff', , )
say x2d('80', 2) x2d('ff', 2)

128 128 255 255
-128 -1
[bif.x2d.n.zero]

With an n of 0 the answer is 0 and hex_string is not examined: a string that is not a valid hexadecimal string, whether it has a character that is not a digit or whitespace in the wrong place, raises no error. Only the checks of n and of the argument count still apply.

say x2d('ffff', 0) x2d('0', 0) x2d('', 0) x2d('zz', 0) x2d(' f f ', 0)
signal on syntax name a
say x2d('ff', -0 - 1)
a: say condition('o')~code
signal on syntax name b
say x2d('zz', 1)
b: say condition('o')~code

0 0 0 0 0
93.923
93.933
[bif.x2d.n.large]

An n larger than the number of digits just pads the digits with zeros, so the answer is not negative; a large n is not an error and does not change the answer.

say x2d('8', 100) x2d('ff', 4) x2d('f', 99999999999) x2d('ffff', 5)

8 255 15 65535
[bif.x2d.null]

When hex_string is the null string, the answer is 0, with an n or without one.

say x2d('') x2d('', 0) x2d('', 1) x2d('', 8)

0 0 0 0
[bif.x2d.not-number]

X2D reads the characters of its argument and not its value as a number, so an argument written as a number is treated as the digits it is written with: NUMERIC DIGITS plays no part in reading it, and a number written with a period or with a signed exponent has a character that is not a digit.

say x2d(10) x2d(0010)
signal on syntax name a
say x2d(1.5)
a: say condition('o')~code
signal on syntax name b
say x2d(1e+3)
b: say condition('o')~code

16 16
93.933
93.933
[bif.x2d.digits-limit]

The answer must fit in the caller's NUMERIC DIGITS setting, by the rule for the answer: when it has more digits than that, the call raises SYNTAX 93.935. The caller's setting decides, not the length of hex_string: the string can be longer than that when its leading digits are 0, or when n cuts it short.

say x2d('3b9ac9ff') x2d(copies('0', 30) || 'ff') x2d('ffffffffff', 2)
signal on syntax name a
say x2d('3b9aca00')
a: say condition('o')~code
signal on syntax name b
say x2d('8000000000', 10)
b: say condition('o')~code
numeric digits 20
say x2d('ffffffffffffffff') x2d('8000000000000000', 16)

999999999 255 -1
93.935
93.935
18446744073709551615 -9223372036854775808
[bif.x2d.inverse]

D2X undoes X2D. For a hexadecimal string without an n whose value has at most NUMERIC DIGITS digits, D2X of the answer of X2D is hex_string with its leading zeros and its whitespace removed, its letters in capitals, and 0 for a string with no digit but 0, or none at all.

say d2x(x2d('00ff')) d2x(x2d('aB 12')) d2x(x2d('0')) d2x(x2d(''))

FF AB12 0 0

Deviations

[bif.x2d.deviation.4]

interrexx does not specify whether the answer of X2D is the same object as another string of equal value, as the shared rule says for every conversion function. A program can rely only on the value, which is equal under ==.

say (x2d('') == 0) (x2d('61') == 97) (x2d('0a') == '10')
