The interrexx Language Specification

OVERLAY

OVERLAY(new, target [, n [, length [, pad]]])

ANSI: 9.3.15; rexxref: Functions > Built-in Functions > OVERLAY

Deviations: D4

OVERLAY writes a string over a run of characters of another string, starting at a given position and adjusting the written string to a given length, and answers the changed string.

Arguments

[bif.overlay.method]

OVERLAY is a builtin that runs as a String method, and target, its second argument, is the receiver; new, n, length and pad become the message's arguments, in that order. new and target are strings, n is a position, length is a length, and pad is a pad. The arguments are checked in the order the conventions give, and the argument count by the builtin call rules: two are required and five is the most.

say overlay('XY', 'abcd', 2) 'abcd'~overlay('XY', 2) '|' 'abcd'~overlay('XY', 2, 3, '.')
signal on syntax name a
say overlay('XY')
a: say condition('o')~code
signal on syntax name b
say overlay('XY', 'abcd', 2, 1, '.', 1)
b: say condition('o')~code
signal on syntax name c
say overlay(, 'abcd')
c: say condition('o')~code
signal on syntax name d
say overlay('XY', , 2)
d: say condition('o')~code
signal on syntax name e
say overlay('XY', 'abcd', 0)
e: say condition('o')~code
signal on syntax name f
say overlay('XY', 'abcd', 1, -1)
f: say condition('o')~code
signal on syntax name g
say overlay('XY', 'abcd', 'x')
g: say condition('o')~code
signal on syntax name h
say overlay('XY', 'abcd', 0, -1, '**')
h: say condition('o')~code
signal on syntax name i
say overlay('XY', 'abcd', 0, 'x')
i: say condition('o')~code

[bif.overlay.n.default]

When n is omitted, it is 1: the overlay begins at the first character of target.

say overlay('zz', 'wxyz') overlay('zz', 'wxyz', ) overlay('zz', 'wxyz', , 1)

zzyz zzyz zxyz
[bif.overlay.length.default]

When length is omitted, it is the length of new, so new is written whole.

say overlay('qq', 'abcd', 2) overlay('qq', 'abcd', 2, ) overlay('', 'abcd', 2)

aqqd aqqd abcd
[bif.overlay.pad.default]

When pad is omitted, it is the blank, '20'x.

say '['overlay('1', 'abc', 5, 3)']' '['overlay('1', 'abc', 5, 3, )']'

[abc 1  ] [abc 1  ]

The result

[bif.overlay.result]

OVERLAY returns the concatenation of three strings, in this order. The first is the first n - 1 characters of target, followed by as many copies of pad as it takes to make n - 1 characters when target has fewer. The second is new adjusted to exactly length characters: cut at the right when it has more, and followed by copies of pad when it has fewer. The third is the characters of target from position n + length on, which is the null string when target has fewer than that many characters. So the result keeps every character of target outside the run of length characters from position n, and the result is longer than target when the run reaches past its end.

say '['overlay(' ', 'uvwxyz', 4)']' '['overlay('#', 'uvwxyz', 2, 3)']' '['overlay('zz', 'wxyz', 4)']'
say overlay('45', 'ab', 4, 5, '*') overlay('xyz', 'abc', 1, 2)
say '['overlay('xyz', 'abc', 2, 5)']'
say overlay('xyz', 'abc', 3) overlay('x', 'abc', 4) overlay('abc', 'abc', 2, 0)

[uvw yz] [u#  yz] [wxyzz]
ab*45*** xyc
[axyz  ]
abxyz abcx abc
[bif.overlay.past-end]

When n is greater than one more than the length of target, the gap is filled from target's side: target is extended on the right with copies of pad to n - 1 characters, the adjusted new follows, and nothing follows it. When n is exactly one more than the length of target, new is appended with no padding between. This holds when length is 0, so the result is then target padded to n - 1 characters.

say overlay('xyz', 'abc', 5, 2, '-') overlay('xyz', 'abc', 4, 2, '-') overlay('xyz', 'abc', 5, , '-')
say overlay('X', 'ab', 5, 3, '.') overlay('xyz', 'ab', 5, 5, '.')
say overlay('xyz', 'abc', 6, 0, '-') overlay('xyz', 'abc', 4, 0, '-')'.'

abc-xy abcxy abc-xyz
ab..X.. ab..xyz..
abc-- abc.
[bif.overlay.length.zero]

When length is 0, the second string is the null string, whatever new is, and the third starts at position n: so no character of target is replaced, and the result is target padded to n - 1 characters when n is more than one past its end. pad is still checked, as a pad always is.

say '['overlay('XYZ', 'abc', 2, 0)']' '['overlay('XYZ', 'abc', 6, 0, '.')']'
signal on syntax name a
say overlay('XYZ', 'abc', 2, 0, '')
a: say condition('o')~code

[abc] [abc..]
40.23
[bif.overlay.empty]

When target is the null string, the first string is n - 1 copies of pad and the result is those copies followed by new adjusted to length. When new is the null string and length is omitted, nothing is written and the result is target padded to n - 1 characters; when length is given, the null string new is padded to that length.

say '['overlay('x', '', 1)']' '['overlay('x', '', 3)']' '['overlay('x', '', 3, 3, '-')']'
say '['overlay('', 'abc', 2)']' '['overlay('', 'abc', 2, 2)']' '['overlay('', 'abc', 6)']'

[x] [  x] [--x--]
[abc] [a  ] [abc  ]
[bif.overlay.bytes]

OVERLAY cuts and pads by character, one byte each, and copies every byte of new and target that stays unchanged: whitespace, control characters and '00'x are characters like any other, in the strings and as pad.

say c2x(overlay('6100'x, '0000'x, 2, 3, '00'x)) c2x(overlay('c3'x, 'a9a9'x, 2))

00610000 A9C3
[bif.overlay.large]

An n or a length that is a whole number below 10**18 is valid, and a value of 10**18 or more raises SYNTAX 40.12 like any whole number that is too large. The caller's NUMERIC DIGITS setting plays no part.

signal on syntax name a
say overlay('x', 'abc', 1000000000000000000)
a: say condition('o')~code
signal on syntax name b
say overlay('x', 'abc', 2, 1000000000000000000)
b: say condition('o')~code
numeric digits 3
say length(overlay('X', 'abc', 1, 1234))

40.12
40.12
1234

Note. Whether, when and with which code OVERLAY fails for an n or a length whose result cannot be held in memory is not specified.

Note. The reference manual says that when n is greater than one more than the length of target, new is padded at the beginning. This page follows ooRexx's behaviour, which pads target as the rule says. The ANSI draft (9.3.15) defines the third string with its SUBSTR, whose count is negative when n + length is at least LENGTH(target) + 2; read literally it would raise from inside the builtin where this page, like ooRexx, pads (see the note on SUBSTR).

Deviations

[bif.overlay.deviation.4]

interrexx does not specify whether the answer of OVERLAY is the same object as another string of equal value: as target itself, when the call returns all of it unchanged as overlay('', s) does, or as an equal string produced some other way, such as the literal 'abc'. Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'ab' || 'c'
say (overlay('', s) == s) (overlay('', s, 1, 0) == 'abc')
