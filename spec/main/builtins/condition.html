The interrexx Language Specification

CONDITION

CONDITION([option])

ANSI: 9.5.3; rexxref: Functions > Built-in Functions > CONDITION

Deviations: D106

CONDITION reports what the running routine knows about the condition that a trap caught most recently: its name, the instruction that handled it, the state of its trap, and the descriptive information it carried. The conditions themselves, and the traps that catch them, are not defined on this page; it specifies what CONDITION answers for each of its options, before any trap has caught a condition, after a SIGNAL ON trap or a CALL ON trap has caught one, and in the code that follows.

Arguments

[bif.condition.args]

CONDITION takes at most one argument, option, which is optional. The argument count is checked by the builtin call rules: none is required and one is the most, so a call with two arguments raises SYNTAX 40.4, whatever they are, and a call with only omitted places counts as a call with no arguments. CONDITION does not run as a String method: sending the message CONDITION to a string raises SYNTAX 97.1.

say '['condition()']' '['condition( )']' '['condition(,)']'
signal on syntax name a
say condition('C', 'D')
a: say condition('o')~code
signal on syntax name b
say 'x'~condition
b: say condition('o')~code

[bif.condition.option]

option is a string. Its first character, in either case, selects what CONDITION answers, and every character after the first is ignored, so Condition, cond and C select the same. The letters are A, C, D, E, I, O, R and S. Any other first character, a blank included, and the null string raise SYNTAX 40.904. When option is omitted, the call is the call with the option I.

[bif.condition.none]

In a routine, method or program where no trap has caught a condition yet, CONDITION answers the null string for the options C, D, E, I and S and for R, and .nil for A and O.

What a trapped condition answers

[bif.condition.name]

After a trap has caught a condition, the option C answers the name of the condition in capital letters: for a SYNTAX error SYNTAX, for an unset variable under NOVALUE NOVALUE. For a user condition raised by the RAISE instruction, it answers USER, a blank and the name of the condition in capital letters.

[bif.condition.description]

After a trap has caught a condition, the option D answers the description that the condition carries, or the null string when it carries none. A user condition carries what the RAISE instruction's DESCRIPTION gave, and a NOVALUE condition the name of the variable, in capital letters. A SYNTAX condition that the interpreter raises because of an error carries no description string; one that the RAISE instruction raises carries what its DESCRIPTION gave, and none when it has no DESCRIPTION, whether or not it has an ADDITIONAL.

[bif.condition.status]

After a trap has caught a condition, the option S answers the state of the trap for that condition as it is now: ON, OFF or DELAY. A SIGNAL ON trap that has caught a condition is OFF, and a CALL ON trap is DELAY while its handler runs. The state changes with the code that follows: a SIGNAL ON or CALL ON instruction for the condition makes it ON, and a SIGNAL OFF or CALL OFF instruction makes it OFF. A change that the routine of a CALL trap makes to the CONDITION entry of its argument does not change which trap that is, as a Deviation states.

signal on syntax name s
x = 1 + 'a'
s: say condition('S')
signal on syntax name s2
say condition('S')
s2: signal off syntax
say condition('S')
call on user foo name u
call raiser
exit
raiser: procedure
raise user foo return
u: say condition('S')
call on user foo name u
say condition('S')
call off user foo
say condition('S')
return

[bif.condition.object]

After a trap has caught a condition, the option O answers a directory that holds the information of the condition, the same information as the other options answer, and more. Its entries CONDITION, DESCRIPTION and INSTRUCTION equal what C, D and I answer, and so does ADDITIONAL when the condition carries additional information. When it carries none, as with NOVALUE, the directory has no ADDITIONAL entry, and ~additional answers .nil as for any absent entry, which is also what A answers. The directory is a new copy of the condition's entries on each call, so two calls answer two objects. A copy holds the same objects as the condition: adding, removing or replacing an entry of a copy changes nothing that CONDITION answers, while a change to an object that an entry holds, such as the array of ADDITIONAL, shows wherever that object is held. The condition itself is the object that a CALL trap's routine gets as its argument, as the argument rule says.

signal on syntax name s
x = 1 + 'a'
s: o = condition('O')
say o~class (o~condition == condition('C')) (o~description == condition('D')),
    (o~instruction == condition('I')) (o~additional == condition('A'))
o~condition = 'changed'
say condition('C') condition('O')~condition

How long the information lasts

[bif.condition.persist]

The information stays until it is replaced. After a SIGNAL ON trap has caught a condition, the code from the handler's label on, running in the same routine, method or program, still gets it from CONDITION, until another trap catches a condition or the option R clears it. When the handler of a CALL ON trap returns, the information is what it was before the handler ran: that of an earlier trap, or none, in which case CONDITION answers as in the case of no condition.

call on user foo name u
call raiser
say '['condition('C')']' '['condition('I')']' '['condition('S')']'
signal on syntax name s
x = 1 + 'a'
s: say condition('C') '/' condition('C')
call raiser
say condition('C') condition('I') condition('S')
exit
raiser: procedure
raise user foo return
u: say 'handler' condition('C')
return

[bif.condition.reset]

[bif.condition.scope]

The information belongs to the code that holds it. An internal routine, a routine that CALL or a function call reaches by its label, starts with a copy of the information of the code that called it, and what it does to the copy, a trap that catches a condition in it or the option R, is not seen by the caller. A ::ROUTINE, a method and a routine made from other source text start with none. INTERPRET runs in the code that holds it, and shares its information.

call raiser
exit
raiser: procedure
raise user foo return
u: say 'handler' condition('C')
say 'internal' inner()
say 'directive' dir()
say 'method' .box~new~m
say 'made' .routine~new('x', 'return "["condition("C")"]"')~call
