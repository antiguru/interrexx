The interrexx Language Specification

STREAM

STREAM(name [, operation [, command]])

ANSI: 9.7.8; rexxref: Functions > Built-in Functions > STREAM

Deviations: D34, D35, D49, D55, D57, D59, D62, D74, D79, D98, D100

STREAM asks a stream for its state, describes the state, or carries out a command on the stream: opening and closing it, moving its positions, and asking about the file behind it. The other stream builtins open a stream when they need it, and the program that needs nothing STREAM offers does not call it.

Note. What a command answers about the host, a size or a time or a handle, is the host's. The examples here read back the file they make, and check the shape of an answer where its value belongs to the host.

Arguments

[bif.stream.args]

name is a string that names the stream, and is required: it must be neither omitted nor null. operation is a string that chooses what STREAM does, and command is a string, the command that the operation C carries out. STREAM is not a String method. It takes three arguments at the most, by the call rules. The call is checked in this order. The count of arguments comes first, by the call rules. An omitted name then raises SYNTAX 40.5 and a null one SYNTAX 40.27; an operation that is none of those of the next rule raises SYNTAX 40.904. Last, a command that is missing for the operation C raises SYNTAX 40.3, and a command given for any other operation raises SYNTAX 40.4.

f = 'spec-stream-args.tmp'
do e over "stream()", "stream(,'s')", "stream('','s')", "stream(f,'x')", "stream('','x')",,
          "stream(f,'c')", "stream(f,'s','close')", "stream(f,'d','close')",,
          "stream(f,'c','close','x')", "stream(f,,'close')", "stream(f,'x','close')",,
          "stream(f,'c','query exists')"
  say left(e, 28) '=>' try(e)
end
exit
try: signal on syntax name oops
  interpret 'r =' arg(1)
  return 'no error'
oops: return condition('o')~code

say stream(f) stream(f, ) stream(f, 'S') stream(f, 'state') stream(f, 'Sxyz')

State and description

[bif.stream.state]

The state of a stream is one of four words. UNKNOWN is the state of a stream that is not open. READY is that of an open stream whose last operation went as asked. NOTREADY is that of an open stream whose last read or write could not do all it was asked to, at the end of the data for example. ERROR is that of a stream whose last read or write failed, such as a read of a name that could not be opened, or a write to a stream that was opened for reading only. The state belongs to the one stream: an operation on another changes nothing in it.

a = 'spec-stream-state-a.tmp'
b = 'spec-stream-state-b.tmp'
call sysfiledelete a
call sysfiledelete b
say stream(a) stream(b)
call charout a, 'xy'
call charout b, 'pq'
say stream(a) stream(b)
x = charin(a, 1, 5)
say stream(a) stream(b)
x = charin(b, 1, 1)
say stream(a) stream(b)
say stream('spec-stream-state-none.tmp', 'c', 'open read')
x = charin('spec-stream-state-none.tmp')
say stream('spec-stream-state-none.tmp')
call charout a
call charout b
call sysfiledelete a
call sysfiledelete b

[bif.stream.change]

Opening a stream, and every read, write, and SEEK or POSITION that succeeds, leave it READY, or NOTREADY when a read or write could not do it all, and a read or write that fails leaves ERROR. CLOSE leaves it UNKNOWN. FLUSH and QUERY leave the state as it was.

[bif.stream.description]

The description of a stream is its state, a colon, and more information about the state when there is any. READY: and UNKNOWN: have none. A stream whose last read stopped at the end of the data is NOTREADY:EOF. A stream in the ERROR state has the host's number for the failure, and may have words after it; in the examples that follow the number is not shown.

f = 'spec-stream-desc.tmp'
call sysfiledelete f

call charout f, 'ab'

x = charin(f, 1, 5)

d = stream(f, 'd')

Commands

[bif.stream.command]

With the operation C, STREAM carries out command, which begins with a word that names the command: OPEN, CLOSE, FLUSH, SEEK, POSITION or QUERY. The word may be in any case, and may be shortened to any of its leading letters down to the first. What is after the word is the command's own, and the rules for each say what it is. A first word that no command begins with raises SYNTAX 93.914, and anything the command does not take after it, SYNTAX 93.0. A command that is the null string, or only blanks, has no first word, and what it does is not specified.

f = 'spec-stream-command.tmp'
call sysfiledelete f
call charout f, 'abc'
say stream(f, 'c', 'seek 2') stream(f, 'c', 'SEEK 2') stream(f, 'c', 's 2') stream(f, 'c', 'se 2')
say stream(f, 'c', 'position 3') stream(f, 'c', 'p 3') stream(f, 'c', 'f') stream(f, 'c', 'q size')
signal on syntax name a
say stream(f, 'c', 'seeker 2')
a: say condition('o')~code
signal on syntax name b
say stream(f, 'c', 'flush now')
b: say condition('o')~code
signal on syntax name c
say stream(f, 'c', 'frobnicate')
c: say condition('o')~code
call stream f, 'c', 'close'

OPEN

[bif.stream.open.result]

OPEN opens the stream and answers READY:. If it cannot, it answers ERROR: and the host's number for the failure, and raises NOTREADY. A name that is a directory, or is in a directory that does not exist, cannot be opened, and the stream is then not open: its state is UNKNOWN. With no option the stream is opened for reading and writing, and the OPEN of a file that does not allow both fails, where a read alone would open it. A file that does not exist is created by OPEN, unless it is opened for reading only. What follows OPEN is a list of options, the next rules give them. The words SHARED, SHAREREAD, SHAREWRITE and NOBUFFER are accepted, and what they do is not specified; so are their shortenings as far as SHARER, SHAREW and NOB. Any other word in the list raises SYNTAX 93.0, a shortening of SHARED among them.

f = 'spec-stream-open.tmp'

[bif.stream.open.mode]

The options of OPEN say what the stream is for and where it begins. READ opens it for reading only, WRITE for writing only, and BOTH, which is the default, for both. APPEND puts the write position after the last character, which is where a stream that is open for writing and neither APPEND nor REPLACE has it as well, and keeps it there: the write position cannot be moved into the data that the file held when it was opened, by SEEK or by a start or line that a write gives; see Deviation 79. A position at the end of that data, or past it, is allowed, but a write still goes after the last character. On a file that the stream can only write, see Deviation 74. REPLACE empties the file and begins the write position at its start. An option may be shortened as far as to REA, W, BO, AP and REP, and its case does not matter. A word that is given twice, two of READ, WRITE and BOTH, READ with APPEND or REPLACE, and APPEND with REPLACE raise SYNTAX 93.0. A stream for reading only refuses a write: it fails, and the state is ERROR.

[bif.stream.open.binary]

The option BINARY RECLENGTH n opens the stream as a stream of records of n characters, n being 1 or more: its lines are not delimited by line ends but are consecutive n characters, whatever they are. Closing and flushing

[bif.stream.close]

CLOSE closes the stream and answers READY:; its state is then UNKNOWN. The characters written are in the file, and the next use of the name opens the stream afresh. A stream that is not open has nothing to close, and the answer is the null string. A standard stream is closed in the same way: CLOSE of the standard input, output or error answers READY: and leaves its state UNKNOWN, and the next stream builtin that reads from it, writes to it, counts what is left in it (CHARS or LINES) or opens it opens it again on the same input or output, so that later reads and writes carry on, as the lifetime rule says. A QUERY or a FLUSH leaves the state as it was.

f = 'spec-stream-close.tmp'
call sysfiledelete f
say '['stream(f, 'c', 'close')']' stream(f)
call charout f, 'abc'
say stream(f) stream(f, 'c', 'close') stream(f) '['stream(f, 'c', 'close')']'
say chars(f) charin(f, , 1)
call charout f
call sysfiledelete f

Positions

[bif.stream.seek]

SEEK sets a position of the stream and answers the new one. POSITION is the same command. After the word there is an offset, and then options in any order. The offset is a whole number, which may have a prefix: = or no prefix for a position counted from the start of the data, 1 being its first character; < for a position counted back from the end, <0 being the one past the last character; + and - for a position counted forward or back from the read position with READ, and from the write position with WRITE (see Deviation 49). READ sets the read position, WRITE the write position, and when neither is given a stream open for reading and writing has both set to the answer, and a + or - then counts from the read position (see Deviation 49). CHAR counts characters and is the default; for LINE see the next rule. A position past the end of the data is allowed: a read there finds nothing, and a write there fills the gap, except on a stream opened APPEND, where a write goes after the last character wherever the write position is. A stream that is not open is opened by SEEK; when it cannot be, SEEK answers 0, raises NOTREADY, leaves the state ERROR, and creates nothing. An offset that is not a whole number or an option that is not one of these raises SYNTAX 93.0, and a missing offset SYNTAX 93.903.

f = 'spec-stream-seek.tmp'
call sysfiledelete f
call charout f, '0123456789'

[bif.stream.deviation.34]

In a stream's name, as in every name interrexx qualifies, each .. removes exactly the one component before it, however the component was written, so .b/../c names the file c beside the directory .b. ooRexx removes none after a doubled slash and two after a component that starts with a period, so its stream can be a different file.

call charout f

call sysfiledelete f
call sysrmdir base || '/.b'
call sysrmdir base

[bif.stream.deviation.79]
