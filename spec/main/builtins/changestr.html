The interrexx Language Specification

CHANGESTR

CHANGESTR(needle, haystack, newneedle [, count])

ANSI: 9.3.4; rexxref: Functions > Built-in Functions > CHANGESTR

Deviations: D4

CHANGESTR copies a string, replacing the occurrences of one string in it with another. Occurrences that overlap are not both replaced, and a count argument can limit how many are.

Arguments

[bif.changestr.method]

CHANGESTR is a builtin that runs as a String method, and haystack, its second argument, is the receiver; needle, newneedle and count become the message's arguments, in that order. needle, haystack and newneedle are strings, and the function form takes needle first. count is a whole number, described by its own rule. The argument count is checked by the builtin call rules: three arguments are required and four is the most.

say changestr('an', 'banana', '__') 'banana'~changestr('an', '__') 'banana'~changestr('an', '__', 1)
signal on syntax name a
say changestr('a', 'abc')
a: say condition('o')~code
signal on syntax name b
say changestr('a', 'abc', 'x', 1, 1)
b: say condition('o')~code
signal on syntax name c
say changestr('a', , 'x')
c: say condition('o')~code
signal on syntax name d
say changestr('a', 'abc', , 1)
d: say condition('o')~code

[bif.changestr.count]

count is a whole-number argument, so it raises SYNTAX 40.12 when it does not have that form or has a value that is not a whole number. A whole number below 0 raises SYNTAX 93.906; -0 is 0. The null string is not a whole number, so an empty count raises 40.12 and does not stand for an omitted one. The form check comes first, so a count that fails it raises 40.12 whatever its sign.

say changestr('a', 'banana', 'x', ' + 2 ') changestr('a', 'banana', 'x', '-0'),
    changestr('a', 'banana', 'x', '2.000')
signal on syntax name a
say changestr('a', 'banana', 'x', -1)
a: say condition('o')~code
signal on syntax name b
say changestr('a', 'banana', 'x', '')
b: say condition('o')~code
signal on syntax name c
say changestr('a', 'banana', 'x', '-0.4')
c: say condition('o')~code
signal on syntax name d
say changestr('a', 'banana', 'x', '-1e5')
d: say condition('o')~code

[bif.changestr.count.default]

When count is omitted, every occurrence that the result rule selects is replaced. A count at least the number of such occurrences has the same effect, however large it is, up to the largest value the argument accepts.

say changestr('a', 'banana', 'x') changestr('a', 'banana', 'x', ),
    changestr('a', 'banana', 'x', 3) changestr('a', 'banana', 'x', 999999999999999999)

bxnxnx bxnxnx bxnxnx bxnxnx

The result

[bif.changestr.result]

CHANGESTR scans haystack from its first character to its last. At each position where needle occurs, it appends newneedle to the result and continues with the character after the occurrence; where needle does not occur, it appends the character at that position and continues with the next one. Every occurrence found this way is replaced, up to count of them when count is given: after the countth replacement the rest of haystack is appended unchanged. The match is exact, so case matters, and every character of the strings, whitespace and '00'x included, is an ordinary character.

say changestr('o', 'foolish', '') changestr('o', 'foolish', '0') changestr('o', 'foolish', '0', 1)
say changestr('A', 'banana', 'x') changestr(' ', 'a b  c', '_')
say c2x(changestr('00'x, 'a' || '00'x || 'b', '0000'x))

flish f00lish f0olish
banana a_b__c
61000062
[bif.changestr.overlap]

Occurrences that overlap are not all replaced: an occurrence is replaced only when it begins after the end of the one replaced before it, as COUNTSTR counts them. The text that newneedle brings in is never searched again, so a newneedle that holds needle does not make the call replace more.

say changestr('aa', 'aaaaa', 'b') changestr('aba', 'ababababa', 'X'),
    changestr('a', 'aaaa', 'aa') changestr('a', 'aaaa', 'aa', 2)

bba XbXba aaaaaaaa aaaaaa
[bif.changestr.count.zero]

When count is 0, nothing is replaced and the result is haystack unchanged. count is still checked, as it always is.

say changestr('a', 'banana', 'x', 0) changestr('a', 'banana', 'x', '0.0')
signal on syntax name a
say changestr('a', 'banana', 'x', 'zero')
a: say condition('o')~code

banana banana
40.12
[bif.changestr.empty-needle]

When needle is the null string, it is taken to occur nowhere, so nothing is replaced and the result is haystack unchanged, for every newneedle and every count that passes its check.

say '['changestr('', 'abc', 'x')']' '['changestr('', 'abc', 'x', 2)']'
say '['changestr('', '', 'x')']'

[abc] [abc]
[]
[bif.changestr.empty-haystack]

When haystack is the null string, needle occurs in it nowhere, and the result is the null string, for every count that passes its check.

say '['changestr('a', '', 'x')']' '['changestr('a', '', 'x', 3)']'
signal on syntax name a
say changestr('a', '', 'x', -1)
a: say condition('o')~code

[] []
93.906
[bif.changestr.empty-newneedle]

When newneedle is the null string, the occurrences replaced are deleted: the result is haystack without them. This is not the same as omitting newneedle, which is an error.

say changestr('a', 'banana', '') '['changestr('banana', 'banana', '')']'
say changestr('a', 'banana', '', 2)

bnn []
bnna

Note. The ANSI draft (9.3.4) has no count argument; it replaces every occurrence, searching from the end of the previous one, which gives the rules above for the call without count. The count argument and its checks follow ooRexx.

Deviations

[bif.changestr.deviation.4]

interrexx does not specify whether the answer of CHANGESTR is the same object as another string of equal value: as haystack itself, when the call replaces nothing, or as an equal string produced some other way, such as the literal 'banana'. Through identityHash, or as a key of an IdentityTable or IdentitySet, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'ban' || 'ana'
say (changestr('x', s, 'y') == s) (changestr('', s, 'y') == 'banana')
