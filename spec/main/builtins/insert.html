The interrexx Language Specification

INSERT

INSERT(new, target [, n [, length [, pad]]])

ANSI: 9.3.11; rexxref: Functions > Built-in Functions > INSERT

Deviations: D4

INSERT puts a string into another string after a given character, adjusting the inserted string to a given length, and answers the combined string.

Arguments

[bif.insert.method]

INSERT is a builtin that runs as a String method, and target, its second argument, is the receiver; new, n, length and pad become the message's arguments, in that order. new and target are strings, n is a whole number of the kind the next rule describes, length is a length, and pad is a pad. The arguments are checked in the order the conventions give, and the argument count by the builtin call rules: two are required and five is the most.

say insert('123', 'abc', 1) 'abc'~insert('123', 1) '|' 'abc'~insert('123', 1, 2, '.')
signal on syntax name a
say insert('123')
a: say condition('o')~code
signal on syntax name b
say insert('123', 'abc', 1, 1, '.', 1)
b: say condition('o')~code
signal on syntax name c
say insert(, 'abc')
c: say condition('o')~code
signal on syntax name d
say insert('123', , 1)
d: say condition('o')~code
signal on syntax name e
say insert('123', 'abc', 'x')
e: say condition('o')~code
signal on syntax name f
say insert('123', 'abc', 1, 1, '')
f: say condition('o')~code

[bif.insert.n.check]

In INSERT, n is a whole-number argument whose value must not be negative. A negative value raises SYNTAX 93.906. An n of 0 is allowed, and so is -0, which is 0. The check is a range check, and falls with those of the conventions, from left to right with the check of length.

say insert('X', 'abc', 0) insert('X', 'abc', '-0')
signal on syntax name a
say insert('X', 'abc', -1)
a: say condition('o')~code
signal on syntax name b
say insert('X', 'abc', -1, -1)
b: say condition('o')~code
signal on syntax name c
say insert('X', 'abc', 0, -1)
c: say condition('o')~code
signal on syntax name d
say insert('X', 'abc', -1, 'x')
d: say condition('o')~code
signal on syntax name e
say insert('X', 'abc', -1, 1, '**')
e: say condition('o')~code

Note. A position elsewhere must be positive; n here counts the characters before the insertion, so 0 is its first value.

[bif.insert.n.default]

When n is omitted, it is 0: new goes before the first character of target.

say insert('45', 'xyz') insert('45', 'xyz', ) insert('45', 'xyz', , 1)

45xyz 45xyz 4xyz
[bif.insert.length.default]

When length is omitted, it is the length of new, so new is inserted whole.

say insert('45', 'xyz', 1) insert('', 'xyz', 1) insert('45', 'xyz', 1, )

x45yz xyz x45yz
[bif.insert.pad.default]

When pad is omitted, it is the blank, '20'x.

say '['insert('1', 'abc', 5, 3)']' '['insert('1', 'abc', 5, 3, )']'

[abc  1  ] [abc  1  ]

The result

[bif.insert.result]

INSERT returns the concatenation of three strings, in this order. The first is the first n characters of target, followed by as many copies of pad as it takes to make n characters when target has fewer. The second is new adjusted to exactly length characters: cut at the right when it has more, and followed by copies of pad when it has fewer. The third is the characters of target after position n, which is the null string when target has n characters or fewer. So the length of the result is length plus the larger of n and the length of target.

say insert('45', 'xyz', 3) insert('45', 'xyz', 1, 1) insert('45', 'xyz', 1, 4, '+')
say insert('45', 'xyz', 5, 6, '*') insert('45', 'xyz', , 5, '=')
say '['insert('45', 'xyz', 1, 0)']' insert('1', 'xyz', 4, 3)'.'

xyz45 x4yz x45++yz
xyz**45**** 45===xyz
[xyz] xyz 1  .
[bif.insert.past-end]

When n is greater than the length of target, the gap is filled from target's side: target is extended on the right with copies of pad to n characters, new adjusted to length follows, and nothing follows new. This holds when length is 0, so the result is then target padded to n characters.

say insert('X', 'ab', 4, 1, '.') insert('X', 'ab', 4, 3, '.') insert('xyz', 'ab', 4, 5, '.')
say insert('X', 'ab', 3, 0, '.') insert('X', 'ab', 2, 0, '.')

ab..X ab..X.. ab..xyz..
ab. ab
[bif.insert.empty]

When target is the null string, the first string is n copies of pad and the third is empty, so the result is those copies followed by new adjusted to length. When new is the null string and length is omitted, the result is target padded to n characters, and when length is given the null string new is padded to that length.

say '['insert('X', '', 0)']' '['insert('X', '', 3, 2, '.')']'
say '['insert('', 'ab', 1)']' '['insert('', 'ab', 1, 2, '.')']' '['insert('', '', 3)']'

[X] [...X.]
[ab] [a..b] [   ]
[bif.insert.length.zero]

When length is 0, the second string is the null string, whatever new is: the result is target, padded on the right to n characters when n is more than its length. pad is still checked, as a pad always is.

say '['insert('XYZ', 'ab', 1, 0)']' '['insert('XYZ', 'ab', 5, 0, '.')']'
signal on syntax name a
say insert('XYZ', 'ab', 1, 0, '')
a: say condition('o')~code

[ab] [ab...]
40.23
[bif.insert.bytes]

INSERT cuts and pads by character, one byte each, and copies every byte of new and target that stays unchanged: whitespace, control characters and '00'x are characters like any other, in the strings and as pad.

say c2x(insert('0061'x, '00'x, 1, 3, '00'x)) c2x(insert('c3a9'x, 'ff'x, 0, 1))

00006100 C3FF
[bif.insert.large]

An n or a length that is a whole number below 10**18 is valid, and a value of 10**18 or more raises SYNTAX 40.12 like any whole number that is too large. The caller's NUMERIC DIGITS setting plays no part.

signal on syntax name a
say insert('X', 'abc', 1000000000000000000)
a: say condition('o')~code
signal on syntax name b
say insert('X', 'abc', 1, 1000000000000000000)
b: say condition('o')~code
numeric digits 3
say length(insert('X', 'abc', 1234)) insert('X', 'abcdefghijkl', 1E1)

40.12
40.12
1235 abcdefghijXkl

Note. Whether, when and with which code INSERT fails for an n or a length whose result cannot be held in memory is not specified.

Note. The reference manual says that when n is greater than the length of target, new is padded at the beginning. This page follows ooRexx's behaviour, which pads target as the rule says. The ANSI draft (9.3.11) defines the third string with its SUBSTR, whose count is negative when n is at least LENGTH(target) + 1; read literally it would raise from inside the builtin where this page, like ooRexx, pads (see the note on SUBSTR).

Deviations

[bif.insert.deviation.4]

interrexx does not specify whether the answer of INSERT is the same object as another string of equal value: as target itself, when the call returns all of it unchanged as insert('', s) does, or as an equal string produced some other way, such as the literal 'abc'. Through identityHash, or as a key of an IdentityTable, the answer may be either, and a program can rely only on the value, which is equal under ==. ooRexx differs: it often answers a new object where interrexx answers the existing one.

s = 'ab' || 'c'
say (insert('', s) == s) (insert('', s, 3, 0) == 'abc')
