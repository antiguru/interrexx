The interrexx Language Specification

SETLOCAL

SETLOCAL()

rexxref: Functions > Built-in Functions > SETLOCAL (Linux only)

SETLOCAL records where the program is and what every environment variable holds, so that ENDLOCAL can put both back later. It answers 1. The save itself changes nothing the program can see; what the program does afterwards to the current directory and to the environment variables, for instance with DIRECTORY and VALUE, is what ENDLOCAL undoes.

The environment variables are those of the process, which the ENVIRONMENT selector of VALUE reads and writes and which the commands the program starts inherit. Variables of the program itself are not among them.

Note. The examples change only variables whose names start with SPEC_SETLOCAL, and compare the current directory with the one the program started in, so they do not depend on what the program starts with. A program that calls SETLOCAL and no ENDLOCAL leaves nothing for the other examples to see. Each example takes at most one save back, counting the one that the reference implementation puts back at the end of a ::routine, a method or the program, because that implementation can fail in a program that takes a save back a second time.

Arguments

[bif.setlocal.args]

SETLOCAL takes no argument. A call with an argument raises SYNTAX 40.4, by the call rules. A trailing omitted place adds nothing to the count, so SETLOCAL(,) is a call without an argument. SETLOCAL does not run as a String method: sending the message SETLOCAL to a string raises SYNTAX 97.1.

signal on syntax name a
say setlocal(1)
a: say condition('o')~code
signal on syntax name b
say setlocal(, 'x')
b: say condition('o')~code
signal on syntax name c
say 'x'~setlocal
c: say condition('o')~code
signal off syntax
say setlocal(,)

The result

[bif.setlocal.answer]

A call answers 1 once the directory and the environment variables are saved, and a call as a subroutine sets RESULT to it. A program can call SETLOCAL any number of times; each call saves the state as it is then, and ENDLOCAL takes the saves back in the opposite order.

say setlocal() datatype(setlocal(), 'W')
call setlocal
say result

1 1
1
[bif.setlocal.nothing]

SETLOCAL does not change the current directory, the environment variables or any variable of the program: they have the same values after the call as before it.

here = directory()
call value 'SPEC_SETLOCAL_A', 'a0', 'ENVIRONMENT'
v = 'kept'
call setlocal
say (directory() == here) value('SPEC_SETLOCAL_A',, 'ENVIRONMENT') v

1 a0 kept
[bif.setlocal.owner]

A save belongs to the code that is running when SETLOCAL is called: the program, a ::routine or a method. An internal routine, with or without PROCEDURE, and the code that INTERPRET runs are part of the code that runs them. A save made in one of them is therefore still outstanding after it has returned, the changes made after the save stay in force, and an ENDLOCAL in the code that ran it takes the save back; a save made by that code can likewise be taken back by an ENDLOCAL in one of them. A ::routine or a method sees only its own saves, as ENDLOCAL in a routine shows.

call value 'SPEC_SETLOCAL_D', 'd0', 'ENVIRONMENT'
call sub
say value('SPEC_SETLOCAL_D',, 'ENVIRONMENT')
interpret "say endlocal()"
say value('SPEC_SETLOCAL_D',, 'ENVIRONMENT')
exit
sub: procedure
call setlocal
call value 'SPEC_SETLOCAL_D', 'd1', 'ENVIRONMENT'
return

[bif.setlocal.return]

When a ::routine or a method ends with saves of its own outstanding, the oldest of them is put back: the code that called it sees the current directory of that save, and each environment variable the save held has the value it held, as an ENDLOCAL would give. A variable the program created after the save keeps its value, as ENDLOCAL says. The return of an internal routine puts nothing back, by the rule above. What the end of the program does with saves outstanding is not specified.

call value 'SPEC_SETLOCAL_B', 'before', 'ENVIRONMENT'
here = directory()
call r
say value('SPEC_SETLOCAL_B',, 'ENVIRONMENT') (directory() == here),
    value('SPEC_SETLOCAL_N',, 'ENVIRONMENT')
exit
::routine r
call setlocal
call value 'SPEC_SETLOCAL_B', 'inside', 'ENVIRONMENT'
call value 'SPEC_SETLOCAL_N', 'new', 'ENVIRONMENT'
call directory '/'
say value('SPEC_SETLOCAL_B',, 'ENVIRONMENT') directory()
return

inside /
before 1 new

call value 'SPEC_SETLOCAL_C', 'c0', 'ENVIRONMENT'
here = directory()
.t~new~m
say value('SPEC_SETLOCAL_C',, 'ENVIRONMENT') (directory() == here)

::method m
call setlocal
