**Goal:** `rxmath`, `rxregexp`, `rxunixsys` and `rxsock` run as Rust builtins with no `.so`, their
`.cls` packages are rewritten, `hostemu` and `orxncurses` build unmodified against our libraries,
and the `Row10NativeApi`/`Phase 10 Extension` groups they unlock pass.

**Architecture:** The four libraries join `internal_routines.rs`'s internal packages beside `REXX`
and `rexxutil`, so `::requires 'x' LIBRARY`, `.Package~loadLibrary` and `RxFuncAdd(..., 'x', ...)`
bind to Rust bodies before any `dlopen`. The rewritten `.cls` packages ship inside the crate and are
found by `::requires` the way this crate finds a package file. `hostemu` and `orxncurses` are C++
built by script, like the PR 3 test binaries.

**Spec:** `docs/superpowers/specs/2026-11-02-phase-10-design.md`, and
`docs/superpowers/specs/extensions-behaviour.md` (the description; its Rulings win).

## Decisions

* **Internal packages.** `Package` in `internal_routines.rs` gains `RxMath`, `RxRegExp`, `RxUnixSys`
  and `RxSock`. Each package's library name matches the oracle's case rule
  (`extensions-behaviour.md` "Loading"). A routine package answers `RxFuncAdd`/`RxFuncQuery` and
  `::requires LIBRARY`. `rxregexp` registers the native methods its `.cls` package binds.
* **Packages on disk.** The rewritten `rxregexp.cls`, `socket.cls`, `streamsocket.cls`, `mime.cls`
  and `smtp.cls` live in `rust/crates/rexx-exec/packages/`. They are embedded in the binary and found
  by `::requires` after the program's own search path, so a program file of the same name still
  wins, as on the oracle.
* **Test framework.** ooTest's `ooTest.frm` requires `rxregexp.cls`. Once Task 2 lands, the crate's
  harnesses use the crate's own package and Rust `rxregexp`. The oracle's `librxregexp.so` symlink in
  `classic_api.rs` and the suite harness goes.
* **Clean-tree oracle.** In the clean tree, the oracle's `bin/rxregexp.cls` is replaced by a link to
  the crate's package once Task 2 has written it, so the oracle can still run ooTest. Oracle targets
  for the groups below were recorded by the controller from the full checkout.
* **hostemu and orxncurses** are built by `scripts/build-extensions.sh` from
  `third_party/ooRexx/extensions/{hostemu,orxncurses}` unmodified, against `api/` and our two
  libraries, into `rust/target/extensions/`, with the same `ldd` check as the test binaries. The
  harnesses put that directory on the library path. A build host without ncurses headers skips
  `orxncurses` with a clear message. The ncurses group then stops for Moritz, with no row added.
