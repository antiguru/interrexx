## Decisions

* **One connection per process,** opened on first need and kept for the process's life, so
  owner-only registrations stay owned. HALT ends a blocked pull through `Transport::cancel`.
* **The session queue is local until shared.** A process that starts with `RXQUEUESESSION` set uses
  the service from its first queue operation. Otherwise the queue lives in process. Before the first
  command or child process starts, its contents move to the service and the child inherits
  `RXQUEUESESSION`; from then on, it is remote. Nothing outside the process could have seen it before.
* **Session queue lifetime, replacing Resolution 4:** a session queue goes when no connection uses it
  and it is empty. A queue holding lines counts as state for the daemon's exit rule. This keeps
  `cmd | rxqueue` working after `rxqueue` exits.
* **Registered functions resolve after internal and builtin functions and before external files,** as
  the description orders it, through the existing native library loader.

## Review Focus

1. `'ls | rxqueue'` then `PULL` in the same program, with no daemon running beforehand.
2. A program that never spawns a command and only uses `QUEUE`/`PULL`: no daemon starts.
3. HALT during a `PULL` on an empty external queue: the HALT raises, the queue stays usable.
4. `RxFuncAdd` in one run, `RxFuncQuery` in a second: 0, as on the oracle.
5. Daemon killed mid-program: the next queue operation raises a clean error, not a hang or panic.
