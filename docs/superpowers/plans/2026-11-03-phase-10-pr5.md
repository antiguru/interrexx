# Phase 10 PR 5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** PPWizard and the Rexx Parser, fetched by a pinned script, run on this crate as on the
oracle, and the results are committed as a record.

**Architecture:** `scripts/fetch-corpus.sh` fetches into the ignored `corpus/` directory and checks
pinned sha256 hashes. `scripts/run-corpus.sh` runs both programs on both sides and prints one TSV
line per program. CI runs neither.

**Spec:** `docs/superpowers/specs/2026-11-02-phase-10-design.md`, "Corpus".

## Global Constraints

As in `docs/superpowers/plans/2026-11-02-phase-10.md`. The corpus sources are never committed:
PPWizard's licence allows distributing its archive only in full.

## Decisions

* **Pins.** These are the archives the 2026-10-17 probe measured:
  * `ppwall.zip`, sha256 `c538b4d8…`, with `ppwizard.rex` at `d6853c29…`.
  * The Rexx Parser at commit `33cf252d`, as GitHub's tarball, sha256 `7b6c0a8e…`.
* **PPWizard's patch** is the two one-word changes in `docs/superpowers/plans/ppwizard-gate.md`,
  applied at fetch time; the licence allows modifying the code. The bar: rc 0 and the page it writes
  for `tryme.it`, byte-identical on both sides.
* **Short paths.** Both sides run from the same short directory. PPWizard writes its input's path
  into the page. It also builds variable names from the hex of that path, so a long path exceeds
  the oracle's symbol length and fails there.
* **The Rexx Parser** runs each suite standalone, as in the 2026-10-17 record. Each side has its own
  `rxregexp.cls` in `tests/framework/`. The bar is the same rc and "Tests ran" line per suite. The
  crate side gets the oracle's Rexx-only packages (`yaml.cls` and the rest) on `PATH`, as the suite
  harness lays them. The five packages this crate rewrites are left out.
