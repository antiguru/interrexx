# Recommended follow-up

The stdin launcher can retain coverage without adding exclusions. Keep the current hard virtual-address cap for ordinary runs, but let an explicitly instrumented child inherit unlimited virtual address space while retaining the resident cgroup cap, open pipe, timeout, and huge-stack failure preflight. All four existing bodies already passed with that arrangement in these probes, although a source change must use a reliable instrumentation signal rather than assuming every `TSAN_OPTIONS` user has an instrumented binary. The helper is shared with scheduler spawn-failure tests, so their coverage must also be retained and checked after an authorized change.

The exact 100,000-level depth contract cannot be exercised faithfully with this runtime's 65,536-entry shadow stack by merely increasing the native thread stack. Preserve the full exact-boundary tests in ordinary debug and release runs, then choose either a sanitizer runtime with sufficient shadow-stack capacity, an evaluation implementation that removes the excessive host recursion, or an explicitly approved sanitizer-specific lower-depth test configuration that still exercises both PARSE and ordinary evaluation at and past the configured boundary. The last option needs approval because the existing fourteen exclusions do not authorize another exclusion or replacement of the production-depth coverage. No option has been implemented here, no new deviation is accepted, and the required repeat sanitizer run with zero diagnostics remains outstanding.
